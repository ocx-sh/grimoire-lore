# Dated facts for GitHub and package-registry presence

Every limit, policy clause and behaviour that a github-presence rule relies on is a row here. A rule cites a row by id in square brackets, for example `[GH-F02]`. Never quote a limit from memory, and never copy one into another file without its id.

- **Format.** Ten columns, as the channel-publishing registry defines them. `source_date` is the page's own date, `relative:<text>@<fetch date>`, or `none` when the page shows no date. `verified` is the date an agent fetched the page and saw the `expect` pattern on it. No cell holds a literal pipe, so `expect` uses no alternation.
- **Cadence.** Every row carries `refresh_days`: 180 for hard limits, 90 for policy, API fields and behaviour claims, `expires:<date>` for an event. `facts_check.py` in the channel-publishing skill fails on the first overdue row. Re-fetch the page, confirm `expect` still matches, then set `verified` to the fetch date. Never extend a date without fetching.
- **Provenance.** `platform` is the registry or host's own page. `authority` is a standards body or a published specification. `independent` is a third-party measurement. A row with `independent` provenance never becomes a threshold in a check.
- **Rows that expire.** OI-F01 expires on 2026-12-05: on that day retire CH-GH-28 and keep the "never cite OSS Insight" line. VS-F04 expires on 2026-12-01: on that day re-read the publishing page and replace the row with the federated-identity wording.
- **Not in this file.** The crop or padding that Meta and LinkedIn apply to a 1280 x 640 card is unmeasured, because the inspectors need a logged-in account. No row states it, and no rule may.
