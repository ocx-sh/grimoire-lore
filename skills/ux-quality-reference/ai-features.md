# AI features: disclosure, rendering model output and conversation mechanics

Owns UX-AI-01 to 25 for a human-facing LLM interface: a chat, an "Ask AI" box, a drafting assistant, an editor panel that shows model text. The rows cover what the interface must say about itself, what the renderer must refuse to draw, which trust cues are allowed, and how a streamed answer and its failures behave. Not here: approval of an agent's tool call (UX-ACT-18 to 28, the `ux-agent-interfaces` skill); the ARIA basics of live regions (the UX-A11Y rows); AI-authorship badges on a published docs page (`docs-quality`, DOC-PLAIN-08); injection defences in the model pipeline (security); crawler policy, posts, videos and generated release notes (the marketing and channel skills).

## Rendering model output

Model output is untrusted input to the renderer, and a markdown image is the leak. With default settings, `marked` 18.3.0, `markdown-it` 15.0.3 and `react-markdown` 10.1.0 each render a remote markdown image as a live fetch, and DOMPurify keeps it. Shipped products leaked conversation data this way: M365 Copilot (CVE-2025-32711) and Salesforce Agentforce (ForcedLeak).

| ID | Rule | Rationale | Verification | Severity |
|---|---|---|---|---|
| UX-AI-09 | Never let model output trigger a network image load. Override the renderer's image hook (`components={{img:...}}`, `renderer.image`, `md.renderer.rules.image`) to render text such as `[image blocked: alt]`, or to allow only hosts on a list the product owns. Back this with a CSP `img-src` that contains no `*`, `http:`, `https:` or user-content host. `'self'` and `data:` are fine, because a `data:` image makes no network request. Every allow-listed host carries a one-line owner note. A host that serves attacker-writable content (document and form hosts, URL shorteners, open redirects, expired domains) is never allow-listed. | MEASURED. All three renderers fetch remote images by default, and `react-markdown` also hoists a `<link rel="preload">`. EchoLeak abused "a Microsoft Teams proxy allowed by the content security policy". ForcedLeak used an expired allow-listed domain bought for about $5. OWASP LLM05:2025 requires strict CSP. | See block UX-AI-09: every renderer found needs an image override in the same module, and the served CSP shows an `img-src` that passes the list. The canary test is part of UX-AI-12. | MUST |
| UX-AI-10 | Never render raw HTML from model output, and accept only `https`, `mailto` and relative URLs in model-supplied links. With `marked`, add a sanitizer. With `markdown-it`, keep `html:false`. With `react-markdown`, never add `rehype-raw` without `rehype-sanitize` and a schema. | MEASURED. `marked` passes `<script>`, `<iframe>`, `onerror`, `javascript:` and `data:` hrefs through ("Marked does not sanitize the output HTML"). `markdown-it` escapes them and `react-markdown` blanks them. | See block UX-AI-10 and review every hit. Unit tests with a link whose target is `javascript:alert(1)` and one whose target is `data:text/html;base64,PHNjcmlwdD4=` assert that no such `href` appears. The cases file carries both. | MUST |
| UX-AI-11 | Do not auto-link bare URLs in model output unless a link policy runs after linkify. Show the destination host beside every model-supplied link, and open it through `rel="noopener noreferrer"` or a confirm step. | MEASURED. `marked`, `markdown-it {linkify:true}` and `remark-gfm` turn a bare URL with a query string into a link. Link text can hide the data in the URL. | See block UX-AI-11: a hit needs a `renderer.link`, `components={{a:` or `link_open` override in the same file. Reading test: `[docs](https://x.example/c?q=...)` renders as `docs (x.example)`. | SHOULD |
| UX-AI-12 | Ship a CI regression test for each model-output renderer. Feed it every case in `checks/model-output-cases.json`: a remote inline image, a reference-style image, a bare URL with a query, a `javascript:` link, a `data:` link, raw `<img onerror>`, `<script>` and `<iframe>`. Assert that the output has no remote `<img>`, no `<link rel="preload">`, no live script and no href with a bad scheme. | MEASURED. A regex for the inline image form misses the reference-style form. EchoLeak bypassed production link redaction "with reference-style Markdown". | The test file exists and CI runs it. Delete the image hook once: the test must fail. Then restore the hook. See "Using the cases file" below. | MUST |
| UX-AI-13 | Keep content from outside the conversation (retrieved pages, files, tool results, third-party packages) labelled at both ends. On the way into a model, pass it inside a named, delimited data boundary that carries its origin. For an MCP server, the tool result wraps third-party text the same way. In the UI, render it as a quoted block with its source host, never as an element that can pass for a button, form or system message. | DESIGN. OWASP LLM01:2025: "separate and clearly denote untrusted content". A label is not a defence alone, and pipeline defences belong to security. | A unit test on the prompt assembler or the tool result: feed a chunk containing `Ignore previous instructions` and the closing delimiter string. Assert that the chunk appears only between the delimiters, that the opening delimiter carries the origin, and that the embedded closing delimiter does not end the boundary early. A word in a tool description does not pass. Reading: retrieved text appears in a labelled quote block. | SHOULD |

## Citations, confidence, explanations

| ID | Rule | Rationale | Verification | Severity |
|---|---|---|---|---|
| UX-AI-14 | Render a citation marker only if its id or URL is in the set the pipeline retrieved for this answer, and drop any other marker. Label markers as "sources", never as "verified", "fact-checked" or "supported by". Show each source's title and host without a click, and link to the passage when the pipeline has it. | DESIGN, by logic: a marker for a source that was never retrieved is fabricated, whatever the model's accuracy. Background only: 74.5% of citations supported their sentence across four commercial engines (Liu et al., 2023). | The unit test is the pass: an answer cites `[9]` with 5 retrieved sources, and no marker 9 renders. The label wording is a reading check, not a gate. | SHOULD |
| UX-AI-15 | Do not display an LLM's self-reported certainty as a number, percentage or probability, unless the owner has a recorded calibration measurement for this exact model, prompt and task type (a reliability diagram, ECE or Brier score on the product's own labelled sample), re-run on every model or prompt change. The record starts with the heading `# Calibration record` and carries one line in the form `model: ID; prompt: PATH sha256 HASH; n=N labelled; Brier=X` (or `ECE=X`). Show a categorical confidence label only if it maps to a defined action ("Check the source before using this") and the owner has a recorded user test showing it improves decisions. Otherwise show none. | DESIGN. Five fetched studies disagree: verbalized confidence better calibrated than token probabilities (Tian et al., EMNLP 2023), overconfident (Xiong et al., ICLR 2024), up to 26% more confident in its own answers after chat tuning (Sanz-Guerrero et al., ACL 2026 Findings), moved by a change of instruction (Kim and Kang, preprint), Brier 0.103 to 0.367 across 15 frontier models (ConfidenceBench, preprint). None measured product answers or user decisions. PAIR (vendor): "Be sure to set aside lots of time to test if showing model confidence is beneficial". | See block UX-AI-15, run with GNU grep. Step 1 is a screen: read each hit, and count it only if it shows an end user a number as the model's certainty about an answer. Log lines, comments, sampler documentation and a developer view of sampling token log-probabilities do not count. Step 2: the record exists. Step 3: it is newer than the last model or prompt change. Step 4: a categorical label has a user-test record. The check proves a fresh, owner-written record exists. Whether the measurement is honest or the sample representative is a reviewer judgement. | SHOULD |
| UX-AI-16 | Consider hedging only when a code condition says support is weak (empty or conflicting retrieval, out of domain), with first-person wording ("I'm not sure, but...") next to the source links, instead of a blanket "always say you might be wrong" line in the system prompt. The evidence is one study and may not transfer. | DESIGN, one study. First-person hedging cut agreement from 80.9% to 74.8% and raised overall accuracy from 63.9% to 72.8%, but cut accuracy on correct answers from 92.2% to 89.2% (N=404, medical questions, a fictional answer engine; Kim et al., FAccT 2024). | Search the hedge string: it is emitted inside a branch keyed to a retrieval or conflict signal. See block UX-AI-16 over the system prompt files only: 0 hits. | CONSIDER |
| UX-AI-17 | Do not add a model-written "why this answer" paragraph as a trust device. Show evidence the user can check instead (a quoted passage, a diff, test output, a retrieved source). On surfaces the owner marks high-stakes (legal, medical, financial, security changes), show sources with the result and give a one-click path to verify. | DESIGN. Explanations "increased the chance that humans will accept the AI's recommendation, regardless of its correctness", with no significant gain over a bare confidence score (Bansal et al., CHI 2021). PAIR (vendor) asks for reasons in high-stakes cases. | Reading test. Pass: "Used 3 sources: [titles]" with passage links. Fail: a "Why I think this" block with no link. The high-stakes list comes from the owner. `unverified: reading heuristic` | SHOULD |
| UX-AI-25 | Consider not showing a retriever's relevance, similarity or distance score to the end user beside an answer or a citation, as a percentage, a colour bin, a bar or a decimal. Show the sources in rank order, or with no number. Show a score only if the owner has a recorded user test showing that it improves decisions. A calibration record does not apply: a retriever score claims relevance, not correctness. | DESIGN, prevalence only. Four of seven held-out open-source AI chat products show such a score beside citations, one as a percentage coloured green from 80% and red below 40%. A vector distance is not a probability that the answer is correct, yet the cue reads like "Confidence: 87%". No study of harm was fetched. | See block UX-AI-25 and read each hit: a score rendered beside a citation or an answer fails. Held out it printed 22 lines in seven repositories, 9 true hits and 13 noise. The filename scope misses a component with another name. Test form: render a citation with a fixed `score: 0.87` and assert that `87` is absent from the rendered citation. | CONSIDER |

| UX-AI-18 | If the UI uses AI SDK 5 or later, render every tool-part state the SDK defines, in one switch with a visible default branch, and never let an unhandled state fall through to a spinner. ### Using the cases file

`checks/model-output-cases.json` holds the renderer inputs. Each case has `markdown`, optional `forbid` and `require` regexes, and a `naive_output` and `safe_output` that prove the case goes red and green. `global_forbid` applies to every case. Apply every regex with the case-insensitive flag. A minimal test, with `renderModelOutput` standing for the product's own renderer:

```js
const cases = JSON.parse(fs.readFileSync("checks/model-output-cases.json", "utf8"));
for (const c of cases.cases) test(c.id, () => {
  const html = renderModelOutput(c.markdown);
  for (const rx of [...cases.global_forbid, ...(c.forbid ?? [])]) expect(html).not.toMatch(new RegExp(rx, "i"));
  for (const rx of c.require ?? []) expect(html).toMatch(new RegExp(rx, "i"));
});
```

`python3 -I "$CHECKS"/actions_scan.py --self-test` validates the file itself. The bare-URL case passes only where the renderer shows the destination host as visible text (UX-AI-11).

## Law notes

- **Article 50(2) marking is a provider duty.** An agent classifies outputs and raises the question as blocking. It never adds a zero-width mark and never stamps "AI-generated" on source code (guidelines para 68).
- **Providers and deployers.** Whether the team is the provider or the deployer of a feature decides which of Art. 50(1), (2) and (4) apply.
- **Companion duties differ by state.** CA adds duties NY art. 47 lacks: known-minor disclosure and break reminders (22602(c)), protocol publication (22602(b)), the minors statement (22604) and reporting (22603). NY art. 48 reaches further than art. 47: its twelve features are unlawful by default for every covered user.
- **Utah and Maine are conditional.** A first-turn notice alone does not reach the Utah safe harbour. UX-AI-01 with UX-AI-03 does.

## Ask the owner

- Whether the team is the **provider** or the **deployer** of each AI feature (own name or trademark, third-party model, white label).
- Whether the "obvious" exception applies. The default is to disclose. The exception needs a written audience assessment and legal sign-off.
- Whether the product is a companion product in New York or California, and which UX-AI-05 duty flags apply. Whether a New York chat feature is a covered AI companion, and which age-determination method is permissible.
- The machine-readable marking technique, and whether to sign the Commission code of practice.
- Whether a feature publishes public-interest text or deep fakes, and who holds editorial responsibility.
- The **wording** of the disclosure, the not-human notice and the crisis-referral copy. An agent drafts options and never ships them alone.
- The image and link host allow-list. Which surfaces are high-stakes. Whether to show any confidence label or retriever score at all. Memory retention and scope.
- Any statement that the product complies with a law, and any jurisdiction this file does not cover.

- NY art. 48: the chaptered slip law of Chapter 368 and the 2026-10-28 approval memo are unread, so a chapter amendment is not ruled out. The Attorney General's regulations under 1803 and the article 45 age-assurance rules were not searched.

## What Agents Get Wrong Here

1. **Ship the renderer defaults.** `marked` or `markdown-it` with defaults draws live remote images, and `marked` also renders raw script (UX-AI-09, UX-AI-10, UX-AI-12).
2. **Read "safe by default" as covering images.** `react-markdown` is XSS-safe and still fetches the image plus a preload. DOMPurify is not an image policy. A regex for the inline image form misses the reference form `![x][r]` (UX-AI-09, UX-AI-12).
3. **Allow-list a host the attacker can write to**: a document host, a CDN with uploads, an open redirect or a domain nobody renews (UX-AI-09).
4. **Put `aria-live="polite"` on the container that receives tokens**, which measured 500 announcements for 500 tokens (UX-AI-19).
5. **Render AI SDK 4 `toolInvocations`** with `call` and `result` only, so a denial or an error is an endless spinner. Render `error.message` raw (UX-AI-18, UX-AI-20).
6. **Treat disclosure as boilerplate**: a footer, a tooltip, terms, an icon-only sparkle, an `aria-hidden` badge, a notice after the first reply, or a human persona with no statement (UX-AI-01, UX-AI-02, UX-AI-03).
7. **Write legal dates and fines from memory**, label a design rule "required by the AI Act", or claim the "obvious" exception for a developer audience (UX-AI-01, UX-AI-08).
8. **Invent a zero-width watermark**, or stamp "AI-generated" on generated code. A check written with `\\u200b` escapes never matches under PCRE, so it passes a planted mark (UX-AI-06).
9. **Conclude that no companion duty applies** because no scope record exists, or replace the tests with a grep for `988` or "3 hours" (UX-AI-05).
10. **Read NY art. 48 as "protect known minors"**, leave persona and memory features on by default, or accept an "I am an adult" tick as the age determination (UX-AI-24).
11. **Show "Confidence: 87%" from the model's own output**, or a retriever score as a percentage or a green badge. Add a "why this answer" paragraph. Render citation numbers as the model emitted them (UX-AI-14, UX-AI-15, UX-AI-17, UX-AI-25).
12. **Obey DOC-PLAIN-08 and strip a required AI label** from a markdown page (UX-AI-01, UX-AI-07).
