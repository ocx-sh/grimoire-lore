# C# Language and Idioms

Binds to .NET SDK 10.0.401 on Linux x64 (runtimes 10.0.12 and 8.0.31), C# 14 at `LangVersion 14` on `net8.0` and `net10.0`, measured
2026-10-11. C# 15 and .NET 11 rows bind to SDK 11.0.100-rc.1.26425.128 (RC1, measured 2026-10-11) and are fenced.

This file owns what an agent writes by habit in C#: nullability and argument guards, what C# 14 does differently per target
framework, the C# 15 and preview fence, primary constructors, records, collection expressions, switch exhaustiveness and
the generated-code markers that switch the analyzers off. The `LangVersion` pin, `AnalysisLevel` and the `Nullable` property
are `CS-BUILD`. Sealing, records on the public surface and open enums are `CS-API`, and the `required` and `[JsonRequired]`
policy is `CS-JSON`. The `NoWarn` and pragma weaken list is `CS-CORE-01`, and the test-project carve-out is `CS-TEST-12`.

## Dates and the Gate

- "The gate" is `CS-BUILD-04`, `-10`, `-13` and `-14`: `LangVersion 14`, `AnalysisLevel 10.0-all`, unconditional
  `TreatWarningsAsErrors` and `EnforceCodeStyleInBuild`. Under it a compiler or CA warning is an error. An IDE rule stays silent
  until a per-rule line raises it, because `AnalysisLevel` does not raise style rules (IDE0370 was silent with no line,
  measured 2026-10-11).
- Severity lines are not restated here. CA, RS and MA IDs live in `analyzers.globalconfig`, and IDE IDs, editorconfig options
  and path-scoped differences in `analyzers.editorconfig`, both shipped under `checks/` of `dotnet-build`. Bans live in the
  shipped `BannedSymbols.txt`. A row names the ID and the file.
- Reach is net8.0 and net10.0 only (D1, listed under Owner Defaults in the index): a netstandard2.0 slice would need polyfills for the
  nullability attributes and `ThrowIfNull`, and this file does not cover it.
- CS-LANG-13, CS-LANG-14, CS-LANG-17 and CS-LANG-25 are retired, not reused. CS-LANG-13 (user-defined compound assignment operators) was
  a two-line niche with no hit in five mature repositories.
- CS-LANG-25 is retired, not reused: `partial` only with a generator attribute flagged legitimate hand-split types in every held-out tree. The C# 15 per-TFM `LangVersion` fence is a `dotnet-upgrade`
  re-check once a net11.0 leg exists.
- Counts in the rationales (directives, `!`, guards, primary constructors, records, generated files) come from a corpus audit
  of public .NET repositories (2026-10-11). The dotnet/runtime nullability guidance and the Roslyn statement on net8.0 with
  C# 14 were read 2026-10-11.
- Every check below runs from the repository root in bash, and a grep check prints violations, so empty output passes. A
  count cell whose `.editorconfig` or `.globalconfig` is absent prints grep's error, which is a violation. `SRC` and `TESTS`
  name the repository's own source and test directories (space-separated lists the caller sets, no default), and the first
  line of every block stops with `MISSING SRC` (or `MISSING TESTS`) for one that is unset, because grep with no operand reads
  the working directory or stdin and an empty output would read as a pass. A directory that does not exist is grep's exit 2,
  never a pass. A cell that evaluates each project prints `EVAL-FAIL <project>` for one `dotnet msbuild` cannot evaluate,
  because it sends that error to stderr and an empty stdout would read as a pass. A tag at the start of a Rule cell narrows
  who it binds, as the index Tags list defines: `[greenfield]` is every shipped TFM net8.0 or newer, `[packable-library]` is
  a project that a consumer references as a package, and an untagged rule binds every project. A row that needs an API
  missing on the project's lowest TFM binds `[greenfield]` and names its fallback. Each block is watched red and green (the
  Verification cells give the dated result).

## Generated-Code Mimicry

An SDK tree generated from a schema starts every file with `// <auto-generated/>` and `#nullable disable`, and an agent copies that
style by hand. A generated comment, file name or `[GeneratedCode]` attribute makes every CA, MA and IDE analyzer skip the file.

| ID | Rule | Rationale | Verification | Severity |
|---|---|---|---|---|
| CS-LANG-23 | No hand-written file carries an analyzer-skipping generated marker: no comment containing `<auto-generated` or `<autogenerated`, no `*.g.cs` name, no `[GeneratedCode]`, and no file committed under an `obj/` directory. Write no prose header such as `// File generated from ...` either: it skips nothing, and it is banned as mimicry only. Tool output committed to the tree (a Visual Studio designer or resx wrapper, T4, a repository's own generator) is the sanctioned exception, under one of the names `*.Designer.cs`, `*.designer.cs`, `*.generated.cs` or `*.Generated.cs`, which the `CS-LANG-24` section marks generated; its tool rewrites the file and nobody edits it by hand.
