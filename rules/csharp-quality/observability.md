# Logging, Telemetry and the Stderr Callback

Binds to SDK 10.0.401 on Linux x64 with `net8.0;net10.0`, `Microsoft.Extensions.Logging.Abstractions` 8.0.0 (library floor) and 10.0.x
(applications), `Microsoft.CodeAnalysis.BannedApiAnalyzers` 5.6.0 and the example wrapped tool `ocx` 0.6.5, measured 2026-10-11 unless a row says
read. Windows, macOS and arm64 are `unverified: read only`. `ocx`, `OcxClient`, `OnStderrLine` and `OCX_LOG` are example names from the
reference consumer: rename them.

Owns what a .NET codebase writes to logs, traces and metrics, and what a wrapper does with its child's stderr. Not owned here: argv order and
the env scrub (`CS-PROC-06`, `CS-PROC-07`), secrets in argv and env (`CS-PROC-08`), stderr capture and cap (`CS-PROC-10`), `PrintMembers` redaction
(`CS-API-06`), exception messages (`CS-ERR-08`), the CA1031 site list (`CS-ERR-06`), the packed-dependency budget (`CS-SEC-09`), the test-project
analyzer relaxations (`CS-TEST-12`) and the cancellation contract (`CS-ASYNC-30`). **CS-OBS-25 is retired, not reused.** It was the reference
consumer's telemetry identity (names, tags, one metric) and moved to that consumer's design record; `CS-OBS-17`, `CS-OBS-20` and `CS-OBS-22` carry the mechanism.

## Dates and Defaults

- The SDK default `AnalysisLevel=10.0` hides the logging rules: only CA2017 and CA2023 fire, CA2254, CA2253 and CA1873 are suggestions and CA1848
  and CA1727 are off. SYSLIB1006 is Info and stays silent even at `10.0-all` with warnings as errors (measured 2026-10-11, net8.0 and net10.0).
  Every analyzer row here therefore has a line in `analyzers.globalconfig`; the gate alone does not raise them.
- `eng/logging-facade.txt` is an adopter file named as an example path: one `<interface> <reason>` line per library-owned logging facade (`CS-OBS-02`).
- Defaults, the adopter may override once: `Warn` as the wrapped tool's default level, the file name `docs/telemetry-allowlist.txt`, the 16 MiB
  cap and the span tag allow-list are the consumer's own choices (`CS-PROC-10`, `CS-OBS-20`).
- A library that logs through MEL references `Microsoft.Extensions.Logging.Abstractions` at its floor and no other logging or telemetry package (`CS-OBS-13`, `CS-OBS-14`).
  An application pins the latest 10.x. A wrapper with one choke point takes no logging package at all and uses the in-box `ActivitySource` and
  `Meter` (`System.Diagnostics.DiagnosticSource`, part of the net8+ shared framework). Zero of nine surveyed CLI-wrapper libraries reference `ILogger`.
- Telemetry is an allow-list, never a redactor: a redactor fails open on a secret it does not know, an allow-list cannot (`CS-OBS-20`).
- The stderr callback fixtures ran under POSIX `sh` on Linux x64. Windows and arm64 behaviour of `CS-OBS-27` and `CS-OBS-28` is `unverified: read only`.
- Applicability tags open a Rule cell; an untagged row is `[always]`. `[packable-library]` ships a nupkg, so an application is out of scope for it.
  `[wrapper]` launches a CLI. A hot path is anything per command, request, item or retry.

- `analyzers.globalconfig` carries the 16 severity lines, each ending `# CS-OBS-nn`: CA2254, CA2253, CA2017, CA2023, CA1727 (`CS-OBS-01`),

  methods sharing an `EventId` build with exit 0 at `10.0` without the lines, fail once the lines are in (CA2254, CA1848 and CA1873 for the template, CA1848 and CA1873 for the call, SYSLIB1006 for the ids), and the twin with unique ids exits 0.   only with `Microsoft.Extensions.Telemetry` referenced and were not run (`unverified: read only`).
- The test-project relaxation of CA1848 and CA1873 is `CS-TEST-12`'s section; there is no second `.globalconfig`. Brownfield code converts its

- `BannedSymbols.Src.txt` (registered from `src/Directory.Build.props` only, because the fake CLI is a console app; a trace channel or a last-resort stderr write suppresses RS0030 per call line, and a console product takes one reasoned block at its one console seam, `CS-OBS-16`) carries the `CS-OBS-16` lines: `T:System.Console`,

## Greps

Every command takes its operands from variables and prints violations: empty output passes, unless a line says otherwise. The rows cite a line by
its `CS-OBS-nn` tag. `rg` is ripgrep; `SRC` and `TESTS` are space-separated directory lists with no default (a block starts `: "${SRC:?MISSING SRC}"`), `ALLOW` the telemetry
allow-list, needed only when `SRC` creates an `ActivitySource` or `Meter` (`TEL` lists those files; empty means `CS-OBS-17` to `CS-OBS-24` do not apply), `APP` the application project directories, the composition roots (empty for a library: `CS-OBS-11` is skipped).
A missing file operand prints `MISSING-OPERAND <path>` (`rg` exits 2 with empty stdout, which reads as a pass); a directory that does not exist makes `rg` print an error.

```bash
# greps (bash, repo root): a MISSING-OPERAND line voids the rest
# SRC and TESTS are required; ALLOW (the allow-list file, example docs/telemetry-allowlist.txt) only when TEL is not empty; APP (application directories) only for CS-OBS-11
: "${SRC:?MISSING SRC}" "${TESTS:?MISSING TESTS}"
TEL=$(rg -l -g '*.cs' -e '\bnew\s+(ActivitySource|Meter)\s*\(' -e '\b(ActivitySource|Meter)\s+\w+\s*=\s*new\s*\(' $SRC)   # CS-OBS-17: the files that create a source or meter; empty means CS-OBS-17 to CS-OBS-24 do not apply
rg -n -U -P -g '*.cs' -e '\bLog\w*\s*\([^;"]*"[^"]*\{[@$]\w+' -e 'Message\s*=\s*"[^"]*\{[@$]\w+' -e '\[LoggerMessage\s*\([^)]*"[^"]*\{[@$]\w+' $SRC   # CS-OBS-01: Serilog operators in a MEL template, in an extension call or a [LoggerMessage] attribute (named or positional)
rg -H -n -U -P -g '*.cs' -e '^(?![ \t]*//).*\b_?(?:[Ll]og(?:ger)?|\w*Log(?:ger)?)\s*\??\s*\.\s*Log(?:Trace|Debug|Information|Warning|Error|Critical)\s*\(' -e '^(?![ \t]*//).*\.Log\s*\(\s*LogLevel' -e '^(?![ \t]*//).*LoggerMessage\s*\.\s*Define\s*[<(]' $SRC | grep -v -F -f <(rg -l -F -f <(awk 'NF { print $1 }' eng/logging-facade.txt 2>/dev/null) -g '*.cs' $SRC)   # CS-OBS-02: the receiver is named log, logger or *Logger, `?.` included; an engine or framework logger (Unity Debug.LogError, a language server Window.LogError) is not a finding, and a logger under another name is a review item; files that name an interface listed in eng/logging-facade.txt (one "<interface> <reason>" line per facade, an absent file lists none) are skipped
rg -n -g '*.cs' 'pragma warning disable SYSLIB1015$' $SRC   # CS-OBS-03: a suppression with no reason
rg -n -U -P -g '*.cs' -e '^[ \t]*\[LoggerMessage\s*\((?!\s*\d+\s*,)(?!(?:[^")]|"[^"]*")*EventId)' -e '^[ \t]*\[LoggerMessage\]' $SRC   # CS-OBS-04: an attribute with no EventId; a positional numeric id counts
rg -H -n -U -P -g '*.cs' -e 'catch\s*\([^)]*\b(?<v>\w+)\)[^{]*\{(?:[^{}/]|/(?!/)|//[^\n]*\n)*?(?:\b_?(?:[Ll]og(?:ger)?|\w*Log(?:ger)?)\s*\??\s*\.\s*\w+|(?<![\w.])Log\w*)\s*\([^;]*\b\k<v>\s*\.\s*(?:Message|ToString\s*\(\s*\))' -e '^(?![ \t]*//).*\{(?:Ex|Exception)\}' $SRC | grep -v -F -f <(rg -l -F -f <(awk 'NF { print $1 }' eng/logging-facade.txt 2>/dev/null) -g '*.cs' $SRC)   # CS-OBS-06: the catch variable passed as Message or ToString() to a logger-named receiver (`?.` included) or a receiver-less Log* call in a single-block catch; comment lines and the files of a listed facade (CS-OBS-02) are skipped
rg -n -U -P -g '*.cs' '(?(DEFINE)(?<B>(?:[^{}"]|@"(?:[^"]|"")*"|"(?:[^"\\]|\\.)*")*?))catch\b[^{]*\{(?&B)(?:(?<![A-Za-z])(?i:log)|Console\.Error|Trace\.Write|Trace\.Trace(?:Error|Warning|Information)|Debug\.Write)(?&B)\bthrow\s*;(?![^\n]*//\s*(?:boundary|retry):)' $SRC   # CS-OBS-07: single-block catches only (braces inside string literals are skipped); a block that names a logger (or writes to `Console.Error` or `Trace`) before a bare `throw;` not marked `// boundary:` or `// retry:`
rg -n -U -g '*.cs' -e 'BeginScope\s*\(\s*\$"' -e '\b_\s*=\s*\w+\s*\.\s*BeginScope\s*\(' $SRC   # CS-OBS-09
rg -n -U -P -g '*.cs' -e '^(?:[^"\n]|"(?:[^"\\\n]|\\.)*")*?\.(Verify|Setup)\s*\([^;]*?\.Log(Trace|Debug|Information|Warning|Error|Critical)\s*\(' -e '^(?:[^"\n]|"(?:[^"\\\n]|\\.)*")*?\.(Received|DidNotReceive)\s*\([^)]*\)\s*\.Log(Trace|Debug|Information|Warning|Error|Critical)\s*\(' $TESTS   # CS-OBS-12: Verify, Setup or Received on an extension method; Verify on ILogger.Log itself is fine
test -z "$APP" || rg -n -g '*.cs' -e 'AddConsole\s*\(\s*\)' -e 'AddSimpleConsole\s*\(\s*\)' $APP   # CS-OBS-11: sites to review in the composition root; APP only, so samples, docs and tests never count
test -z "$APP" || { rg -q -g '*.cs' 'DataClassificationAttribute' $APP && ! rg -q -g '*.cs' -e 'EnableRedaction\s*\(' -e 'AddRedaction\s*\(' $APP && echo 'classified data, redaction not enabled'; }   # CS-OBS-11: prints the message on a violation
rg -n -g '*.cs' -e 'Microsoft\.Extensions\.Logging' -e '\bILogger\b' $SRC   # CS-OBS-13: the packable library's directory, one-choke-point libraries only
rg -n -g '*.cs' -P -e 'ILogger(<[^>]+>)?\??\s+\w+\s*=\s*null' -e 'static\s+(readonly\s+)?ILogger(<[^>]+>)?\s+\w+\s*=\s*(?!NullLogger)' -e 'LoggerFactory\s*\.\s*Create\s*\(' $SRC   # CS-OBS-15: the packable library's directory
rg -n -g '*.cs' -P -e '\bnew\s+(ActivitySource|Meter)\s*\(' -e '\b(ActivitySource|Meter)\s+\w+\s*=\s*new\s*\(' $SRC | grep -v -E 'static readonly|\?\?=\s*new'   # CS-OBS-17: the second pattern catches target-typed new(...); a static `Meter ??= new Meter(...)` built once behind the consumer's opt-in call passes
rg -n -U -g '*.cs' 'StartActivity\s*\([^;]*\)\s*!' $SRC   # CS-OBS-19
rg -n -U -P -g '*.cs' -e 'process\.command_(args|line)' -e 'process\.executable\.path' -e '\.AddException\s*\(' -e 'ActivityStatusCode\.Ok' -e 'SetStatus\s*\([^;]*\.Message' -e 'StartActivity\s*\(\s*\$"(?!\{nameof\([^)]*\)\}(_\{nameof\([^)]*\)\})*")' -e '\b(SetTag|AddTag)\s*\(\s*+(?!")' -e '\.(?:Record|Add)\s*\((?:[^;(),]|\([^()]*\))+,\s*new\s+KeyValuePair<string, ?object\??>\s*\(\s*+(?!")' $SRC   # CS-OBS-20, CS-OBS-21: a nameof-only span name is a constant and passes; a tag key that is not a literal is a hit, and so is a metric tag pair built from a non-literal key
KEYS=(-o -N -U -P --no-filename -g '*.cs' -e '\b(?:SetTag|AddTag)\s*\(\s*"\K[^"]+(?=")' -e 'KeyValuePair<string, ?object\??>\s*\(\s*"\K[^"]+(?=")')
test -z "$TEL" || test -f "${ALLOW:?MISSING ALLOW}" || echo "MISSING-OPERAND $ALLOW"; test -z "$TEL" || test -n "$(rg "${KEYS[@]}" $SRC)" || ! rg -q -g '*.cs' -e '\b(SetTag|AddTag)\b' $SRC || echo "SetTag calls but no literal key extracted"   # CS-OBS-20: an empty extraction beside tag calls is a miss, not a pass; skipped when no source or meter exists
test -z "$TEL" || rg "${KEYS[@]}" $SRC | LC_ALL=C sort -u | diff - "$ALLOW"   # CS-OBS-20: allow-list diff over span tags and metric tag keys; the file is byte-sorted, one key per line, empty output passes; skipped when no source or meter exists
rg -o -N --no-filename -g '*.cs' -e 'Create(Histogram|Counter|UpDownCounter|Gauge|Observable\w+)\b' $SRC | wc -l   # CS-OBS-22: prints 0 (no metrics) or 1; an opt-in library with one Meter per subsystem prints one per subsystem (counted per match, not per line)
rg -q -g '*.cs' -e '\bnew\s+(ActivitySource|Meter)\s*\(' -e '\b(ActivitySource|Meter)\s+\w+\s*=\s*new\s*\(' $SRC && ! rg -q -g '*.cs' -e '\bnew\s+(ActivityListener|MeterListener)\b' $TESTS && echo 'telemetry emitted, no listener test'   # CS-OBS-24: prints the message when the library emits telemetry and no test listens
test "$(rg -o -N --no-filename -g '*.cs' '\bnew\s+ActivityListener\b' $TESTS | wc -l)" -le "$(rg -o -N --no-filename -g '*.cs' '\bSample\s*=[^=]' $TESTS | wc -l)"   # CS-OBS-24: exit 1 when a listener lacks Sample (counted per match)
rg -n -g '*.cs' -e 'OCX_LOG_LEVEL' -e '"OCX_LOG"' -e 'RUST_LOG' $SRC   # CS-OBS-26: the tool's log env, example names
rg -n -g '*.cs' -e 'IProgress<string>' -e '\bProgress<string>' $SRC   # CS-OBS-27
rg -n -g '*.cs' -i -e '"(TRACEPARENT|TRACESTATE|BAGGAGE)"' -e 'Environment\[[^]]*(traceparent|tracestate|baggage)' $SRC   # CS-OBS-29: the env names only; Activity.Baggage use is not a hit
```

## What Agents Get Wrong Here

1. **`logger.LogInformation($"User {user} ...")`, string concatenation, or `{@X}`.** Any `string` is accepted as a template. `CS-OBS-01`.
2. **Adding `ILogger<OcxClient>` and Abstractions to a wrapper "because .NET libraries log".** Microsoft's library page centres `ILoggerFactory`; a wrapper has one choke point. `CS-OBS-13`.
3. **`LogError("failed: {Ex}", ex)` or `ex.Message` as an argument.** A valid `params object[]`, no analyzer. `CS-OBS-06`.
4. **Tagging spans with `process.command_args`, a joined argv or the resolved path.** They are in the semconv registry. `CS-OBS-20`.
5. **`SetStatus(Error, ex.Message)`, `AddException(ex)`, `SetStatus(Ok)`.** Spec text and blog posts; `AddException` also fails to build on net8.0. `CS-OBS-20`, `CS-OBS-21`.
6. **Extension `LogX` calls everywhere with `NullLogger` treated as free.** 88 B per disabled call. `CS-OBS-02`.
7. **`new ActivitySource(...)` per call or per instance, often target-typed `new(...)`.** It looks like ordinary scoped disposal. `CS-OBS-17`.
8. **`psi.Environment["OCX_LOG_LEVEL"] = "debug"`, or the log-level flag after the verb.** Most CLIs accept trailing flags; this one exits 64. `CS-OBS-26`.
9. **Copy-pasted `EventId = 1`, or none.** Valid, and SYSLIB1006 is Info and per class. `CS-OBS-04`.
10. **`catch (Exception ex) { logger.LogError(ex, ...); throw; }`.** The "log everything" habit. `CS-OBS-07`.
11. **A stderr callback invoked inline unguarded, with its fault swallowed, or as `IProgress<string>`.** It reads cleanly and the hang or reorder shows only under load. `CS-OBS-27`, `CS-OBS-28`.
12. **A generator parameter `password` left out of the template "for context".** It builds with a warning and lands in `State`. `CS-OBS-03`.
13. **An Activity started in a non-async `Task RunAsync()` wrapper.** A console exporter shows correct parenting. `CS-OBS-18`.
14. **`Mock<ILogger<T>>.Verify(l => l.LogX(...))`.** Compiles, throws at runtime. `CS-OBS-12`.
15. **`ActivityListener { ShouldListenTo = ... }` with no `Sample`, then "StartActivity is broken".** `CS-OBS-24`.
