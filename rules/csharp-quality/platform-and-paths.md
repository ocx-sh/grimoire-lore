# Portable Paths, Culture, Platform and Clock

Binds to .NET SDK 10.0.401 on Linux x64, targets `net8.0` and `net10.0` (measured 2026-10-11). Windows statements were
measured on a Windows 11 host with SDK 10.0.102 (2026-10-11). macOS and native arm64 statements are
`unverified: read only`. TFM-dependent rows say which TFM they were watched on.

This file owns how .NET code stays correct on every operating system: path joining and comparison, file names,
the home directory, links, the working directory, culture, platform guards, platform identity, clocks and line
endings. Neighbours cite by ID. `CS-PROC` owns the child process, `CS-BIN` binary selection and delivery,
`CS-TEST` and `CS-CI` the proof that runs on the matrix, and `CS-BUILD` the analyzer packs. Example names
(`OCX_HOME`, `.ocx`, `tests/Ocx.Sdk.UnitTests`) come from the reference consumer; rename them.
CS-BIN-03 and CS-BUILD-07 are retired, not reused: CS-XP-04 and CS-XP-10 replace them.

Applicability: an untagged row binds every repo this file loads for. `[cli-wrapper]` binds a library that wraps a command-line tool, `[library]` a library as opposed to an application. A mandate that names an API a TFM lacks (`Path.Join` before netstandard2.1,
`OperatingSystem.Is*` before net5.0, `TimeProvider` before net8.0) binds only the TFMs that have it. On a legacy TFM (netstandard2.0, net4x) use the
polyfill (`Microsoft.Bcl.TimeProvider`, or a local `Join` and `OperatingSystem` shim) or a site `#pragma warning disable RS0030 // legacy TFM`.

## The Static Gate

Most rows below are enforced by the build, not by reading. The lines live in the shipped analyzer files, not here:
the ban lines in `BannedSymbols.txt` (repo-wide) and `BannedSymbols.Src.txt` (registered from `src/Directory.Build.props`
only, so tests keep real deadlines and may join their own paths with `Path.Combine`), and the severity lines in `analyzers.globalconfig`. Each ban message names one
rule ID in this file. A row below quotes at most the banned symbol.

`SRC` and `TESTS` list the production and test project directories, space-separated; they may sit under `src/` side by side, so name them.
`SLN` is the solution or project file the build takes. An unset operand stops the block (`${SRC:?MISSING SRC}`) and a missing path prints
`MISSING OPERAND`: a check over it prints nothing and reads as a pass.

```sh
# set once per repository, no defaults: SRC=src TESTS=tests SLN=Acme.slnx
: "${SRC:?MISSING SRC}" "${TESTS:?MISSING TESTS}" "${SLN:?MISSING SLN}"
for d in $SRC $TESTS; do [ -d "$d" ] || echo "MISSING OPERAND $d"; done
for v in SRC TESTS; do for p in ${!v}; do case $p in /*) echo "MISSING repo-relative $v";; esac; done; done   # an absolute path under a tests/ ancestor can match an exclusion and count zero files
rg --files -g '*.cs' $SRC | head -1 | grep -q . || echo 'MISSING scanned zero files'
[ -f "$SLN" ] || echo "MISSING OPERAND $SLN"
L=${L:-$(mktemp -d)}   # the log folder of the index Gate when it ran in this shell, else a fresh one outside the work tree
timeout 900 dotnet build "$SLN" --tl:off --interactive false --disable-build-servers -nologo -v:q --no-incremental > "$L/build.log" 2>&1; echo $?   # DN-RULE-01; read $L/build.log; exit 1 is a finding only for the rule IDs on the next line
grep -Eo 'error (RS0030|CA1304|CA1305|CA1307|CA1309|CA1310|CA1311|CA1416|MA0076)' "$L/build.log" | sort | uniq -c   # the findings, by rule ID (all are errors under the gate); a count of 0 with exit 1 means the build failed for another reason
grep -E ' error (MSB|NU|NETSDK)[0-9]+' "$L/build.log" | head -1   # a host or restore condition, not a finding (MSB1003, MSB1009 and MSB1011 name a wrong SLN, NETSDK1045 an SDK older than a target framework, MSB3202 a missing submodule): route it through dotnet-diagnose and run from the build root so global.json applies
grep ' error ' "$L/build.log" | grep -Ev 'error (RS0030|CA1304|CA1305|CA1307|CA1309|CA1310|CA1311|CA1416|MA0076|MSB[0-9]+|NU[0-9]+|NETSDK[0-9]+)' | head -1   # the first error of another family (CA2000, CS0103): another row's finding, not this one's
# P1 (CS-XP-04) [cli-wrapper]: a file that names "HOME" without "USERPROFILE" prints. Empty output is the pass.
rg -l --null -g '*.cs' -e '"HOME"' $SRC $TESTS | xargs -0 -r rg --files-without-match -e '"USERPROFILE"'
# P2 (CS-XP-09): a file with a P/Invoke and no SupportedOSPlatform prints; a POSIX-only import (libc) prints too, so read each. Empty output is the pass.
rg -l --null -g '*.cs' -e 'DllImport' -e 'LibraryImport' $SRC | xargs -0 -r rg --files-without-match -e 'SupportedOSPlatform'
# P3 (CS-XP-12): a newline split in a file that reads a process stream prints. Empty output is the pass.
rg -l --null -g '*.cs' -e 'StandardOutput' -e 'StandardError' -e 'OutputDataReceived' -e 'ErrorDataReceived' $SRC | xargs -0 -r rg -n -e 'Split\s*\([^)]*NewLine' -e 'Split\s*\(.*\\[rn]'
# P4 (CS-XP-07): a file that builds a linguistic comparer through CompareInfo.GetStringComparer (unbanned) with no CS-XP-07 pragma line prints. Empty output is the pass.
rg -l --null -g '*.cs' -e 'GetStringComparer\s*\(' $SRC | xargs -0 -r rg --files-without-match -e 'pragma warning disable RS0030 // CS-XP-07'
```

RS0030 defaults to a warning on BannedApiAnalyzers 4.14.0 and 5.6.0 (measured 2026-10-11), so a ban without its `error`
severity line, or without its `AdditionalFiles` registration, is silent. Watched per TFM, because overload sets differ
between `net8.0` and `net10.0`: every ban line fired on a planted site and the twin built green (measured 2026-10-11,
both TFMs). The build-log filter was watched on a log holding two rule IDs and an MSB3202 (the host line printed it, the other-family line stayed empty) and on a log of rule IDs only (both empty); on the four held-out posture builds it printed the rule-ID counts, no host line, and a CA2000 or CA2016 line as the other family (held-out round 3). Every `xargs` here exits 123 when it lists nothing (the pass case) and 0 when it lists a file; read the output, not the status.

## Path Rules

```csharp
internal static class PathSafe   // CS-XP-01 reference shape
{
    public static string Combine(string root, string rel)
    {
        var r = rel.Replace('\\', '/');
        if (r.Length == 0 || r[0] == '/' || r.Contains(':') || Path.IsPathRooted(r))
            throw new ArgumentException("rooted or volume-qualified", nameof(rel));
        var rootFull = Path.GetFullPath(root);
        var prefix = Path.EndsInDirectorySeparator(rootFull) ? rootFull : rootFull + Path.DirectorySeparatorChar;
        var full = Path.GetFullPath(Path.Join(prefix, r));
        var cmp = OperatingSystem.IsWindows() || OperatingSystem.IsMacOS() ? StringComparison.OrdinalIgnoreCase : StringComparison.Ordinal;
        return full.StartsWith(prefix, cmp) ? full : throw new ArgumentException("escapes the root", nameof(rel));
    }
}
```

## What Agents Get Wrong Here

Ranked by how often the idiom appears in training data.

1. **`Path.Combine(dir, segment)` everywhere**, including five arguments on `net10.0`. `CS-XP-01`.
2. **`$"--flag={number}"` into argv and `double.Parse(s)` with no culture.** `CS-XP-07`, `CS-XP-08`.
3. **`DateTime.UtcNow`, `Task.Delay(ms)`, `CancelAfter` and `Thread.Sleep` in retry and timeout code.** `CS-XP-11`.
4. **`StringComparison.InvariantCultureIgnoreCase` "to be culture-safe"** and `ToLower()` on keys. `CS-XP-07`, `CS-XP-02`.
5. **Reading `HOME` only, `GetFolderPath(UserProfile)` only, or `SpecialFolder.Personal` as home.** `CS-XP-04`.
6. **`Is64BitOperatingSystem`, `ProcessArchitecture` or a parsed `RuntimeIdentifier` to pick a binary**, and probing `/lib/ld-musl*`. `CS-XP-10`.
7. **`InvariantGlobalization` in the test csproj "for determinism".** `CS-XP-08`.
8. **`Environment.OSVersion` or an unattributed `IsWin()` as a guard**, and an unannotated `[DllImport("kernel32")]`. `CS-XP-09`.
9. **`Split(Environment.NewLine)` on child output.** `CS-XP-12`.
10. **Deleting the `AdditionalFiles` line or the RS0030 severity line, so the bans go silent.** `CS-XP-01`, `CS-CORE-01`.
