# Performance and Allocation

Binds to SDK 10.0.401 with `AnalysisLevel` `10.0-all` and `TreatWarningsAsErrors`, built for `net8.0` and `net10.0` in one build, on Linux x64, runtime 10.0.12 (measured 2026-10-11). Timings are ratios measured on Linux x64, .NET 10.0.12, BenchmarkDotNet 0.15.8; `Allocated` values are exact. Nothing here was timed on net8.0, and macOS and arm64 are `unverified: read only`.

Owns the performance gate and the claims an agent makes about speed: which analyzer lines exist, which syntax forms the analyzers cannot see, buffer ownership, per-chunk allocation, the rewrites that benchmarks contradict and the proof a "faster" claim carries. Under the gate (CS-BUILD-13) `warning` means a build error. Not owned here: culture (`CS-XP-07`), `ValueTask` (`CS-ASYNC-04`), hex encoding (`CS-BIN-07`) and the logging, async and JSON analyzers named under [Not Covered](#not-covered). No row of this family is retired.

Applicability: an untagged row binds every repo this file loads for. `[cli-wrapper]` binds a library that wraps a command-line tool. A mandate that names an API a TFM lacks (`[GeneratedRegex]` before net7.0, `TimeProvider` before net8.0) binds only the TFMs that have it: on a legacy TFM (netstandard2.0, net4x) use the polyfill package, or a site `#pragma warning disable RS0030 // legacy TFM`, and for a regex the `// CS-PERF-03: legacy TFM` marker.

## Gap Checks

Run from the repository root. `SRC` and `TESTS` list the production and test project directories, space-separated; they may sit under `src/` side by side, so name them. An unset operand stops the block (`${SRC:?MISSING SRC}`) and a missing directory prints `MISSING OPERAND`, because a check over it prints nothing and reads as a pass. `BASE` is the merge target from `origin/HEAD`, never assumed `main`. `PUMP` is the list of files that hold the stdout and stderr pump and the per-line callbacks (G8 and G9 read only those; the block discovers them, and an empty list means no pump, so both are a reading heuristic). Every `-P` check needs ripgrep built with PCRE2, and `\s*\(` tolerates the spaced call style `Name (args)`. Each prints the offending lines, so empty output means pass unless the label says candidate list. All were watched red and green on a planted pair that builds with exit 0 on both TFMs (measured 2026-10-11, SDK 10.0.401), and again in the spaced style and on eleven held-out trees.

```sh
# set once per repository, no defaults: SRC=src TESTS=tests
: "${SRC:?MISSING SRC}" "${TESTS:?MISSING TESTS}"
for d in $SRC $TESTS; do [ -d "$d" ] || echo "MISSING OPERAND $d"; done
for v in SRC TESTS; do for p in ${!v}; do case $p in /*) echo "MISSING repo-relative $v";; esac; done; done   # an absolute path under a tests/ ancestor can match an exclusion and count zero files
rg --files -g '*.cs' $SRC | head -1 | grep -q . || echo 'MISSING scanned zero files'
BASE=$(git symbolic-ref --short refs/remotes/origin/HEAD) || echo 'no origin/HEAD: run git remote set-head origin -a'   # G10 and G11 only
PUMP=${PUMP:-$(rg -l --glob '*.cs' -e 'OutputDataReceived|ErrorDataReceived|StandardOutput|StandardError' $SRC | tr '\n' ' ')}   # G8 and G9 only: the pump and callback files; name them when the heuristic misses
# G1  CS-PERF-01: a CA18xx mention outside a comment that lowers or hides a rule. rg -n -P --hidden -g '*.globalconfig' -g '.editorconfig' -g '*.ruleset' -g '*.csproj' -g '*.props' -g '*.targets' '^[^#]*CA18[0-9]{2}' . | rg -v -P -e 'CA1822\.api_surface = private, internal' -e 'CA1867\.severity = none' -e 'CA1849\.severity = error # CS-ASYNC-19' -e 'CA18(48|73)\.severity = error # CS-OBS-02' -e 'CA18(48|73)\.severity = none # CS-TEST-12' -e 'CA18[0-9]{2}\.severity\s*=\s*(error|warning)\b' -e '<WarningsAsErrors>' -e 'CA18(47|65|66)\.severity\s*=\s*none\s*#.*(netstandard|net4[0-9]|legacy TFM)' -e '<NoWarn Condition="[^"]*(netstandard|net4[0-9])[^"]*">(?:(?!CA18(?!47|65|66)[0-9]{2})[^<])*</NoWarn>' -e '\.editorconfig:[0-9]+:dotnet_diagnostic\.CA1851\.severity\s*=\s*(suggestion|silent|none)'
```

## Procedure: when a performance claim needs proof

`CS-PERF-09` triggers these steps. `[cli-wrapper]` A benchmarks project is never merged: a small JSON decode takes 0.56 µs while a trivial process spawn takes 822 µs (1,465x), so managed code is invisible next to a child process, and a squash merge would lose a commit-and-delete anyway. The first candidate worth proof is pump throughput, the one per-chunk managed loop. Each "exits 0" trap below was measured (2026-10-11, BenchmarkDotNet 0.15.8).

1. **Where.** Create `benchmarks/Example.Benchmarks/` on the PR branch (example name; rename): `OutputType` Exe, `IsPackable` false, its own `benchmarks/Directory.Build.props` (`<Project />`) and `Directory.Packages.props`. A minimal benchmark class fails the library gate with CA1050, CA1051, CA1515 and CS1591. Never put benchmarks in `src` or in a test project: a `[Fact]` calling `BenchmarkRunner.Run` passed in 0.43 s under Debug with no measurement and took 146 s under Release.
2. **Class.** `[MemoryDiagnoser]` and one `[Benchmark(Baseline = true)]`. Inputs are fields set in `[GlobalSetup]`, and every body returns its result, because constants fold (a `0.0000 ns` row was measured). Use `OperationsPerInvoke` for nanosecond bodies. No process, file or network work: a spawn has `Error` larger than its mean. Benchmark the pump over a `MemoryStream`.
3. **Run.** Pass `-c Release` and an explicit `--filter`; without a filter the switcher waits on stdin, then exits 0 having run nothing. After changing configuration properties delete `bin` and `obj`, because `<Configuration>Release</Configuration>` in the csproj leaves `Optimize=false`.
4. **Assert, never trust exit 0.** A Debug refusal, an ambiguous project and a missing filter all exit 0. The run counts only when this succeeds:
   ```sh
   rm -rf benchmarks/Example.Benchmarks/BenchmarkDotNet.Artifacts
   timeout 1800 dotnet run -c Release --project benchmarks/Example.Benchmarks -- --filter '*Pump*' --job short -m --artifacts benchmarks/Example.Benchmarks/BenchmarkDotNet.Artifacts > benchmarks/bench.log 2>&1; echo $?
   test -n "$(ls benchmarks/Example.Benchmarks/BenchmarkDotNet.Artifacts/results/*-report-github.md 2>/dev/null)"
   ```
   Read `benchmarks/bench.log` (`DN-RULE-01`). Without `--artifacts` BenchmarkDotNet writes `BenchmarkDotNet.Artifacts` under the current directory, so the `test` path would be empty from the repository root. The `rm` comes first because the results directory survives between runs: a rerun whose filter matches nothing exits 0 ("returned 0 benchmarks") and a stale report still satisfies the `test`. Smoke runs use `--job short`; a decision drops it. Watched red on an empty results directory and on a rerun with a non-matching filter after the `rm`, green with a report (measured 2026-10-11).
5. **Read.** Use `Ratio`, `Error` and `Allocated`. A row with a `ZeroMeasurement`, `MultimodalDistribution` or `BaselineCustomAnalyzer` footer is not evidence; re-run it with the default job.
6. **Land.** Paste the BenchmarkDotNet header, the table and the benchmark class into the PR body, then, `[cli-wrapper]`, delete `benchmarks/` before merge so that `test ! -d benchmarks` holds on main. A library that committed its benchmarks keeps the directory and keeps it out of the pack gate (`IsPackable` false). Stay on BenchmarkDotNet 0.15.x until 0.16 is GA, and re-check step 4 when upgrading.
