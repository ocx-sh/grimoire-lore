# Security beyond quoting (SH-SEC)

Two sub-artifacts feed this group: `shell-security/injection-and-secrets.md` (`[is]`; 15 candidate rules, 12 verification runs, 27 sources) and `shell-security/argv-through-variables-and-credentials.md` (`[av]`, the follow-up round the first version commissioned: secrets on argv through variables, git and cargo credential forms, dynamic names outside bash; 4 amended or new rules, 15 verification runs, 24 sources). This document merges them into 14 rules, rewrites every verification into the SH-GATE-21 to 28 dialect, re-runs each on five hosts, and adds a held-out round over the 40 code clones of the exemplar corpus (the dive sampled 12; the 41st clone, `koalaman/shellcheck.wiki`, is Markdown) and the fleet. The 2026-10-11 revision (Revision log) folded `[av]` in: every rule ID kept its number and meaning, SH-SEC-02 and SH-SEC-09 were amended in place, SH-SEC-13 and 14 were added, and the first version's own gate block was corrected (C21 to C25). Everything below was either re-run on 2026-10-11 or is cited to `[is §n]` or `[av §n]` (its section) or to a URL in Key sources. Fixture roots: `FX/` is `~/.cache/research-lang/shell-tools/fixtures/injection-and-secrets/` (the dive's); `SS/` is `~/.cache/research-lang/shell-tools/fixtures/shell-security/` (the first version's: `gate-checks.sh`, `plant/`, `twin/`, `hosts.sh`, `fleet-scan.sh`, `ex-scan.sh`, `rerun-key.sh`, the runtime fixtures, `out/`); `AV/` is `~/.cache/research-lang/shell-tools/fixtures/argv-through-variables-and-credentials/` (the revision's: `checks/secret-argv.sh`, `cells/`, `plant/`, `twin/`, `names/dyn.sh`, `cred/`, `out/`; `[av]` itself calls it `FX/`). Scope: the channels that carry a secret or hostile data other than through quoting: argv, traces, imported environment, PATH, sourced files, option positions, patterns, names, locks, parallel output, sudo, and the credential forms of git and cargo. Quoting is SH-EXP, `eval` is SH-EXP-13, GitHub Actions expression injection is SH-CI-07/08, emitter quoting is SH-EMIT. macOS and BSD behaviour was not run (no host): every such claim says "unverified: read only".

## Verdict

1. **Fourteen rules, twelve MUST** (SH-SEC-01 to 14). Script kinds are the SH-DIAL-03 ones: INST (installer, bootstrap), TOOL (dev script), CI (step helper), LIB (sourced library), RC and EMIT (rc snippets and emitted code), GATE (verifier). Rules 01 and 04 bind every kind; 02, 03, 06 bind INST, TOOL, CI (02 also GATE; 06 on Linux); 05, 08, 10 add LIB (10 also RC); 07 binds any script that claims mutual exclusion; 09 TOOL, CI, LIB on any POSIX-family interpreter (the first version said bash only); 13 binds INST, TOOL, CI and 14 TOOL, CI; 11 and 12 are the two SHOULD rows.
2. **A secret never rides on argv, by any route** (02, INST/TOOL/CI/GATE). It goes on stdin (`curl -K -`, `curl -H @-`, `docker login --password-stdin`), in a 0600 file, or in the environment of the one command. `/proc/<pid>/cmdline` is mode 0444. This is the dominant real defect: 15 of the 40 exemplar clones carry it by the single-line cells (50 true lines) and the fleet carries it in 8 files of 7 repos. The first version could not see a secret that reaches argv through a variable, an array, `set -- "$@"` or `read -s`; the revision's flow-aware cell `s02-argv-var` finds 71 lines in 11 of the 40 clones, 26 of them invisible to `s02-argv`, and 80 lines in a 57-clone held-out set, 32 invisible (both cells stay: each sees shapes the other cannot). The class includes `https://user:$TOKEN@host` URLs, which `git remote add` also writes to `.git/config`, and `docker run -e K=V`, `docker build --build-arg K=V` and `cargo publish --token`, whose client argv carries the value.
3. **No xtrace where a secret is expanded** (03, MUST in such a file). xtrace prints the expanded value on 11 of 11 POSIX-family shells; the bracket `{ set +x; } 2>/dev/null` leaks nothing. The cargo-culted `set -euxo pipefail` header is how it arrives (`jdx/mise`, 3 files).
4. **PATH and sourcing name explicit paths** (04, 05). An empty or `.` PATH entry is the current directory on bash 3.2 to 5.3 alike (the 5.3 NEWS item is a clarification, not a change); `. lib.sh` and `. .env` fall back to the current directory on bash, busybox ash 1.37, yash and `bash 3.2 --posix`, and dash refuses, so the bug hides on Debian CI.
5. **Data never becomes an option, a pattern, a name or a code file** (01, 08, 09, 10). `--` before variable operands (`ssh -oProxyCommand`, `git ls-remote --upload-pack`, `rsync --rsh`, `env -S` all executed), quoted patterns, validated identifiers, no sourcing of a file another principal can write. Names: on bash 3.2 to 5.3, zsh 5.0.8 to 5.9, mksh R59c and posh 0.14.1 a data-valued name executes `a[$(cmd)]` through `local`, `typeset`, `export`, `readonly`, `unset`, `read`, `printf -v`, `[[ -v ]]`, `declare -n` and `${!k}`, a different subset per interpreter; dash 0.5.12, busybox ash 1.35 and 1.37, ksh93u+m (2023 and 1.0.10) and yash 2.52 executed none of 26 constructs. The first version's "safe on all eight" list was a bash-only fact (09).
6. **ShellCheck 0.11.0 sees five of these** (SC2254, SC2053, SC2295, SC2035, SC2156). On the plants of rules 02 (the variable, array, docker and cargo shapes included), 03, 04 (literal forms), 06, 07, 11, 12, 13 and 14 it prints no finding that names the hazard even at `--enable=all` (ran today; the revision's plants give only SC2250 style notes and SC2154 unassigned-variable warnings); for 05 only "cannot follow" notes (SC1090, SC1091), for 09 only the SC2229 hint on `read`. SH-SEC-01 puts the five on SH-GATE-06's never-disable list, and the other thirteen rules carry their own greps, script and hostile-value runs.
7. **sudo-rs ignores bare `-E`** with a warning and exit 0 (06); name the variables. **Locks** are `mkdir`/`set -C`/`ln` with exit 75 on a held lock, never test-then-create, never an automatic stale break (07).
8. **Demoted by evidence:** exporting startup variables (11) is SHOULD: 0 true violations in 40 clones, all test harnesses or debug gates. Parallel output and waits (12) is SHOULD.
9. **Dropped as owned elsewhere:** temp files, atomic replace and the meta rule (SH-USER-11/12, SH-ERR-15, SH-GATE-20, SH-EXP-23).
10. **Every check is in the gate dialect and was watched red.** One block of 22 cells plus a PREFLIGHT block: plant 1 to 18 lines per cell, twin 0, byte-identical on five hosts (host dash; busybox 1.37 userland; GNU; uutils; Alpine plus GNU), re-run for the revision on 8 trees with empty stderr. Cells named `-listing` print sites to read; the others print the violation. `s02-argv-var` is a script (`checks/secret-argv.sh`, awk only, exit map of SH-GATE-31) and the only cell that needs a file beside the block.
11. **Documented gaps (the research established them; nothing here closes them).** (a) `s02-argv-var` is file-level taint over six tools. It misses a secret held in a non-secret-shaped name (`T`: a plant using `$T` was not reported, which is how the ceiling was found), a positional `$1`, function scope and flow, `eval`, sourced files, embedded Python or Node, heredoc semantics (bodies are scanned as lines), lines over 1500 characters, and every tool but `curl`, `wget`, `git`, `docker`, `gh` and `cargo` (those get only `s02-argv`'s fixed shapes). A pass is not proof of absence; the reading heuristic ("does a variable that holds a secret reach an argument?") stays. (b) Not run, so read only: macOS and BSD userland, Windows cross-user argv, the Windows Credential Manager and macOS Keychain git helpers, cargo credential providers, the wget and `gh auth login --with-token` stdin forms, `docker --env-file` mode, network-filesystem locks, whether a CI product masks a derived value (the Open questions' subareas).
12. **Credential forms have measured remedies** (13, 14). git: no remedy puts the token on argv. `GIT_ASKPASS`, `credential.helper store` (plaintext, mode 600) and `cache`, and `GIT_CONFIG_COUNT`/`KEY_0`/`VALUE_0` in the environment of the one command (git 2.31 or later) authenticated with `ARGV none` on git 2.43.0 to 2.54.0; a userinfo URL is argv in three processes plus `.git/config`, and `git -c http.extraheader=...` is argv in the parent. `GIT_TRACE_CURL` redacts `Authorization` only. cargo: `--token` is argv on 1.93.1 to 1.99.0; `CARGO_REGISTRY_TOKEN` authenticates crates.io only (exit 101 against any other registry); `CARGO_REGISTRIES_<NAME>_TOKEN` and `cargo login` on stdin keep the token off argv.
13. **What the revision changed besides the new rules.** The first version's SH-SEC-09 "safe" list overclaimed and was withdrawn; its gate block failed on a tracked `-x.sh` (`shfmt -f` and `shellcheck` without `--`), claimed a waiver rule that no cell enforced (a bare `# sec-ok:` passed and four cells ignored waivers entirely), and `s14` flagged the right form of `cargo login`. All three are fixed in the block (C21, C22, C24).

## The ruleset

How to read it. **MUST** and **SHOULD** as in the sibling sets; no CONSIDER rows survived. Each rule gives the imperative, a rationale with its citation, the verification by cell id, whether it was watched red, and the scope (kinds, shells and versions, OS). A **hit** in a cell without `-listing` is a violation; a hit in a `-listing` cell is a site to read, and it is closed by a fix or by `# sec-ok: <reason>` on the same line (the waiver every cell honours except the s01 trio, whose escape is the SH-GATE-05 reason; every filter is `grep -v -e 'sec-ok: *[^ ]'`, so a bare `# sec-ok:` with no reason is a hit, C22). Commands live only in the block below (SH-GATE-29); a rule names a cell. The block is the whole check, except that `s02-argv-var` runs the script `checks/secret-argv.sh` (`$SECRET_ARGV`, default `checks/secret-argv.sh`; text in the appendix of `[av]` plus the one waiver patch of C22). `SS/gate-checks.sh` is the first version of the block (17 cells, preceded by `cd DIR`); the revised block below was run from this document's text and wrote no fixture file. Run it from the repository root; any `PREFLIGHT:` line means the host cannot judge (fix the host and rerun, SH-GATE-25), and a cell passes only with empty stdout and empty stderr (SH-GATE-26).
