## Summary

- `AnalysisMode=Default` turns on zero CA warnings for ordinary library code. Measured on SDK 10.0.401 with a 12-hazard probe: Default 0 warnings, Recommended 17, All 24 (command in section 1). An agent that "builds clean" under Default has learned nothing.
- The SDK ships 92 (Minimum), 145 (Recommended) and 280 (All) warning-level rules in `analysislevel_10_*.globalconfig`; the official page confirms Default enables only a small set ([overview](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/overview)).
- The rules that matter most for an async process wrapper are all off at Recommended: CA2007 (ConfigureAwait), CA1031 (catch-all), CA2000 (dispose), CA1849 (sync call in async), CA1062 (argument validation), CA1063 (IDisposable pattern). They appear only at `All` (measured).
- Culture rules CA1304/1305/1309/1310/1311 turn on at Recommended; CA1307 and CA1303 only at All (measured).
- No Microsoft rule flags the process hazards that bite a CLI wrapper: building `Arguments` by string concatenation, a missing `UseShellExecute=false`, an un-disposed `Process`, `Encoding.Default`, `DateTime.Now`, path concatenation. In the probe, only Meziantou MA0163 and a `BannedSymbols.txt` (RS0030) caught any of these.
- Meziantou.Analyzer has the only process-specific rules found: MA0161 (set `UseShellExecute` explicitly, off by default), MA0162 (off), MA0163 (`UseShellExecute` must be false when redirecting, on) ([README](https://raw.githubusercontent.com/meziantou/Meziantou.Analyzer/main/README.md)).
- `ProcessStartInfo.ArgumentList` escapes for you; the docs still say untrusted data in it is a security risk ([API doc](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo.argumentlist)). CA3006 is web-request taint only, off by default, and cannot track across assemblies ([CA3006](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca3006)). It does not fit an SDK.
- The closest exemplar (adamralph__simple-exec, net8-10, `AnalysisMode=All`, VSTHRD analyzers) needed `#pragma` suppressions for CA2025, CA1849, VSTHRD103, CA1031, CA1032 and RS0026. Each suppression marks a real design tension, not noise (section 3).
- `IsAotCompatible=true` implies `IsTrimmable`, `EnableTrimAnalyzer`, `EnableSingleFileAnalyzer` and `EnableAotAnalyzer`; AOT analysis needs a `net8.0`+ target ([native AOT](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/)).
- Microsoft's cross-platform guidance: DO start with `net8.0` or later; CONSIDER `netstandard2.0` only for .NET Framework or broad reach; DO NOT publish `netstandard2.0` if the project or its dependencies multi-target ([cross-platform targeting](https://learn.microsoft.com/en-us/dotnet/standard/library-guidance/cross-platform-targeting)). In the corpus CliWrap ships `netstandard2.0`+; simple-exec ships only `net8.0;net9.0;net10.0`. The netstandard question is a cost trade, not a default.
- Public-API tracking has three codified answers: PublicApiAnalyzers (RS0016/RS0017, `PublicAPI.*.txt`), SDK Package Validation (`EnablePackageValidation` baseline), and a snapshot test (simple-exec `tests/Tests/PublicApi.cs`). They answer different questions (source surface, binary break vs a baseline, review diff).
- Behavioural change is a breaking change too. Microsoft's library guidance lists source, binary and behaviour breaks and says a bug fix can break users ([breaking changes](https://learn.microsoft.com/en-us/dotnet/standard/library-guidance/breaking-changes)). No analyzer covers JSON-shape or exit-code-semantics drift.
- `NuGetAuditMode` defaults to `all` for `net10.0` targets; NU1901-1904 become build errors under blanket `TreatWarningsAsErrors`. New advisories then break unrelated builds ([NuGet audit](https://learn.microsoft.com/en-us/nuget/concepts/auditing-packages)).
- Bulk severity entries in `.editorconfig` (`dotnet_analyzer_diagnostic.*`) are silently ignored when `AnalysisMode`/`AnalysisLevel` is set to enable all rules ([config options](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-options)). A config that "looks right" can be a no-op.
- SDK 11 RC1 adds six rules over SDK 10 at the same level: CA1517, CA1876, CA1877, CA2026, CA2027, CA2028 (measured). With `AnalysisLevel=latest` plus warnings-as-errors, an SDK bump breaks the build.
- Toolchain pitfall measured: `global.json` is resolved from the current working directory, not the project path. Building `Probe.csproj` by absolute path from another cwd silently used SDK 11.0 RC1 (NETSDK1057 preview message). Agents must `cd` into the pinned directory.
- Gaps: SonarAnalyzer S-rule pages and Roslynator docs were unreachable; Sonar and StyleCop are covered only through exemplar configs (section 11).

## Findings

### 1. The default analyzer posture is almost silent

- Code analysis is on by default for `net5.0`+ projects, but "only a small number of rules are enabled as build warnings" in `Default` mode. `None/Default/Minimum/Recommended/All` are the documented values; `AnalysisLevel` compound values like `latest-Recommended` are accepted ([overview](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/overview), [msbuild-props](https://learn.microsoft.com/en-us/dotnet/core/project-sdk/msbuild-props)).
- Under .NET 10 the on-by-default error/warning set is 29 rules (counted from the table), mostly interop, a few reliability checks, and CA2200 rethrow ([overview, .NET 10 tab](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/overview)). That list includes CA2022 (inexact `Stream.Read`, .NET 9) and CA2023 (log template braces, .NET 10).
- Measured counts of `severity = warning` lines, SDK 10.0.401: `grep -o 'severity = warning' .../analysislevel_10_<mode>.globalconfig | wc -l` gives Default 0, Minimum 92, Recommended 145, All 280. The `All` mode excludes CA1017, CA1045, CA1005, CA1014, CA1060, CA1021 and the metrics rules ([overview](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/overview)).
- Probe: fixture `fixtures/codified/Probe.csproj` (net10.0, nullable on, 12 planted hazards in `src/Probe.cs`), built with `run.sh dotnet build Probe.csproj -p:Mode=<m> --no-incremental` from inside the fixture directory (global.json pin). Unique warnings (`grep -o -E 'Probe.cs\([0-9,]+\): warning [A-Z]+[0-9]+' | sort -u`): Default 0; Recommended 17 (CA1304 x2, CA1305, CA1309, CA1310, CA1311 x2, CA1822 x7, CA1862, CA1869, CA2251); All 24 (adds CA1002, CA1031, CA1062 x2, CA1849, CA2007, CA2227).
- Precedence trap: single-rule `dotnet_diagnostic.X.severity` beats category beats all-rules; but if `AnalysisMode`/`AnalysisLevel` enables all rules, any bulk `dotnet_analyzer_diagnostic` entries are ignored. Microsoft's own advice is to use `AnalysisMode<Category>=All` for a category ([config options](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-options)).
- `CodeAnalysisTreatWarningsAsErrors=false` keeps CA warnings out of `-warnaserror` ([overview](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/overview)). IDE (style) rules do not run on command-line builds unless `EnforceCodeStyleInBuild=true`, and a handful stay IDE-only.
- Exemplar postures (all `git grep` of `*.props/*.targets/*.csproj`): simple-exec `AnalysisMode=All` (adamralph__simple-exec@f80913246993:Directory.Build.props:4); Pulumi.Automation `Recommended` (pulumi__pulumi-dotnet@2a0dca84f09b:sdk/Pulumi.Automation/Pulumi.Automation.csproj:15); xunit `latest-All` (xunit__xunit@0c7aa4991fa3:src/Directory.Build.props:61); Humanizer `Minimum` (Humanizr__Humanizer@4574b93883bf:Directory.Build.props:18); cake `Default` (cake-build__cake@08885933e936:src/Directory.Build.props:8); Polly `latest` plus a hand-generated per-project-type globalconfig (App-vNext__Polly@e4476096da5b:eng/Analyzers.targets:17). Seven repos pick five different levels.

Notes:
- CA2007 text says it "is intended for libraries" and is "generally appropriate to suppress ... for projects that represent application code". It supports `dotnet_code_quality.CA2007.output_kind = DynamicallyLinkedLibrary` ([CA2007](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca2007)). Meziantou MA0004 is on by default and covers the same ground.
- CA1031 says "Do not suppress a warning from this rule", yet the process-kill code in the closest exemplar has to (simple-exec `ProcessExtensions.cs:117`, comment above: `System.Diagnostics.Process is "fine"` and the same exception is thrown for different reasons) ([CA1031](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1031)).
- CA2000 documents that it does not fire for locals of type `Stream`, `TextReader`, `TextWriter`, etc., and treats passing to a constructor as ownership transfer ([CA2000](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca2000)). In the probe `var p = Process.Start(psi);` was not flagged even at `All` (nullable return, `Process.Start` ownership is ambiguous).
- CA1849 cause includes "calling `Task.Wait()`, `Task<T>.Result`, or `Task.GetAwaiter().GetResult()`" in a Task-returning method; safe to suppress when sync and async code paths are separate ([CA1849](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1849)). Probe: `Process.WaitForExit()` flagged, message points to `WaitForExitAsync(CancellationToken)`.
- CA1416 is on by default as a warning for `net5.0`+; the fix is `OperatingSystem.IsWindows()` style guards or `[SupportedOSPlatform]` forwarding ([CA1416](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1416)). CliWrap suppresses it around `Process.PriorityClass`/`ProcessorAffinity`/`MinWorkingSet` (Tyrrrz__CliWrap@7dbc252fa773:CliWrap/Command.Execution.cs:341).

### 3. Process spawning: the catalogs have a hole

- Official rules: CA3006 (process command injection) analyses "potentially untrusted HTTP request input", cannot track across assemblies, off by default ([CA3006](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca3006)). CA1837/CA1839 are `Environment.ProcessId` / `ProcessPath` micro-rules ([quality rules index](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/)).
- Meziantou: MA0161 (`UseShellExecute` must be set explicitly, off), MA0162 (use the `ProcessStartInfo` overload, off), MA0163 (`UseShellExecute` must be false when redirecting I/O, on). MA0161 documents that the default is `true` on .NET Framework and `false` on .NET Core, a migration trap (`meziantou__Meziantou.Analyzer@161b7e948ad3:docs/Rules/MA0161.md`, `MA0163.md`; enabled column from the [README](https://raw.githubusercontent.com/meziantou/Meziantou.Analyzer/main/README.md)).
- Probe 2 (`fixtures/codified/Probe2.csproj`, packages resolved by `*`: Meziantou.Analyzer 3.0.297, Microsoft.VisualStudio.Threading.Analyzers 18.7.23, Microsoft.CodeAnalysis.BannedApiAnalyzers 5.6.0, plus a two-line `BannedSymbols.txt`): flagged MA0004, MA0006, MA0009 (regex timeout), MA0011 x3, MA0016, MA0048 x2, MA0074, MA0163, RS0030 x2 (banned `DateTime.Now`, `Encoding.Default`), VSTHRD103. Not flagged by anything: `"run " + arg` into `Arguments`, un-disposed `Process`, `a + "/" + b` path join, `!` null-forgiving.
- BannedApiAnalyzers is the lever for what no rule covers: `BannedSymbols.txt` with doc-ID entries (`P:System.DateTime.Now; reason`) registered as `AdditionalFiles` ([help](https://raw.githubusercontent.com/dotnet/roslyn-analyzers/main/src/Microsoft.CodeAnalysis.BannedApiAnalyzers/BannedApiAnalyzers.Help.md)). Rule IDs RS0030/RS0031 were observed in the probe, not on that page.
- Exemplar bans: Polly bans `DateTime.Now/Today`, `DateTimeOffset.Now/Today` and implicit `DateTime` to `DateTimeOffset` conversion in favour of `TimeProvider` (App-vNext__Polly@e4476096da5b:eng/analyzers/BannedSymbols.txt:1-5); Azure bans `Uri.ToString()` (Azure__azure-sdk-for-net@32c48fc3d524:eng/BannedSymbols.txt:1); coverlet and testfx ban `string.IsNullOrEmpty` and `Debug.Assert` in favour of local helpers. Nobody in the corpus bans `Process.Start`, `Encoding.Default` or `Environment.GetEnvironmentVariable`.
- Suppressions in the closest analogue are a map of the tension points (adamralph__simple-exec@f80913246993):
  - `src/SimpleExec/Command.cs:409` CA2025 (passes an `IDisposable` `Process` into an unawaited `RunAsync` task).
  - `Command.cs:432-433` CA1849 + VSTHRD103 (`readOutput.Result` after `Task.WhenAll`; safe because already complete).
  - `Internal/ProcessExtensions.cs:117` CA1031 (`Process.Kill` throws many unrelated exceptions).
  - `ExitCodeException.cs:6` CA1032 (exception carries exit code; standard ctors do not apply).
  - `Command.cs:12` RS0026 (multiple overloads with optional parameters).
- The OWASP .NET cheat sheet says allowlist-validate untrusted input to `Process.Start` and is silent on path traversal; the summary I retrieved paraphrases `ArgumentList` as "not safe with untrusted input", which is looser than the Microsoft doc, so cite the Microsoft doc ([OWASP](https://cheatsheetseries.owasp.org/cheatsheets/DotNet_Security_Cheat_Sheet.html), [ArgumentList](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo.argumentlist)).

### 4. Async, cancellation, blocking

- VSTHRD analyzers (vs-threading): relevant to a non-UI library are VSTHRD002 (avoid problematic synchronous waits, warning), VSTHRD003 (foreign Tasks, warning), VSTHRD100 (async void), VSTHRD103 (call async methods when in an async method), VSTHRD105 (overloads that assume `TaskScheduler.Current`), VSTHRD110 (observe result of async calls), VSTHRD114 (no null from Task-returning), VSTHRD200 (Async suffix, warning). VSTHRD111 (`ConfigureAwait(bool)`) is Hidden by default. Main-thread / JoinableTaskFactory rules (VSTHRD001/004/010/012/108/109/115) are VS-extension specific and should not be adopted by default ([VSTHRD index](https://microsoft.github.io/vs-threading/analyzers/index.html); the "UI-only" grouping is my reading of the titles).
- Meziantou async set on by default: MA0004, MA0040 (forward token), MA0042 (blocking in async), MA0079, MA0100, MA0129, MA0134, MA0147; off by default: MA0032 (use token overload even without a token in scope), MA0045, MA0155 (async void), MA0137/MA0138 (Async suffix) ([README](https://raw.githubusercontent.com/meziantou/Meziantou.Analyzer/main/README.md)).
- Roslynator (local clone): `src/Analyzers.xml` lists 338 analyzers, 200 enabled by default, 140 not (`grep -o '<Analyzer>' ... | wc -l`, `grep -o 'IsEnabledByDefault>true'`). RCS1090 (ConfigureAwait) is off by default; RCS1046/1047 (Async suffix) and RCS1229 (async/await when necessary) exist (dotnet__roslynator@167f43468118:src/Analyzers.xml).
- CA2016 sits in `Minimum`, so forwarding tokens is cheap to enforce; SDK 11 RC1 adds CA2027 (cancel `Task.Delay` after `Task.WhenAny`) (measured, section 10). Nothing in the catalogs states a cancellation contract for a child process (graceful signal vs kill-tree vs timeout). simple-exec encodes the choice as a `cancellationIgnoresProcessTree` parameter threaded to `process.Kill(!ignoreProcessTree)` (adamralph__simple-exec@f80913246993:src/SimpleExec/Internal/ProcessExtensions.cs:~111).
- ConfigureAwait use in the corpus: CliWrap has 49 `ConfigureAwait(false)` occurrences (`git grep -n 'ConfigureAwait(false)' | wc -l` in Tyrrrz__CliWrap@7dbc252fa773). simple-exec uses it throughout (`Command.cs:~418`).

### 5. JSON, trimming, AOT

- CA1869 (reuse `JsonSerializerOptions`) is a suggestion by default and a warning from Minimum; the options object caches metadata and is immutable after first use ([CA1869](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1869), [configure options](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/configure-options)). `JsonSerializerOptions.Web` singleton exists from .NET 9.
- STJ source generation: `JsonSerializerContext` + `[JsonSerializable]`; reflection can be disabled with `JsonSerializerIsReflectionEnabledByDefault=false` (automatic under `PublishTrimmed`); non-generic `JsonStringEnumConverter` is not supported in Native AOT, use `JsonStringEnumConverter<TEnum>`; `JsonSourceGenerationOptions` can carry most options from .NET 8 ([source generation](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/source-generation)).
- Meziantou has four JSON-strictness rules, all off by default: MA0222/MA0223 (`JsonSourceGenerationOptions` should set `RespectNullableAnnotations` / `RespectRequiredConstructorParameters`) and MA0224/MA0225 (the `JsonSerializerOptions` equivalents) ([README](https://raw.githubusercontent.com/meziantou/Meziantou.Analyzer/main/README.md)). These are the only analyzer-level hooks I found for "deserialize CLI output strictly".
- SDK 11 RC1 adds CA2026 (prefer `JsonElement.Parse` over `JsonDocument.Parse().RootElement`) (measured).
- Trimming: `IsTrimmable` marks the assembly and enables trim warnings; `EnableTrimAnalyzer` gives warnings without the marker; trim analysis needs `net6.0`+; "introducing trim analysis warnings is a breaking change" for a library when consumers use `PublishTrimmed`; avoid reflection in static constructors; avoid annotating virtual/interface methods ([prepare libraries](https://learn.microsoft.com/en-us/dotnet/core/deploying/trimming/prepare-libraries-for-trimming)).
- AOT: `IsAotCompatible` implies the four analyzer properties; `VerifyReferenceAotCompatibility` (IL3058) and `VerifyReferenceTrimCompatibility` (IL2125) are opt-in and the `IsAotCompatible` assembly metadata only exists from .NET 10 builds ([native AOT](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/)). IL3050 = a `RequiresDynamicCode` member such as `MakeGenericType` ([IL3050](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/warnings/il3050)).
- Exemplars: Polly.Core `IsAotCompatible=true` (App-vNext__Polly@e4476096da5b:src/Polly.Core/Polly.Core.csproj:15); Humanizer both flags (Humanizr__Humanizer@4574b93883bf:Directory.Build.props:41-42); npgsql `IsAotCompatible` (npgsql__npgsql@9c47244547c2:src/Directory.Build.props:5); CliWrap conditions the flags on TFM and turns the trim/AOT analyzers off for older TFMs (Tyrrrz__CliWrap@7dbc252fa773:Directory.Build.props:19-22, CliWrap/CliWrap.csproj:5-11); openai-dotnet explicitly sets both false (openai__openai-dotnet@1f0e8829acac:Directory.Build.props:100-101).

### 6. Public API, binary compatibility, TFMs

- PublicApiAnalyzers: RS0016 (public symbol missing from `PublicAPI.txt`), RS0017 (removed symbol must be marked `*REMOVED*`), RS0022 (constructor makes a noninheritable base class inheritable), RS0026/RS0027 (optional-parameter overloads), RS0036/RS0037/RS0041 (nullability tracking, oblivious types), RS0048 (file missing). Internal-API variants RS0051-RS0061 exist and are off by default. Per-TFM files are supported (`PublicAPI/$(TargetFramework)/PublicAPI.Shipped.txt`) ([help](https://raw.githubusercontent.com/dotnet/roslyn-analyzers/main/src/PublicApiAnalyzers/PublicApiAnalyzers.Help.md), [rule list](https://raw.githubusercontent.com/dotnet/roslyn-analyzers/main/src/PublicApiAnalyzers/Microsoft.CodeAnalysis.PublicApiAnalyzers.md)).
- Adoption in the corpus: Polly.Core, Dapper, npgsql, GitVersion, pulumi-dotnet (Pulumi, Pulumi.Automation), StackExchange.Redis, testfx, StyleCopAnalyzers ship `PublicAPI.Shipped.txt` + `Unshipped.txt` (`git ls-files | grep PublicAPI` per clone, e.g. pulumi__pulumi-dotnet@2a0dca84f09b:sdk/Pulumi.Automation/PublicAPI.Shipped.txt). simple-exec instead snapshots the API with `PublicApiGenerator` and compares with `tests/Tests/PublicApi.Surface.expected.txt` (adamralph__simple-exec@f80913246993:tests/Tests/PublicApi.cs:11-17).
- Package Validation: `EnablePackageValidation` runs baseline-version, compatible-framework and compatible-runtime checks after `Pack` ([overview](https://learn.microsoft.com/en-us/dotnet/fundamentals/apicompat/package-validation/overview)). Users: vs-threading (microsoft__vs-threading@f6d817997090:Directory.Build.props:21), stripe-dotnet (stripe__stripe-dotnet@dbdca6ba5efc:src/Stripe.net/Stripe.net.csproj:27), nodatime test lib, FluentValidation DI extensions. Polly sets it false for samples.
- Breaking-change taxonomy and rules of thumb from Microsoft: source break (new overload ambiguity, renamed parameter), binary break (signature change, assembly rename, strong-name key change), behaviour break (even a bug fix). CONSIDER abstract base classes over interfaces because adding a member to an interface breaks implementers; CONSIDER keeping `[Obsolete]` members indefinitely in low-level libraries; DO NOT change the assembly name ([breaking changes](https://learn.microsoft.com/en-us/dotnet/standard/library-guidance/breaking-changes)).
- TFM guidance: DO start with `net8.0`+; CONSIDER `netstandard2.0` for .NET Framework / broad reach; CONSIDER multi-targeting even when code is identical if there are dependencies; AVOID different assembly names per TFM; multi-targeted `netstandard2.0` caveat; NU5128 appears when `lib/<tfm>` and nuspec dependency groups disagree ([cross-platform targeting](https://learn.microsoft.com/en-us/dotnet/standard/library-guidance/cross-platform-targeting), [NU5128](https://learn.microsoft.com/en-us/nuget/reference/errors-and-warnings/nu5128)).
- TFM choices in process-wrapper exemplars (`git grep -n -E '<TargetFrameworks?>'`): CliWrap `netstandard2.0;netstandard2.1;net6.0;net7.0;net10.0` (Tyrrrz__CliWrap@7dbc252fa773:CliWrap/CliWrap.csproj:3), MedallionShell `netstandard1.3;netstandard2.0;net45;net46;net471` (madelson__MedallionShell@e45f1f6ffd4c:MedallionShell/MedallionShell.csproj:4), simple-exec `net8.0;net9.0;net10.0` (adamralph__simple-exec@f80913246993:Directory.Build.props:13), Pulumi.Automation `net6.0` (pulumi__pulumi-dotnet@2a0dca84f09b:sdk/Pulumi.Automation/Pulumi.Automation.csproj:4, now past EOL). The cost of netstandard in CliWrap: it ships polyfill packages (PolyShim, System.Memory, Microsoft.Bcl.AsyncInterfaces, System.Management) and sets `Nullable=annotations` below `netstandard2.1` "because there is no nullability info for BCL" (Directory.Build.props:15-16, CliWrap.csproj:30-50).
- Sealing and seams: CA1852 (seal internal types, Recommended), Meziantou MA0053 (seal classes/records), MA0017 (abstract types should not have public constructors), RS0022 above, and the Microsoft advice on abstract classes. runtime coding-style: make internal/private types `static` or `sealed` unless derivation is needed ([coding-style](https://raw.githubusercontent.com/dotnet/runtime/main/docs/coding-guidelines/coding-style.md)).

### 7. Culture, encoding, time, paths

- Culture: CA1304/1305/1309/1310/1311 (Recommended), CA1307 (All), Meziantou MA0001/MA0011/MA0074/MA0075/MA0076 on by default (all measured/README). In the probe `a.ToLower() == b.ToLower()` triggered CA1304, CA1311, CA1862, CA1309 and `string.Compare(a, b) == 0` CA1310 + CA2251.
- Invariant globalization: casing only affects ASCII, comparisons become ordinal, normalization is a no-op, ICU is required on Linux when the mode is off or the app fails to start ([runtime doc](https://raw.githubusercontent.com/dotnet/runtime/main/docs/design/features/globalization-invariant-mode.md)). npgsql, vs-threading AOT tests set `InvariantGlobalization=true` in test/AOT projects (npgsql__npgsql@9c47244547c2:test/Npgsql.NativeAotTests/Npgsql.NativeAotTests.csproj:7; microsoft__vs-threading@f6d817997090:test/AOT.props:6).
- Encoding: no analyzer flagged `Encoding.Default` in the probe except a custom ban (RS0030). Meziantou's table has no encoding rule ([README](https://raw.githubusercontent.com/meziantou/Meziantou.Analyzer/main/README.md)). Child-process stream decoding is an uncodified area.
- Time: Meziantou MA0113/MA0114 (`UnixEpoch`), MA0132/MA0133 (implicit `DateTimeOffset` conversion), MA0166 (forward `TimeProvider`), MA0188 (prefer `System.TimeProvider`), MA0167 off. `DateTime.Now` itself is not flagged by any shipped rule (probe); Polly bans it (section 3).
- Paths: no rule in the Microsoft or Meziantou lists addresses separators, traversal or long paths. CA3003 (file path injection) is HTTP-taint based; SDK 11 RC1 adds CA1877 (collapse consecutive `Path.Combine`/`Path.Join`) (measured). The OWASP sheet is silent on path traversal ([OWASP](https://cheatsheetseries.owasp.org/cheatsheets/DotNet_Security_Cheat_Sheet.html)).
- Platform: CA1416 plus `OperatingSystem.IsWindows()` guards; Meziantou MA0144 (use `System.OperatingSystem` to check OS) is on by default.

### 8. Security and supply chain

- BinaryFormatter: Microsoft says it "is insecure and can't be made secure"; from .NET 9 the in-box implementation throws on use. SoapFormatter, NetDataContractSerializer, LosFormatter, ObjectStateFormatter are also dangerous. Safe in-box alternatives include System.Text.Json and XmlSerializer/DataContractSerializer ([guide](https://learn.microsoft.com/en-us/dotnet/standard/serialization/binaryformatter-security-guide)). Rule family CA2300+ and CA2326-CA2330 (Newtonsoft `TypeNameHandling`) are off by default ([quality rules index](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/)).
- NuGet audit: NU1901 low, NU1902 moderate, NU1903 high, NU1904 critical, NU1900 (cannot fetch advisories), NU1905 (audit source lacks data); `NuGetAuditMode` default `all` for `net10.0` and `direct` otherwise; `NuGetAuditLevel` default low; MS recommends a CI-only audit pipeline with `WarningsAsErrors` for the codes and `WarningsNotAsErrors` elsewhere; `NuGetAuditSuppress` is a "last resort" ([NuGet audit](https://learn.microsoft.com/en-us/nuget/concepts/auditing-packages)). Polly sets `NuGetAuditMode=direct` (App-vNext__Polly@e4476096da5b:eng/Common.props:9).
- TLS/certificates: Meziantou MA0039 (do not write custom certificate validation) is on by default; CA5359 is the Microsoft equivalent ([README](https://raw.githubusercontent.com/meziantou/Meziantou.Analyzer/main/README.md), [quality rules index](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/)). Relevant if the SDK downloads the `ocx` binary.
- OWASP sheet for a downloader: allowlist protocols and domains, do not follow redirects blindly, sign assemblies, use NuGet package signing, run SCA in CI ([OWASP](https://cheatsheetseries.owasp.org/cheatsheets/DotNet_Security_Cheat_Sheet.html)). Integrity verification of a downloaded executable (hash/signature) is not something any analyzer checks.
- Sonar: Polly enables SonarAnalyzer.CSharp with a generated `Library.globalconfig` (App-vNext__Polly@e4476096da5b:eng/analyzers/Library.globalconfig, generated 2023-02-20). Counting lines: `awk` over `dotnet_diagnostic.S<num>` shows 313 warning, 95 none, 4 suggestion, 1 error. Notably S4036 (PATH-searched process start) and S5445 are warnings; S2930 and S3881 (disposable patterns) are none. I did not read the Sonar rule pages, so rule meanings here are from IDs only.

### 9. Style layers and how real repos configure them

- Layers: CA (quality, SDK, build-time), IDE (style, IDE-only unless `EnforceCodeStyleInBuild`), third party: StyleCop SA (style/layout/docs; severity via ruleset or globalconfig, `stylecop.json`) ([StyleCop README](https://raw.githubusercontent.com/DotNetAnalyzers/StyleCopAnalyzers/master/README.md)), Roslynator, Meziantou, SonarAnalyzer, xUnit analyzers, VSTHRD ([overview](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/overview)).
- dotnet/runtime style is a convention set, not a rule set: Allman braces, `_camelCase`, `s_` statics, `t_` thread-statics, explicit visibility, `var` only when the type is evident, language keywords over BCL names, `\uXXXX` over literal non-ASCII, `nameof`. The page says an existing file's style wins, and ships an `.editorconfig` ([coding-style](https://raw.githubusercontent.com/dotnet/runtime/main/docs/coding-guidelines/coding-style.md)). The single-line `if` ban and the non-ASCII escape rule are unusual; most exemplars do not follow them.
- Warnings-as-errors: simple-exec only in `Release` (Directory.Build.props:20-21); CliWrap, npgsql, xunit, Pulumi always. CliWrap also sets `CheckEolTargetFramework=false` and `SuppressTfmSupportBuildWarnings=true` (Directory.Build.props:9-10), which hides end-of-life TFM warnings.
- A rationale string on every suppression is the pattern in simple-exec (`#pragma warning disable CA1849 // Call async methods when in an async method` plus paired restores). Polly instead generates a whole globalconfig per project type (Library/Test/Benchmark).
- Docs: simple-exec sets `GenerateDocumentationFile=true` with the comment "workaround for https://github.com/dotnet/roslyn/issues/41640" (adamralph__simple-exec@f80913246993:Directory.Build.props:8) and suppresses IDE0005 in `Global.cs:1`; I did not fetch the issue, so the link between them is unverified. CS1591 is the missing-XML-comment compiler warning. Meziantou adds MA0154, MA0196-MA0199, MA0203 for doc comments.

### 10. Era flags

- .NET 8 floor: only `net8.0` analyzers; `analysislevel_9_all` is the highest file in SDK 8.0.425 (`ls .../config`), so `AnalysisLevel=latest` on SDK 8 never includes CA2022+ (CA2022 and CA2264/2265 arrived in .NET 9, CA2023 and CA2266 in .NET 10 per the [overview](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/overview)).
- Quirk: SDK 10.0.401 already ships an `analysislevel_11_*` set with identical rule counts to 10 (280/92/145). SDK 11.0 RC1 (11.0.100-rc.1.26425.128) adds six rules to the 11 set: CA1517 (prefer `ReadOnlySpan`/`ReadOnlyMemory` over `Span`/`Memory`), CA1876, CA1877, CA2026, CA2027, CA2028 (All 286, Recommended 151, Minimum 98). Anything specific to these is .NET 11 / RC1 era and must be flagged. Measured with `comm -13` of the rule-ID lists from the two SDKs' `analysislevel_11_all.globalconfig`.
- NuGet 7.0 / .NET 10 SDK changed the `NuGetAuditMode` default to `all` for `net10.0`; NuGet 6.11/.NET 8.0.400 added `NuGetAuditSuppress` ([NuGet audit](https://learn.microsoft.com/en-us/nuget/concepts/auditing-packages)).
- BinaryFormatter throws from .NET 9 ([guide](https://learn.microsoft.com/en-us/dotnet/standard/serialization/binaryformatter-security-guide)).
- `System.Threading.Lock` (MA0158), `TimeProvider` (MA0188), `JsonSerializerOptions.Web` (.NET 9), `IsAotCompatible` assembly metadata (.NET 10) are all .NET 8-10 era features that need TFM guards on a multi-target.
- Toolchain: the rule set depends on which SDK built it. `global.json` is resolved from the cwd; the probe built from outside the fixture dir used SDK 11 RC1 until run from inside it. Reproduce: `cd /; run.sh dotnet --version` prints `11.0.100-rc.1.26425.128`; `cd fixtures/codified; run.sh dotnet --version` prints `10.0.401`.
