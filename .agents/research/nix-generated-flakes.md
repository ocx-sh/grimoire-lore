# Generated flakes from the ocx index

## Verdict

These are decisions. They bind the **generated flake** shape (D) unless a line names another shape.

1. **The architecture is committed data, a small reader, and a CI updater. The generator is ocx code.** An `ocx` subcommand resolves manifests and config blobs through ocx's registry client and `platform.rs:416`, then writes `data.json`. The flake repository holds no platform logic. An eval-time index reader fails at three separate gates, and all three were watched. A literal absolute-path read of an index checkout is refused by pure evaluation (`access to absolute path '…' is forbidden in pure evaluation mode`) before IFD applies at all. With IFD off, evaluation refuses the build. With IFD on, the manifest fetch is not a fixed-output derivation, so the sandbox gives it no network (builder exit 6). This confirms map conflict 17.
2. **The fetch is plain nixpkgs `fetchurl` with the fixed header `Authorization: Bearer QQ==`.** `hash` is the OCI layer digest itself, `sha256:<hex>`, stored once. Both dives are overruled on part of this. index-data-model and the ocx audit ("token exchange inside the FOD", "never a plain fetchurl") lose to a sandboxed build that went red without the header (401) and green with it. The oci-fetch-prototype data format loses too: it stores the digest and an SRI copy side by side, and a drift test turned that into a hash mismatch. `builtins.convertHash` is rejected because Lix 2.95.2 does not have it. The generator's *manifest* fetch (not the layer fetch) also needs an `Accept: application/vnd.oci.image.manifest.v1+json` header; without it ghcr.io answers a bare 404 (wave-3 re-run §8).
3. **Naming.** `packages.<system>.<ns>-<pkg>` is flat and holds only the latest version. `legacyPackages.<system>.<ns>.<pkg>."<version>"` holds every canonical version plus its aliases. The quoted version selects the attribute (unquoted `#kitware.cmake.4.4.2` fails with `does not provide attribute …`). **`nix run` works only where NIX-GEN-13 sets `mainProgram`:** `nix run <flake>#legacyPackages.x86_64-linux.actionlint.actionlint."1.7.12" -- -version` prints `1.7.12`, while the same form on five-binary `kitware.cmake."4.4.2"` fails with `unable to execute '…/bin/kitware-cmake': No such file or directory` (map E26; the earlier Verdict claimed the cmake form "resolves" under `nix run`, which it never did). The overlay adds exactly one attribute, `ocx`. 96 of 122 index basenames already exist under nixpkgs `pkgs/by-name` (index-data-model §4), so this is about safety, not style. The `systems` list never contains `x86_64-darwin` (NIX-FLK-09); the re-run hit that throw on the full corpus.
4. **Derivation template.** Every Linux package gets `autoPatchelfHook` plus `stdenv.cc.cc.lib`, whatever its libc tag. On a static ELF the hook is a measured no-op with an identical closure. The hook fails the whole derivation when any one bundled binary lacks a library, so a package carries a per-package list of named sonames to ignore, taken from the data file and never `["*"]` (NIX-GEN-19). `sourceProvenance` is always set. `mainProgram` is set only when there is exactly one binary. Licenses come from SPDX ids that the generator splits out of the annotation, and they resolve without warnings. `description` and `homepage` come from the ocx package index, never from OCI annotations (Verdict 11, NIX-GEN-21). This overrides the prototype's original rule of adding the hook only for glibc offers.
5. **Gate.** `nix flake check --no-build` is necessary and never sufficient. It passed a corrupted digest (exit 0, twice, on two separate fixture pairs), and it passed `kitware-cmake` while that package could not build at all. Every update PR also builds a sandboxed smoke check that runs the binaries. Cost is no reason to thin the gate. On the full corpus shape (125 packages, 1,293 versions, 3 systems), `check --all-systems --no-build` takes 4.38 s wall, and forcing every version's `drvPath` on all systems takes 0.25 s wall, both on a warm nixpkgs eval cache. The network-bound smoke build is what dominates CI time.
6. **Update loop.** Updates land as a reviewed PR under a GitHub App token. One item's failure never blocks the rest, and nothing is pushed directly while ocx does not verify publisher signatures (M-E-20). This follows index-data-model. zig-overlay, fenix and nix-index-database push directly, and they are not the model here.
7. **History.** Keep every digest. The projected size is about 2.1 MiB, well under owner Q5's 20 MB trigger. Handling of yanked and deprecated versions waits until the index populates `status`, which is set on 0 of 125 packages today.
8. **Env, token and entrypoint translation (M-E-11) is settled from a live token census, with three documented gaps.** ocx `env` entries become `makeWrapper` flags: `path` becomes `--prefix`, `constant` becomes `--set`, `list` becomes `--suffix`. Every literal segment is shell-escaped, and only `"$installPath"` is spliced in (NIX-GEN-20). The wave-3 census fetched every reachable package's latest linux/amd64 manifest and config blob (122 of 125) and counted token *forms*, not just env types:
    - `${installPath}` / `${self.installPath}`: 121 of 122. Translated.
    - `:native` / `:posix` render modifiers: 0. Stripped as a no-op; both render `/` on the only two Nix targets, Linux and Darwin.
    - `${self.env.KEY}`, `${deps.NAME.installPath}`, `$${`: 0 each. `entrypoints`: 0 packages. `dependencies`: 0 packages. Env types: `path` 120, `constant` 2, `list` 0.

    **Gap 1, `${self.env.KEY}`.** The re-run translated it into a spliced `"$KEY"` and argued that the wrapper's earlier `export` sets it. That is wrong: the splice is expanded by the *builder* shell when `makeWrapper` runs, where `$KEY` is unset or holds the sandbox's own value (for `PATH`, the build `PATH`). Watched at the shell level: the prototype's rendered line yields `SDK_TOOL=/bin/tool` instead of `…/libexec/p/sdk/bin/tool`. ocx defines the token as this package's own resolved value, never a consumer's folded one (`metadata.md` §`self.env`), so the only correct translation is textual inlining of the earlier entry's value by the generator. The reader throws on any `${self.env.…}` that reaches it (NIX-GEN-20). No Nix-level twin was run (Environment note).
    **Gap 2, `${deps.NAME.installPath}`.** Refused with a `throw` until a real package declares a dependency. The visibility mapping (`buildInputs` / `propagatedBuildInputs`) is verified only on synthetic data.
    **Gap 3, `entrypoints`.** The launcher design is proven by one watched twin (NIX-GEN-22) but not wired into the prototype, which today ignores the field silently. A reader that does not translate `entrypoints` or `dependencies` must throw on a non-empty one.
9. **The same rules bind any prebuilt-binary flake that is not ocx:** architecture, attribute shape, overlay, template, meta and gate. The ocx-only rows are NIX-GEN-02, 04, 05, 08, 16, 20, 21 and 22. The fleet's own flakes (shape A) inherit only NIX-GEN-12 to 14, and only when they add a `-bin` package.
10. **The handoff prototype (`nix-generated-flakes/prototype/`) now satisfies NIX-GEN-11, 17 and the escaping half of 20, but it is still not a compliant reference.** The wave-3 re-run fixed Verdict 10's three breaks and passed the full checklist cold: Q5, `--rebuild` on all four packages with no diff, the smoke check, the `aarch64-darwin` `drvPath` evaluation, `gen13-check.sh`, the NIX-GEN-19 and NIX-GEN-07 jq checks, `nixfmt --check` and `deadnix --fail`, all exit 0. A planted `HOSTILE=pre$(touch /tmp/PWNED)post` value stayed inert. This revision re-checked two of the fixes by hand: `jq -S . data.json | cmp - data.json` exits 0, and `lib/mk-package.nix` gates the hook on `-linux` only. It still breaks four things, all latent against today's data:
    - NIX-GEN-20: `lib/mk-ocx-env.nix` splices `${self.env.KEY}` as the builder variable `"$KEY"` (Gap 1).
    - NIX-GEN-20: `renderChunk` splits on the *first* recognised token only and `escapeShellArg`s the rest. A second, different token in the same value is passed through as literal text instead of throwing. ocx's own `metadata.md` example, `${self.installPath}/bin:${deps.cmake.installPath}/bin`, would ship the literal `${deps.cmake.installPath}`. This was found by reading; no twin was run.
    - NIX-GEN-22: `lib/mk-package.nix` never reads `entrypoints` or `dependencies`, so it drops them silently.
    - NIX-GEN-21: `meta.description` is synthesised (`"Prebuilt ${ns}/${pkg} from the ocx index"`), and `homepage` is absent.

    ocx fixes all four before it adopts the prototype.
11. **Meta source for D (M-E-31, map E15) is settled.** Of 1,720 image indexes, 0 carry `org.opencontainers.image.description` and 0 carry `.url`. 1,691 carry `.source`, and it names the mirror repository (`https://github.com/ocx-contrib/mirror-astral-sh` for ruff), never the upstream. The package index's own files carry the data: `desc.description` is non-empty in 125 of 125, and `upstream.repository_url` is present in 123 of 125. Only `ocx/cli` and `ocx/mirror` lack it. This revision re-measured all five numbers over `/home/mherwig/dev/index@9eba2cc3929b`. `meta.description` comes from `desc.description` and `meta.homepage` from `upstream.repository_url`. `homepage` is omitted when absent (NIX-GEN-21). NIX-PKG-07's description-presence clause is therefore satisfiable for D. Its license-presence clause stays replaced by NIX-GEN-14 for D (E15).

The w2 re-run and the second revision ran through `run.sh` on the shared store, uncontended. The wave-3 re-run reported no contention either. **At this third revision the toolchain was gone.** `~/.cache/research-lang/nix-tools/` held only `run.sh`, with no `.nix-portable/` store, and neither the fixture tree nor `~/.cache/research-lang/exemplars/` existed. `timeout 60 run.sh nix --version` failed with `bwrap: Can't find source path …/.nix-portable/emptyroot: No such file or directory`, exit 1, and there is no host Nix. ## AI-agent failure modes

Ranked by how often they bite. Each has the mechanical check that catches it.

1. **Pointing a header-less `fetchurl` or `nix-prefetch-url` at a ghcr.io blob, then reaching for `--impure`, a token script, or `dockerTools.pullImage`/skopeo after the 401.** Check: NIX-GEN-08, `nix build --rebuild .#<pkg>.src`.
2. **Believing a fetch fix worked because the FOD path was already in the store.** Measured: the header-less twin "built" with exit 0 until it was run with `--rebuild`. Check: `--rebuild` on every changed FOD (NIX-GEN-15).
3. **Treating every tag as a version**, which emits `latest`, floats and date-suffixed duplicates as separate builds, or dropping digests that have only a build number. Check: the NIX-GEN-03 jq count must equal the number of unique digests.
4. **Flattening the overlay into `pkgs`**, which shadows cmake, neovim and jq for most packages. Check: NIX-GEN-07's jq.
5. **Nesting versions under `packages`.** Check: Q5 fails with `… is not a derivation` (NIX-GEN-06).
6. **Selecting a manifest by first match on (os, arch)**, or assuming every package has a bare offer. Measured on real data: ruff is misrouted to its bare manifest, and corretto, which has no bare offer, is dropped. Check: the NIX-GEN-04 ambiguity count and a selector unit test over those two indexes.
7. **Trusting `nix flake check --no-build` as evidence that a package builds.** It passed a corrupted digest, twice, and it passed a `kitware-cmake` that could not build at all. The measured failure for a bad digest is a 404, because the URL carries the digest. A mismatch appears only when a second hash copy drifts. Check: NIX-GEN-15's smoke build, and NIX-GEN-09 (store one copy).
8. **Calling `getLicenseFromSpdxId` on SPDX expressions**, which warns on every evaluation, or defaulting a missing annotation to `free` or `unfree`. Check: `--option abort-on-warn true` (NIX-GEN-14).
9. **Guessing `mainProgram`** for a package with several binaries. Check: `gen13-check.sh` (NIX-GEN-13).
10. **Committing the resolved SAS URL "so generation runs once"**, or adding `--location-trusted` "to make the redirect work". Check: the NIX-GEN-10 grep.
11. **Reaching for `builtins.convertHash` or `nix hash convert` in the reader.** The first breaks Lix 2.95.2. Check: `grep -rn -e 'convertHash' --include='*.nix' .` is empty. The digest is passed verbatim (NIX-GEN-09).
12. **Omitting the hook for "bare" offers** on the assumption that bare means static. The handoff prototype did exactly this until wave 3. Check: the NIX-GEN-11 smoke run and the interpreter `readelf`.
13. **Reaching for `autoPatchelfIgnoreMissingDeps = [ "*" ]`, or dropping `autoPatchelfHook`, the first time one bundled binary's missing library fails a multi-binary package.** A blanket ignore hides a real missing library on every other binary, permanently. Check: NIX-GEN-19's jq over `data.json`. That replaces the earlier `grep … lib/mk-package.nix`, which searched the wrong file.
14. **Quoting env values as a unit.** The two variants fail in opposite directions:
    - `lib.escapeShellArgs` over whole values ships the literal `$installPath` (w2 re-run).
    - Hand double-quoting executes `$(…)` from registry data at build time and turns ocx's `$${` into a PID (second revision). The w2 re-run's own fix was this variant.

    Check: NIX-GEN-20's literal-line test on a planted hostile value.
15. **Moving a `makeWrapper` output onto the path it wraps** (`makeWrapper orig tmp; mv tmp orig`). The wrapper `exec`s itself and hangs at 0% CPU with no error (w2 re-run, `env-proto/`). Check: the wrapped binary lives at `libexec/<pkg>/…` and the wrapper at `bin/…`, never the same path. The smoke check (NIX-GEN-15) under `timeout` catches the hang.
16. **Translating `${self.env.KEY}` into a spliced shell variable `"$KEY"`** on the theory that the wrapper's earlier `export` sets it. The splice expands in the builder, at build time, where `KEY` is empty or holds the sandbox's value. The w3 re-run made exactly this mistake. Check: NIX-GEN-20's `self.env` twin; the generator inlines the earlier value textually.
17. **Splitting a value on its first recognised token and escaping the remainder**, so a second, different token in the same value (`${self.installPath}/bin:${deps.cmake.installPath}/bin`) ships as literal text instead of throwing. Check: after splicing, every rendered segment must be free of `${`; otherwise throw (NIX-GEN-20).
18. **Writing `"$${x}"` or `''$${x}''` to mean "one literal `$`, then interpolate `x`".** Both CppNix 2.35.2 string forms treat `$${` as literal text, and `nix eval` prints `"$\${x}"` with no warning. The w3 re-run hit this while writing the NIX-GEN-20 fix. Check: build the splice by concatenation (`"\"$" + name + "\""`), and `grep -n '\$\${' lib/*.nix` should match only comments.
19. **Wrapping an entrypoint's raw binary, which drops the package's env,** or silently ignoring `entrypoints` and `dependencies` because today's data has none. Check: NIX-GEN-22's env-var twin and the throw on a non-empty field.
20. **Mapping `org.opencontainers.image.source` to `meta.homepage`,** or synthesising a description because the OCI layer has none. `.source` names the ocx-contrib mirror. Check: NIX-GEN-21's grep.
21. **Fetching an OCI manifest with only the bearer header**, then reading ghcr.io's bare 404 as a missing package. Check: add `Accept: application/vnd.oci.image.manifest.v1+json` (NIX-GEN-05) before concluding that a reference is invalid.
22. **Documenting a `nix run` example that was only evaluated or built.** The earlier Verdict claimed `nix run …#kitware.cmake."4.4.2"` resolved, but cmake has no `mainProgram`. Check: execute every `nix run` example (Verdict 3).
