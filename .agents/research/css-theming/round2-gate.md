## Blocking — fix while drafting

Each has a known corrected form; none needs new measurement.

- CSS-TOK-01's literal-colour check goes red on correct code. I ran the design's exact command against its own certified-compliant build (`perl -pe 's/var\(\s*--[A-Za-z0-9-]+\s*,[^;)]*\)/var(X)/g' r2/tailwind-v4/dist/assets/index-DNsDMt4v.css | grep -nE '#[0-9a-fA-F]{3,8}\b|rgba?\(|hsla?\(|oklch\('`): 9 hits — `--color-brand:#35f`, `--color-static-only:#123456`, `--color-red-500:oklch(...)`, `#fff`, `#0000`. Every one is a token DECLARATION, i.e. exactly the tier the rule mandates. "Empty output is the pass" is therefore false for any tree that declares tokens. The check must exclude custom-property declaration right-hand sides as well as var() fallbacks — otherwise the ALWAYS gate is red on the reference implementation, which is the precise failure mode the design names for dark-parity ("a lint that goes red on correct code, which is how a gate gets switched off").
- CSS-CAS-02 / CSS-GATE-01's brace-matcher "assert the remainder is empty" is false on a compliant Tailwind v4 build. I implemented the matcher as the design specifies (skip any `@layer <name> {` span, print the rest) and ran it on the same artifact: the remainder holds the license comment, the bare content-free `@layer components;` statement, ~30 `@property --tw-*` registrations, and Tailwind's own `:root{...}`. `@property`, `@font-face`, `@charset`, `@import` and bare `@layer a, b;` statements are not layerable rules — a checker that reports them fails the surface the design lists as "already layered, do not wrap". gate.md must ship the ignore-list, not only the documented `content: "{"` false positive.
- vscode-webview.md is the one annex at ~0% round-2 reproduction and its key_facts are worded as measured behaviour: "`body{--vscode-x:...}` WINS AND PERSISTS", "the host's stale-property sweep iterates documentElement.style only", "a CDN `<link>` is silently blocked by the CSP with no console error unless devtools is open". Per the stated bar, a claim shipping as verified when no probe touched it is blocking. Half the `:root`-loses claim IS measured (engine case 4a: inline normal beats unlayered `#i`), but the premise that VS Code writes tokens inline on `documentElement` — and every persistence and CSP claim — is source-read only. The annex needs a per-file provenance banner and per-claim markers before it ships; the core file's "*Measured:* / *Spec-derived:*" convention currently applies only to the Non-Negotiables table rows, not to annex facts.
