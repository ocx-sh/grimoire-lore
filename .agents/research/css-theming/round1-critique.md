# Round-1 completeness critique

Verdict: **`needs-another-round`**. This is what commissioned round 2.

## Surfaces never studied

- forced-colors / Windows High Contrast — not a framework, a rendering MODE, and the only cascade mechanism that sits above everything the design describes. Under `forced-colors: active` the UA replaces color, background-color, border-color, outline-color and box-shadow with system colours regardless of layer, specificity, origin or `!important`; the entire token contract is void and `forced-color-adjust: none` is the only opt-out. Zero occurrences across all four local repos (verified: grep returns nothing in grimoire-indexer, ocx-catalog, kate-middlechild, grimoire-vscode) and zero mentions in the design. A theming rule that never names it is incomplete, and it is an accessibility obligation, not a nicety.
- Sass / SCSS / Less as a compile layer. The frontmatter already globs `.scss .sass .less` and the rule has nothing to say about them. `$brand: #ff0000` interpolated into a declaration compiles to `color:#ff0000` — CSS-TOK-01's defect, committed in the most widely deployed preprocessor, and it is the exact same failure the design names for CSS-in-JS interpolation and Style Dictionary aliasing but never generalises. Also unaddressed: `@use`/`@forward` ordering vs `@layer` first-appearance order, and Sass nesting flattening away the selector you reasoned about. The Angular annex states that Material's whole public contract is a Sass mixin vocabulary and then covers no Sass.
- Lit. The shadow-dom annex covers the platform; Lit is how people actually reach it. `static styles` + `adoptedStyleSheets` (not `<style>`, so a `shadowRoot.styleSheets` walk misses everything), the `css` tagged template and `unsafeCSS` escape, and Lit's own guidance to expose `--component-*` properties on `:host` — none studied. The shadow-dom annex's `adoptedStyleSheets` override channel is its only selector-based remedy and it was never exercised against the library that owns that API.
- Stencil. A third scoping mode the six-cause diagnosis table has no row for: `scoped: true` emits `sc-<tag>` classes with NO shadow root — neither attribute-scoped like Astro/Vue/Angular nor boundary-isolated like shadow DOM. An agent holding the design's table will diagnose it as one or the other and be wrong both times. Stencil is also the compiler behind Ionic, i.e. a large deployed surface.
- Radix / shadcn / Base UI. The design defers to `data-slot` and `data-state` 'where an ecosystem already has an accepted identity-attribute convention' without having studied the ecosystem it defers to. shadcn additionally inverts the publisher/consumer framing the whole rule is built on: the source is copied INTO the consumer's repo, so there is no downstream retheming audience and no injected stylesheet — the retheming surface is a git diff. CSS-API-01 and the tokens-are-a-public-API rationale have no target there.
- Shoelace / Web Awesome. The reference implementation of `::part()` + per-component `--<component>-*` custom properties — the exact contract the shadow-dom annex prescribes, shipped at scale, never checked against it. If the annex's advice diverges from what the ecosystem's flagship actually does, that is worth knowing before publishing.
- Solid / SolidStart and Qwik. Solid's `solid-styled` compiles to `data-s-<hash>` attribute scoping (a fifth attribute-scoping compiler, with its own tuple) and Solid's `style={{}}` prop is inline-style painting under CSS-CAS-04. Qwik's `useStylesScoped$` emits a `⭐️<hash>` class and loads component CSS lazily per component, which breaks the gate's premise that a production build yields one inspectable stylesheet.
- Nuxt and Remix / React Router 7. The css-modules annex's determinism claim — 'the root-layout global sheet is `<link>` #1, the module chunk #2, so the theme file loses every tie' — is a Next App Router observation stated as if it were a CSS Modules property. Remix's `links()` export and Nuxt's own CSS emission order are different mechanisms with different answers, and the annex's headline finding does not transfer.
- React Server Components as a boundary, not a framework. styled-components and Emotion require `"use client"`; a server component cannot use them at all. The css-in-js annex's remedies (`StyleSheetManager stylisPlugins`, `createCache`) are client-only, and the annex never says which half of a modern React app it applies to.
- Astro islands with a client framework. The astro annex covers `.astro` `<style>` blocks; a React or Vue island inside an Astro build puts two scoping regimes and two emission pipelines in one page. The annex's own gate instruction ('brace-match ANY `@layer <name>`, assert the remainder is empty') now has to survive the island framework's output too, and nothing in the design says what to expect there.
- Email HTML. CSS-CAS-04 inverts completely: inline styles are not an escape from the contract, they ARE the contract (no `@layer`, no custom properties in Outlook/Word rendering, no external stylesheet). Worth one table row saying the doctrine does not apply, rather than letting an agent carry `never paint through an inline style` into a mail template.
- iframe / widget embeds. A widget shipped as an iframe has no cascade relationship with its host at all — no layer, no specificity, no `::part()`. The retheming contract becomes postMessage or a token query parameter. One row, so an absent row does not read as 'the layer doctrine applies here'.

## Load-bearing claims resting on nothing

- happy-dom drops `@layer` at parse time / jsdom parses but never applies layered declarations. Traced to its only source today: `/home/mherwig/dev/ocx-catalog/.claude/rules/quality-css-overrides.md:152-153` — our own rule file, no upstream issue, no reproduction, no pinned versions. This is the sole justification for the heaviest single requirement in the whole rule set: the mandatory `npx <browser-driver>` line in The Gate that 'is not optional and cannot move into the unit-test runner'. The design's own open_questions calls it 'the single most quotable line in the gate rule' and it is still self-cited.
- Every Shadow DOM specificity tuple AND the Context-step claim. The reviewer states plainly that no browser and no shadow-DOM component exists on this machine, so nothing was reproduced from a live cascade. The annex's headline — `custom-element::part(x)` at (0,0,1) beating an internal `:host([secondary][disabled]:hover) .base` at (0,5,0), above layers and specificity — is spec-derived only. It is also the claim that tells an agent NOT to layer, NOT to raise specificity, and NOT to reach for `!important` in an entire framework family.
- The Svelte preprocess `style` hook. It is the annex's only remedy for the framework whose baseline inverts the doctrine, and it was verified only through `preprocess()` + `compile()` in isolation — never through a real `vite build`, which the reviewer names as 'the one unexercised link'. The companion claim that `svelte-package` bakes the wrapper into `dist/**/*.svelte` (and therefore that the contract is testable in the library's own CI) was read from `src/index.js`, never run.
- Angular multi-layer runtime ordering. Component style blocks are `head.appendChild`-ed in first-render order, so layer precedence for a library that ships more than one layer is first-render order. The design's annex proposes to state this; the research marks it explicitly unverified ('needs a real `ng build` plus browser check before the annex states it'). Unlayered-consumer-wins is safe either way, so the risk is bounded — but the design plans to publish the corollary as fact.
- `provideCssVarNamespacing()` × Angular Material. The design promotes 'author `--global--<name>`' to a MUST for any public token on Angular ≥22.1, which is correct, but the interaction that decides how much of the ecosystem this breaks — Material's partially-compiled components getting rewritten by the consuming app's linker while `mat.theme()`'s Sass output is not — was reasoned about and never built.
- StyleX `useLayers` plumbing beyond `@stylexjs/babel-plugin` and `@stylexjs/postcss-plugin`. It is the annex's ONLY actionable remedy for a default output of `(2,1,0)` that no unlayered consumer rule can ever beat. If it is not plumbed through webpack/rollup/unplugin, the annex names a fix that a reader cannot apply.
- Astro's `@layer astro.images` landing in the BUNDLED CSS asset. Inferred from a vite plugin `load` handler returning `{ code: css }`, never observed in a real `astro build` output. The whole 'a contract test matching `@layer <yourname>` false-positives on Astro's own image CSS' claim — which the design elevates into a core-level 'brace-match ANY @layer name' instruction — rests on it.
- VitePress 2.0.0-alpha.18's layer-ORDER interaction between `__vitepress_base` and a project's own layer. The layer's existence and byte extent were verified from the shipped package; the ordering consequence the annex proposes to publish was asserted, never tested.
- Tailwind's stacked-variant `(0,2,0)` tuple and the `:where()`-wrapped `@custom-variant` recipe. Both were explicitly absent from the only local build inspected (zero variant utilities compiled; `data-theme` appears once, in hand-written CSS). The annex ships `@custom-variant` guidance on a path the ground-truth repo declares and never exercises.
- 'Two of our own repos ran the identical DRY test and got zero primitives and a small primitive set respectively' — the design's justification for refusing to pin a tier count, repeated twice including in the closing line. Partially checkable: `ocx-catalog/.claude/rules/quality-design-tokens.md:41` says 'Three. The primitive tier is private' — so that repo HAS primitives. `grimoire-indexer/.claude/rules/quality-design-tokens.md:38` states the condition for a primitive tier but I found no statement that it got zero. The 'zero vs small set' framing is not supported by the two files it cites.
- Whether `@layer` survives Next.js `experimental.inlineCss`, and whether CSS Modules hashing is stable across Next majors. The design's own open_questions names these; the css-modules annex nonetheless states 'hand-written `@layer` inside a `.module.css` survives the production build under both bundlers' with no scope qualifier on the pipeline it was tested against.
- Whether VS Code's injected `<style id="_defaultStyles">` survives an extension CSP of `style-src ${webview.cspSource}` with no `unsafe-inline`. The annex's `@layer` version boundary is partly load-bearing on it. The reviewer notes codicon.css independently proves a second author stylesheet exists, so the ≤1.103 'do not layer' instruction survives regardless — but the annex should not state the boundary as unconditional until someone opens devtools.

## Overreach in the proposed design

- Frontmatter globs `**/*.ts **/*.js **/*.mjs **/*.cjs **/*.mts **/*.cts`. This loads a CSS theming index on every TypeScript and JavaScript file in every repo the rule is installed in, including backends and CLIs with no stylesheet anywhere. The glob rationale prices the MISS cost ('an untokenized literal with no warning') and never prices the LOAD cost, which is paid on every edit in every repo forever. `**/*.css.ts`, `**/*.styles.{ts,js}`, `**/*.stylex.ts`, `**/*.{tsx,jsx}`, `**/panda.config.*`, `**/tailwind.config.*` covers the actual CSS-in-JS surface at a fraction of the breadth.
- The Gate mandates five commands including a browser driver, unconditionally, for every repo. A plain-CSS project with one stylesheet — the case the design itself says the core file already fully covers — is told to run a production build, discover CSS output, run three node scripts and drive a headless browser to assert a layered-vs-unlayered relationship it may not use. The gate never says 'scale it to the surface', and its own justification (the DOM-emulation claim) is the least verified thing in the document.
- CSS-API-01 as a blocking MUST. 'No generated class name or scope hash is documented, pinned, or relied on as a selector target. Ship a `data-*` identity attribute.' The first half is right wherever a compiler hashes. The second half mandates a parallel identity layer in surfaces where the author's own class names are already stable, build-invariant public API: plain CSS, Tailwind (utility names are the contract), a VS Code webview (one flat unscoped stylesheet, author-controlled classes, verified: zero `@layer` and no scope attribute anywhere in `dist/webview/*.css`). That is a tier promised with no consumer — an extra public surface to version, in repos with nothing generating a name.
- CSS-CAS-05 (`@scope` is not a substitute) is a predicted mistake, not an observed one. No local repo contains `@scope`; no research entry records an agent reaching for it. The mechanics are correct and worth two lines. The framing — 'the most likely wrong turn for an agent reaching for a newer, more targeted-sounding feature' — is an unearned frequency claim in a file whose whole premise is 'every line names a mistake that gets made'.
- 'Rules This File Owns' as a second full table (ID | Rule | Rationale | Verification | Severity, fourteen rows) sitting under a thirteen-row Non-Negotiables table that already carries ID + rule. That is the same content twice in one index file, plus a third copy of the mechanics in per-principle `check` strings, plus a fourth in the Gate block. Pick one table. The reader who needs the rationale is not the reader scanning for what blocks a merge.
- The css-in-js annex at 115 lines covering five libraries. The reviewer's own recommendation was to trim it — styled-components + Emotion (one shared runtime failure mode) and StyleX (the specificity inversion) carry nearly all the non-derivable content; Panda contributes one trap (`.dark` not `[data-theme]`) plus 'do not add a layer, it is already there', vanilla-extract contributes two name-stability splits. Four lines, not a third of the file.
- The astro annex's `is:global` vs `is:inline` material, framed as 'the consumer entrypoint'. The reviewer specifically flagged the positioning argument as unverified AND irrelevant under a layer contract that is position-independent by design. What survives is one real consequence (a relative `url()` or `@import` in consumer CSS silently fails to resolve under `is:inline`); the rest is the layout file's architecture, discoverable by opening it.
- Fourteen core principles, each with statement + rationale + check + exceptions, in a file whose stated job is to be an INDEX that routes to depth. The design's own routing table is the thing that earns the file. Every principle that already carries 'see the annex' in its exceptions is being written twice — once generically in the core, once concretely where it is true.
- The `@property` rule (CSS-TOK-07) is named in 'Rules This File Owns' and absent from the thirteen-row Non-Negotiables table. So one of fourteen core principles silently does not block a merge, and no reader can tell whether that was a decision or an oversight. Either is a defect in a file whose Severity section defines MUST as 'blocks a merge'.

## "Core" principles that are not universal

- CSS-TOK-01 'Untokenized appearance value is a defect' — marked `holds_everywhere: true`, broken by VS Code webviews. The stated rationale is 'a downstream consumer's entire retheming surface is usually one injected stylesheet loaded alongside the framework's own CSS'. In a webview that stylesheet is structurally impossible: the CSP is `default-src 'none'; style-src ${webview.cspSource}` with no `unsafe-inline` and no external host, and the extension is the CONSUMER of a host-owned vocabulary rather than a publisher with a downstream audience. The rule survives in a different form (read appearance through `var(--vscode-<id>, <fallback>)`), but its rationale does not, and the exception field says nothing about it.
- CSS-TOK-03 'A colour token must be declared in every scheme' — marked `holds_everywhere: true`, broken twice. (a) VS Code webviews: you declare no colour tokens per scheme at all; the host recomputes `--vscode-*` on `document.documentElement.style` on every theme change, so the design's `css-dark-parity.mjs` has nothing to assert. (b) Any theme built on `light-dark()` declares each colour ONCE, resolved against the element's computed `color-scheme` — the parity check as specified would flag every token in such a theme as a violation. The design demotes `light-dark()` to a table-row fact and never connects it to the rule whose check it breaks. The exception list names only measurements and geometry.
- CSS-API-01 'The only stable selector target is an identity attribute you author' — the statement generalises 'every scoping mechanism in this study generates its target name and none of them generate a stable one' into a universal ban on documenting a class. Two of the eleven surfaces studied have no name-generating compiler at all — plain CSS, and the VS Code webview (verified: one flat unscoped stylesheet, `grep -c '@layer' dist/webview/*.css` → 0, no scope attribute) — and a third, Tailwind, ships stable utility names as its entire public contract. In those the author's class names ARE the durable target, and the MUST mandates a second one with nothing to protect against.
- CSS-CAS-03 '`!important` inside your own layer is a permanent lock' — the framing is wrong for Shadow DOM in a way that inverts the remedy. The rule's exception list offers 'two legitimate uses, both OUTSIDE the layer'. But across an encapsulation boundary the cascade's Context step reverses for importance: for important declarations the INNER context wins. So a component-side `!important` locks the outer consumer out whether or not it sits inside a layer, and 'move it outside the layer' buys nothing there. The shadow-dom annex knows this ('the only thing that inverts it is `!important` INSIDE the component — which is the defect here, not the fix'), but the core rule is marked `holds_everywhere: true` with an exception list that does not cover it.
- CSS-GATE-01 'runs its cascade assertion in a real browser engine' — the exception clause covers a missing artifact and not a missing mechanism. In Shadow DOM the consumer wins by Context, not by layers, so there is no layered-vs-unlayered assertion to run; on VS Code ≤1.103 you deliberately do NOT layer, so running the assertion asserts the opposite of the contract. Marked `holds_everywhere: true` with 'exceptions: None'.
