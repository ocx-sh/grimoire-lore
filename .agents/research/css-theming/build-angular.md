## Findings

| Claim | Status | Evidence |
|---|---|---|
| Angular's SharedStylesHost injects component `<style>` tags via `document.head.appendChild()` the first time each component type is instantiated (first-render order); because CSS cascade layers fix priority by the order a layer NAME is first encountered in the document, two components each wrapping conflicting rules in differently-named `@layer` blocks will have their effective override precedence flip depending purely on which one happens to mount first at runtime — not on any source-level ordering the author controls. | **confirmed** | Built two ViewEncapsulation.None fixture components (layer-a: `@layer alpha{.race{color:red}}`, layer-b: `@layer beta{.race{color:blue}}`) and two routes rendering them in opposite orders. Production build + live Chromium (Google Chrome for Testing 151.0.7922.34 via playwright-core 1.62.1): route /ab (layer-a mounts first) -> getComputedStyle(#race-target).color = 'rgb(0, 0, 255)' (beta wins, mounted/declared second). Route /ba (layer-b mounts first) -> color = 'rgb(255, 0, 0)' (alpha wins, mounted/declared second). document.querySelectorAll('style') head order confirmed to match mount order in each case. This is the exact defect the brief flagged as unverified — it is real. |
| provideCssVarNamespacing() and the --global--<name> custom-property convention exist and behave as round-1's critique described, at the actually-installed version. | **confirmed** | @angular/compiler 22.1.4 fesm2022/compiler.mjs:3294-3300 contains `function namespaceCssVariable(varName){ if (varName.startsWith('--global--')) return '--'+varName.substring('--global--'.length); else return '--%NS%'+varName.substring('--'.length); }`. @angular/platform-browser 22.1.4 fesm2022/_dom_renderer-chunk.mjs exports `provideCssVarNamespacing`, whose factory is `` `${namespace ?? appId}_` `` (literal underscore separator, not documented in round-1's citation). Runtime-reproduced: default app (no provider) -> live style text `border-color:var(--consumer-token)` (namespace substituted to empty string); after adding `provideCssVarNamespacing('acme')` to app.config.ts providers and rebuilding -> live style text `border-color:var(--acme_consumer-token)`. The static build artifact (main-*.js) always contains the literal, unresolved `--%NS%consumer-token` placeholder regardless of provider config — substitution is DI-driven and happens only at render time via `.replace(/%NS%/g, cssVarNamespace)`. |

## Overturns round 1

- **Was:** "ViewEncapsulation.ShadowDom attaches a real `shadowRoot` instead — no attribute rewriting; scoping is browser-enforced and the specificity question is moot since page-level selectors cannot cross the boundary without `::part`/`::slotted` (Angular exposes no first-class author hook for either)."<br>**Now:** ViewEncapsulation.ShadowDom attaches a real shadowRoot instead — no attribute rewriting; scoping is browser-enforced and the specificity question is moot since page-level selectors cannot cross the boundary without ::part/::slotted (Angular exposes no first-class author hook for either).

## What belongs in the annex

- Trap — scoping attribute shape: emitted as `_ngcontent-ng-c<hash>` / `_nghost-ng-c<hash>` where `ng` is the default APP_ID (not a fixed constant — changes with a custom APP_ID) and `<hash>` is a large per-component-type integer, never a small sequential `c0`/`c1`. A rule/test hardcoding `ng-c0` or similar breaks on the first real build.
- Trap — a component with NO styles at all (empty styleUrl/styles array) is silently downgraded by the compiler from Emulated to None: its elements get zero scoping attribute. Whether `_ngcontent-*` appears is conditional on the component actually declaring styles, not on `encapsulation` being left at default.
- Trap — `@layer <name> { .sel {...} }` inside a component style block survives both the Angular compiler and esbuild production minification verbatim (layer name intact), and the ShadowCss shim correctly appends the scoping attribute to selectors nested inside the `@layer` block. `@layer` is safe to use inside a component style — it does not get stripped or leave the selector unscoped.
- CRITICAL trap — cascade-layer precedence between two different Angular components is decided by RUNTIME RENDER ORDER, not by source/import order or by where the `@layer` block sits in either file. `SharedStylesHost` appends each component type's `<style>` to `document.head` the first time that type is instantiated; CSS fixes a layer's priority by the order its name is FIRST seen in the document, so whichever of two conflicting-`@layer` components happens to mount SECOND wins — and this can flip between route orders / conditional renders with zero code change. Reproduced directly: swapping render order of two components each declaring a different `@layer` around the same global selector flips which color wins (rgb(0,0,255) vs rgb(255,0,0)) with identical source. A published rule must warn against relying on `@layer` order to arbitrate between separately-compiled Angular components.
- Trap — `ViewEncapsulation.ShadowDom` is NOT full isolation from other components' CSS: Angular's `ShadowDomRenderer` calls `sharedStylesHost.addHost(shadowRoot)`, which copies EVERY globally-registered style (every `ViewEncapsulation.None` component's CSS, including 100% of Angular Material's own styles, since Material ships `None`) into every ShadowDom component's shadow root. An unscoped selector from an unrelated `None` component that happens to match an element inside your Shadow DOM component WILL apply. Shadow DOM blocks outside PAGE styles from crossing in; it does not block Angular's own internally-shared component styles, which Angular deliberately re-injects into the shadow root.
- Trap — since Angular 22.1.0 (confirmed live at 22.1.4), every custom property in a component's styles — both `--foo:` declarations and `var(--foo)` reads — is rewritten to `--<namespace>_<foo>` (literal underscore separator) the moment the app calls `provideCssVarNamespacing(ns)`; calling it with no argument namespaces to `${APP_ID}_` (default `ng_`). The BUILD ARTIFACT always contains the literal placeholder `--%NS%foo` — the real namespaced name only exists at runtime via DI substitution, so grepping dist/**/*.js for a resolved name will never match; grep for `%NS%` in the artifact, or assert against live DOM/computed styles for the resolved name. The only escape hatch is authoring the property as `--global--foo`, which strips unconditionally to plain `--foo` regardless of namespace config, in every encapsulation mode — the one convention a design-token component library MUST use for any public custom property.
- Trap — Angular Material's CSS-custom-property surface at 22.1.4 is exclusively `--mat-sys-*` (system/M3 tokens) and `--mat-<component>-*` (per-component tokens, e.g. `--mat-button-filled-container-color`); `--mdc-*` custom properties are entirely gone (0 occurrences in the shipped package at this version). A test scoped to `--mat-(sys|mdc)-` misses every real component-token override.
- Trap — toolchain currency: `@angular/cli` 22.1.6 (current as of 2026-08-30) hard-refuses to run on Node 24.14.0, requiring `^22.22.3 || ^24.15.0 || >=26.0.0`. A rule that says "just run ng build" with no version-pinning guidance can fail at the very first command on a machine one Node patch behind.
