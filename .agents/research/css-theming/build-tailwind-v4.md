## What belongs in the annex

- TRAP: `@theme inline { --x: var(--y); }` never emits --x as a custom property at all — it inlines the resolved var() reference directly into every utility that would have used it. A downstream consumer redefining --x from an unlayered stylesheet does nothing; the property does not exist in the shipped CSS. Reach for @theme inline only for tokens you accept as build-time-frozen; use plain @theme for anything meant to stay consumer-overridable.
- TRAP: `@import "tailwindcss" important;` (project-wide) or a `bg-red-500!` per-utility modifier makes that utility's declaration !important inside its @layer — and ANY !important declaration beats ANY non-important declaration regardless of cascade-layer rank or selector specificity. An unlayered consumer override with no !important of its own silently loses to it. Before relying on 'stay unlayered to win', grep the entry CSS for `@import "tailwindcss" important` and for a trailing `!` on the utility class in question.
- TRAP: Preflight's own `[hidden]{display:none!important}` (@layer base) is !important in EVERY Tailwind v4 build, important flag or not — a consumer's unlayered `[hidden]{display:block}` loses to it today, unconditionally, in every project.
- TRAP: `--breakpoint-*` (and `--container-*`) tokens are never emitted as custom properties — they resolve into literal `@media (width>=Npx)` text at build time. Listing them in a 'tokens are consumer-overridable' table is wrong; they require a rebuild, not an injected stylesheet.
- FACT (reproduced this round; was spec-derivation only in round 1): Tailwind's own @custom-variant dark recipe, `&:where([data-theme="dark"], [data-theme="dark"] *)`, keeps a stacked `dark:hover:*` utility at (0,2,0) specificity — identical to a plain `hover:*` utility, because :where() contributes zero specificity regardless of what condition it wraps. Without :where(), the same stack would be (0,3,0).
- FACT: `@theme` (and `@theme static`) tokens compile into `@layer theme{:root,:host{...}}` — real custom properties, referenced by generated utilities via var() indirection, and therefore genuinely overridable by an unlayered consumer `:root{}` redeclaration (verified: overriding --color-brand from outside changed what .bg-brand resolves to, with zero utility-class changes needed) — PROVIDED the important-flag trap above doesn't apply.
