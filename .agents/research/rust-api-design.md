# API Design — Derive Discipline, Conversions, and Naming

## Verdict

1. **This group has one sub-artifact, and that is the correct size.** The topic map commissioned exactly one api-slot topic (`derive-discipline-and-standard-conversions`, [topic-map.md:215](topic-map.md)) and explicitly deferred the rest of the API-shape column — sealed traits, `C-VALIDATE`, bitflags, `Deref`-as-inheritance, lifetimes-in-public-API — because neither `ocx_lib` nor `grimoire` publishes a library, so the semver blast radius is internal ([topic-map.md:233](topic-map.md)). Nothing here re-opens that.
2. **Derives are the cheapest security control in the codebase and the least enforced one.** `#[derive(Debug)]` on a credential struct is a one-token change that leaks a token into every `{:?}`, panic message, and `anyhow` chain ([derive-discipline §3](rust-api-design/derive-discipline-and-standard-conversions.md)). The audit found secrets currently clean — `secrecy::Secret`/`SecretString` in 2 ocx_lib files and 6 grimoire files, zero secret values reaching `log::*` ([errors-async-security.md:85](ocx-codebase-audit/errors-async-security.md)) — but that is convention, not a gate. API-02/API-03/API-14 turn it into one.
3. **We scope eager-derive rather than adopt it wholesale.** C-COMMON-TRAITS is written for library authors who cannot retrofit an impl past the orphan rule; ocx/grim ship binaries. We take it as MUST for types that cross the lockfile / OCI-manifest / cache-key / `--json` boundary (those *are* a public API), and SHOULD-with-judgment for internal plumbing. This resolves the split the sub-artifact flagged as contested.
4. **`Debug` is the exception: it is MUST everywhere, enforced by a compiler lint, not a grep.** `missing_debug_implementations` is allow-by-default and must be switched on at each crate root ([derive-discipline §2](rust-api-design/derive-discipline-and-standard-conversions.md)).
5. **Two existing OCX rules are wrong as written and are superseded here.** `quality-core.md`'s newtype rule says "Always implement `Display`, `Debug`, `From`" ([rules-inventory.md:88](ocx-codebase-audit/rules-inventory.md)) — an infallible `From` on an invariant-bearing newtype is precisely the hole that makes the newtype worthless (API-10). And the DRY section blesses `Debug, Clone, PartialEq, Serialize, Deserialize` as the boilerplate-killing derive line ([rules-inventory.md:221](ocx-codebase-audit/rules-inventory.md)) — that exact line is the LLM template that leaks secrets and manufactures unversioned wire formats (API-02, API-11).
6. **One existing rule is right and we only add teeth**: "`From` impl hiding `.unwrap()` — `From` must be infallible; use `TryFrom`" ([rules-inventory.md:141](ocx-codebase-audit/rules-inventory.md)). API-09 keeps it verbatim and adds the `impl Into<`/`impl TryInto<` grep.
7. **`Ord`-on-enum is the one hazard with no lint at all.** Declaration order *is* the semantics; an alphabetizing refactor silently reverses every `sort()`/`BTreeMap` ([derive-discipline §8](rust-api-design/derive-discipline-and-standard-conversions.md)). The only mechanical guard is a pinned comment plus an ordering assertion (API-07).
8. **Lint enforcement lands in `[workspace.lints]`, not per-crate.** grimoire already has a lint table (`unsafe_code = "forbid"`, `unwrap_used`/`expect_used = "warn"`, [grimoire/Cargo.toml:79 via errors-async-security.md:35](ocx-codebase-audit/errors-async-security.md)); the ocx crates have none. API-14 adds three derive lints there and API-01's `#![warn(...)]` at each root.
9. **Dropped as things an LLM already gets right:** the `iter`/`iter_mut`/`into_iter` triad (models reproduce it reliably, and neither codebase exposes a custom collection), `#[derive(PartialEq, Eq, Hash)]` internal consistency (safe by construction — only hand-written halves are dangerous, which API-14 lints), and `derivable_impls` (a redundancy nudge, subsumed by API-08).

## The ruleset

### Debug and secrets

| ID | Rule | Rationale | Verification | Severity |
|---|---|---|---|---|
| **API-01** | Every `pub struct`/`pub enum` implements `Debug`, and every crate root (`lib.rs`/`main.rs`) carries `#![warn(missing_debug_implementations)]`. | The lint is allow-by-default in rustc; without it a missing `Debug` fails at a caller three files away, never at the definition ([rustc allowed-by-default listing](https://doc.rust-lang.org/rustc/lints/listing/allowed-by-default.html)). | `grep -rn 'warn(missing_debug_implementations)' --include=lib.rs --include=main.rs crates/ src/` must hit once per crate root; then `cargo check --workspace` surfaces violations. | MUST |
| **API-02** | Never `#[derive(Debug)]` on a type with a field named/typed `token\|secret\|password\|key\|credential\|auth`. Write a `Debug` impl that opens with `let Self { .. } = self;` destructuring and prints `[REDACTED]` for the secret. | `Debug` output reaches logs, panic messages and `anyhow` error chains; the destructure turns "someone added a field and forgot to redact" into a compile error instead of a silent leak ([corrode.dev](https://corrode.dev/blog/pitfalls-of-safe-rust/)). | `grep -rn -B15 '#\[derive([^)]*Debug' --include='*.rs' src/ crates/ \| grep -iE '(token\|secret\|password\|key\|credential\|auth)\s*:'` — every hit is a finding unless the field type is `SecretString`/`SecretBox<_>`/`Zeroizing<_>`. Clippy has no equivalent lint; this grep *is* the gate. | MUST |
| **API-03** | A credential becomes `secrecy::SecretString`/`SecretBox<T>` at the point it enters the process (env read, credential-file parse, registry auth header) — not later, and never stored as bare `String`/`Vec<u8>` on a struct. | Wrapping at ingress makes every downstream `Debug`, clone and drop redacted/zeroizing by construction, instead of relying on each new struct to remember ([secrecy docs](https://docs.rs/secrecy/latest/secrecy/)). | `grep -rn 'env::var\|docker_credential\|Authorization' src/ crates/` and confirm each credential-valued result is wrapped before being stored. | MUST |
| **API-04** | Never `#[derive(Zeroize)]` or `impl Zeroize` directly on a type that *always* holds a secret; use `ZeroizeOnDrop` plus a custom `Drop`. | A bare `Zeroize` lets `.zeroize()` run mid-lifetime, leaving a wiped-but-still-typed-valid value — a distinct bug class from forgetting to wipe ([zeroize docs](https://docs.rs/zeroize/latest/zeroize/)). | `grep -rn 'derive(Zeroize\|impl Zeroize for' src/ crates/` — every hit must be paired with `ZeroizeOnDrop` on the same type. | SHOULD |

### Derive completeness and derive hazards

| ID | Rule | Rationale | Verification | Severity |
|---|---|---|---|---|
| **API-05** | Any type that appears in a lockfile, an OCI manifest, a cache key, or `--json` output derives `Debug, Clone, PartialEq, Eq, Hash`; each omission carries a one-line comment naming the blocking field (float, non-`Eq` external type, resource handle). Internal plumbing types are judgment. | These types are a de-facto public API even though the crate is not published; an eligible-but-missing `Eq` only fails when a caller three files away needs a `HashMap` key ([C-COMMON-TRAITS](https://rust-lang.github.io/api-guidelines/interoperability.html)). Scoped rather than blanket — see Verdict 3. | `grep -rn -B3 '^pub struct\|^pub enum' <lockfile/manifest/cache modules>`; any hit with no `#[derive(` at all, or a derive list missing one of the five without an adjacent comment, is a finding. | SHOULD |
| **API-06** | Derive `Copy` only for types that are plain data *forever* — numeric wrappers, fixed-size handles, payload-free enums. Anything named `*Config`/`*Options`/`*Policy`/`*Settings` omits `Copy` even when eligible today. | Removing `Copy` later breaks at every *use* site simultaneously, not at the definition; std's own docs recommend omitting it up front if the type might grow ([std::marker::Copy](https://doc.rust-lang.org/std/marker/trait.Copy.html)). | Reading heuristic per `#[derive(..., Copy, ...)]`: "could this struct's next field plausibly be `String`/`Vec`/`PathBuf`/`Box`?" If yes and `Copy` stays, require `// Copy: fixed-size, will not grow heap fields`. | SHOULD |
| **API-07** | Derive `PartialOrd`/`Ord` on an enum only when declaration order *is* the intended order; pin it with `// order is significant: A < B < C, do not reorder` and a unit test asserting the ordering. | Derive generates comparison from variant index; alphabetizing during an unrelated refactor silently reverses every `sort()`/`BTreeMap`/`BinaryHeap` with no compiler signal, and no clippy lint covers declaration-order drift ([derive reference](https://doc.rust-lang.org/reference/attributes/derive.html)). | `grep -rn -B2 'derive(.*Ord' --include='*.rs' src/ crates/`, restricted to `enum`; each hit needs the comment *and* a matching `assert!(A < B)` in tests. | MUST |
| **API-08** | `#[derive(Default)]` is allowed only when a doc comment names the concrete runnable state `T::default()` produces. Otherwise delete it and add a named constructor or a builder. | A zero state (`port: 0`, empty required `PathBuf`) type-checks and propagates as if valid; the failure lands at first use, far from the derive ([corrode.dev](https://corrode.dev/blog/pitfalls-of-safe-rust/)). | `grep -rn -B3 'derive(.*Default' --include='*.rs' src/ crates/` filtered to `*Config`/`*Settings`/`*Options` types; require a `///` justification or a `fn minimal()`/builder in the same `impl`. | MUST |
| **API-11** | Do not derive `Serialize`/`Deserialize` reflexively. A type gets them only if it genuinely crosses a process/file/network boundary; a type with any `unsafe` method relying on a field invariant never derives `Deserialize`. | A reflexive derive turns every field into an unversioned wire format nobody designed, and on an invariant-bearing type it is a second, unchecked constructor (clippy `unsafe_derive_deserialize`, [clippy derive/mod.rs](https://raw.githubusercontent.com/rust-lang/rust-clippy/master/clippy_lints/src/derive/mod.rs)). | `cargo clippy --workspace -- -W clippy::unsafe_derive_deserialize` for the `unsafe` half; for the rest, review question per derive: "which file or wire message is this type written into?" | SHOULD |
| **API-15** | Decide `#[non_exhaustive]` when the type is introduced, for every wire/manifest/config type — not only error enums. Internal, crate-private enums stay exhaustive so matches remain total. | Adding it later is a breaking change ([Cargo semver reference](https://doc.rust-lang.org/cargo/reference/semver.html)); ocx already uses it at 82 sites and grimoire at 66 with no stated rule ([errors-async-security.md:41](ocx-codebase-audit/errors-async-security.md)), while a sibling rule correctly wants internal enums exhaustive ([rules-inventory.md:928](ocx-codebase-audit/rules-inventory.md)). | Review gate on any new `pub enum`/`pub struct` in a serde-facing module: `#[non_exhaustive]` present, or a comment saying why the variant set is closed. | SHOULD |
| **API-14** | Add `derive_partial_eq_without_eq`, `derived_hash_with_manual_eq` and `derive_ord_xor_partial_ord` at `warn` to the workspace `[lints.clippy]` table, and audit that table against the current clippy lint index each toolchain bump. | These are the mechanically-checkable halves of API-05/API-07; several live in `nursery`/`pedantic` so a bare `cargo clippy` never surfaces them, and clippy moves lints between groups release to release. | `grep -A10 '\[lints.clippy\]' Cargo.toml` shows all three; `cargo clippy --workspace` is then the gate. | MUST |

### Conversions and naming

| ID | Rule | Rationale | Verification | Severity |
|---|---|---|---|---|
| **API-09** | Owned conversions are `From`/`TryFrom`; borrowing conversions are `AsRef`/`AsMut`. Never `impl Into`/`impl TryInto` directly. A conversion that can fail is `TryFrom` — a `From` that panics or `.unwrap()`s is a bug, not a shortcut. | Only the standard traits satisfy `impl Into<T>` bounds and the `?` operator's automatic conversion; `Into` comes free from the blanket impl ([std::convert::From](https://doc.rust-lang.org/std/convert/trait.From.html)). Restates the existing OCX rule ([rules-inventory.md:141](ocx-codebase-audit/rules-inventory.md)) with a grep. | `grep -rn 'impl Into<\|impl TryInto<' src/ crates/` — any hit is a finding. `grep -rn -A6 'impl From<' src/ crates/ \| grep -n 'unwrap()\|expect(\|panic!'` — any hit must become `TryFrom`. | MUST |
| **API-10** | A newtype whose point is an invariant (validated digest, non-empty host, canonical path, non-zero port) enforces it in exactly one place: a `TryFrom` impl, reached from deserialization via `#[serde(try_from = "Raw")]`. Its field is private and it has no infallible `From` from the unvalidated shape. | An invariant with a second, unchecked constructor is not an invariant; `derive(Deserialize)` on the real type is exactly that second constructor ([C-NEWTYPE](https://rust-lang.github.io/api-guidelines/type-safety.html); [corrode.dev](https://corrode.dev/blog/pitfalls-of-safe-rust/)). **Supersedes** "newtypes always implement `From`" ([rules-inventory.md:88](ocx-codebase-audit/rules-inventory.md)) for invariant-bearing newtypes; plain unit-tag newtypes may still take `From`. | For each newtype with a validating constructor, `grep -n 'derive(.*Deserialize' <file>` must show `#[serde(try_from = ...)]` alongside, and `grep -n 'pub struct X(pub ' <file>` must not match. | MUST |
| **API-12** | `as_*` never allocates or clones; `to_*` never consumes `self`; `into_*` always consumes `self`. | The prefix is documentation every caller trusts without reading the body; violating it moves a wrong ownership/cost assumption to every call site ([API Guidelines naming](https://rust-lang.github.io/api-guidelines/naming.html)). | `grep -rn -A8 'fn as_[a-z_]*(&self' src/ crates/ \| grep '\.clone()\|to_vec()\|to_owned()\|String::from'` — any hit is a naming violation; check `to_*`/`into_*` receivers against the prefix by signature. | SHOULD |
| **API-13** | Getters are `x(&self)`/`x_mut(&mut self)`, never `get_x`; reserve `get`/`get_mut` for a single obvious accessor (`Cell::get`-shaped). | Prediction: a reviewer or agent should be able to guess the method name without opening the docs ([API Guidelines naming](https://rust-lang.github.io/api-guidelines/naming.html)). | `grep -rn 'pub fn get_[a-z_]*(&self' --include='*.rs' src/ crates/` — any plain field accessor hit is a finding. | SHOULD |

## Applied to OCX

### Already satisfied

- **Secrets are wrapped and are not logged today.** `secrecy::Secret`/`SecretString` appears in 2 `ocx_lib` files and 6 `grimoire` files, and a targeted grep found zero token/password values flowing into `log::info!`/`debug!`/`warn!` ([errors-async-security.md:85](ocx-codebase-audit/errors-async-security.md)). API-03 is largely met; what is missing is the gate, not the practice.
- **`From`-must-be-infallible is already house rule.** ([rules-inventory.md:141](ocx-codebase-audit/rules-inventory.md)) API-09 adopts it unchanged.
- **`AsRef` at parameter boundaries is already ruled.** `PathBuf` where `&Path` suffices, and `String` where `&str`/`impl AsRef<str>` suffices, are both existing anti-patterns ([rules-inventory.md:171](ocx-codebase-audit/rules-inventory.md), [:173](ocx-codebase-audit/rules-inventory.md)) — API-09's borrowing half is a restatement, not a new burden.
- **`#[non_exhaustive]` is already the fleet-forward-compat posture** at 82 (ocx_lib) / 66 (grimoire) sites ([errors-async-security.md:41](ocx-codebase-audit/errors-async-security.md)). API-15 only writes down the decision point.
- **`ExitCode` is a correctly-derived value type** — `#[derive(Debug, Clone, Copy, PartialEq, Eq)]` on a payload-free enum with a `From<ExitCode> for std::process::ExitCode` impl ([rules-inventory.md:580](ocx-codebase-audit/rules-inventory.md), [:599](ocx-codebase-audit/rules-inventory.md)) is exactly API-05/API-06/API-09 done right.

### Violated

- **The newtype rule mandates the wrong conversion.** "Newtype Pattern … Always implement `Display`, `Debug`, `From`" ([rules-inventory.md:88](ocx-codebase-audit/rules-inventory.md)) names `Digest` wrapping a hash string as a use case — an invariant-bearing newtype that must be `TryFrom`, not `From`. API-10 supersedes it.
- **The DRY guidance blesses the leaking derive template.** "derive macros (`Debug, Clone, PartialEq, Serialize, Deserialize`) kill boilerplate" ([rules-inventory.md:221](ocx-codebase-audit/rules-inventory.md)) is the reflexive line API-02 and API-11 exist to stop. Scope it to non-secret, genuinely-serialized types.
- **No crate sets `missing_debug_implementations`.** No hit anywhere in the audit's lint-configuration survey ([errors-async-security.md:35](ocx-codebase-audit/errors-async-security.md), which enumerates grimoire's lint table as `unsafe_code`/`unwrap_used`/`expect_used` only). API-01 unmet across all crates.
- **The ocx crates have no `[lints]` gate at all** — discipline "followed by convention, not enforced by clippy" ([errors-async-security.md:35](ocx-codebase-audit/errors-async-security.md)). API-14 unmet there; grimoire has a table to extend.
- **No rule covers serde attribute conventions**, explicitly listed as gap #10 in the rules inventory ([rules-inventory.md:1078](ocx-codebase-audit/rules-inventory.md)). API-10 and API-11 are the api-design slice of that gap; the on-disk-format wave owns the rest.

### New commitments

1. Add `#![warn(missing_debug_implementations)]` to every crate root in ocx, grimoire and ocx-mirror (API-01).
2. Add the three derive lints to `[workspace.lints]` in each workspace, and create the table for the ocx crates that lack one (API-14).
3. Add the API-02 secret-field grep to the pre-merge check set — it needs no Rust semantics, only a derive-line-plus-field-name match, so it runs on every diff touching a `struct` (API-02).
4. Amend `quality-core.md`'s newtype bullet to require `TryFrom` + `#[serde(try_from)]` for invariant-bearing newtypes, and scope the DRY derive line away from secret-bearing and non-serialized types (API-10, API-11).
5. Audit `ocx_lib`'s `Digest`-shaped newtypes for a public tuple field or a bare `derive(Deserialize)` — the audit never counted derive lines, so this is a measurement, not a known violation (API-10).

## AI-agent failure modes

Ranked by how often it bites in practice.

1. **The reflexive `#[derive(Debug, Clone, Serialize, Deserialize)]` template.** It is the single most common derive line in any Rust corpus, so an agent asked for a `TokenStore`/`AuthConfig` reaches for it without scanning field names for `token`/`secret` ([derive-discipline, AI-agent angle](rust-api-design/derive-discipline-and-standard-conversions.md)). Caught only by API-02's grep in CI, never by review judgment.
2. **Deriving the minimum set that makes the current test pass.** `Debug` because a `{:?}` needs it, no `Eq`/`Hash` because nothing in this diff uses them — the gap surfaces in an unrelated later PR as a trait-bound error at a distant call site. API-05 plus API-14's `derive_partial_eq_without_eq`.
3. **Patching the call site instead of the derive.** Told a `HashMap` lookup misses, an agent adds a normalization step before `.get()` rather than noticing a hand-written `PartialEq` disagreeing with a derived `Hash`; the symptom vanishes either way and the diff is smaller. `derived_hash_with_manual_eq` catches the real defect regardless of which call site the agent is staring at.
4. **`impl From` with an `.expect()` inside** to satisfy a caller that wants `.into()`. The agent optimizes for the call-site ergonomics it can see and inherits an undocumented panic path into every generic `impl Into<T>` consumer (API-09).
5. **`#[derive(Default)]` to make a struct literal shorter.** Reaching for `..Default::default()` in a test or constructor silently mints an unrunnable config that then escapes into non-test code (API-08).
6. **Alphabetizing enum variants during an unrelated tidy-up.** A pure-formatting-looking diff that reverses every ordering derived from it, with zero compiler or clippy signal (API-07).
7. **`get_`-prefixed accessors and ad-hoc `.to_x()` conversions**, imported from Go/Java/Python habits. Lowest severity, highest grep-ability (API-12, API-13).

## Open questions

- **Deserving another research round: the deferred API-shape column.** `C-VALIDATE` (validate at the boundary, not the call site), `bitflags` over bool-parameter runs, returning the caller's consumed argument inside `Err`, `Deref`-as-inheritance, and lifetime misconceptions distorting public signatures were all scored medium in the topic map and never commissioned ([topic-map.md:113-118](topic-map.md)). They were deferred as "substantially inside rust-type-architecture's remit" ([topic-map.md:238](topic-map.md)) — but that wave shipped without them. One focused round, scoped to *API surface shapes an LLM gets wrong* (bool params, consumed-arg-on-error, `Deref` abuse), would close it.
- **Deserving another research round: secret redaction at the `Display`/serialize boundary, not just `Debug`.** This group covered `Debug`; a `thiserror` `#[error("failed to auth to {registry} as {user}: {token}")]` interpolation, or a `Serialize` on a struct with a secret field, leaks through paths API-02 does not touch. ocx has 15 `error.rs` files with heavy `#[source]` chaining ([errors-async-security.md:41](ocx-codebase-audit/errors-async-security.md)) — a real surface, unresearched.
- **Which ocx/grimoire types actually violate API-05/API-10?** The codebase audit counted free functions, impl blocks, `#[non_exhaustive]` and error derives — never derive completeness or newtype field visibility. That is a scan to run, not a question to research.
- **Which `secrecy` major version is pinned?** The sub-artifact notes the `Secret<T>` → `SecretBox`/`SecretString` + `ExposeSecret`/`ExposeSecretMut` API split; the audit records `secrecy::Secret` usage ([errors-async-security.md:85](ocx-codebase-audit/errors-async-security.md)), which is the *older* spelling. API-03's type names must be pinned to the version actually in `Cargo.toml` before it becomes an enforceable rule.
- **Is `zeroize` used directly anywhere?** API-04 is written defensively; the audit found no direct `zeroize` usage independent of `secrecy`. If it is genuinely absent, API-04 stays as a guardrail on future code rather than a live finding.
- **Does clippy still group `unsafe_derive_deserialize` under `nursery`?** It moves between groups release to release; API-14's periodic-audit clause exists because of this, but the current group is unverified as of this consolidation.
