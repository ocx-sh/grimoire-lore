## Summary

- Localize an evaluation failure in this order: read the *first* `error:` line without `--show-trace`, decide the input shape (which catalog section it falls in), then re-run with `--show-trace` only if the first line does not already name a rule ([§1](#1-the-localization-procedure)).
- `--show-trace` adds the call chain; it does not change the final `error:` line, and nixpkgs 26.11pre's own module system now prints a *targeted hint* for the imports/config recursion even without it ([§1](#1-the-localization-procedure), fixture `imports-from-config`).
- `--no-eval-cache` is the fix for a result that looks stale after you changed something and re-ran the identical command; the eval cache is keyed by flake narHash plus attribute path, and it is real (NixOS/nix#3872) even though this dive could not force it on a bare flake attribute in this environment ([§1](#1-the-localization-procedure), [§5](#5-debugging-traps-that-are-not-evaluation-bugs)).
- The **same fault prints different text by Nix version and by implementation** (class C20): `points outside of its parent's store path` (2.20.6) is `access to absolute path '…' is forbidden in pure evaluation mode` (2.31.5, 2.35.2); `follow cycle detected` (CppNix) is `stack overflow (possible infinite recursion)` (Lix 2.95.2); `path '…' is not valid` (CppNix) is `did not exist in the store during evaluation` (Lix). A catalog keyed by string alone silently stops matching after an upgrade — key every row by **input shape** first, string second ([§2](#2-why-the-same-fault-changes-text-class-c20)).
- The catalog below has 46 rows, drawn from what six earlier consolidations already reproduced (harvested, not re-run) plus 11 new fixtures this dive planted and ran ([§3](#3-the-verbatim-error-catalog), [Verification runs](#verification-runs)).
- Four fault classes are routinely **misattributed** by an agent under time pressure: `self.packages.<system>.<name>` blamed for a cold-store `-source is not valid`, when the real cause is any eval-time read through the source store path; helix's `nix flake show --all-systems` cost blamed on its inputs, when it is 303 eval-time `fetchTree` calls; a `pkgs.system` deprecation warning blamed on the `import nixpkgs { system = …; }` argument spelling; and a corrupted layer digest producing a **404**, not `hash mismatch`, because the URL itself carries the digest ([§4](#4-misattributed-diagnostics-class-c7)).
- `nix eval --json` over any attrset that carries an `outPath` (a derivation, or anything shaped like one) prints **only that string**, silently discarding every other attribute you asked for — new row M-C-16, reproduced here ([§5](#5-debugging-traps-that-are-not-evaluation-bugs), fixture `eval-json-outpath-collapse`).
- `error: undefined variable 'x'` is a **static, parse-time** error when nothing in the file could dynamically bind `x` (no enclosing `with`) — it fires no matter which attribute you evaluate, contradicting the common assumption that it is always a lazy runtime error. It genuinely *is* lazy — reached only when forced — precisely when an enclosing `with` makes the name's binding depend on a runtime value (measured, both directions, fixtures `undefined-var-forced` and `undefined-var-forced-withscope`).
- A flake reached through a symlink (NixOS/nix#8013, filed against 2.14.1, still open) **did not reproduce** on CppNix 2.35.2 in this environment: `nix eval` through a symlinked directory resolved cleanly. The issue is dated and its repro no longer holds at the pinned version — record the version, do not carry the old assumption forward ([§5](#5-debugging-traps-that-are-not-evaluation-bugs)).
- `nixf-diagnose` is not on `PATH` in the pinned toolchain snapshot; it is reachable via `nix run nixpkgs#nixf-diagnose --`. It statically catches the undefined-variable case with no `with` in the way, and both occurrences in a file at once — useful as an editor/pre-commit check, never as a CI gate (NIX-GATE-07, unchanged here).
- nixpkgs 26.11pre already ships a targeted `addErrorContext` hint for "imports computed from config" (`lib/modules.nix:268`) even though the fancier per-attribute trace (nixpkgs PR [#370967](https://github.com/NixOS/nixpkgs/pull/370967)) is still open and unmerged as of 2026-09-27 — do not assume the richer trace exists yet.
- `NIX-FLK-19`'s Lix leniency is **wider than the earlier consolidation recorded**: Lix 2.95.2 also accepts an `apps` entry with an unsupported attribute (`app-extrakey` exits 0 on Lix, exits 1 on CppNix 2.31.5 and 2.35.2) — templates stayed enforced on both. This dive re-ran the previously-unrun 2.31.5/Lix legs of NIX-FLK-03 and found the gap (new evidence, [§3](#3-the-verbatim-error-catalog) row 12, [surprise](#surprises)).
- 11 of the catalog's 46 rows are freshly reproduced by this dive (fixtures under `fixtures/evaluation-failures/`); the remaining 35 are harvested verbatim, with exit code, version and implementation, from the six wave-3 consolidations that already ran the real tools — this dive re-ran only the rows the brief named as missing a version, an implementation, or an exit code.
- Localization rules that generalize become NIX-LANG MUSTs (run `--show-trace` before reporting an unlocalized "infinite recursion"; never string-match a diagnostic without checking implementation and version first); the 46-row catalog itself stays **skill-only** — nix-diagnose reads it, no rule enumerates it.

## Findings

### 1. The localization procedure

An agent facing an evaluation failure follows this order, each step cheaper than the next:

1. **Read the first `error:` line as printed, with no flags.** Most of the catalog below is diagnosable from this line alone plus the input shape (is it a flake output check, a fetcher, a module, a per-system helper). Do not reach for `--show-trace` first — for several rows (all `is not a derivation`, `is not valid` rows, the deprecation warnings) it adds nothing.
2. **Decide the implementation and version before matching a string.** `nix --version` (or the shell wrapper that ran it) names it. The catalog is keyed by shape first and string second because of class C20 ([§2](#2-why-the-same-fault-changes-text-class-c20)); skipping this step is how a Lix diagnosis gets filed as a CppNix bug or vice versa.
3. **Escalate to `nix eval --show-trace <attr>` only when the first line names no rule** — chiefly `infinite recursion encountered`, where the trace is the only way to find *which* self-reference is looping. Reproduced here: the bare run on `imports-from-config`'s bad module already prints a targeted one-line hint (`… if you get an infinite recursion here, you probably reference 'config' in 'imports'. …`, nixpkgs `lib/modules.nix:268`, rev `8d5d2709`) even without `--show-trace`; the flag adds the full call chain through `lib/modules.nix:742` (`while evaluating the module argument 'config' in ":anon-1"`) but the same final `error: infinite recursion encountered` line either way. For a plain, non-module infinite recursion (the `overlay-final-not-prev` fixture), there is no such hint: `--show-trace` there is the only way to find the offending line, and it points straight at the overlay's own `final.greeting` read.
4. **`--no-eval-cache` when a result looks stale after a change and a re-run of the identical command.** The eval cache (`~/.cache/nix/eval-cache-v6/*.sqlite`, keyed by flake narHash and attribute path) is real and dated to NixOS/nix#3872, closed as "cached failure of attribute" hiding the original message on a second `nixos-rebuild switch`. This dive planted two fixtures to force it (a plain `nix eval` of a `builtins.throw`, and a `nix flake show` of a broken `packages` attribute) and neither one triggered a stale hit in this environment: both runs, cached or not, re-printed the full original message ([Verification runs](#verification-runs), rows `eval-cache-stale`/`-stale2`). Read this as: the caching mechanism exists and is real for the *NixOS module* evaluation chain the issue reports (`nixosConfigurations.<host>.config.system.build.toplevel`, many attribute-path hops deep), and this rig has no NixOS module builder to force that specific path. Treat `--no-eval-cache` as the fix to reach for whenever a message looks wrong after a fix that should have changed it, and do not assume its absence here means the bug does not exist.
5. **`nix repl` (or an isolated `nix eval` of one field) to work around the `outPath` collapse** ([§5](#5-debugging-traps-that-are-not-evaluation-bugs)): `nix repl` lets you inspect `builtins.attrNames`, individual fields, and force sub-thunks one at a time, which `nix eval --json` on a whole derivation cannot do.
6. **The implementation check is NIX-FLK-19's**: on a Lix host (`nix --version` prints `Lix`), the output-contract battery (`nix flake check --no-build`) is not admissible evidence for the fleet's CppNix-gated MUSTs until it is re-run through `nix shell nixpkgs#nixVersions.nix_2_31 --command nix flake check …` — this dive found the same asymmetry extends to `apps` unknown-attribute checking, not only `formatter` and overlay arity ([§3](#3-the-verbatim-error-catalog) row 12).
7. **`nixf-diagnose` stays editor-only**, per NIX-GATE-07 — it is a static, non-lazy pass (it catches an undefined variable at "reached" position even when the value is never forced) and it exits 1 on a deliberate deprecation shim, so it cannot gate CI. It is genuinely useful as the *first* localization step for `sema-undefined-variable` and `sema-duplicated-attrname`, both of which it finds without evaluating anything.

### 2. Why the same fault changes text: class C20

A diagnosis keyed by a literal string breaks the moment the pinned Nix version or implementation changes. Measured triples, all for the *same underlying fault*:

| Fault (shape) | CppNix 2.20.6 (nix-portable's own bundle) | CppNix 2.31.5 / 2.35.2 | Lix 2.95.2 |
|---|---|---|---|
| Local input path escapes the flake's tree | `points outside of its parent's store path` | `access to absolute path '…' is forbidden in pure evaluation mode` | same as 2.35.2 (measured, [nix-inputs.md](../nix-inputs.md) NIX-INP-04) |
| A `follows` chain cycles back on itself | (not separately measured) | `error: follow cycle detected: [nixpkgs -> a/nixpkgs -> nixpkgs]` | `error: stack overflow (possible infinite recursion)` — no attribute path named ([nix-inputs.md](../nix-inputs.md) NIX-INP-08) |
| `--no-build` on a cold store, eval-time read of the flake's own source | `error: path '/nix/store/…-source' is not valid` | same text | `… did not exist in the store during evaluation` ([nix-flakes.md](../nix-flakes.md) NIX-FLK-07, [nix-gates.md](../nix-gates.md) NIX-GATE-09) |
| `nix flake lock --update-input` | (pre-2.19: worked outright) | deprecation warning, exit 0 (a no-op alias) | `error: 'nix flake lock --update-input systems' has been replaced by 'nix flake update systems'`, exit 1 ([nix-inputs.md](../nix-inputs.md) NIX-INP-07) |
| A string `formatter` / a `self: super:` overlay | (schema not enforced pre-flakes) | hard `error: flake attribute '…' is not a derivation` / `error: overlay does not take an argument named 'final'` | exits 0 on both (Lix's `checkApp`/arity-only `checkOverlay`) ([nix-flakes.md](../nix-flakes.md) NIX-FLK-01/02/19) |
| An `apps` entry with an unsupported key | (n/a pre-flakes) | `error: app '…' has unsupported attribute 'name'` | **exits 0** — this dive's own re-run, new evidence ([§3](#3-the-verbatim-error-catalog) row 12) |
| A rec-set merge that mixes recursive and non-recursive definitions | permitted silently | permitted silently | `error: attribute 'meta.minor' cannot be merged, because one set is marked as recursive and the other isn't` ([nix-gates.md](../nix-gates.md) NIX-GATE-16, [Lix 2.95 release](https://lix.systems/blog/2026-03-25-lix-2.95-release/)) |

The rule this argues for: **a catalog row's "verbatim string" column is a fingerprint for one (implementation, version-range) pair, never a universal key.** Every row below carries both explicitly.

### 5. Debugging traps that are not evaluation bugs

- **`nix eval --json` collapsing to `outPath`** (row 10): this is an encoder behavior, not a bug in the derivation. `nix eval --json .#pkg` and `nix eval --json .#pkg.meta` behave identically — both print a bare string — the moment `pkg` (or the sub-attrset) carries `outPath`. Selecting a scalar field (`.#pkg.pname`) or dropping `--json` entirely both work. This is the reason [nix-release.md](../nix-release.md)'s own AI-failure-mode list flags "debugging `self` with `nix eval --json`" as a trap distinct from any real versioning bug.
- **Eval-cache staleness** (row 11): real (NixOS/nix#3872, closed as a documented behavior, not literally fixed away), but this dive's environment could not force it outside the NixOS module-evaluation chain the issue names. Do not read "did not reproduce here" as "does not exist"; read it as "reach for `--no-eval-cache` first, and expect it to matter most on deep module-system evaluation, not a bare flake attribute."
- **Flake-through-symlink** (row 14): NixOS/nix#8013 is filed against 2.14.1 and remains open on GitHub, but the exact reported shape resolved cleanly under CppNix 2.35.2 in this environment. Treat an old, still-open issue as a *candidate*, not a guarantee, once several major versions separate the report from the pinned toolchain — re-test before citing it.

## Normative guidance candidates

1. **Read the bare `error:` line before adding `--show-trace`.** Rationale: several of the catalog's most common rows (`is not a derivation`, `is not valid`, the deprecation warnings) are fully diagnosable without a trace, and adding one first wastes a re-run and can bury the line that matters under call-chain noise. Verify: compare `nix eval <attr>` and `nix eval --show-trace <attr>` output on `overlay-final-not-prev/bad` — the final `error:` line is identical either way; the trace only adds the chain. RUN: yes, `fixtures/evaluation-failures/overlay-final-not-prev/`.
2. **Never string-match a diagnostic without first reading `nix --version`.** Rationale: class C20 — the same fault's text differs by implementation and by version (six measured triples, [§2](#2-why-the-same-fault-changes-text-class-c20)). Verify: `nix --version` names the implementation; a nix-diagnose lookup keys on (implementation, version-range, input shape) before the string. RUN: yes, six measured triples across the harvested consolidations plus this dive's row 12/13 Lix `apps` re-run.
3. **`--show-trace` on an unlocalized `infinite recursion encountered` is the escalation, not the first move.** Rationale: for a plain non-module recursion, the bare error names only the final expression forced, not the cycle; for a module-system recursion, nixpkgs 26.11pre already prints a scoped hint (`… you probably reference 'config' in 'imports'`) without the flag. Verify: `nix eval --show-trace .#bad` on `overlay-final-not-prev/` names the exact `final.greeting` line; the bare run on `imports-from-config/` already gives the targeted hint. RUN: yes, both fixtures.
4. **Treat `--no-eval-cache` as the fix whenever a diagnostic looks stale after a change and an identical re-run.** Rationale: NixOS/nix#3872 is a real, dated (2020, still open as of the last upstream check in this program) caching behavior on the flake attribute-path eval cache. Verify: `ls ~/.cache/nix/eval-cache-v6/` shows populated per-narHash sqlite files after any flake eval. RUN: partial — cache-directory presence confirmed; a stale-message repro was attempted on a bare `nix eval`/`nix flake show` and did not trigger (documented, not silently dropped).
5. **Never call `nix eval --json` on anything that might carry `outPath` and expect a structured object back.** Rationale: the JSON encoder collapses to the bare `outPath` string, silently dropping every other field you asked for — a debugging trap, not a version-gated behavior (class C9, a command that "succeeds" without doing what its shape implies). Verify: `nix eval --json .#packages.x86_64-linux.default` prints a bare string. RUN: yes, `fixtures/evaluation-failures/eval-json-outpath-collapse/`.
6. **Diagnose "undefined variable" by checking for an enclosing `with` before assuming it is either always-static or always-lazy.** Rationale: without `with`, the error is a static, whole-file, parse-time check (fires regardless of which attribute you evaluate); with an enclosing `with` in scope, resolution defers to a runtime lookup and the error appears only when the value is forced. Getting this backwards wastes time chasing "why didn't this error earlier" or "why does this only fail sometimes." Verify: compare `nix eval .#{bad,good}` on `undefined-var-forced/` (identical failure either way, no `with`) against `nix eval .#{onlyX,forceY}` on `undefined-var-forced-withscope/` (only the forcing one fails). RUN: yes, both fixture pairs.
7. **Use `nixf-diagnose` as the first, cheapest localization step for `sema-undefined-variable` and `sema-duplicated-attrname`, and never as a CI gate.** Rationale: it is static (no evaluation, catches names that would never be forced) but exits 1 on a deliberate `builtins.warn`/unused-`self` shim, so a green run proves nothing about behavior and a red run can be a false CI failure (NIX-GATE-07). Verify: `nix run nixpkgs#nixf-diagnose -- flake.nix` on `undefined-var-forced/` finds both occurrences without evaluating either. RUN: yes.
8. **Before citing an implementation's known-leniency gap, re-run it: it may be wider than the last measurement.** Rationale: this dive's own re-run of NIX-FLK-03 on Lix 2.95.2 found a previously unrecorded gap (`apps` unknown-attribute checking) beyond the two gaps (`formatter`, overlay arity) the prior consolidation had already watched. Verify: `nix flake check --no-build ./app-extrakey` under `nix shell nixpkgs#lix` exits 0; the same command under CppNix 2.31.5/2.35.2 exits 1. RUN: yes, `fixtures/nix-flakes/oc/app-extrakey` (existing fixture, re-run by this dive).
9. **Before trusting an old, open upstream issue as still-blocking, re-test its exact repro at the pinned version.** Rationale: NixOS/nix#8013 (flake through a symlink) did not reproduce under CppNix 2.35.2 although the issue is still open against a 2.14.1 report; carrying the old assumption forward would misdiagnose a real, different symlink failure as "known and unfixable." 10. **Isolate a suspected cause by removing it and re-running, not by reasoning from the first plausible line in a trace.** Rationale: class C7's four instances ([§4](#4-misattributed-diagnostics-class-c7)) were each first misdiagnosed by a plausible-sounding but wrong first guess, and each was corrected only by a targeted re-run that isolated one variable. ## AI-agent angle

Ranked by how often an unsupervised agent would hit each, given what training-era material teaches:

1. **Treating every `infinite recursion encountered` the same way.** An agent reflexively deletes a system from the list, removes an overlay entirely, or rewrites `final:` to `self:` — three different fixes for three different rows (2, 3, 4) that share one error string. Check: read the file and line `--show-trace` names, then match against the catalog's *shape* column, not the string alone.
2. **Assuming `undefined variable` is always a lazy, per-thunk error "that would have shown up eventually."** It is a whole-file static check unless a `with` is in the way; an agent who "fixes" a name in one branch and assumes the sibling branch (never reached in a test) is fine is often wrong — the parser already checked it (row 5), unless a `with` genuinely defers it (row 6). Check: `nixf-diagnose` first, before touching any evaluation.
3. **Calling `nix eval --json` on a whole package or flake output "to inspect it" and reading the resulting string as the whole answer.** The agent then reports "the meta fields are missing" when it only ever received `outPath`. Check: select individual fields, or drop `--json`.
4. **Citing a remembered error string from training data without checking the pinned Nix version or implementation first.** `points outside of its parent's store path` (2.20.6-era material) is dead on 2.31.5/2.35.2; `follow cycle detected` (CppNix) does not exist on Lix. Check: `nix --version` before any string match (class C20, [§2](#2-why-the-same-fault-changes-text-class-c20)).
5. **"Fixing" a cold-store `-source is not valid` failure by touching the `self.packages` alias**, the exact class-C7 misattribution this dive re-confirmed. Check: grep for `"${src}/`/`"${self}/` reads first; the alias is innocent.
6. **Reaching for `--accept-flake-config` or `--option abort-on-warn true` as a generic "make the error go away" move** when a diagnostic is confusing. Neither belongs in a debugging session: the first is a root-equivalent trust escalation (NIX-SEC), the second turns every deliberate deprecation shim into a hard CI failure and is swallowed silently by `nix flake show` anyway ([nix-release.md](../nix-release.md) NIX-REL-11). Check: neither flag appears in a diagnosis session's command history.
7. **Believing a green `nix flake check` proves a diagnostic is resolved.** Rows 27 (`nix run` mismatch) and 32 (foreign-system IFD skipped by `--no-build`) are both invisible to that one command. Check: run the specific probe the catalog row names (`nix run`, a real `nix build`), not only `check`.
8. **Citing an old, still-open GitHub issue as current fact without re-testing.** Row 14 (symlinked flake, #8013) is the concrete instance this dive measured; the smallest mechanical check is simply re-running the issue's own repro at the pinned version before repeating its claim.

Re-check whether it merged before authoring the skill's exact wording for this row.

- **NixOS/nix#8013 (flake through a symlink) is open but did not reproduce.** Either the underlying path-resolution logic changed silently somewhere between 2.14.1 and 2.35.2 without the issue being closed, or the specific symlink shape this dive tested differs from the reporter's. Flag as "likely fixed, issue stale" rather than "known-broken."
