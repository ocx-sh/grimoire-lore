# Type-Driven Architecture — Traits, Structs, Modules, Crates

## Verdict

1. **The owner's stated pain point is half wrong, and the correction changes the rules.** The local audit measures ocx at 24.6% free functions and grimoire at 38.9% ([crate-architecture.md:44](ocx-codebase-audit/crate-architecture.md)) — grimoire is the free-function-heavy one. ocx's real defect is the opposite: a `PackageManager` with **603 methods across 23 inherent `impl` blocks in 23 files** ([crate-architecture.md:72](ocx-codebase-audit/crate-architecture.md)). A blanket "turn free functions into methods" rule is exactly the pressure that produced that god struct. This project therefore adopts a **two-sided** rule (ARCH-01 + ARCH-02 + ARCH-03), not a one-sided one.
2. **A function becomes a method when a parameter tuple repeats, not when a receiver is imaginable.** The signal is mechanical: the same 2–3 arguments threaded through a family of functions ([crate-architecture.md:176](ocx-codebase-audit/crate-architecture.md), [crate-architecture.md:194](ocx-codebase-audit/crate-architecture.md)) is a struct that hasn't been written. A free function with no privileged argument stays free — `bin_scan.rs`'s pipeline ([crate-architecture.md:196](ocx-codebase-audit/crate-architecture.md)) and the exit-code `classify_error` free function ([rules-inventory.md:606](ocx-codebase-audit/rules-inventory.md), where a trait method would create a circular dependency) are correct as written.
3. **Traits are for seams the tests actually cross, and for real second implementations — nothing else.** The four sub-researchers agree ([traits-vs-free-functions.md §15](rust-type-architecture/traits-vs-free-functions.md), [di-and-testability-seams.md §4](rust-type-architecture/di-and-testability-seams.md)) and so does the audit's own conclusion: "Neither codebase needs *more* traits across the board" ([crate-architecture.md:289](ocx-codebase-audit/crate-architecture.md)). ocx's four `StringExt`/`SerdeExt`/`ResultExt`/`VecExt` utility traits are the pattern to stop, not extend.
4. **Dispatch ladder: generic parameter → enum → `dyn`.** `di-and-testability-seams` argues generics-first at seams; `traits-vs-free-functions` argues enum-dispatch for closed sets. Both are right about different axes and we take both: generic when a single seam is threaded through a call chain, enum when a closed crate-owned variant set is stored heterogeneously, `dyn` only for genuinely open sets or to stop a type parameter propagating through the composition root. `dyn` + `async fn` in the same trait is forbidden outright (ARCH-10).
5. **We diverge from the existing OCX rule on visibility.** `quality-rust.md` currently calls `pub(crate)`/`pub(super)` "a design smell" and demands `pub`-or-private only ([rules-inventory.md:156](ocx-codebase-audit/rules-inventory.md)). That is contradicted by rustc's own `unreachable_pub` docs, by RFC 2126, and by tokio's shipped `lib.rs` ([module-and-visibility-design.md §7](rust-type-architecture/module-and-visibility-design.md)). It also produced 1,118 bare-`pub` items in `ocx_lib` ([crate-architecture.md:215](ocx-codebase-audit/crate-architecture.md)) inside a crate nothing external consumes. **ARCH-15 supersedes it: private by default, `pub(crate)` for cross-module, bare `pub` only for a genuine external contract.**
6. **The crate split is mandated, with a named target shape.** `ocx_lib` is 183,167 LOC / 283 files — 82.9% of the workspace ([crate-architecture.md:51](ocx-codebase-audit/crate-architecture.md)) — and grimoire has no internal boundary at all. The split axis is **capability**, flat under `crates/*`, per matklad/ripgrep/uv precedent ([workspace-and-crate-splitting.md §9](rust-type-architecture/workspace-and-crate-splitting.md)): `-types` → `-core` (ports + orchestration) → `-oci` / `-store` (adapters) → bin, plus `xtask` and `-testsupport`. The justification we lean on today is **dependency isolation** (`-types` must not pull tokio/reqwest/starlark) and a shared test-support boundary — *not* compile time, which is unmeasured (Open questions).
7. **We do not adopt sealed traits, `cargo-semver-checks`, `missing_docs`, dependency re-export, or `workspace-hack`.** Neither ocx nor grim publishes a library to crates.io; every one of those rules pays semver or docs overhead for a contract that has no consumer. They stay out until publishing is a real decision (ARCH-22 is the single conditional stub).
8. **Layering already works — protect it, don't rebuild it.** The audit found zero `lib → cli` import violations in ocx ([crate-architecture.md:211](ocx-codebase-audit/crate-architecture.md)). The one-way edge is real today; ARCH-16 makes it enforceable at module granularity before any crate split, because a crate split will not compile until module cycles are broken ([module-and-visibility-design.md §10](rust-type-architecture/module-and-visibility-design.md)).

## The ruleset

### Where behaviour lives

| ID | Rule | Rationale | Verification | Severity |
|---|---|---|---|---|
| ARCH-01 | When three or more functions in a module share the same leading parameter pair/triple, introduce a struct holding those values and convert the functions to `&self`/`&mut self` methods on it. | Repeated threaded parameters *are* the missing type; this is the actual "should be `&self`" signal, not "a receiver is imaginable" ([crate-architecture.md:176](ocx-codebase-audit/crate-architecture.md)). | `rg -o --no-filename '^\s*(pub(\(crate\))?\s+)?(async\s+)?fn\s+\w+\(([^,)]+,\s*[^,)]+)' <module> \| sed -E 's/.*fn \w+\(//' \| sort \| uniq -c \| sort -rn` — any leading tuple repeated ≥3× is a violation. | MUST |
| ARCH-02 | Keep a free function when it has no privileged argument (a pure step in a pipeline), or when making it a method would create a dependency cycle. | Not every free-function cluster is a smell ([crate-architecture.md:196](ocx-codebase-audit/crate-architecture.md)); `classify_error` is a free function *by design* to keep `errors → ExitCode → main` acyclic ([rules-inventory.md:606](ocx-codebase-audit/rules-inventory.md)). | Code review: name the receiver the function would take. If it is `()`, a config the caller already owns, or a type in a lower layer, it stays free. | MUST |
| ARCH-03 | A single type gets at most **2** inherent `impl` blocks and **25** inherent methods. Beyond that, split the method clusters into cooperating types. | 603 methods over 23 blocks is `impl` sprawl used as a poor man's module system ([crate-architecture.md:72,108](ocx-codebase-audit/crate-architecture.md)); the existing 15-field god-struct rule ([rules-inventory.md:184](ocx-codebase-audit/rules-inventory.md)) never counted methods. | `rg -o --no-filename '^impl(<[^>]*>)?\s+[A-Za-z_]\w*' <src> \| grep -v ' for ' \| sort \| uniq -c \| sort -rn \| head` then `rg -c '^    (pub(\(crate\))?\s+)?(async\s+)?fn\s+\w+' <file>`. | MUST |
| ARCH-04 | Any `String`/`&str`/`Vec<u8>` carrying a format invariant (digest, registry reference, credential, relative extraction path, version) is parsed once at the trust boundary into a newtype with a **private** field and a fallible constructor, and is never re-validated downstream. | Parse, don't validate — the highest-leverage pattern for a digest-verifying, tarball-extracting CLI ([traits-vs-free-functions.md §3](rust-type-architecture/traits-vs-free-functions.md)); already half-stated in grimoire's "Domain types over `String`" style row ([rules-inventory.md:936](ocx-codebase-audit/rules-inventory.md)). | `rg -n 'fn \w+\([^)]*\b(digest\|reference\|token\|credential\|url\|path)\b\s*:\s*&?(str\|String)\b' <src>`; separately `rg -n 'pub struct \w+\(pub '` must return nothing. | MUST |
| ARCH-05 | No bare `bool` or open `String` parameter for a closed set of choices — use an enum. | C-CUSTOM-TYPE; the compiler exhaustiveness-checks an enum and cannot check a string ([traits-vs-free-functions.md §15](rust-type-architecture/traits-vs-free-functions.md)). Already Warn-tier in the existing rules ([rules-inventory.md:177](ocx-codebase-audit/rules-inventory.md)). | `rg -n 'fn \w+\([^)]*:\s*bool' <src>` — each hit must be a genuine yes/no, not a mode. | SHOULD |
| ARCH-06 | Never `impl Deref`/`DerefMut` except on a real smart pointer that owns exactly one inner value. | Deref-as-inheritance is the reflex an agent reaches for when told "make `Wrapper` behave like `Inner`"; it violates C-DEREF and poisons method resolution ([traits-vs-free-functions.md §15](rust-type-architecture/traits-vs-free-functions.md)). | `rg -n 'impl(<[^>]*>)?\s+(std::ops::)?DerefMut?\s+for' <src>` — every hit justified in review. | MUST |

### Traits

| ID | Rule | Rationale | Verification | Severity |
|---|---|---|---|---|
| ARCH-07 | Define a trait only when there is a **second real implementation** or a **test double the suite actually exercises**. One impl and no double → inherent `impl`. | The single most-repeated finding across all four sub-artifacts, and the audit's own verdict ([crate-architecture.md:289](ocx-codebase-audit/crate-architecture.md)); a decorative trait is indirection a reviewer and an agent must both read through. | For each `trait T`: `rg -c "impl(<[^>]*>)?\s+T\s+for" <src>` — if 1, then `rg -n 'MockT\|FakeT\|StubT'` must be non-empty. | MUST |
| ARCH-08 | Two parallel families of functions differing only by a backend prefix (`github_*` / `gitlab_*`, `local_*` / `remote_*`) are one trait with two impls. | Near-1:1 parallelism is a trait already written in longhand — the clearest missing-trait case in either codebase ([crate-architecture.md:192](ocx-codebase-audit/crate-architecture.md)). | `rg -o --no-filename '^\s*(pub(\(crate\))?\s+)?(async\s+)?fn\s+(\w+)_(\w+)' <src> \| sed -E 's/.*fn [a-z0-9]+_//' \| sort \| uniq -d` | SHOULD |
| ARCH-09 | Choose dispatch in this order: **generic parameter** by default; **enum + `match`** when the implementor set is closed and crate-owned and must be stored heterogeneously; **`dyn`** only for a genuinely open set, or to stop a type parameter propagating through the composition root. | Static dispatch is free and catches wiring mistakes at compile time; `dyn` in a hot loop measured ~3.4× slower, mostly from lost inlining ([traits-vs-free-functions.md §14](rust-type-architecture/traits-vs-free-functions.md)); enum dispatch restores inlining for closed sets ([di-and-testability-seams.md §2](rust-type-architecture/di-and-testability-seams.md)). Reinforces the existing "`Box<dyn Trait>` where `impl Trait` suffices" Warn rule ([rules-inventory.md:169](ocx-codebase-audit/rules-inventory.md)). | `rg -n 'Box<dyn \|Arc<dyn ' <src>` — for each, confirm ≥2 concrete types are actually constructed against it, or that it is a composition-root field. | MUST |
| ARCH-10 | Never write `async fn` (or RPITIT) in a trait that is also used as `dyn Trait`. Use `#[async_trait]` on the trait, once, or keep dispatch generic. | AFIT/RPITIT stabilized in 1.75 are **not dyn compatible**; the failure mode is an agent scattering ad-hoc `Box::pin(async move {…})` at call sites instead of fixing the trait ([di-and-testability-seams.md §2](rust-type-architecture/di-and-testability-seams.md), [traits-vs-free-functions.md §13](rust-type-architecture/traits-vs-free-functions.md)). | `cargo build` fails with "not dyn compatible"; pre-empt with `rg -n 'async fn' $(rg -l '^\s*(pub(\(crate\))?\s+)?trait ' <src>)` cross-checked against `dyn <TraitName>`. | MUST |
| ARCH-11 | Do not add an `…Ext` extension trait purely to hang sugar on a `std` or foreign type. Reach for one only when method-call syntax on a foreign type is genuinely required at many call sites. | ocx's `StringExt`/`SerdeExt`/`ResultExt`/`VecExt` are named in the audit as the "trait for trait's sake" pattern to avoid ([crate-architecture.md:254,289](ocx-codebase-audit/crate-architecture.md)). | `rg -n '^\s*(pub(\(crate\))?\s+)?trait \w+Ext' <src>` — each hit needs a named reason. | SHOULD |

### Seams and wiring

| ID | Rule | Rationale | Verification | Severity |
|---|---|---|---|---|
| ARCH-12 | A function that contains decision logic must not also call `std::fs::*` / `tokio::fs::*`, an HTTP client, `Command::new`, `Instant::now()`/`SystemTime::now()`, or `env::var` inline. Those calls live in a thin adapter `impl` behind a port trait, or in composition code. | 1,664 fs call sites in ocx and 906 in grimoire ([crate-architecture.md:221](ocx-codebase-audit/crate-architecture.md)) with named examples (`load_logo` at `description.rs:51`, `write_shims` at `shims.rs:314`, `build_client` at `forge.rs:263` — [crate-architecture.md:226-228](ocx-codebase-audit/crate-architecture.md)). Without the seam, rename-failure, partial-write, permission-denied and 5xx branches are untestable ([di-and-testability-seams.md §8](rust-type-architecture/di-and-testability-seams.md)). | `rg -n 'std::fs::\|tokio::fs::\|reqwest::\|Command::new\|Instant::now()\|SystemTime::now()\|env::var' <src>` — every hit must be inside an adapter impl or composition code. | MUST |
| ARCH-13 | Read CLI args and `env::var` exactly once, in `main`/composition, into a `Context` struct passed down by reference. No `OnceLock`/`lazy_static`/`thread_local!` for anything a test needs to vary. | Globals force every test in the process onto one value or `#[serial]`, and `env::set_var` is `unsafe` under edition 2024 because it races parallel test threads ([di-and-testability-seams.md §9,§11](rust-type-architecture/di-and-testability-seams.md)). | `rg -n 'env::var\|env::set_var\|OnceLock\|lazy_static!\|thread_local!' <src>` — hits outside `main.rs`/config loading are violations. | MUST |
| ARCH-14 | Domain and application code names only port traits, never a concrete adapter type (`OciHttpClient`, `PhysicalStore`, `SystemClock`). Concrete adapters are constructed only in `main`/composition. | This is what makes the hexagonal boundary real rather than aspirational; the compiler will not catch a stray concrete reference on its own ([di-and-testability-seams.md §4](rust-type-architecture/di-and-testability-seams.md)). | `rg -ln '<ConcreteAdapterName>' <src>` — should match only the adapter's own module and the composition root. | MUST |

### Modules and visibility

| ID | Rule | Rationale | Verification | Severity |
|---|---|---|---|---|
| ARCH-15 | Default every item to private. Widen to `pub(crate)` for cross-module use, `pub(super)`/`pub(in path)` where narrower fits, and bare `pub` **only** for a crate's genuine external contract. Enable `unreachable_pub` at `warn` workspace-wide. **This supersedes the existing "`pub(crate)` is a design smell" rule.** | Bare `pub` always compiles and never errors, so nothing pushes an author toward the truthful annotation; 1,118 bare-`pub` items in a crate with no external consumer is the result ([crate-architecture.md:215](ocx-codebase-audit/crate-architecture.md), [rules-inventory.md:156](ocx-codebase-audit/rules-inventory.md) for the superseded rule, [module-and-visibility-design.md §6-§7](rust-type-architecture/module-and-visibility-design.md) for the counter-evidence: RFC 2126, rustc lint docs, tokio's `lib.rs`). | `[workspace.lints.rust] unreachable_pub = "warn"`, then `cargo clippy --workspace` — zero new hits. | MUST |
| ARCH-16 | Module dependencies run one way: `bin → adapters → application → core`, and `core` imports nothing above it. No module-level `use` cycle may exist, even though one crate tolerates them. | A crate split will not compile until every module cycle is broken; codebases that skip this pay for it later in "long sequences of commits untangling internal dependencies" ([module-and-visibility-design.md §10](rust-type-architecture/module-and-visibility-design.md)). ocx's crate-level layering is already clean ([crate-architecture.md:211](ocx-codebase-audit/crate-architecture.md)) — this extends it inward. | Build the edge list: `rg -o --no-filename 'use crate::[a-z_]+' <module>/ \| sort -u` per module; any mutual pair is a violation. `cargo modules dependencies --lib` for a visual cross-check. | MUST |
| ARCH-17 | New multi-file modules use `name.rs` + a sibling `name/` directory. Never `name/mod.rs`. | 2018+ convention; a directory listing full of `mod.rs` gives a human editor and a grepping agent zero filename signal ([module-and-visibility-design.md §2,§12](rust-type-architecture/module-and-visibility-design.md)). Already the stated house style ([rules-inventory.md:930](ocx-codebase-audit/rules-inventory.md)). | `find crates src -name mod.rs` returns nothing. | SHOULD |
| ARCH-18 | No `pub use module::*;` glob re-export outside a module whose path contains `prelude`. | A glob re-export makes the exported surface un-auditable from the re-export site, and any later same-named private item silently shadows it away ([module-and-visibility-design.md §4](rust-type-architecture/module-and-visibility-design.md), [workspace-and-crate-splitting.md §8](rust-type-architecture/workspace-and-crate-splitting.md)). | `clippy.toml`: `warn-on-all-wildcard-imports = true`, then `cargo clippy -- -W clippy::wildcard_imports`. | SHOULD |

### Crates and workspace

| ID | Rule | Rationale | Verification | Severity |
|---|---|---|---|---|
| ARCH-19 | Every new workspace member must name, in the PR description, at least one of: an actual second consumer, a hard dependency/feature isolation need, a **measured** compile-time bottleneck, or an independent semver promise. "For organization" is not a reason. | Crate boundaries cost publish/version/link overhead; crate-per-module and speculative `utils` crates are the dominant anti-pattern, and tokio explicitly reversed a finer split ([workspace-and-crate-splitting.md §1,§10](rust-type-architecture/workspace-and-crate-splitting.md)). This rule does not exist in the current rule set at all ([rules-inventory.md:1069](ocx-codebase-audit/rules-inventory.md), Gap #8). | Review gate: a diff adding `crates/*/Cargo.toml` without a stated reason is rejected. | MUST |
| ARCH-20 | Target crate shape for an ocx/grim-class tool, flat under `crates/*`: **`-types`** (domain newtypes + on-disk/wire schema, serde only, no async/HTTP deps) → **`-core`** (port traits + orchestration, no concrete adapters) → **`-oci`** and **`-store`** (adapters implementing `-core`'s ports) → **bin** (clap, exit codes, TUI, composition root); plus `xtask` and `-testsupport` (dev-dependency only). Never nest crate directories. | Capability-scoped, flat `crates/*` is what ripgrep, rust-analyzer and uv all converged on; Cargo's crate namespace is flat regardless of directory nesting, so a nested tree drifts ([workspace-and-crate-splitting.md §3,§9,§10](rust-type-architecture/workspace-and-crate-splitting.md)). `ocx_lib` at 82.9% of its workspace is exactly the shape this replaces ([crate-architecture.md:51,57](ocx-codebase-audit/crate-architecture.md)). | `find crates -mindepth 3 -name Cargo.toml` returns nothing; `cargo tree -p <name>-types -e normal` shows no tokio/reqwest/starlark. | MUST |
| ARCH-21 | Declare dependency versions, package metadata and lints once in `[workspace.dependencies]` / `[workspace.package]` / `[workspace.lints]`, and add `[lints] workspace = true` to **every** member manifest. | Workspace lints are **not** implicitly inherited — a member without the opt-in silently gets none, which is how ARCH-15's `unreachable_pub` gate would quietly stop applying ([workspace-and-crate-splitting.md §4](rust-type-architecture/workspace-and-crate-splitting.md)). | `for f in crates/*/Cargo.toml; do rg -q '^\[lints\]' "$f" \|\| echo "missing lints inherit: $f"; done` | MUST |
| ARCH-22 | If any crate is ever published to crates.io, then and only then: declare internal deps as `{ path = "…", version = "…" }`, gate merges on `cargo semver-checks`, enable `missing_docs`, and seal public traits. Until publishing is decided, do none of it. | Every one of these pays semver/docs overhead for a contract with no consumer; the mechanics are real but conditional ([workspace-and-crate-splitting.md §7,§8](rust-type-architecture/workspace-and-crate-splitting.md), [module-and-visibility-design.md §5](rust-type-architecture/module-and-visibility-design.md)). | `rg -n 'publish = false' crates/*/Cargo.toml` — if any member lacks it, this rule activates for that member. | CONSIDER |

## AI-agent failure modes

Ranked by how often it bites.

1. **Bare `pub` reflex.** `pub` always compiles and never produces a visibility error, so there is no feedback loop pushing toward `pub(crate)`. The single most common LLM visibility mistake ([module-and-visibility-design.md](rust-type-architecture/module-and-visibility-design.md), AI-agent angle). Catch: `unreachable_pub` at warn, treat every new hit as a required fix.
2. **Trait-per-struct on the word "extensible" or "testable".** Asked to make something flexible, an agent adds a trait with one impl and a mock nobody varies ([traits-vs-free-functions.md §15](rust-type-architecture/traits-vs-free-functions.md), [di-and-testability-seams.md §5](rust-type-architecture/di-and-testability-seams.md)). Catch: ARCH-07's grep.
3. **Growing the nearest big type instead of making a new one.** Given "add X to the package manager," an agent appends another method to the existing `impl` — 603 methods is what that looks like after two years ([crate-architecture.md:72](ocx-codebase-audit/crate-architecture.md)). Catch: ARCH-03's counter, run on the diff.
4. **`async fn` in a trait plus `dyn` storage.** Compiles as two separate edits, fails on use; the agent's instinct is then to scatter `Box::pin(async move {…})` at call sites rather than apply `#[async_trait]` once ([di-and-testability-seams.md §2](rust-type-architecture/di-and-testability-seams.md)).
5. **Newtype without the invariant.** `struct Digest(pub String)` with a public field and a bare tuple constructor at every call site — type-distinct, zero enforcement, so it buys none of the "parse, don't validate" safety it was asked for ([traits-vs-free-functions.md §19](rust-type-architecture/traits-vs-free-functions.md)).
6. **`OnceLock` presented as dependency injection.** Asked to "make X configurable," the agent adds a static `OnceLock<Config>`; it compiles, removes the literal, and still stops two tests in one process from differing ([di-and-testability-seams.md §9](rust-type-architecture/di-and-testability-seams.md)).
7. **Recommending crate-per-module as "good architecture."** Generic modularity bias, contradicted by tokio's own consolidation and by measured per-crate overhead ([workspace-and-crate-splitting.md §2,§10](rust-type-architecture/workspace-and-crate-splitting.md)).
8. **Assuming `[workspace.lints]` is inherited.** The agent adds the root table and stops; every member silently gets no lints ([workspace-and-crate-splitting.md §4](rust-type-architecture/workspace-and-crate-splitting.md)).
9. **`mod.rs` layout in new code.** Pre-2018 training habit ([module-and-visibility-design.md §2](rust-type-architecture/module-and-visibility-design.md)).
10. **Deref-as-inheritance.** "Let `Wrapper` behave like `Inner`" → `impl Deref for Wrapper`. Compiles, looks clever, violates C-DEREF ([traits-vs-free-functions.md §15](rust-type-architecture/traits-vs-free-functions.md)).
11. **Splitting a crate without checking module cycles first.** The plan reads correctly and does not compile, wasting a full refactor pass ([module-and-visibility-design.md §10,§12](rust-type-architecture/module-and-visibility-design.md)).
12. **`env::set_var` in tests without understanding edition 2024.** Either it fails to compile, or the agent wraps it in `unsafe` — which silences the compiler and leaves the parallel-test data race intact ([di-and-testability-seams.md §11](rust-type-architecture/di-and-testability-seams.md)).
13. **Hallucinated tooling.** `clippy::pub_use` (does not exist — it is `wildcard_imports` plus a config key), `cargo publish --workspace --dependency-order` (no such flag) ([module-and-visibility-design.md §8](rust-type-architecture/module-and-visibility-design.md), [workspace-and-crate-splitting.md](rust-type-architecture/workspace-and-crate-splitting.md) AI-agent angle).
14. **`vfs::MemoryFS` for atomic-write tests.** Passes and proves nothing about rename-across-filesystems, permission bits, or partial writes — the exact bug class a package manager's lockfile and cache writes need covered ([di-and-testability-seams.md §6](rust-type-architecture/di-and-testability-seams.md)).

## Open questions

1. **Is `ocx_lib`'s compile time actually a bottleneck?** ARCH-19 demands a *measured* reason and none exists. Run `cargo build --timings` before the split is justified on compile grounds; today it rests on dependency isolation alone.
2. **Does anything ever publish to crates.io?** This one answer decides ARCH-22, `missing_docs`, sealed traits, `cargo-semver-checks`, and dependency re-export — five rules currently dropped.
3. **What are the decomposition targets for `PackageManager`?** The audit suggests one type per existing file (`Composer`, `Resolver`, `Inspector`, `PatchSync`, …), but 23 types is a lot; a smaller set of 5–7 is likely right, and the choice is close to a one-way door for the internal API shape.
4. **Does grim's TUI become its own crate?** `tui/app.rs` alone is 7,563 LOC ([crate-architecture.md:138](ocx-codebase-audit/crate-architecture.md)). ARCH-20 puts it in the bin crate; a `-tui` crate is defensible but needs an ARCH-19 reason.
5. **Is ARCH-15 retroactive?** Flipping 1,118 + 913 `pub` items to `pub(crate)` is enormous mechanical churn. New crates only, or a one-shot sweep?
6. **Delete ocx's four utility extension traits, or grandfather them?** ARCH-11 forbids adding more; it does not say whether `StringExt`/`SerdeExt`/`ResultExt`/`VecExt` get removed, and they are referenced from the Utility Catalog ([rules-inventory.md:903](ocx-codebase-audit/rules-inventory.md)).
