# Registry listings that reuse repository metadata and the README

Scope: crates.io, PyPI, npm, VS Code Marketplace, Homebrew, Docker Hub and GHCR listing fields, their published limits, how each registry renders a README, and measurements of the fleet's manifests. Out of scope: README copy and keyword strategy (marketing), download-number policy beyond one section. Doc pages cited below mostly state no date; "fetched 2026-11-27" is then the only date. ## Summary

- Only 1 of the 5 fleet Cargo manifests that matter is publishable (`grimoire`, `publish = None`), and it has 0 keywords, 0 categories and no homepage; every other workspace crate has `publish = []`. Measured with `cargo metadata --no-deps --format-version 1` (F1).
- crates.io accepts max 5 keywords (ASCII, max 20 chars, start alphanumeric, letters/digits/`_`/`-`/`+`) and max 5 categories that must match slugs exactly; `description` is required and must be plain text, not Markdown ([Cargo manifest](https://doc.rust-lang.org/cargo/reference/manifest.html), fetched 2026-11-27).
- `grim` and `grimoire` are held on crates.io by other projects (checked 2026-11-27 with `curl -s -A research-script https://crates.io/api/v1/crates/grim`: repository `Vaishnav-Sabari-Girish/grimoire`, updated 2026-07-02), so the CLI cannot publish under its own name. Naming is an owner decision.
- PyPI: Summary is one line; `Description-Content-Type` legal values are `text/plain`, `text/x-rst`, `text/markdown`; Project-URL labels are free text up to 32 chars; `Home-page` is deprecated in favour of Project-URL ([core metadata spec](https://packaging.python.org/en/latest/specifications/core-metadata/), fetched 2026-11-27, latest history entry May 2026).
- npm: `description`, `keywords`, `homepage`, `repository` (object, `directory` for monorepos), `bugs` are the discovery fields; name max 214 chars incl. scope; the registry README updates only on publish ([package.json](https://docs.npmjs.com/cli/v11/configuring-npm/package-json), [README page](https://docs.npmjs.com/about-package-readme-files), fetched 2026-11-27).
- Fleet npm gap: `@grimoire-rs/indexer@0.8.0` has no `keywords` (measured with `jq`/Python over `package.json` and `https://registry.npmjs.org/@grimoire-rs%2findexer`) and its published README carries 9 relative links (`./docs/...`, `./CHANGELOG.md`).
- Relative README links are not equal across registries. Measured: crates.io rewrites them to `https://github.com/<owner>/<repo>/blob/HEAD/<path>` (live check on ripgrep 16.0.0); vsce rewrites them at package time to `blob/HEAD` and `raw/HEAD` (live check on the fleet's own extension); PyPI leaves them relative (live check on typer 0.29.3); npm rendering could not be fetched (npmjs.com returns a 403 challenge to every non-browser client tried) and the npm docs are silent; the fleet's PyPI README rendered with PyPI's own `readme_renderer` leaves its one relative link `LICENSE` dead (F3).
- Decision: absolute URLs in any README a registry reuses are a SHOULD for GitHub-hosted links (two of four registries rewrite) and a MUST for images and for PyPI (PyPI's own guide says relative paths break and to use a public HTTPS URL; [PyPA guide](https://packaging.python.org/en/latest/guides/making-a-pypi-friendly-readme/)).
- VS Code Marketplace: `keywords` max 30; `icon` at least 128x128 px (256x256 for Retina); README and CHANGELOG images must be `https` and SVG is restricted except from trusted badge providers; `galleryBanner` takes `color` and `theme` (`dark` or `light`) ([manifest](https://code.visualstudio.com/api/references/extension-manifest), [publishing](https://code.visualstudio.com/api/working-with-extensions/publishing-extension), fetched 2026-11-27).
- The fleet extension `grimoire-rs.grimoire-vscode` is live (0.5.0, 1,378 installs, 2026-11-27 Marketplace API), which resolves the audit's "404, not conclusive". It sets no `galleryBanner`.
- The Marketplace manifest page lists no `AI` category, yet the live fleet extension shows category `AI`. Docs lag the platform; treat the doc list as non-exhaustive and do not lint against it (F5).
- Homebrew `desc` is one line with no marketing adjectives, no feature lists, no comparisons, no addressing the reader; the formula name is prepended automatically ([Description Guidelines](https://docs.brew.sh/Description-Guidelines), [Formula Cookbook](https://docs.brew.sh/Formula-Cookbook)).
- homebrew-core notability is 30 forks, 30 watchers or 75 stars; 90/90/225 when the owner self-submits; repositories under 30 days old are normally ineligible ([Package Acceptance Policy](https://docs.brew.sh/Package-Acceptance-Policy)). Fleet: `ocx-sh/ocx` has 20 stars, 2 forks, 0 watchers; `grimoire-rs/grimoire` 17, 2, 2 (`gh api repos/<r>`, 2026-11-27). Neither qualifies; ship a tap first.
- Docker Hub short description max 100 chars, overview has no stated size limit, up to 3 categories, overview syncs from README on automated builds ([Docker docs](https://docs.docker.com/docker-hub/repos/manage/information/)). The fleet publishes images to GHCR, not Docker Hub, so those rules apply only if that changes. GHCR honours `org.opencontainers.image.description` (512 chars), `.source`, `.licenses` (256 chars) ([GitHub Docs](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry)).
- GitHub README: first match in `.github`, root, `docs`; content past 500 KiB is truncated ([About READMEs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)). Topics: max 20, lowercase letters/digits/hyphens, 50 chars or less ([topics](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics)). Social preview under 1 MB, 1280x640 best, 640x320 minimum recommended ([social preview](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/customizing-your-repositorys-social-media-preview)). Fleet: both flagship repos have `usesCustomOpenGraphImage` false.
- No README staleness was found in the fleet: for 4 of 4 published packages the README at the latest tag equals HEAD (`git show <tag>:README.md | sha256sum` against `sha256sum README.md`, 2026-11-27). The mechanism risk is real (npm and PyPI copy at publish; crates.io versions are permanent) but unmeasured as a current defect.

### F2. crates.io

Source: [Cargo manifest](https://doc.rust-lang.org/cargo/reference/manifest.html) and [Publishing](https://doc.rust-lang.org/cargo/reference/publishing.html), fetched 2026-11-27.

- Per [Cargo manifest](https://doc.rust-lang.org/cargo/reference/manifest.html) and [Publishing](https://doc.rust-lang.org/cargo/reference/publishing.html): required to publish: `license` or `license-file`, `description`. Publishing guide also lists `homepage`, `repository`, `readme` as fields to fill, and `keywords`, `categories` as recommended. The `.crate` file limit is 10 MB; a publish is generally permanent, yank does not delete code.
- `homepage` must not duplicate `repository` or `documentation`: "Do not make `homepage` redundant with either the `documentation` or `repository` values." A rule that demands `homepage` on every crate is therefore wrong when no dedicated site exists. The `grimoire` crate has a site (`https://grimoire.rs`, the repository's homepage field) so it should set it.
- Category slugs: the page [crates.io/category_slugs](https://crates.io/category_slugs) is client-rendered and returns no list to a fetcher. The same data is served by the API, fetched 2026-11-27 with `curl -s -A research-script 'https://crates.io/api/v1/categories?per_page=100'` (URL quoted so zsh does not glob the `?`); `meta.total` is 58 top-level slugs: `api-bindings accessibility aerospace algorithms artificial-intelligence asynchronous authentication automotive caching command-line-utilities command-line-interface compilers compression computer-vision concurrency config cryptography data-structures database-implementations database date-and-time development-tools email embedded emulators encoding external-ffi-bindings filesystem finance gui game-development game-engines games graphics hardware-support internationalization localization mathematics memory-management multimedia network-programming no-std os parser-implementations parsing rendering rust-patterns science security simulation template-engine text-editors text-processing value-formatting virtualization visualization web-programming wasm`. Sub-categories (`development-tools::build-utils` style, written with `::`) are separate slugs not listed in this call. Slugs an LLM tends to invent (`cli`, `tools`, `developer-tools`) are absent from the list; the real ones are `command-line-utilities`, `command-line-interface` and `development-tools`. A second call a minute later returned a non-JSON body (rate limit suspected), so a lint must handle failure and not stall a release. A lint must read the live list, not a copy.
- Exemplars measured with `curl -s -A research-script https://crates.io/api/v1/crates/<n>`: ripgrep (5 keywords `search, regex, pattern, grep, egrep`; categories `command-line-utilities, text-processing`; description 202 chars), fd-find (5 keywords; `command-line-utilities`; description 59), bat (0 keywords; one category; 26 chars), eza (0 keywords; one category; 27), tokio (4 keywords; `asynchronous`, `network-programming`; homepage `https://tokio.rs`). Two of five use all five keyword slots; none uses more than 2 categories. Even top crates leave keywords empty, so keyword filling is a SHOULD, not a MUST.
- README rendering: crates.io interprets `readme` as Markdown. Relative links resolve against the repository root, via a fix merged in 2021-09 and 2022-01 ([rust-lang/crates.io#3484](https://github.com/rust-lang/crates.io/issues/3484), closed 2022-01-03): links become `{repo}/blob/HEAD/{path of README in repo}/{relative url}`. Reproduced live 2026-11-27: `curl -sL -A research-script https://crates.io/api/v1/crates/ripgrep/16.0.0/readme` redirects to `https://static.crates.io/readmes/ripgrep/ripgrep-16.0.0.html`, where `](CHANGELOG.md)` became `href="https://github.com/BurntSushi/ripgrep/blob/HEAD/CHANGELOG.md"`. The target is `HEAD`, the default branch, not the released tag, so a relative link can point at content that has since changed or moved.
- Badges: crates.io removed its own badge display; badges go in the README ([Cargo manifest](https://doc.rust-lang.org/cargo/reference/manifest.html)).

### F3. PyPI

Sources: [core metadata](https://packaging.python.org/en/latest/specifications/core-metadata/), [PyPI project metadata](https://docs.pypi.org/project_metadata/), [PyPI-friendly README guide](https://packaging.python.org/en/latest/guides/making-a-pypi-friendly-readme/), all fetched 2026-11-27.

- Per [core metadata](https://packaging.python.org/en/latest/specifications/core-metadata/): Summary: "A one-line summary of what the distribution does." In `pyproject.toml` it is `[project] description`.
- `Description-Content-Type`: `text/plain`, `text/x-rst`, `text/markdown` (variant `GFM` default or `CommonMark`). If omitted, tools try reStructuredText and fall back to plain text. Build backends infer the type from a `.md` or `.rst` README extension when `readme = "README.md"` is set. Measured: `ocx-indexbot` serves `text/markdown`; five exemplars (ruff, httpx, rich, typer, pydantic) all serve `text/markdown`.
- Project-URL: free-text label, max 32 chars. Recognised labels (case-insensitive, first match in table order wins): Homepage = Home, Homepage, Home Page; Source = Source, Source Code, Sourcecode, Repository; Changelog = Changelog, Change log, Changes, News, Whatsnew, What's new, History; Release notes; Documentation = Docs, Documentation. A link labelled "Homepage" gets the Homepage icon even if it points at GitHub.
- `Home-page` is deprecated since metadata 1.2 in favour of Project-URL.
- Version length: "As of 2026-10-23, PyPI rejects new uploads whose version is longer than 128 characters" (stated by PyPI; about 99% of releases use 20 or fewer).
- Relative paths: PyPI's guide says relative paths such as `docs/screenshot.png` "can work on your repository's site but break on PyPI", PyPI does not serve images from the uploaded files, so use a public HTTPS URL, raw file URL for repository files. Measured: typer 0.29.3 serves 2 relative links (`tutorial/install.md`) in its PyPI long description, and the live HTML keeps `href="tutorial/install.md"` unrewritten (`curl -s -A 'Mozilla/5.0' https://pypi.org/project/typer/`, parsed with `re` after the `project-description` marker). `pypi.org/project/ocx-indexbot/` (and `/0.6.3/`) returned a 3,038-byte "Client Challenge" page to curl with three user agents and to WebFetch, so the fleet's live page could not be fetched. Substitute measurement with the renderer PyPI itself uses: [readme_renderer](https://github.com/pypa/readme_renderer) ("designed to be used in Warehouse to render the `long_description`", README fetched 2026-11-27; Warehouse's `warehouse/utils/readme.py` imports it). Command: `uv run --no-project --with 'readme_renderer[md]' python -I -c '...markdown.render(description, variant="GFM")...'` over the `description` field of `https://pypi.org/pypi/ocx-indexbot/json` (3,571 chars). Result: 10 anchors, 9 absolute or in-page (`#user-content-...`) and exactly one broken relative `<a href="LICENSE" rel="nofollow">`; 0 images. So on PyPI the fleet's one relative link renders as a dead href; no fleet PyPI image is at risk today.
- Exemplars measured with `https://pypi.org/pypi/<p>/json`: ruff 0.17.6 (summary 68 chars; Project-URLs Changelog, Documentation, Homepage, Repository), httpx 0.29.0 (32; Changelog, Documentation, Homepage, Source), rich 15.0.0 (95; Documentation, Homepage), typer 0.29.3 (66; Changelog, Documentation, Homepage, Issues, Repository), pydantic 2.14.4 (39; Changelog, Documentation, Funding, Homepage, Source). 5 of 5 set Homepage and Documentation. Only ruff sets keywords. Fleet `ocx-indexbot` sets 7 Project-URLs, more than any exemplar.
- Validation: `twine check dist/*` "will report any problems rendering your README" ([PyPA guide](https://packaging.python.org/en/latest/guides/making-a-pypi-friendly-readme/)). Raw reStructuredText failure shows the source unformatted.

### F4. npm

Sources: [package.json](https://docs.npmjs.com/cli/v11/configuring-npm/package-json), [About package README files](https://docs.npmjs.com/about-package-readme-files), [download counts](https://github.com/npm/registry/blob/main/docs/download-counts.md), fetched 2026-11-27.

- Per [package.json docs](https://docs.npmjs.com/cli/v11/configuring-npm/package-json): `description` and `keywords` are what `npm search` indexes. No count or length limit is stated for either. `repository` should be an object `{type, url}`; shorthand is normalised on publish with a warning (fix with `npm pkg fix`); monorepo packages add `directory`. `bugs` takes a URL. Name max 214 chars incl. scope.
- Per [About package README files](https://docs.npmjs.com/about-package-readme-files): README must be at the package root (`README.md`), is always included regardless of `files`, rendered as GitHub Flavored Markdown through GitHub's API, and "will only be updated on the package page when you publish a new version". Relative link handling is not documented. A search of community reports found only issue-tracker anecdotes that npm rewrites relative links to the repository on GitHub; treat as unverified. `https://www.npmjs.com/package/@grimoire-rs/indexer` returned 403 (5.6 KB Cloudflare challenge) to `curl` with a Chrome user agent, a Googlebot user agent, WebFetch and a third-party reader proxy (2026-11-27), so the live rendering of the fleet's 9 relative links could not be measured. A web search found no official npm statement either; only community pull requests, which report that relative paths break on the npm page and fix it with absolute GitHub URLs (for example [stagehand#3066](https://github.com/browserbase/stagehand/pull/3066), [sasori#99](https://github.com/karthikuj/sasori/pull/99)) and disagree on whether npm rewrites Markdown images but not raw HTML `<img>`. Treat npm as "relative is unsafe, undocumented".
- Registry JSON carries the README: `curl -s https://registry.npmjs.org/@grimoire-rs%2findexer` gives `readme` (8,641 chars) with 9 relative `](./docs/...)` links; `@ocx-sh/theme` readme (2,614 chars) has 0.
- Exemplars (`curl -s https://registry.npmjs.org/<p>/latest`, 2026-11-27, platform data): [typescript](https://registry.npmjs.org/typescript/latest) 7.0.2 (description 69 chars, 5 keywords, homepage set), [prettier](https://registry.npmjs.org/prettier/latest) 3.10.1 (41, 0 keywords), [esbuild](https://registry.npmjs.org/esbuild/latest) 0.28.2 (58, 0), [zod](https://registry.npmjs.org/zod/latest) 4.6.7 (85, 5), [vite](https://registry.npmjs.org/vite/latest) 8.4.0 (37, 6). Two of five have no keywords, so as with crates.io keyword filling is a SHOULD. All five set `repository` as an object and `homepage`.
- Download counts: the npm download API holds data from 2015-01-10, answers at most 18 months per query (bulk 128 packages and 365 days), per-version counts only for the previous 7 days, and does not state in that document how mirrors, bots or CI installs are counted ([doc](https://github.com/npm/registry/blob/main/docs/download-counts.md)).

### F5. VS Code Marketplace

Sources: [Extension Manifest](https://code.visualstudio.com/api/references/extension-manifest), [Publishing Extensions](https://code.visualstudio.com/api/working-with-extensions/publishing-extension), fetched 2026-11-27; live Marketplace API `POST https://marketplace.visualstudio.com/_apis/public/gallery/extensionquery` (filterType 7, flags 950).

- Per the [Extension Manifest](https://code.visualstudio.com/api/references/extension-manifest) (fetched 2026-11-27): `name` lowercase, no spaces, unique; `displayName` unique; `publisher` required, ID cannot change after creation. `keywords` limited to 30. `icon` "at least 128x128 pixels (256x256 for Retina screens)". `galleryBanner.color` (example `#C80000`) and `galleryBanner.theme` (`dark` or `light`, the font colour). `repository`, `bugs`, `homepage` become Marketplace Resources links.
- Per the [publishing page](https://code.visualstudio.com/api/working-with-extensions/publishing-extension) and [manifest](https://code.visualstudio.com/api/references/extension-manifest): README and CHANGELOG images "need to resolve to `https` URLs"; SVG images are rejected unless from trusted badge providers; badges only from an approved list (`img.shields.io`, `badgen.net`, `codecov.io`, `vsmarketplacebadges.dev`, `github.com` from Workflows only, and others). If `repository` points to a public GitHub repo, vsce rewrites relative links on the `main` branch by default; `--githubBranch`, `--baseContentUrl`, `--baseImagesUrl` override.
- Measured on the fleet extension: the live README (`Microsoft.VisualStudio.Services.Content.Details` asset, 17,918 bytes) shows `<img src="https://github.com/grimoire-rs/grimoire-vscode/raw/HEAD/assets/logo.png">` where the source README has `src="assets/logo.png"`, and `](CONTRIBUTING.md)` became `https://github.com/grimoire-rs/grimoire-vscode/blob/HEAD/CONTRIBUTING.md`. So vsce rewrote correctly at package time. Note the rewrite is baked into the VSIX and points at `HEAD`.
- Live listing properties for five exemplars (Marketplace API, 2026-11-27): prettier-vscode (short description 29 chars, 39 tags, banner `#ffe04b` light), rust-analyzer (44, 7 tags, no banner), redhat.vscode-yaml (73, 18 tags), gitlens (258 chars, 8 tags, `#8647ae` dark), vscode-docker (70, 5 tags, `#1e1e1e` dark). 3 of 5 set a banner; all 5 fill `Source`, `Support` and a homepage link. Fleet extension: 135-char description, 9 tags, no banner, `Source`/`Learn`/`Support` links all set.
- Categories: the manifest page lists 17 values and not `AI`; the live fleet listing shows category `AI` and was accepted (version 0.5.0 live). The doc page is not a complete allow-list; a lint against it would false-fail on `AI`.
- Release plumbing seen in the fleet: `grimoire-rs/vscode/.github/workflows/release.yml:79` uses `vsce publish --azure-credential`. The [publishing page](https://code.visualstudio.com/api/working-with-extensions/publishing-extension) states (re-fetched 2026-11-27): "On December 1, 2026, global Personal Access Tokens (PATs) in Azure DevOps are retired" and tells publishers to use federated identity. So the fleet is already compliant; any other repository publishing with a PAT breaks four days after this research date.
- Verified publisher, same [publishing page](https://code.visualstudio.com/api/working-with-extensions/publishing-extension): "one or more extensions on the VS Marketplace for a minimum of 6 months", a domain registered at least six months, and ability to add a DNS TXT record. Fleet extension is 1,378 installs; the publisher `grimoire-rs` is not shown as verified in the data fetched, and the 6-month rule makes that an owner timing decision.
- Same page, image rules (quoted): "`vsce` will not publish extensions that contain user-provided SVG images"; "The icon provided in `package.json` may not be an SVG"; "Image URLs in `README.md` and `CHANGELOG.md` need to resolve to `https` URLs." The icon therefore must be PNG.

### F6. Homebrew

Sources: [Description Guidelines](https://docs.brew.sh/Description-Guidelines), [Formula Cookbook](https://docs.brew.sh/Formula-Cookbook), [Acceptable Formulae](https://docs.brew.sh/Acceptable-Formulae), [Package Acceptance Policy](https://docs.brew.sh/Package-Acceptance-Policy), fetched 2026-11-27.

- [Description Guidelines](https://docs.brew.sh/Description-Guidelines): `desc` is one line; "Describe, don't sell"; no "modern", "powerful", "lightweight", "beautiful", no slogans; no feature lists; no comparisons ("Alternative to", "like X but faster") unless factual ("Fork of X with Y support"); do not address the reader. The formula name is prepended in listings, so do not repeat it. `brew style --fix` handles mechanical length and capitalisation. No numeric length limit is on the guideline page.
- [Formula Cookbook](https://docs.brew.sh/Formula-Cookbook): a homepage and an SPDX-identified, DFSG-compatible license are mandatory for homebrew-core; a `test do` block is required, and "`foo --version` and `foo --help` are bad tests" yet "a bad test is better than no test at all". Submission gate: `brew audit --new --formula <formula>`; routine check `brew audit --strict --online`.
- [Acceptable Formulae](https://docs.brew.sh/Acceptable-Formulae): upstream must identify a stable version and provide an immutable tag or release; no moving branches; archives verified by SHA-256; no stable release means not eligible.
- [Package Acceptance Policy](https://docs.brew.sh/Package-Acceptance-Policy): 30 forks, 30 watchers or 75 stars; self-submission (owner, or commit author with an email at the project's `homepage`, `url` or `head` domain) 90 forks, 90 watchers or 225 stars; repository under 30 days old normally ineligible; working `livecheck`; maintainer discretion even when thresholds pass.
- Fleet against thresholds (`gh api repos/<o>/<r> -q '[.stargazers_count,.forks_count,.subscribers_count,.created_at]'`, 2026-11-27): ocx 20 stars, 2 forks, 0 watchers, created 2026-03-03; grimoire 17 stars, 2 forks, 2 watchers, created 2026-05-15. ### F8. README reuse and staleness

- GitHub: `.github`, root, then `docs` in that precedence; 500 KiB truncation; relative links resolve against the viewed branch and also work in clones ([About READMEs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes), fetched 2026-11-27). A README that the registry copies therefore has three different base contexts: the repository branch view, the registry page, and the tarball.
- Staleness by mechanism: npm updates the page only on publish ([npm README page](https://docs.npmjs.com/about-package-readme-files)); PyPI metadata is fixed at upload ([`https://pypi.org/pypi/<p>/json`](https://pypi.org/pypi/typer/json) carries the description captured at upload, measured); crates.io stores a rendered README per version, `https://static.crates.io/readmes/<crate>/<crate>-<version>.html` ([example](https://static.crates.io/readmes/ripgrep/ripgrep-16.0.0.html)); the vsix bakes README and rewritten links at package time ([publishing page](https://code.visualstudio.com/api/working-with-extensions/publishing-extension)); Docker Hub syncs the overview on automated builds ([Docker docs](https://docs.docker.com/docker-hub/repos/manage/information/)). So a README-only edit does not reach any registry until the next release or build. GHCR has no README channel.
- Measured fleet state (2026-11-27, `git show <latest tag>:README.md | sha256sum` vs `sha256sum README.md`): indexer v0.8.0 same, indexbot v0.6.3 same, website `packages/theme/README.md` v0.7.0 same, vscode v0.5.0 same. 0 of 4 stale. Last README edits predate the releases (indexer 2026-11-23 vs tag 2026-11-24).
- Absolute versus relative, by registry (measured unless marked): crates.io rewrites to `blob/HEAD` (verified ripgrep 16.0.0); vsce rewrites to `blob/HEAD` and `raw/HEAD` when `repository` is a public GitHub repo (verified fleet vscode 0.5.0); PyPI keeps relative (verified typer 0.29.3; PyPA guide says to use public HTTPS URLs); npm not measurable here (403), docs silent. The `HEAD` target is the default branch, so even the rewritten links can drift from the released version.
- Image rule differs: Marketplace requires `https` and restricts SVG ([publishing page](https://code.visualstudio.com/api/working-with-extensions/publishing-extension)); PyPI's guide says relative images "can work on your repository's site but break on PyPI" and to use a public URL ([PyPA guide](https://packaging.python.org/en/latest/guides/making-a-pypi-friendly-readme/)); npm: only community reports, see F4. The fleet READMEs: `ocx-sh/ocx/README.md` uses `src="./assets/logo.svg"`, an SVG at a relative path, and `grimoire-rs/grimoire/README.md` uses `./assets/logo.png`. If either README becomes a registry README, the ocx SVG fails Marketplace rules and the relative path fails PyPI.

### F9. Numbers a team may report (short)

- GitHub traffic: "visitors from the past 14 days", viewable with push access, clones count "full clones (not fetches)" ([GitHub Docs](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository)). Any longer window needs the team to snapshot it; no snapshot exists for the fleet.
- Release asset `download_count` is a schema field with no definition of what it counts ([REST releases assets](https://docs.github.com/en/rest/releases/assets), fetched 2026-11-27). Fleet value: ocx v0.6.8 assets sum to 3,485 (`gh api repos/ocx-sh/ocx/releases -q ...`), which includes CI and install-script fetches by construction; the fleet's own installer script is one source. It is an upper bound on use, not a user count.
- npm download counts: see F4. Marketplace installs are the platform's own statistic (`statisticName: install`, 1,378 for the fleet extension, 2026-11-27) and the platform does not state a bot filter in the pages read.
- Stars, forks, watchers are the Homebrew gate; they are the only registry-adjacent number with a documented threshold use (F6).

Rules:

1. MUST: every package that reaches a registry (crates.io with `publish` not `false`, npm without `"private": true`, PyPI project, Marketplace extension) sets a one-line `description` of 1 line and at most 160 characters, plain words, no Markdown. Rationale: `description` is required by crates.io and must be plain text ([Cargo manifest](https://doc.rust-lang.org/cargo/reference/manifest.html)), is PyPI's one-line Summary ([core metadata](https://packaging.python.org/en/latest/specifications/core-metadata/)), and is one of the two fields `npm search` indexes ([package.json docs](https://docs.npmjs.com/cli/v11/configuring-npm/package-json)); I did not verify which fields each registry shows in its search list, so the claim is limited to these three documented roles. Verify: `cargo metadata --no-deps --format-version 1 | jq -r '.packages[]|select(.publish==null)|.description|length'` ≤ 160 and no newline; `jq -r '.description|length' package.json`; `python3 -I -c 'import tomllib;print(len(tomllib.load(open("pyproject.toml","rb"))["project"]["description"]))'`. The 160 figure is this catalog's budget, not a registry limit; no registry stated one for these fields.
2. MUST: crates.io `keywords` has at most 5 entries, each ASCII, at most 20 characters, matching `^[A-Za-z0-9][A-Za-z0-9_+-]*$`; `categories` has at most 5 entries, each equal to a live slug. Rationale: the registry rejects violations at publish ([Cargo manifest](https://doc.rust-lang.org/cargo/reference/manifest.html)). Verify: `cargo metadata --no-deps --format-version 1 | jq '.packages[]|select(.publish==null)|[.name,(.keywords|length),(.keywords|map(length)|max),(.categories|length)]'`; slugs checked against the live `https://crates.io/category_slugs` list at lint time, not a stored copy.
3. SHOULD: every publishable crate and npm package fills `keywords` (crates.io: 3 to 5; npm: 3 to 8) with terms from the README's first paragraph. Rationale: free discovery surface, yet 2 of 5 crates and 2 of 4 npm exemplars leave it empty, so absence is not an error. Verify: `jq '.keywords|length' package.json` ≥ 3; the fleet's `@grimoire-rs/indexer` and `grimoire` fail today. (Keyword choice belongs to marketing.)
4. MUST: each PyPI project sets `readme` so `Description-Content-Type` is present, and `twine check dist/*` passes before upload. Rationale: without a content type PyPI tries reStructuredText and can show raw source ([core metadata](https://packaging.python.org/en/latest/specifications/core-metadata/)). Verify: `twine check dist/*` prints `Passed`; `python3 -I -c 'import json,urllib.request as u;print(json.load(u.urlopen("https://pypi.org/pypi/<p>/json"))["info"]["description_content_type"])'` is non-empty.
5. SHOULD: PyPI Project-URL labels use recognised names: Homepage, Source or Repository, Changelog, Documentation, plus Issues; each label at most 32 characters. Rationale: recognised labels get icons; first match wins, so a GitHub URL labelled Homepage shows the Homepage icon ([project metadata](https://docs.pypi.org/project_metadata/)). Verify: `python3 -I -c 'import tomllib;[print(k,len(k)) for k in tomllib.load(open("pyproject.toml","rb"))["project"].get("urls",{})]'`; fail on any label over 32 chars or when none of the four recognised groups is present.
6. MUST: npm `repository` is an object with `type` and `url`; in a monorepo package it also has `directory`. Rationale: npm warns and rewrites shorthand at publish; without `directory` registry-derived links point at the repository root ([package.json](https://docs.npmjs.com/cli/v11/configuring-npm/package-json)). Verify: `npm pkg fix --dry-run` prints no change; `jq -e '.repository|type=="object"' package.json`.
7. MUST: Marketplace manifests set `icon` to a PNG of at least 128x128 px (256x256 preferred), at most 30 `keywords`, `repository`, `bugs`, `homepage`. Rationale: hard rejection or blank listing otherwise ([manifest](https://code.visualstudio.com/api/references/extension-manifest)). Verify: `jq '.keywords|length' package.json` ≤ 30; `file "$(jq -r .icon package.json)"` reports PNG with both dimensions ≥ 128; `npx @vscode/vsce ls` lists the icon.
8. SHOULD: Marketplace manifests set `galleryBanner` with `color` and `theme` matching the icon. Rationale: `galleryBanner.color` and `.theme` (`dark` or `light`) are documented manifest fields ([Extension Manifest](https://code.visualstudio.com/api/references/extension-manifest), fetched 2026-11-27); 3 of 5 exemplars set it (F5 measurement, Marketplace API 2026-11-27); the fleet extension does not and shows the default header. Verify: `jq -e '.galleryBanner|has("color") and has("theme")' package.json`.
9. MUST: README and CHANGELOG images in a VS Code extension resolve to `https` URLs and are not SVG unless from a trusted badge host. Rationale: Marketplace rejects `http` and restricts SVG ([publishing](https://code.visualstudio.com/api/working-with-extensions/publishing-extension)). Verify: `grep -nE '(src=|\()"?[^"( ]*\.svg' README.md CHANGELOG.md` finds nothing outside `img.shields.io`/`badgen.net`/`vsmarketplacebadges.dev`; `grep -nE 'src="http://|\(http://' README.md CHANGELOG.md` finds nothing.
10. MUST: any image in a README that PyPI or npm reuses uses an absolute `https` URL. SHOULD: links in the same README use absolute `https` URLs. Rationale: PyPI keeps relative paths and does not serve repository files; crates.io and vsce rewrite to `blob/HEAD`/`raw/HEAD` and so link to the default branch rather than the release; npm's behaviour is undocumented ([PyPA guide](https://packaging.python.org/en/latest/guides/making-a-pypi-friendly-readme/), measurements in F8). The split MUST for images, SHOULD for links is chosen because broken images are visible failures on every registry while a link rewritten to `HEAD` still resolves. For PyPI, links are MUST too, because PyPI does no rewriting. Verify: `grep -nE '!\[[^]]*\]\((\./|\.\./|[^h#/][^):]*)\)|<img[^>]*src="(\./|\.\./|[^h"/])' README.md` returns no line; `grep -nE '\]\((\./|\.\./|docs/|[A-Za-z_]+\.md)' README.md` returns no line for PyPI and npm packages.
11. SHOULD: a README-only change that must reach a registry triggers a release (patch bump) in the same pull request. Rationale: npm, PyPI and the VSIX copy README at publish; crates.io versions are permanent so only a new version can change the page ([npm](https://docs.npmjs.com/about-package-readme-files), [Publishing](https://doc.rust-lang.org/cargo/reference/publishing.html)). Verify: `t=$(git describe --tags --abbrev=0); [ "$(git show $t:README.md | sha256sum)" = "$(sha256sum README.md)" ] || echo STALE-ON-REGISTRY`. Fleet result 2026-11-27: 0 of 4 stale.
12. MUST: a Homebrew `desc` is one line and contains none of: `modern`, `powerful`, `lightweight`, `beautiful`, `alternative to`, `replacement for`, `like .* but`, a leading article or the formula name. Rationale: `brew audit --strict` rejects and the guidelines ban it ([Description Guidelines](https://docs.brew.sh/Description-Guidelines)). Verify: `brew audit --new --formula <name>` and `brew style <name>`; grep `grep -inE 'modern|powerful|lightweight|beautiful|alternative to|replacement for' <formula>.rb` returns nothing. Note four of five popular formulae fail this grep (F6); the rule applies to new submissions.
13. MUST NOT: submit to homebrew-core or claim eligibility before the thresholds hold. Rationale: the [Package Acceptance Policy](https://docs.brew.sh/Package-Acceptance-Policy) (fetched 2026-11-27) sets 30 forks, 30 watchers or 75 stars (90/90/225 for a self-submission), a minimum repository age of 30 days and maintainer discretion, so an early submission is public, predictably rejected and costs reputation with maintainers; a tap has no gate. Verify: `gh api repos/<o>/<r> -q '[.stargazers_count,.forks_count,.subscribers_count]'` shows ≥ 75 stars or ≥ 30 forks or ≥ 30 watchers (≥ 225 / 90 / 90 when submitted by an owner) and `created_at` older than 30 days. Today both fleet repositories fail (F6). Until then, publish a tap.
14. SHOULD: if a Docker Hub repository exists, its short description is at most 100 characters; if GHCR is the registry, the image sets `org.opencontainers.image.source`, `.description` (at most 512 chars) and `.licenses`. Rationale: documented caps; `source` links the package to the repository. Verify: `docker buildx imagetools inspect <ref> --format '{{json .Manifest.Annotations}}'` or `docker inspect <image> --format '{{json .Config.Labels}}'` shows the three keys; Docker Hub `curl -s https://hub.docker.com/v2/repositories/<ns>/<name>/ | jq '.description|length'` ≤ 100.
15. SHOULD: each public repository sets a one-line description, a homepage, 3 to 20 topics (lowercase letters, digits, hyphens, ≤ 50 chars) and a custom social preview of 1280x640 px under 1 MB. Rationale: GitHub documents these limits; description, topics and preview are the unfurl and search surface. Verify: `gh repo view <r> --json description,homepageUrl,repositoryTopics`; `gh api graphql -f query='{repository(owner:"o",name:"r"){usesCustomOpenGraphImage}}'` is true. Fleet 2026-11-27: both flagships set description and homepage; both lack a custom preview; per the audit 22 of 29 original repositories have no topics.
16. MUST NOT: report GitHub release-asset downloads, npm downloads or Marketplace installs as users, adopters or active installs. Report them as "downloads" with the source and window, and report GitHub traffic only with the 14-day window stated. Rationale: none of the pages read defines bot, CI or mirror handling (F9). Verify: reading heuristic for a changelog, README or post draft: every number is followed by its source name and window. Pass: "3,485 release-asset downloads of v0.6.8 (GitHub API, all time)". Fail: "3,485 users run ocx".

Manifest lint a skill step runs (decision): one read-only script run before any release, with this order: (1) classify each manifest as published or not (`cargo metadata` `publish`, `package.json` `private`, presence of `pyproject.toml` with a publish workflow); (2) apply rules 1 to 3, 5, 6, 7, 8 as field counts; (3) apply rule 10 by grep on the README that the manifest names; (4) apply rule 11 by hash; (5) print one line per failure with rule number and path. It exits non-zero on MUST failures only.

## What an agent must not decide alone

- Which crates.io name the CLI publishes under, since `grim` and `grimoire` are held by other projects: the owner chooses the name, a rename, or not publishing. Registry squatting policy sits at [Rust blog 2023-09-22](https://blog.rust-lang.org/2023/09/22/crates-io-usage-policy-rfc/) as cited in the audit.
- Whether to submit to homebrew-core or run a tap, because a self-submission is public and counts against the project's reputation with maintainers.
- Whether to open a Docker Hub namespace and publish there in addition to GHCR.
- Whether to become a verified Marketplace publisher (domain DNS TXT record and a 6-month presence requirement are legal and ownership facts).
- The public description of the org and the product category picked on each registry (brand positioning); an agent proposes, the owner approves.
- Any statement of "users", "adopters" or "growth" derived from registry counts.
- Publishing a patch release only to refresh a README: release cadence is an owner decision.

## Contested / evolving

- Absolute versus relative links. For absolute: PyPA says relative paths break on PyPI ([guide](https://packaging.python.org/en/latest/guides/making-a-pypi-friendly-readme/)); against: GitHub says relative links keep working in clones and on any branch ([About READMEs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)), and crates.io and vsce now rewrite them. Direction as of 2026-11-27: registries that rewrite do so to `HEAD`, which drifts. This catalog's resolution: images MUST be absolute, links SHOULD (MUST on PyPI).
- Marketplace categories: manifest docs list 17 values without `AI`; live listings use `AI` (fleet extension accepted). Docs lag the platform; direction is more categories added without a doc update.
- Homebrew `desc`: guidelines ban comparisons and adjectives; the most-installed formulae still carry them (ripgrep, fd, jq). Whether existing formulae get cleaned up is not stated.
- Badge rows in registry READMEs: crates.io says put badges in the README; Marketplace restricts badge hosts; no source read settles a budget. The scout flagged the arXiv study and awesome-list rule; neither was re-fetched here.
- GitHub repository description cap: no GitHub doc states one; third-party pages say 350. Unconfirmed.
- Azure DevOps global Personal Access Tokens retire 2026-12-01 per the publishing page; the fleet already uses `--azure-credential`. Other repositories that publish with a PAT must migrate.
