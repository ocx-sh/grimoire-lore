## Summary

- Of the 23 commissioned sites, 22 got a real breaking-edit-and-run cycle; OCX-04's owner is a `#[cfg(all(target_os = "windows", ...))]` compile-time `assert!` that is inert on this Linux host and on `SHIM_BYTES` itself (empty off-Windows) — reported unrun, matching the eval-sites.md disclosure, not cross-compiled given the effort budget for one assert.
- 15 of 22 (68%) sites are cleanly owned: the single named test goes from green to red on the literal breaking edit, with no compile-lint detour needed. OCX-01, OCX-11, OCX-12, OCX-15, OCX-18, OCX-19, OCX-22, OCX-10, OCX-24, GRM-01, GRM-02, PY-02, PY-04, TS-02, TS-04.
- 4 of 22 (18%) sites name **two** tests and only **one** of the two catches the specific breaking edit: OCX-16 (`resolve_flag_wins_over_env` reds, `resolve_env_decides_when_no_flag` stays green), OCX-20 (the `None`-subtracts-nothing test reds, the `Some(false)` test stays green), GRM-05 (`plain_write_replaces_the_link` reds, `through_symlink_writes_the_target_and_keeps_the_link` correctly stays green as the unaffected control), GRM-08 (`duplicate_in_flight_row_checks_are_deduped` reds, `finished_task_frees_its_in_flight_slot_for_re_check` stays green). A cleanup that names only one of a complementary pair can name the wrong half.
- 3 of 22 (14%) sites are outright noun-only mismatches: the named test stays **green** on the literal breaking edit. GRM-07's `acquire_retries_past_a_ghost_inode` never constructs genuine lock contention (`TryLockError::WouldBlock`); PY-03's `test_archive_member_size_is_capped` uses a tar fixture whose declared size is honest, so "check the declared size once instead of per-chunk" — the literal breaking edit text — also raises the error; TS-01 is the already-known symlinked-parent-directory gap, now reconfirmed twice (hand edit stays green, and a fresh Stryker mutation run on the same line has 3/3 mutants **survive**).
- Combined with tests-as-guards.md's own read-verified OCX-13 mismatch, 4 of 23 distinct scenario-verified sites (17%) are noun-only: OCX-13, GRM-07, PY-03, TS-01.
- The FIFO-ordering guard (OCX-01) doesn't just fail its test on the breaking edit — the process **hangs** (`timeout 15 cargo test ...` exits 124 with the test never printing a result line), a stronger and more expensive failure mode than a red assertion.
- The `-D warnings` compile-lint interaction tests-as-guards.md found in `cargo-mutants` output reproduces on a **hand-applied** edit too: removing `.to_relaxed_slug()` (OCX-11) or the self-heal re-hash (OCX-19) leaves an unused import/binding that fails the build before the test runs — an agent applying the "simplification" would almost certainly also delete the now-dead import/binding as part of the same edit, and once that's done the test does fail correctly. The lint is not a substitute proof; it just changes what the agent has to also delete.
- OCX-10 and OCx-22, which tests-as-guards.md could only mutation-test (and found `cargo-mutants` has no operator for `.min()`/`.saturating_add()`), both go cleanly **red** when the literal breaking edit text is hand-applied: `self.ttl_seconds.min(TTL_SECS)` → `self.ttl_seconds` fails `a_file_declared_ttl_cannot_outlive_the_built_in_ceiling`, and dropping the zip per-entry floor charge fails `a_zip_of_empty_entries_is_bounded_by_the_byte_cap`. The tool's blind spot was never evidence the guard was unowned.
- OCX-18's guard-collapse edit (`Err(e) if e.kind()==NotFound => continue` → `Err(_) => continue`) is exactly the mutant cargo-mutants reported "unviable" (an orphaned `e` binding under `-D warnings`) in tests-as-guards.md. Written by hand without leaving `e` unused, it compiles clean and the named test goes red — confirming the guard IS owned; the mutation tool's own instrumentation, not the guard, was the obstacle.
- A Stryker run on `grimoire-indexer/src/validate/adapters/files.ts`, scoped via a dedicated `vitest.config` to sidestep an unrelated failing test elsewhere in the suite, found 86 mutants, 48 killed, 14 survived, 0 no-coverage-relevant misses on the target line: **all 3 mutants on line 70** (`if (real === null || !contained(base, real))`, TS-01's exact guarded line) survived — independent, mechanical confirmation of the hand-edit finding, obtained in about 20 seconds of test time once the scoping config was in place.
- Getting Stryker to run at all took two real fixes: `npx @stryker-mutator/core@latest` fails with `ERR_MODULE_NOT_FOUND: typescript` because the ESM resolver walks up from npx's own cache, not the project's `node_modules` — installing the packages into the project (`npm install --no-save`) instead of using `npx --yes` fixes it; then the default dry run fails because Stryker requires the **whole** vitest suite green before mutating one file, which a pre-existing, unrelated failing test elsewhere blocks — pointing `vitest.configFile` at a project-local config that scopes `include` to the one test file being verified fixes that.
- mutmut 3.8.0 could not be made to run at all on ocx-sdk-python's `src/ocx_sdk/` layout in the time budgeted: `collect_or_load_stats` fails with `ImportError: cannot import name 'Ocx' from 'ocx_sdk' (unknown location)` from inside mutmut's own `mutants/` sandbox copy, regardless of `paths_to_mutate`/`source_paths`, `tests_dir`, a from-scratch git init, or `debug=true`. This matches a live, open, workaround-free upstream defect class for mutmut 3.8.0 on `src/`-layout Python packages ([boxed/mutmut#585](https://github.com/boxed/mutmut/issues/585)), though the exact symptom differs (my failure is an editable-install/sandbox-path mismatch, not #585's `src.` module-name assertion). Reported as a tooling-friction finding, not attempted further given the budget.
- No cargo-mutants run was repeated here: the three Rust sites tests-as-guards.md already scoped it to (OCX-10, OCX-18, OCX-22) are the same three re-verified here by hand-edit, and installing+re-running it for the other 9 Rust sites would not add information the hand-edit already gives more precisely (it can literally apply the exact breaking-edit text; cargo-mutants' operator catalog cannot).
- Ownership share, restated: 15/22 (68%) sites are singly and cleanly owned, 4/22 (18%) are owned only jointly by two named tests, 3/22 (14%) are not owned by the named test at all. "A test is named" is a true statement for all 22; "the named test fails on the breaking edit" is true for 19/22 (86%) taken as a set and true for a single test in isolation for only 15/22 (68%).

## 3. Findings

1. **OCX-01's breaking edit hangs the test process rather than failing it.** `ocx:crates/ocx_config/src/env.rs:1866-1874` — swapping the `is_file()` check to run after `File::open` makes `a_fifo_is_not_a_trampoline_and_is_never_opened` (`env.rs:4474`) open a real FIFO with no writer. `timeout 15 cargo test -p ocx_config a_fifo_is_not_a_trampoline_and_is_never_opened` exits 124 after printing `running 1 test` and nothing further — no green, no red, just gone. A CI runner without a per-test timeout would hang, not fail loudly.

2. **`-D warnings` turns a "simplify the guard" edit into two edits, and the test only sees the second one.** `ocx:crates/ocx_sign/src/sign/state.rs:53,61` — deleting `.to_relaxed_slug()` alone fails to *compile* (`unused import: ocx_util::prelude::StringExt`), not to test; only after also deleting the now-dead `use` does `cache_files_reject_hostile_slug` (`state.rs:133`) go red. Same shape at `ocx:crates/ocx_index/src/store.rs:202` (OCX-19, unused `claimed` binding). This is the hand-edit analogue of tests-as-guards.md's cargo-mutants "unviable" finding (§3 there): the lint fires on the incidental leftover, not the guard, and a competent agent doing the "simplification" would clean up the leftover anyway — at which point the real test result appears and it is red both times measured here.

3. **The two Rust sites tests-as-guards.md could only mutation-test are, in fact, cleanly owned by their named test — the tool's blind spot was never evidence otherwise.** `ocx:crates/ocx_sign/src/verify/trust_cache.rs:155` (OCX-10): hand-removing `.min(TTL_SECS)` fails `a_file_declared_ttl_cannot_outlive_the_built_in_ceiling` (`trust_cache.rs:364`) at `trust_cache.rs:376`. `ocx:crates/ocx_util/src/archive/zip.rs:256-263` (OCX-22): hand-removing the floor-charge block fails `a_zip_of_empty_entries_is_bounded_by_the_byte_cap` (`zip.rs:599`) at `zip.rs:612`. cargo-mutants generates no operator for a bare `.min()`/`.saturating_add()` call ([mutants.rs/mutants.html](https://mutants.rs/mutants.html)); that is a property of the tool's operator catalog, not of the guard.

4. **OCX-18's cargo-mutants "unviable" mutant is a real, catchable edit once hand-written without the incidental unused binding.** `ocx:crates/ocx_package/src/bin_scan.rs:184-186` — tests-as-guards.md's cargo-mutants run reported the match-guard-to-`true` collapse as `unviable` because it orphans the bound `e`. Rewriting the same collapse as `Err(_) => continue` (never binding `e`) compiles clean under `--features ocx_util/__testing,ocx_oci/__testing,ocx_index/__testing,ocx_store/__testing,ocx_config/__testing` and fails `scan_propagates_metadata_error_for_self_referential_symlink` (`bin_scan.rs:948`) at `bin_scan.rs:957`.

5. **Four sites split ownership across two named tests; naming only one in a shrunk comment would misattribute the guard.** OCX-16 (`ocx:crates/ocx_cli/src/options/verify.rs:87-95`): the "boolean algebra" collapse `verify || !env_opt_out` is caught only by `resolve_flag_wins_over_env` (`verify.rs:145`, fails on `!resolve(&["--no-verify"], false)`); `resolve_env_decides_when_no_flag` (`verify.rs:155`) never sets `no_verify=true` and stays green. OCX-20 (`ocx:crates/ocx_config/src/insecure.rs:128`): `entry.insecure == Some(false)` → `!entry.insecure.unwrap_or(false)` is caught only by `a_system_locked_entry_that_never_states_insecure_subtracts_nothing` (`insecure.rs:284`); `a_system_locked_false_subtracts_the_host_from_the_environment` (`insecure.rs:271`) stays green because the collapse coincides with the original on a `Some(false)` input. GRM-05 and GRM-08 are the same shape, but there the second test is a deliberate, correctly-unaffected control (§2 table), not a coverage gap — the distinguishing question for a cleanup agent is "does the second test even touch the edited branch," which requires reading both bodies, not just seeing two names.

6. **Three sites are outright noun-only: the named test cannot see the literal breaking edit at all.**
   - `grimoire:src/lock/advisory_lock.rs:117-119` (GRM-07): changing `Err(TryLockError::WouldBlock) => return Err(LockError::new(target_path, LockErrorKind::Locked))` to `continue` — "make contention retry too" — leaves `acquire_retries_past_a_ghost_inode` (`advisory_lock.rs:311`) at `1 passed`, because that test only ever exercises the ghost-inode identity-mismatch branch, never genuine lock contention.
   - `ocx-sdk-python:src/ocx_sdk/_bootstrap.py:856-874` (PY-03): replacing the per-chunk `written > ARTIFACT_MAX_BYTES` check with one `entry.size > ARTIFACT_MAX_BYTES` check before the copy loop leaves `test_archive_member_size_is_capped` (`test_bootstrap.py:619-625`) at `1 passed`, because the test's own tar fixture (`_tar_archive([("ocx", b"x"*2048)])`) reports an honest, accurate size — the two implementations only diverge on an archive that *lies* about its declared size, which this fixture never constructs.
   - `grimoire-indexer:src/validate/adapters/files.ts:69-72` (TS-01, already flagged by both the audit and tests-as-guards.md): deleting the second `realpath`+`contained` re-check leaves all 5 tests in `test/validate/files.test.ts` passing.

7. **Independent mechanical confirmation of the TS-01 mismatch: 3/3 mutants on the guard's own line survive under Stryker.** Scoped to `src/validate/adapters/files.ts` via a project-local `vitest.stryker.config.mts` (`{ test: { include: ["test/validate/files.test.ts"] } }`, needed because Stryker's dry run otherwise fails on an unrelated pre-existing test failure elsewhere in the 315-file project — `build compiles a scaffolded repo into dist/`). Result: 86 mutants, 48 killed, 14 survived, mutation score 55.81%. All three mutants whose span is line 70 (`if (real === null || !contained(base, real))`) — `LogicalOperator ||→&&`, `ConditionalExpression→false`, `ConditionalExpression→(false || !contained(...))` — are in the 14 survived, and no mutant on that line was killed. This is the same conclusion the hand-edit reached, obtained mechanically in ~3s of Stryker test time once configured (`npm install --no-save @stryker-mutator/core @stryker-mutator/vitest-runner`; `npx stryker run` with the config above).

8. **Getting a mutation tool to run at all cost real setup time, in both directions (TS worked, Python didn't).** `npx --yes @stryker-mutator/core@latest run` fails immediately with `Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'typescript'` — its own dynamically-imported `ts-config-preprocessor.js` resolves `typescript` via Node's ESM algorithm from *its own* npx cache location, not the project's `node_modules`, even though the project has `typescript` installed. Installing the same packages into the project (`npm install --no-save --no-audit --no-fund @stryker-mutator/core @stryker-mutator/vitest-runner`) and using the project-local `npx stryker run` fixes it. mutmut 3.8.0, by contrast, could not be made to run on `ocx-sdk-python`'s `src/ocx_sdk/` layout: `mutmut run` (with `paths_to_mutate`/`source_paths` and `tests_dir` set in `setup.cfg`, then with a from-scratch `git init`, then with `debug=true` to surface the underlying pytest error) consistently fails at the `collect_or_load_stats` step with `ImportError: cannot import name 'Ocx' from 'ocx_sdk' (unknown location)` raised from inside mutmut's own `mutants/tests/conftest.py` sandbox copy — the installed (editable) `ocx_sdk` still points at the original `src/`, not mutmut's copy. This is a distinct symptom from, but the same general class as, a live open upstream defect ([boxed/mutmut#585](https://github.com/boxed/mutmut/issues/585): "3.8.0: projects whose top-level package is named `src` always fail the `record_trampoline_hit` assert," confirmed with no viable workaround as of the issue's last update). Not investigated further given the time budget — this is itself the "giving up on the tool" failure mode tests-as-guards.md already named (§AI-agent angle, bullet 4), now observed from the other side (a genuine, not-yet-resolvable blocker rather than a discoverable flag).

9. **The noun-only rate, measured directly rather than inferred from name overlap.** Across this dive's 22 empirically-run sites: 15/22 (68%) cleanly red, 4/22 (18%) split-owned (red only as a pair), 3/22 (14%) stay fully green. Folding in tests-as-guards.md's own read-verified OCX-13 mismatch (not re-run here — already deeply verified there): 4 of 23 distinct scenario-checked sites (17%) are noun-only mismatches — OCX-13, GRM-07, PY-03, TS-01.

## Normative guidance candidates

1. **MUST — Before crediting a named test as a guard's owner, run the site's own breaking edit (as literally as the language allows) against that exact test and require it to fail; treat a lint/compile-error detour caused by an incidental leftover (an unused import or binding) as "not yet proven," fix the leftover, and re-run.** Confirms **GRD-07** and **CLN-07** directly: this dive is the planted-edit proof those rules already prescribed, run at scale (22 sites) rather than per-site. It also extends GRD-07/CLN-07's rationale with a concrete new failure shape: a compile-lint failure caused by the *incidental* leftover of a plausible simplification (§Findings 2, 4) is not the same as the test itself failing, and must not be read as "the owner caught it" — it has to be cleared and the test re-run, exactly as tests-as-guards.md's guidance candidate 2 already said for cargo-mutants' `unviable`/`CompileError`, now shown to apply to hand-written edits too.
   - Verification: for Rust, apply the edit in a scratch copy, `cargo test -p <crate> <test::path>`, require `... ok`; if the build fails first, remove the specific leftover the compiler names and re-run before concluding anything. For Python, `pytest -k <name>` after the edit. For TS, `npx vitest run <file>` or the project's runner with a name filter.
   - Severity: MUST. Portability: portable.

2. **MUST — When a site names more than one test as its guard, verify each one individually against the breaking edit; a comment shrink that names only one of a complementary pair is wrong when the omitted one is the one that actually catches the edit.** New commitment, refining **RTE-03**/**RTE-12**. Four of 22 sites here (OCX-16, OCX-20, GRM-05, GRM-08) name two tests where only one catches the specific edit; a cleanup agent that reads "two tests exist" as "either one line suffices" can pick the wrong name.
   - Rationale: OCX-16 and OCX-20's non-catching test is a genuine coverage gap on that half of the matrix (the flag/env or `Option<bool>` value the collapse coincides with); GRM-05 and GRM-08's non-catching test is a deliberately unaffected control, which is fine only because the *other* named test does catch it — a shrink still has to point at the one that does.
   - Verification: apply the breaking edit once, run every named test for the site, and keep in the shrunk comment only the test name(s) that actually went red. If none did, the site is not owned (guidance candidate 3, below) regardless of how many tests are named.
   - Severity: MUST. Portability: portable.

3. **MUST — "A test is named for this constraint" is not evidence of ownership; only "the named test fails on the literal breaking edit" is.** Confirms the premise of **GRD-07** as literally true at measured scale, and quantifies it: naive credit-by-naming would have been wrong for 3/22 sites outright (14%) and incomplete for 4/22 more (18%) — a combined 32% of "has a named test" sites where believing the name alone would have been the wrong call. GRM-07, PY-03 and TS-01 (plus the previously-found OCX-13) share nouns with their guard's prose and still do not build its scenario.
   - Verification: the same breaking-edit-and-run cycle as candidate 1; a green result after the literal edit is the finding, not a caveat.
   - Severity: MUST. Portability: portable.

4. **SHOULD, and — where the toolchain cooperates cheaply — worth trying before a hand edit.** Confirms routing.md's downgrade of tests-as-guards.md's original mutation MUST to SHOULD, with a new per-language qualifier: Stryker on a TypeScript file whose test suite is already scoped or scopeable is cheap (one `npm install --no-save`, one project-local vitest config, ~20s of run time) and gave a decisive, independently-corroborating result (Finding 7); cargo-mutants' operator gaps and `-D warnings`-driven unviable rate (tests-as-guards.md §3) make it a supporting signal at best for Rust; mutmut 3.8.0 could not be made to run on a `src/`-layout Python package inside a reasonable budget (Finding 8) and a hand-applied breaking edit is the more reliable path there today.
   - Verification: for TypeScript, `npm install --no-save @stryker-mutator/core @stryker-mutator/{vitest,jest,jasmine}-runner`, a project-local runner config scoped with `include`/`configFile` to the target test file, `npx stryker run`, then read the survived list for the guard's own line/column range. For Rust, `cargo mutants -f <file> --in-place`, treating any `unviable` on the guard's own span as unproven (tests-as-guards.md guidance candidate 2). For Python, attempt `mutmut run` once; if `collect_or_load_stats` fails inside the sandbox's own import, do not spend further budget chasing it — fall back to the hand-applied breaking edit (candidate 1).
   - Severity: SHOULD. Portability: portable, with the per-language caveat above documented so the next agent doesn't rediscover it.

5. **CONSIDER — Where a breaking edit's literal application would leave a test hanging rather than failing (a blocking syscall with no timeout, as in OCX-01), the cleanup check should run the named test under a bounded `timeout` and treat a timeout as a pass for "the test would catch this," not as inconclusive.** New commitment; not previously named in guard-shape, lint-owned-guards or cleanup-procedure.
   - Rationale: `cargo test`'s own harness has no default per-test wall clock; a CI gate that only checks exit code and total-suite time could plausibly time out the whole run and report an ambiguous failure rather than pinpointing the one hung test.
   - Verification: `timeout <n> cargo test -p <crate> <test>`; exit 124 with no `test result:` line is a hang, and — for a guard whose consequence is explicitly a hang or block (grep the guard's prose for "forever"/"blocks"/"hang") — counts as the test proving the guard, same as a red assertion would.
   - Severity: CONSIDER. Portability: portable.

## Decisions this dive proposes

- **RTE-03 (keep one line naming the test)**: HOLDS for the 15/22 (68%) singly-owned sites. Amended, not overturned, for the 4/22 (18%) split-owned sites: the shrunk line must name every test the breaking-edit run shows actually catches the edit, not an arbitrary one of the site's listed tests. "Never zero lines" is unaffected by this dive either way — no site examined here made a stronger case for zero than for one.
- **GRD-07 / CLN-07 (owner must be shown to fail on the edit)**: HOLDS, and is now the most directly evidenced rule in the set — this dive is exactly its planted-edit proof, run at n=22 rather than per-site, with a measured 32% combined rate (14% outright miss + 18% partial) at which naming-only credit would have been wrong.
- **RTE-06 (mutation before shrinking security/durability guards)**: the downgrade to SHOULD HOLDS. Refined per-language: cheap and decisive for TypeScript once Stryker's two setup gotchas (ESM resolver, whole-suite dry run) are known; still supporting-evidence-only for Rust (tests-as-guards.md's unviable-rate finding, now further corroborated by two hand-edit reconfirmations of OCX-10/OCX-22 that the tool itself could never generate); not runnable at all within budget for this Python repo's layout today (Finding 8) — the rule cannot require a tool that a competent agent cannot get to run.
- **What share of Tier-B-shaped tests truly own their guard**: 15/22 (68%) alone, 19/22 (86%) as a set including split-owned pairs, 3/22 (14%) not at all — and combined with tests-as-guards.md's own prior finding, 4/23 (17%) of every distinct scenario-checked site across both dives is a noun-only mismatch.
