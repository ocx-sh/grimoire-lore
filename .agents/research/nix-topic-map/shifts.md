## Summary

- Flakes are **still an experimental feature in Nix 2.35.2** (confirmed live against the manual's "Currently available experimental features" list, 2026-09-27); RFC 136 ("stabilize-incrementally", opened 2022-09-15) is the only governing plan, and it stabilises the *non-flake* CLI first — flakes get "another RFC" later. Any agent output claiming flakes are "stable now" is wrong as of this date.
- `nix flake lock --update-input <name>` was replaced by `nix flake update [<name>...]` back in **Nix 2.19 (2023-11-17)** — `nix flake lock` now only ever adds missing locks, never updates existing ones. This is older than the 18–24 month window but is exactly the kind of command agents still emit from stale training data.
- `nix profile install` was renamed to `nix profile add` in **Nix 2.30 (2025-07-07)** (old name kept as an alias); `nix profile install` should not appear in new docs or scripts.
- **Nix 2.35 (2026-06-22)** made flake source-tree copies to the store lazy: sources are hashed without being copied when the `outPath` is never used as a derivation input — this is the CppNix analogue of Determinate Nix's "lazy trees" (which shipped in Determinate Nix 3.6.7 on top of Nix 2.24, over a year earlier) finally landing upstream, and it is reported to roughly halve the time to fetch/unpack a nixpkgs tarball.
- **Nix 2.26 (2025-01-22)** added `path:` relative flake inputs (`inputs.foo.url = "path:./foo"`) — a lock-file-format-breaking change: pre-2.26 Nix cannot read a lock file containing a relative-path lock.
- **Nix 2.27 (2025-03-03)** added `inputs.self.submodules = true` and `inputs.self.lfs = true` as flake-declared attributes, so a flake author no longer has to tell every consumer to pass `submodules = true`/`lfs = true` by hand.
- **Nix 2.33 (2025-12-09)** shows the Determinate-Nix-to-CppNix upstreaming pipeline explicitly working: `nix registry resolve` and full-input-type `nix flake clone` are both labelled "Upstreamed from Determinate Nix 3.14.0 / 3.12.0" in the release notes, and multithreaded git `revCount` computation is upstreamed from Determinate Nix 3.12.2.
- **nixfmt reached 1.0/stable status and became `pkgs.nixfmt` in nixpkgs 25.11** (2025-11), retiring the placeholder name `nixfmt-rfc-style`; the pre-RFC-166 tool is kept only as `nixfmt-classic`. `nixpkgs-fmt` (nix-community) is **archived** (confirmed via GitHub API, last commit 2024-07-24) — dead, do not recommend it. `alejandra` is still actively maintained (last commit 2026-09-11) and remains a legitimate non-RFC-166 alternative for teams that already use it, but nixfmt is now the *official* formatter.
- `rustPlatform.buildRustPackage` switched its default vendoring mechanism to `fetchCargoVendor` in **nixpkgs 25.05**, which changes every `cargoHash`; packages need `useFetchCargoVendor = true` only if they must stay compatible with 24.11. `cargoSha256` (the pre-SRI hash attribute) stopped being accepted at all in that same release — it now hard-errors, not just warns.
- `buildGoModule` had three separate breaking changes across 25.05/25.11: `CGO_ENABLED` must go through `env.CGO_ENABLED` (direct passing first became a compat-shimmed warning in 25.05, then a hard error in 25.11); `buildGoPackage` (the old GOPATH-style builder) was removed outright in 25.05.
- `substituteInPlace`'s `--replace` flag is deprecated in favour of `--replace-fail` / `--replace-warn` / `--replace-quiet` (tracking issue opened 2024-11-14, still open, ~7000 in-tree usages as of that issue) — **not yet removed**, so this is a "warn now, will break later" shift, not a done one.
- **magic-nix-cache's free tier died on 2025-02-01** when GitHub silently swapped the Actions cache backend to an undocumented Twirp/Protobuf API; DeterminateSystems recommended migrating to FlakeHub Cache, then the community got a compatible `magic-nix-cache-action` working again against the new API (still shipping releases through v15, 2026-09-09) — so "use magic-nix-cache" advice from before 2025-02 needs re-verification, not blanket revival.
- `DeterminateSystems/nix-installer-action` **now installs Determinate Nix by default**, not upstream CppNix (its own README says so explicitly) — a CI pipeline that adopted this action expecting vanilla Nix is silently running a different implementation. `determinate-nix-action` is the version-pinned sibling (tags track Determinate Nix releases exactly, e.g. `@v3.5.2` ⇒ Determinate Nix 3.5.2) and is the one to use when FlakeHub private-flake or FlakeHub-Cache access is needed.
- `flake-utils` (numtide) is functionally in maintenance mode: last commit **2024-11-13**, and its own issue tracker carries an open, unresolved "Potential feature-freeze or deprecation in favor of flake-parts" issue (#86). `eachDefaultSystem` is still everywhere in the wild (H1 confirmed pattern), but new authoring guidance should point at `flake-parts` + `systems` or hand-rolled `forEachSystem`, not flake-utils.
- Lix shipped four releases in the window (2.92 Jan 2025 → 2.95 Mar 2026, no release since as of 2026-09-27) and is beginning to **extract flakes out of Lix's core into a plugin** — a structural divergence from CppNix's monolith, plus several Nix-language strictness changes CppNix doesn't have (`rec`-set merge/dynamic-attrs now forbidden, floats require a leading zero, `or` moving toward a full keyword) that will break code that only ever ran on CppNix.
- Determinate Nix's differentiators as of 3.22.5 (2026-09-17): lazy trees (3.6.7, now also landing upstream in 2.35), flake schemas via a `schemas` output merging `DeterminateSystems/flake-schemas` (3.17.0, 2026-03-06), parallel evaluation for `nix search`/`flake check`/`eval --json` (3.11.1), a native Linux builder on macOS (3.8.4), and FlakeHub Cache endpoint overrides (3.21.8). None of the flake-schema or parallel-eval work is confirmed upstreamed into CppNix as of 2.35.
- `nix flake check` learned to **skip derivations that can be substituted** in Nix 2.32 (2025-10-06), which changes the meaning of "flake check passed in CI" — a green check may now mean "cache had it," not "we rebuilt it."
- Nix's git fetcher moved substantial work onto libgit2 and threading in this window: multithreaded `revCount` computation (2.33, ~9.1s→3.7s on nixpkgs) and the general funnelling of flake-input I/O through the original filesystem location rather than the store, in place since 2.32, which the 2.35 lazy-copy change builds directly on.
- macOS/Darwin platform support moved twice in the window: the 24.11 Darwin SDK rework, then nixpkgs 25.11 raising the **minimum to macOS Sonoma 14.0** with default SDK 14.4, and 25.11 explicitly telegraphing that **x86_64-darwin support is expected to be dropped by nixpkgs 26.11** given Apple ending Intel-Mac macOS updates.

## Survey

### 1. Nix release notes, 2.18 → 2.35 (NixOS/nix repository, `doc/manual/source/release-notes/rl-*.md`)

Read directly from `raw.githubusercontent.com/NixOS/nix/master/doc/manual/source/release-notes/rl-{2.18..2.35}.md` (18 files) and cross-checked against the rendered manual at [nix.dev/manual/nix/2.35/release-notes/](https://nix.dev/manual/nix/2.35/release-notes/). Version/date pairs, each read start-to-finish:

- **2.18 (2023-09-20)**: `builtins.parseFlakeRef`/`flakeRefToString` added; `discard-references` stabilised (no longer needs the experimental flag).
- **2.19 (2023-11-17)**: [`nix flake lock`](https://nix.dev/manual/nix/2.19/command-ref/new-cli/nix3-flake-lock) becomes add-only; [`nix flake update [input...]`](https://nix.dev/manual/nix/2.19/command-ref/new-cli/nix3-flake-update) becomes the only way to update inputs, explicitly said to replace `nix flake lock --update-input`. `builtins.fetchTree` splits into its own `fetch-tree` experimental flag, stabilisable independently of `flakes`.
- **2.20.0 (2024-01-29)**: `nix search` disallows an empty regex (must pass `^` to list everything); new `eval-system` setting distinct from `system` (affects `builtins.currentSystem` only, not build scheduling).
- **2.21.0 (2024-03-11)**: fixes CVE-2024-27297 (FOD sandbox escape via abstract-namespace Unix sockets); adds `--arg-from-file`/`--arg-from-stdin`.
- **2.22.0 (2024-04-23)**: removes the `repl-flake` experimental feature entirely (folded into `flakes`); `nix eval` now prints derivations as `.drv` paths instead of looping into recursive attrsets when evaluating e.g. `nixpkgs#bash`.
- **2.23.0 (2024-06-03)**: `builtins.warn` added (structured warning distinct from `builtins.trace`, controlled by `debugger-on-trace`/`debugger-on-warn`/`abort-on-warn`); `nix derivation {add,show}` JSON reshaped (hash algo and CA method split into separate fields).
- **2.24.0 (2024-07-31)**: fixes CVE-2024-38531 (build-directory sandbox hardening); `nix-shell <dir>` (and `#!nix-shell` shebangs) now look for `shell.nix` in that directory first, `default.nix` otherwise — opt back into old behaviour via `nix-shell-always-looks-for-shell-nix`.
- **2.25.0 (2024-11-07)**: adds `NIX_CACHE_HOME`/`NIX_CONFIG_HOME`/`NIX_DATA_HOME`/`NIX_STATE_HOME` env overrides; integer overflow in the Nix language becomes a hard error, not silent C++ wraparound (`fromJSON` of out-of-i64-range values now errors too; negative `nixConfig` values in flakes are rejected).
- **2.26.0 (2025-01-22)**: [relative path flake inputs](https://nix.dev/manual/nix/2.26/command-ref/new-cli/nix3-flake.html#path-fetcher) (`inputs.foo.url = "path:./foo"`) — **breaks lock-file backward compatibility**, pre-2.26 Nix cannot parse a lock containing such a lock. Flake-lock generation stops consulting system/user flake registries (only the global registry and `--override-flake` apply), specifically to stop local registry overrides leaking into committed lock files. Nix's build system switches to Meson (RFC 132).
- **2.27.0 (2025-03-03)**: `inputs.self.submodules = true` — a flake declares its own submodule requirement instead of forcing every consumer to pass `submodules = true`. Git LFS support added to the git fetcher (`lfs = true` fetcher attribute, or `inputs.self.lfs = true`). Chroot-store evaluator now presents a union view of host+chroot `/nix/store`, fixing `builtins.path`/`filterSource` breakage under chroot stores.
- **2.28.0 (2025-04-02)**: explicitly an "atypical," non-feature patch branched off 2.27 (not master) so that Nixpkgs 25.05 could get an ABI-safe Nix; completes the Meson/RFC-132 header/pkg-config layout cleanup (all C++ headers now included as `nix/....hh`).
- **2.29.0 (2025-05-14)**: prettified terminal JSON output (`--json --pretty`, auto-detected TTY, `--no-pretty` escape hatch); `nix repl`'s `:load-flake` and `:reload` finally compose.
- **2.30.0 (2025-07-07)**: `build-dir` no longer defaults to `$TMPDIR`/`/tmp` (avoids world-writable escape surface) — now defaults to `builds` under `NIX_STATE_DIR`. `nix profile install` **renamed to `nix profile add`** (old name kept as alias). Manual `__json`-attribute structured-attrs construction deprecated in favour of `__structuredAttrs = true`.
- **2.31.0 (2025-08-21)**: `build-cores = 0` now auto-detects CPU count instead of passing literal `0` to the builder; Git-LFS-over-SSH fixes (`NIX_SSHOPTS` respected, correct port parsing); `user@address:port` store-URI syntax.
- **2.32.0 (2025-10-06)**: drops daemon-worker-protocol support for pre-2.0 (Feb 2018) clients/daemons; derivation JSON now uses store-path *basenames* only (no store-dir prefix, matching the "don't require a store-dir parameter" data-modelling goal); **`nix flake check` skips derivations that are substitutable** instead of always building/copying them; substituted flake inputs are cached (regression since 2.25, ~2× faster in I/O-bound / many-input cases); HTTP binary caches gain transparent `.narinfo`/`.ls`/log compression (`narinfo-compression`, `ls-compression`, `log-compression`).
- **2.33.0 (2025-12-09)**: `nix registry resolve <name>` (new command) — explicitly "**Upstreamed from Determinate Nix 3.14.0**"; `nix flake clone` now supports arbitrary input types including FlakeHub tarball flakes — "**Upstreamed from Determinate Nix 3.12.0**"; git fetcher computes `revCount` on multiple threads (9.1s→3.7s on nixpkgs) — "**Upstreamed from Determinate Nix 3.12.2**" (skip entirely via the `shallow = true` input attribute if `revCount` isn't needed); `builtins.stringLength` now O(1).
- **2.34.0 (2026-02-27)**: the Rust-rewrite `nix-installer` reaches beta (`curl -sSfL https://artifacts.nixos.org/nix-installer | sh -s -- install`; ships its own `uninstall` subcommand); explicitly "a modified version of the Determinate Nix Installer by Determinate Systems"; `no-url-literals` experimental feature stabilises with a new lint-diagnostics infrastructure (`lint-url-literals`, `lint-short-path-literals`, `lint-absolute-path-literals` settings).
- **2.35.0 (2026-06-22)**: **lazy store copies for flake/tarball sources** — Nix hashes a source input without copying it to the store first when the resulting `outPath` will never be used as a derivation input (the common case: importing nixpkgs), yielding "~2x speedup for fetching and unpacking a nixpkgs tarball." Builds directly on the 2.32 I/O-funnelling groundwork. `builtins.fetchTarball` gets the same lazy treatment; `builtins.storePath` short-circuits substitution on lazy-ish paths. This is CppNix converging on the effect Determinate Nix's "lazy trees" (3.6.7) already delivered.

### 2. RFC 136 — "stabilize-incrementally" ([raw source](https://raw.githubusercontent.com/NixOS/rfcs/master/rfcs/0136-stabilize-incrementally.md), NixOS/rfcs, author John Ericson, opened 2022-09-15, shepherd @tomberek)

The only concrete, currently-referenced governance plan for flake stabilisation. Its own words: flakes and the new CLI have been "marked as experimental, with no clear plan forward" since RFC 49 closed. The plan is explicitly two-phase: **first** stabilise the non-flake CLI, in phases matching Nix's architecture; **only afterwards** can "Flakes itself and its CLI components... be stabilised," and even then "the final design of Flakes will also require another RFC." Nix is explicitly allowed to make *breaking* changes to flakes at any time until stabilisation — this is the license under which 2.26's lock-format break and 2.19's `nix flake update` rename happened.

### 3. Experimental-features status, read live against 2.35.2 ([nix.dev/manual/nix/2.35/development/experimental-features](https://nix.dev/manual/nix/2.35/development/experimental-features))

Confirms `flakes` is still listed among "Currently available experimental features" as of this manual build, alongside `fetch-tree` (split off in 2.19, "always enabled" whenever `flakes` is on, and usable standalone as a "release candidate"), `auto-allocate-uids`, `blake3-hashes`, `git-hashing`, `impure-derivations`. The lifecycle diagram in this page is itself the source of truth for "what does experimental mean": a PR-gated flag that can still be arbitrarily changed or entirely removed before a maintainer decision to stabilise or remove.

### 4. Community discussion of flake stabilisation status ([discourse.nixos.org/t/is-nix-flakes-really-out-of-experimentation/62529](https://discourse.nixos.org/t/is-nix-flakes-really-out-of-experimentation/62529))

A 2025-04-01 thread confirms flakes remain flagged experimental in community Nix/NixOS, and that a rumor of stabilisation traced back to an April Fool's video (Vimjoyer). No respondent names an official timeline or supporting RFC beyond what RFC 136 already states. Practical community consensus: treat flakes as de facto stable "with the modest inconvenience of the feature flag," not as formally stabilised.

### 5. nixpkgs-manual release notes, 25.05 / 25.11 / 26.05 / 26.11-unstable (`doc/release-notes/rl-*.section.md`, distinct from the NixOS-manual notes; first appeared as its own doc starting 25.05)

Read from [raw.githubusercontent.com/NixOS/nixpkgs/master/doc/release-notes/](https://github.com/NixOS/nixpkgs/tree/master/doc/release-notes):

- **25.05**: `rustPlatform.buildRustPackage` **defaults to `fetchCargoVendor`**; every `cargoHash` needs regenerating, and packages that need 24.11 compatibility must set `useFetchCargoVendor = true` explicitly. `cargoSha256` support is fully dropped (hard error, not warning) — the deprecation-to-removal window closed this release. `buildGoModule` moves environment passing to the `env` attribute (`env.CGO_ENABLED`; direct `CGO_ENABLED` gets a compat-shim warning this release, an outright error the next); `buildGoPackage` removed; `goSum` attribute added for optional explicit `go.sum` path (fixes stale-rebuild detection). `postgresql`/`libpq` stop shipping `pg_config` by default (now `postgresql.pg_config` / `libpq.pg_config`, addable to `nativeBuildInputs`). Darwin SDK evaluation extended to aarch64-linux (cross-building Darwin SDKs from Linux, not all packages functional yet).
- **25.11**: **`nixfmt` reaches stable and becomes `pkgs.nixfmt`**, deprecating the placeholder `pkgs.nixfmt-rfc-style` attribute name; the pre-RFC-166 formatter is kept only as `pkgs.nixfmt-classic`. `buildGoModule`'s `CGO_ENABLED` compat shim is removed — direct (non-`env.`) `CGO_ENABLED` is now a hard error. `buildPythonPackage`/`buildPythonApplication` switch their default `updateScript` to `nix-update-script` (displacing the in-tree update script, "since nix-update is better maintained ... and has more robust fetcher support" — an explicit statement that `nix-update` is the maintained path). `meta.mainProgram` now feeds a real `NIX_MAIN_PROGRAM` env var and can trigger rebuilds on change. Minimum macOS raised to **Sonoma 14.0**, default SDK 14.4; Darwin switches to system libc++. LLVM 19→21. **x86_64-darwin drop expected by 26.11** (explicit advance notice, tied to Apple ending Intel-Mac OS support).
- **26.05**: no packaging-surface breaking changes matched the keyword sweep in this release's notes — a quieter cycle for the packaging conventions this survey tracks (module/service churn dominates instead).
- **26.11-unstable**: `requireFile`-based derivations now default `meta.license = lib.licenses.unfree`, so consumers relying on the old (no-license) default must now explicitly allow unfree evaluation. `buildFHSEnv`/`appimageTools.wrapAppImage`/`wrapType2` gain `finalAttrs` support; passing extracted AppImage contents via `src` (instead of the new `contents`) is now deprecated. `nixexprs.tar.xz` is scheduled for discontinuation after nixpkgs 27.05 (2027-12-31) in favour of `nixexprs.tar.zst` — anyone pulling nixpkgs via `channels.nixos.org/.../nixexprs.tar.xz` needs to plan the swap.

### 6. NixOS-manual release notes, 24.11 / 25.05 / 25.11 / 26.05 / 26.11 (`nixos/doc/manual/release-notes/rl-*.section.md` — system/module-level, a different document from #5)

24.11 is the last cycle where Darwin/packaging breaking changes were folded into the *NixOS* manual rather than a dedicated nixpkgs one: it documents the **Darwin SDK redesign** (native-Xcode-like build environment, SDKs from Sierra 10.12 through Sequoia 15, "old mechanisms... removed by 25.11 at the latest" — which 25.11 then did), the **last release supporting macOS Sierra–Catalina** (next minimum: Big Sur 11), and the **last release supporting pre-12.0 CUDA**. From 25.05 onward this document is almost entirely NixOS module/service churn (COSMIC desktop alpha, `nixos-rebuild-ng` Python rewrite made default in 25.11 then the old Bash implementation removed in 25.05... — module surface, not packaging surface), confirming this manual is the wrong place to look for flake/packaging shifts going forward; use the nixpkgs-manual notes (#5) instead.

### 7. Lix release history ([lix.systems/blog/](https://lix.systems/blog/), individually: [2.95 "Kakigōri"](https://lix.systems/blog/2026-03-25-lix-2.95-release/))

Four numbered releases fell in the window: 2.92 "Bombe glacée" (2025-01-18), 2.93 "Bici Bici" (2025-05-06), 2.94 "Açaí na tigela" (2025-11-18), 2.95 "Kakigōri" (2026-03-25) — **no release since**, as of 2026-09-27 (last blog entry is a 2026-05-05 CVE writeup, not a release). 2.95 specifics, all confirmed language/behaviour divergences from CppNix: the team has **started extracting Flakes out of Lix core into a plugin** (explicitly called out as harder than expected); several Nix-language strictness changes not present in CppNix — `rec`-set merges and `rec`-set dynamic attrs are now **forbidden** (not just deprecated), floats must have a leading zero (`0.123`, not `.123`), `or` is moving toward full-keyword status, whitespace is required around some token boundaries (`tokens-no-whitespace`); the daemon cache directory moves from `/root/.cache/nix` to `/var/cache/nix`; `fetch-closure`/`builtins.fetchClosure` is **removed** entirely (CppNix still has it); flake permission prompts are consolidated into one approval; sandboxed Linux builds start ~80% faster.

### 8. Determinate Nix — divergent-feature timeline ([determinate.systems/blog/determinate-nix-recap/](https://determinate.systems/blog/determinate-nix-recap/), [.../introducing-flake-schemas/](https://determinate.systems/blog/introducing-flake-schemas/), release list via `gh api repos/DeterminateSystems/nix-src/releases`)

Current version **3.22.5** (2026-09-17; the repo tags roughly weekly). Confirmed Determinate-only features and their introduction versions: **lazy trees** (3.6.7 — the feature 2.35's "lazy source copies" independently converges toward upstream, roughly a year-plus later), **native Linux builder on macOS** via Apple's Virtualization framework (3.8.4), **parallel evaluation** for `nix search`/`nix flake check`/`nix eval --json` (3.11.1), **flake schemas** via a `schemas` output merging `inputs.flake-schemas.schemas` with custom entries so `nix flake show` can label non-standard outputs instead of printing "unknown" (3.17.0, 2026-03-06), and **FlakeHub Cache endpoint overrides** in Determinate Nixd (3.21.8, 2026-07-29). The recap post itself does not claim any of parallel-eval or flake-schemas is upstreamed; only `nix registry resolve`, full-input-type `nix flake clone`, and multithreaded `revCount` are confirmed upstreamed (per #1, Nix 2.33's own release notes).

### 9. GitHub Actions cache API break and the magic-nix-cache saga

Confirmed via WebSearch synthesis of DeterminateSystems' own blog posts (`magic-nix-cache-free-tier-eol`, `bringing-back-magic-nix-cache-action`) plus direct inspection of the `DeterminateSystems/magic-nix-cache-action` repository (not archived; README + release history via `gh api`): GitHub replaced the undocumented Actions-cache backend with a new Twirp/Protobuf API starting **2025-02-01**; magic-nix-cache's free CI cache depended on the old, undocumented endpoints and could not be updated in time (no released `.proto` files), so its free tier was discontinued and DeterminateSystems pointed users at **FlakeHub Cache** instead. A community contributor later got `magic-nix-cache-action` working again against the new API — the action is alive and still shipping (`v11` 2025-06-16 through **`v15` 2026-09-09**), but any doc written before 2025-02 recommending it needs re-verification, not blind trust.

### 10. Installer/cache action landscape ([DeterminateSystems/nix-installer-action README](https://github.com/DeterminateSystems/nix-installer-action), release histories via `gh api`)

`DeterminateSystems/nix-installer-action`'s own README states plainly: "This Action installs Determinate Nix by default. You can still use it to install upstream Nix, although that isn't a supported configuration." Release cadence: v21 (2025-11-12) → v22 (2026-03-29) → v23 (2026-09-09). Its sibling `determinate-nix-action` is explicitly the version-pinned one — tags are synced to Determinate Nix releases (`@v3.22.5` installs exactly Determinate Nix 3.22.5) and it is the action required for FlakeHub private-flake/cache access. `cachix/install-nix-action` remains separately maintained (v31 → v31.11.0 → v31.11.1, latest 2026-08-13) and installs upstream CppNix, not Determinate Nix — the two installer families genuinely diverge in *what Nix implementation ends up on the runner*, which is a fact worth stating explicitly in any CI-authoring guidance because the naming ("nix-installer-action" sounds generic) invites the wrong assumption.

### 11. Formatter and lint tool maintenance status (GitHub API: archived flag, `pushed_at`, latest commit, latest release — `gh api repos/<org>/<repo>` and `.../commits` and `.../releases`)

- `NixOS/nixfmt`: actively released, v1.3.1 (2026-06-01) → v1.4.0 (2026-07-07) → **v1.5.0 (2026-09-11)**, latest commit 2026-09-15. Official, RFC-166-conformant, now stable per #5.
- `nix-community/nixpkgs-fmt`: **`archived: true`**, description still says "Nix code formatter for nixpkgs," last commit 2024-07-24 — dead; do not recommend as current.
- `kamadorueda/alejandra`: **not archived**, last commit 2026-09-11 — actively maintained, but is a different (non-RFC-166) formatting style; a legitimate choice for teams already using it, not the default recommendation going forward.
- `oxalica/nil`: not archived, last commit 2026-07-26 — maintained but slower cadence.
- `nix-community/nixd`: last commit 2026-09-21 — the more actively maintained of the two language servers as of this survey.
- `oppiliappan/statix`: not archived, last commit/push 2026-07-26 — alive, moderate cadence, contradicts an assumption that it is abandoned.
- `astro/deadnix`: last commit 2026-09-05 — actively maintained; version 1.3.2 matches the frame's measured baseline.
- `DeterminateSystems/flake-checker`: v0.2.13 (2025-05-31) → v0.2.14 (2026-08-08) → **v0.2.15 (2026-09-23)** — active, matches the frame's measured baseline exactly.

### 12. flake-utils maintenance status (`numtide/flake-utils` README + issue tracker, via `gh api`)

Last commit **2024-11-13** (matches the exemplar-corpus fetch log's own SHA/date exactly). Repository is not archived, but carries an open, unresolved issue titled "[Potential feature-freeze or deprecation in favor of flake-parts](https://github.com/numtide/flake-utils/issues/86)," plus a second open issue proposing to move its functions into nixpkgs directly (#62). No maintainer response committing to a future beyond the current function set. Read together with H1 (still the single most common `eachDefaultSystem`/per-output `import nixpkgs { inherit system; }` pattern in the wild): the *tool* is stalled but the *idiom* is not dying on its own — authoring guidance needs to actively steer people to `flake-parts`/`systems`, not wait for flake-utils to visibly break.

### 13. `substituteInPlace --replace` deprecation (`NixOS/nixpkgs` issue [#356002](https://github.com/NixOS/nixpkgs/issues/356002), via `gh api`)

Tracking issue opened 2024-11-14, last updated 2025-06-26, still open. `--replace` is deprecated in `setup.sh` in favour of `--replace-fail` (errors if the search string isn't found), `--replace-warn` (warns), `--replace-quiet` (silent) — but as of the issue's own text, roughly 7000 in-tree usages of the bare `--replace` remained, and it currently behaves like `--replace-warn`, not an error. This is a "watch this" shift, not a completed one: agent-authored packaging code should already prefer `--replace-fail` (the strict, fail-fast choice for reproducibility) but must not assume the old flag has been removed from nixpkgs' own `stdenv`.

### 14. Nix profile command/format renames

`nix profile install` → `nix profile add` (Nix 2.30, 2025-07-07, old alias kept — confirmed at #1). A related but **older**, pre-window data point surfaced during search: a manifest-version-3 incompatibility (`error: profile manifest ... has unsupported version 3`) was already being reported against Nix 2.21.2 in an [April 2024 NixOS/nix issue](https://github.com/NixOS/nix/issues/10628) — i.e., the profile manifest format break predates this survey's 18–24 month window and should not be cited as a "recent" shift; only the `install`→`add` rename is within-window.

### 15. Toolchain confirmation runs (this survey's own toolchain, `/home/mherwig/.cache/research-lang/nix-tools/run.sh`)

## Contested

- **Is `alejandra` or `nixfmt` the better default?** Both are actively maintained (checked live: nixfmt last commit 2026-09-15, alejandra 2026-09-11). The nixpkgs project itself has picked a side — `nixfmt` is now *the* official formatter (stable, RFC-166, `pkgs.nixfmt` since 25.11) — but plenty of existing flakes and teams standardised on alejandra before that, and nothing forces a migration. Trending toward nixfmt as the default for *new* work, without alejandra becoming wrong.
- **Is magic-nix-cache safe to recommend?** Split opinion in the ecosystem: DeterminateSystems' own post-mortem steered people toward FlakeHub Cache (a paid product they sell) after the Feb-2025 break; the community fork that revived `magic-nix-cache-action` is unaffiliated goodwill maintenance, not an official guarantee. Trending toward "usable again, but treat any recommendation older than 2025-02 as unverified, and prefer determinate-nix-action + FlakeHub Cache if budget allows."
- **Is Determinate Nix "just Nix" for CI purposes?** DeterminateSystems markets it as a drop-in, and `nix-installer-action` defaults to it silently; but Lix and CppNix maintainers do not treat Determinate Nix as identical (RFC 136's incremental stabilisation plan is CppNix's own process, independent of Determinate's fork), and Determinate-only features (flake schemas, parallel eval) are not confirmed portable to plain CppNix or Lix. Trending toward "close enough for most CI, but a published flake's compatibility claims should be tested against upstream CppNix specifically, not assumed from a Determinate Nix CI run."
- **Will flakes ever formally stabilise?** RFC 136 commits only to an *order* (CLI, then flakes), not a date; the April-2025 Discourse thread shows the community treating "still experimental" as effectively permanent in practice while functionally universal in adoption. No primary source in this survey gives a date; trending toward "no near-term date, plan flake-authoring guidance around permanent-experimental, not a pending 1.0."
- **Is `flake-utils` actively dying or just idle?** Not archived, no formal deprecation notice from its maintainer, but zero commits in ~22 months and an open self-questioning issue. Trending toward "still works, actively discouraged for new code," not "broken."
