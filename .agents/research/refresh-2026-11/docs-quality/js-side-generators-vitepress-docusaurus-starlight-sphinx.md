## Summary

- VitePress 2.0 is not stable. The npm dist-tags are `latest` = 1.6.4 and `next` = 2.0.0-alpha.21, published 2026-10-25 ([registry](https://registry.npmjs.org/vitepress), confirmed with `npm view vitepress dist-tags`).
- The single VitePress version the pair should cite is `2.0.0-alpha.21`. Both `examples.md` ("2.0.0-alpha.16") and `checks/doc_declaration.py` line 47 ("2.0.0-alpha.20") are stale; alpha.16 dates from 2026-01-31 and alpha.20 from 2026-09-04, the day before the baseline.
- Every VitePress behavior claim at risk is unchanged in the current docs and source: sections open by default, depth past 6 ignored, `ignoreDeadLinks` defaults to `false` and so a dead link fails the build, code-group syntax, the unconditional copy button, and the `txt` fallback with a warning.
- One claim is attributed to the wrong file. The `txt` fallback with a warning lives in `src/node/markdown/plugins/highlight.ts`, not in `preWrapper.ts`. `preWrapper.ts` only injects the copy button.
- Docusaurus stable is still 3.10.2 (2026-07-10), so nothing stable changed in the window. Version 4 exists only as canary builds (`4.0.0-canary-7133`, 2026-11-27). Docusaurus 4 is not released, and the `markdown.format` default is still `'mdx'` in both the stable and canary docs.
- The canary docs say `onBrokenAnchors` throws by default; stable 3.10.2 docs say it warns. That is a pending change in an unreleased major, not a change to the pair's claim today.
- `@mdx-js/mdx` is still 3.1.1 (2025-08-29). No release in the window, so the `Unexpected character `!`` claim is unchanged.
- Starlight moved from 0.42.0 to 0.43.2 inside the window. Two changes matter at the edges: 0.39.0 (before the window) stopped autogenerated subgroups from inheriting `collapsed`, and `starlight-links-validator` 0.26.0 now requires Starlight 0.42.0 or newer.
- Sphinx 9.1.1 and 9.2.0 and MyST-Parser 5.2.0 changed nothing about `linkcheck`, `-n` or `-W`. MyST 5.2.0 changes duplicate-heading slugs, and a link to an old slug now emits `myst.xref_missing`, which fails `-W` builds.
- AsciiDoc `//` line comments are documented as never rendering, and they are explicitly allowed in the document header. One caveat: inside a verbatim block `//` is literal text.
- Antora 3.2.0 shipped 2026-08-29, before the window. Patches 3.2.1 (2026-10-01), 3.2.2 (2026-10-30) and 3.2.3 (2026-11-15) appeared in the window; their notes could not be fetched.

## Normative guidance candidates

1. Rule: cite VitePress as `2.0.0-alpha.21` everywhere the pair names a version, and say "2.0 is a prerelease; stable is 1.6.4".
   Rationale: the pair currently pins alpha.16 and alpha.20, and the registry says `next` is alpha.21.
   Verification: `grep -rn "alpha\.[0-9]*" skills/docs-quality-reference rules/docs-quality.md` returns only `alpha.21`; compare with `npm view vitepress dist-tags --json`.
2. Rule: in examples.md, attribute the `txt` fallback with a warning to Shiki highlighting (`highlight.ts`), and keep the button-injection claim attributed to `preWrapper.ts`.
   Rationale: the two behaviors live in different files and a reader who opens `preWrapper.ts` will not find the warning.
   Verification: grep examples.md for `preWrapper.ts` and read the sentence that follows; reading heuristic only.
3. Rule: state the AsciiDoc declaration caveat beside "`//` for AsciiDoc": the opener is a comment only outside a verbatim block.
   Rationale: `//` inside a `----` block renders literally, so a declaration there would show on the page.
   Verification: `python3 checks/doc_declaration.py` fixture with `//` doc_type inside a `----` fence expected to be rejected or ignored; today the regex does not track blocks, so this is a new fixture to add, not an existing check.
4. Rule: add a Docusaurus 4 watch line to DOC-TYPE-30 and the `onBrokenAnchors` text: "canary docs default `onBrokenAnchors` to `throw`; 3.10.2 warns".
   Rationale: the change lands with the first 4.x release and the pair's anchor-gate advice would silently go stale.
   Verification: `npm view @docusaurus/core dist-tags.latest` is below 4.0.0 means the current wording holds; recheck at the next refresh.
5. Rule: for MyST sites, note that a link to a third or later duplicate heading slug fails `-W` from MyST-Parser 5.2.0.
   Rationale: the slug scheme changed from `x-1-2` to `x-2`, so existing links break under the `-n -W` gate the pair recommends.
   Verification: `sphinx-build -b html -n -W` on a page with three headings named alike and a `[](#x-1-2)` link; expect `myst.xref_missing`.

## AI-agent angle

- An agent that reads "VitePress 2.0" from training data will treat 2.0 as stable. Smallest check: `npm view vitepress dist-tags.latest` returns `1.6.4`.
- An agent will recall `markdownlint`-style behavior for Docusaurus "v4" and assume `.md` is parsed as CommonMark. Smallest check: grep the project's `docusaurus.config.*` for `format:`; absent means `'mdx'`.
- An agent may add `searchOptions.boost: {}` or equal weights to VitePress search to "simplify" it. Check: grep for `boost` in the VitePress config; it should be absent or keep title above text.
- An agent will recommend `onBrokenAnchors: 'throw'` as a default, which is true only for canary. Check: the config must set it explicitly on 3.x.
- An agent trained before 2026 will cite Starlight 0.3x collapse behavior for autogenerated groups. Check: `grep -rn "collapsed" astro.config.*` and read against the 0.39.0 note.

## Contested and evolving

- VitePress 2.0 stable has no date. Seven alphas in 14 months (alpha.15 on 2025-11-22 to alpha.21 on 2026-10-25); trend: a monthly to quarterly cadence, with breaking changes in alpha.17, alpha.18 (Vite 8, Node 22 required) and alpha.21. As of 2026-11-27.
- Docusaurus 4: canary builds exist daily, the migration doc page does not. Trend: v4 behaviors arrive first as `future.v4.*` flags in 3.x. As of 2026-11-27.
- Starlight and `starlight-links-validator` both require ever-newer Starlight and Astro minimums (0.42.0, Astro 7). Pinning an old Starlight blocks the validator.
- MyST-Parser 5.2.0 is an upgrade-notes release rather than a breaking one, but it can fail `-W` builds.
