## Summary

- llms.txt shipped September 2024 and grew adoption ~9x by May 2026, but Ahrefs found 97% of published files get zero requests, and Google states the file affects nothing in Search — treat it as cheap insurance, not a traffic strategy.
- The bigger 2026 shift is content negotiation: serving the *same* docs as clean Markdown on `Accept: text/markdown` or a `.md` suffix, which Mintlify and Vercel both ship by default — this is what agents actually fetch, not the llms.txt index.
- Anthropic's Agent Skills spec (SKILL.md, released 2025-12-18) reached 25+ compatible agent products within about 12 weeks — any fleet writing "docs for AI agents" now has a second artifact type to consider besides prose, one this very program is itself producing.
- Progressive disclosure — the core information-architecture move for human docs — actively works against agents: Cloudflare states the same page costs ~31x more bytes as HTML than as Markdown, so chrome that helps a human scan is pure token tax to a bot.
- Algolia shipped DocSearch v4 with an "Ask AI" layer (bring-your-own LLM key) and Docusaurus 3.9.0 (2025-09-25) added first-class support for it — but Algolia's own docs mark DocSearch v4's Ask AI as legacy, superseded by Agent Studio, within the same year.
- The em-dash-as-AI-tell is measurably real but weak: one 2026 study puts GPT-4.1 at 10.62 em-dashes/1,000 words against a 3.23 human baseline (~3.3x), but Twain's own prose lands in GPT-4.1's range — a single-signal em-dash lint will both over- and under-flag.
- VitePress 2.0 is alpha-only as of August 2026 (latest alpha 2.0.0-alpha.19); stable VitePress is still 1.6.x — a fleet standardizing "current VitePress practice" should target 1.x, not assume 2.0 features exist yet.
- Material for MkDocs entered maintenance mode in late 2025; its own team shipped Zensical (Rust-based, `mkdocs.yml`-compatible) as the intended successor, but Zensical isn't at feature parity as of 2026 — this matters nowhere in the current fleet (no repo runs MkDocs) but would matter if one adopts it.
- Pagefind is now the default answer for static-site search: it chunks the index so a browser only downloads the shards a query needs (typically well under 300kB total), which is why it beat Orama (which ships the whole index to the client) in independent comparisons.
- Tested-documentation tooling exists per-language, not just for shell scripts: `cargo test --doc` / `mdbook test` (Rust, Rust-only fenced blocks), Sybil and pytest-codeblock (Python), `doctest MyModule` via ExUnit.DocTest (Elixir, `iex>` prompts), and Runme (polyglot, shebang-per-cell) — a fleet with Python and Rust docs trees has options beyond the ocx shell-script-plus-cast pattern.
- asciicast v3 (asciinema CLI 3.0, Rust rewrite, September 2025) is **not** backward compatible with v2: it switched from absolute to relative-interval timestamps and changed the header schema — any pipeline generating `.cast` files should confirm which version it emits and which player version it targets.
- VHS (Charm) complements asciinema: it's declarative (`.tape` scripts) rather than a live recording, and its ASCII/text output mode is diffable in version control — asciinema captures a real session, VHS scripts a reproducible one; documentation pipelines increasingly use both for different jobs (real walkthroughs vs. CI-verified demos).
- Animated terminal demos are a live WCAG surface: content playing over 5 seconds needs pause/stop controls, nothing may flash more than 3 times/second, and `prefers-reduced-motion` should serve a static frame — a shipped rule about `<Terminal>`/asciicast embeds that doesn't mention this is incomplete.
- Docs observability moved from "traffic dashboards" to feedback loops: Mintlify's analytics report per-page thumbs-up/down plus a bar chart over time, and separately reports what fraction of traffic is AI-agent vs. human — "which pages people vote down" is now a shippable metric, not just an aspiration.
- Vale is the de facto prose-linting CI gate (used at AWS, NVIDIA, Microsoft, GitLab, Red Hat per its own site) with a known rollout pattern: start at `MinAlertLevel = warning`, gate only lines a PR touches (`filter_mode: added`) so old prose debt doesn't block CI, then tighten to `error`. This is the verification mechanism the frame's own constraints require for any plain-English rule.
- Diataxis (tutorial / how-to / reference / explanation, created 2020, gaining fresh relevance in 2026 specifically because agents retrieve fragments rather than reading front-to-back) splits content into **four** types, not the frame's assumed three (landing / guide / reference) — landing pages are a navigation layer over these four, not a fifth content type in the same series.
- Redocly's "Try It" console for OpenAPI references is paywalled behind their commercial Reference product; Scalar ships a comparable try-it console free and open-source — a rule recommending "try it" consoles needs to say which one, not just the concept.
- Starlight (Astro) still has no first-party versioned-docs story as of 2026; the community `starlight-versions` plugin is the working option, and one real adopter (Arcjet) gave up on it for branch-based versioning instead — "just use Starlight's version support" is not yet a safe instruction.

## Findings

### 1. llms.txt and the AI-readership question

The proposal is dated, authored, and versioned: Jeremy Howard (Answer.AI) published it 2024-09-03, with a v2 spec update on 2026-08-10 — it is still evolving as this scout writes, not a settled standard ([llmstxt.org](https://llmstxt.org/)). The file is a Markdown document at the site root: an H1 title, a blockquote summary, then H2-delimited link lists, plus a recommendation to also publish `.md` twins of every page.

Adoption is large by file count and small by request count. One analysis puts llms.txt-family files at ~4,088 sites in June 2025 growing to ~36,120 by May 2026 (~8.8x), while an Ahrefs pass over 137,000 domains found 97% of published `llms.txt` files logged zero requests in May 2026, with AI-bot traffic among the requests that did land measured at GPTBot 4.51%, ClaudeBot 0.80%, DeepseekBot 0.02% ([mecanik.dev](https://mecanik.dev/en/posts/does-llms-txt-do-anything-yet/)). Google states publicly it has no plans to consume the file for Search or AI Overviews; OpenAI's crawler guidance points at `robots.txt` instead; Perplexity is the stated exception that does prioritize pages by it (same source). Net: publishing an llms.txt is near-zero cost and worth doing for the sites that already generate it for free (Mintlify, Vercel do this by default), but it is not a substitute for making the actual pages legible to agents.

### 2. Docs written for agents as readers

The substitute is content negotiation on the real pages. Cloudflare's own docs-for-agents guidance argues progressive disclosure — hiding detail behind clicks, which is the standard human-UX move — actively hurts agents, and that the same page "costs 31x more bytes as HTML than as markdown," concluding "chrome is a token tax on every agent that reads you"; its prescription is more entry points into the same content (llms.txt, per-page `.md`, an MCP server), not separate agent docs ([developers.cloudflare.com/docs-for-agents](https://developers.cloudflare.com/docs-for-agents/)).

Vercel implements this concretely: every docs page is available as Markdown via `Accept: text/markdown` or a `.md` suffix, plus site-wide discovery files — `llms.txt` (compact index), `llms-full.txt` (whole corpus), `sitemap.md` (summaries + prerequisites), `taxonomy.json` (canonical names/aliases), and `graph.json` (the full cross-link graph) — and a page-actions menu offering "View as Markdown" / "Copy page" to humans too ([vercel.com/docs/agent-resources](https://vercel.com/docs/agent-resources), fetched 2026-09-05, page self-dated `last_updated: 2026-09-03`). Mintlify's equivalent reports a "30x reduction in token usage" for Markdown vs. HTML delivery, serves Markdown on the same `Accept: text/markdown` header, adds `Link` and `X-Llms-Txt` response headers so agents can discover the index without parsing the body, and — as of a 2026-01-29 post — moved the llms.txt instructions from the bottom of the file to the top because "coding agents like Claude Code and Cursor often truncate or summarize long pages to preserve their own context window" ([mintlify.com/blog/context-for-agents](https://www.mintlify.com/blog/context-for-agents)).

### 3. Agent Skills as a new documentation artifact type

Anthropic's Agent Skills open spec (a folder with `SKILL.md` plus optional scripts/resources, three-tier progressive disclosure so the agent loads full instructions only when a task matches) shipped 2025-12-18. Within about 12 weeks it had compatible implementations across 25+ products including OpenAI, Microsoft (VS Code, within 48 hours), Cursor, Google Gemini CLI, and Block's Goose ([search-sourced from thenewstack.io / paperclipped.de coverage](https://thenewstack.io/agent-skills-anthropics-next-bid-to-define-ai-standards/)). Vercel now ships its own skills via `npx skills add vercel-labs/agent-skills` and points to the community `skills.sh` directory covering 18+ agents ([vercel.com/docs/agent-resources](https://vercel.com/docs/agent-resources)). Cloudflare ships a whole skills bundle for its platform layers ([github.com/cloudflare/skills](https://github.com/cloudflare/skills), via Cloudflare's own docs-for-agents index). For a project deciding how to document itself for agent readers, "ship a skill" is now a real alternative or complement to "write a page," and it is the exact artifact type this research program itself is building.

### 4. AI chat/search inside docs sites

Algolia's DocSearch v4 ships "Ask AI": a conversational layer that answers from the site's own indexed content, configured with the user's own LLM provider key (OpenAI, Anthropic, Mistral, etc.), domain-whitelisted per assistant, with custom system prompts ([docsearch.algolia.com/docs/v4/v4/askai](https://docsearch.algolia.com/docs/v4/v4/askai/)). That same page is marked "Legacy (v4.x)... no longer actively maintained," with the functionality folded into Algolia's newer Agent Studio — meaning a fleet adopting "DocSearch v4 + Ask AI" today is adopting something Algolia itself is already sunsetting toward a successor product. Docusaurus 3.9.0 (released 2025-09-25) added first-class DocSearch v4 support specifically so sites get this embedded chat-style assistant without custom integration work (search-sourced from InfoQ coverage, corroborated by the official Docusaurus changelog listing 3.9.0/3.9.1/3.9.2 in that window: [docusaurus.io/changelog](https://docusaurus.io/changelog)). Kapa.ai and Inkeep occupy the same space as standalone products rather than search-bar add-ons, with Inkeep positioning itself broader than docs (customer experience, GTM) via a no-code multi-agent builder.

### 5. AI-generated prose and the detection backlash

The em-dash tell is real but weak, and now has numbers behind it. A 2026 study (cited via slopdetector.org, which republishes the "Freeburg 2026" dataset) measured GPT-4.1 at 10.62 em-dashes/1,000 words against a human control baseline of 3.23/1,000 (~3.3x), but also found Claude Opus 4.6 at 9.09, DeepSeek V3 at 6.95, Gemini 2.5 Pro at 3.53 (inside the human range), and Llama 3.1 8B at 0.00; separately, a pooled sample of five classic novels (Twain, Melville, Dickens, Thoreau, Austen) averaged 6.43/1,000 with Twain's *Huckleberry Finn* alone at 10.13 — matching GPT-4.1's rate ([slopdetector.org/blog/em-dash-ai-tell-data](https://slopdetector.org/blog/em-dash-ai-tell-data)). The study's own conclusion: "the em dash is a weak signal, not a fingerprint." Practically: an em-dash count is a cheap, gameable heuristic, not a reliable detector, and a rule that treats it as a hard "no em-dash" gate (as this program's frame does) is choosing a house style, not enforcing an anti-AI-slop test — say so explicitly rather than implying the ban catches AI writing.

### 6. Static-site generators, September 2026 state

- **VitePress**: stable is 1.6.4; 2.0 is alpha-only, latest alpha `2.0.0-alpha.19` dated 2026-08-02 — do not assume 2.0-only features are available to the fleet.
- **Docusaurus**: 3.9.x is current (3.9.0 2025-09-25, 3.9.2 2025-10-17); 3.9 raised the Node baseline to v20, added DocSearch v4 support, and added per-locale `baseUrl`/`url` overrides via `i18n.localeConfigs[locale]` for multi-domain i18n deployments (search-sourced, corroborated by the official changelog dates above).
- **Starlight** (Astro): actively released through 2026 (v0.41.0 added Astro v7 support, 2026-06-23); ships Pagefind search, i18n with RTL, and automatic dark/light out of the box, but has **no first-party versioned-docs support** — the community `starlight-versions` plugin ([github.com/HiDeoo/starlight-versions](https://github.com/HiDeoo/starlight-versions)) is "still in early development," and at least one real team (Arcjet) abandoned it for branch-based versioning instead.
- **Material for MkDocs / Zensical**: Material for MkDocs entered maintenance mode in late 2025; the same team's Zensical (announced November 2025, Rust-powered rebuild, reads `mkdocs.yml` natively) is the intended successor but "has not reached full feature parity" and its third-party module system only just opened up ([squidfunk.github.io/mkdocs-material/blog/2025/11/05/zensical](https://squidfunk.github.io/mkdocs-material/blog/2025/11/05/zensical/), search-sourced).
- **Fumadocs**: Next.js-native, 10k+ stars, directly competes with Docusaurus/Nextra/Vocs — forces a JS/Next stack, a poor fit for a non-JS product's docs.
- No fleet repo currently runs MkDocs, Fumadocs, or Nextra, so these are "watch" items, not action items, for this program.

### 7. Static-site search engines

Pagefind is the pragmatic default: it builds a chunked index after the static build so a page load only fetches the shards its query touches, keeping network payload "typically under 300kB (often closer to 100kB)" even on large sites, works with any static HTML output regardless of generator, and ships as drop-in web components (`<pagefind-modal>`, `<pagefind-modal-trigger>`) ([pagefind.app](https://pagefind.app/)). Orama is the alternative in-memory/edge engine, but independent comparisons found it ships the whole index to the browser, which becomes a real bandwidth problem past a few thousand pages (search-sourced, sarthakmishra.com comparisons) — exactly the failure mode Pagefind's chunking avoids. Algolia DocSearch (now v4, see §4) remains the hosted, infra-managed option with the AI layer bolted on.

### 8. Tested/executable documentation, by language

This is not a single mechanism — the ocx shell-script-plus-cast pattern is one instance of a broader category with per-language native tooling:

- **Rust**: `cargo test --doc` runs fenced Rust blocks in doc comments as ordinary doctests (search-sourced, corroborates official rustdoc docs); `mdbook test` does the same for fenced Rust blocks inside an mdBook — but **only Rust**: unmarked/non-Rust fenced blocks are skipped, and an unmarked block with invalid Rust syntax fails the build unless tagged `ignore` ([rust-lang.github.io/mdBook/cli/test.html](https://rust-lang.github.io/mdBook/cli/test.html)). It needs `-L target/debug/deps/` to resolve the crate's own dependencies.
- **Python**: Sybil (`PythonCodeBlockParser`, hooks into `pytest_collect_file`, supports GFM and MyST Markdown) and `pytest-codeblock`/`pytest-markdown-docs`/`phmdoctest` all run fenced Python blocks in docs as pytest tests — several competing small tools rather than one standard, all search-sourced.
- **Elixir**: `ExUnit.DocTest` runs `iex>`-prefixed examples inside `@doc`/`@moduledoc` via `doctest MyModule` in a test file; `...>` continues multi-line expressions, `** (` lines assert exceptions, and a `doctest_file/2` macro (added in Elixir 1.15.0) extends this to Markdown files outside module docs ([ex-unit.hexdocs.pm/ExUnit.DocTest.html](https://ex-unit.hexdocs.pm/ExUnit.DocTest.html)).
- **Polyglot**: Runme runs fenced code blocks in ordinary Markdown as an interactive "notebook" via a per-cell shebang, supporting Shell/Bash, Python, Ruby, JS/TS, Lua, PHP, Perl and more — closest in spirit to "make the README itself runnable" rather than generating a separate test file (search-sourced, runme.dev). byexample is the older literate-programming equivalent (Python/Ruby/Shell/C/C++ regression-tested from prose).

The fleet has a Rust indexer (`grimoire-indexer`... actually Astro; `grimoire` itself and the ocx-rs crates are Rust) and a Python SDK (`ocx-sdk-python`); neither currently has a language-native tested-docs mechanism documented anywhere in the fleet's existing rules — the ocx ADR's shell-script-plus-cast approach does not reach non-shell code examples in Python or Rust doc comments.

### 9. Terminal recording: asciinema v3 and VHS

asciinema CLI 3.0 (September 2025) was a full Rust rewrite that introduced live streaming and the asciicast v3 format; v3 is **not backward compatible** with v1/v2 — it changed the header schema (now requires `version: 3`, a `term` object with cols/rows/type/version/theme, plus optional timestamp/idle_time_limit/command/title/env/tags) and switched event timestamps from absolute time to a per-event interval relative to the previous event; events stay a 3-tuple `[interval, code, data]` with codes `o`/`i`/`m`/`r`/`x` (output/input/marker/resize/exit) ([docs.asciinema.org/manual/asciicast/v3](https://docs.asciinema.org/manual/asciicast/v3/)). Player support landed separately (asciinema player v3.10.0, server v20250509) — a pipeline recording with CLI 3.x needs a player that also speaks v3, and any existing `.cast` corpus generated before September 2025 is almost certainly v2 and needs to be checked, not assumed compatible.

VHS (Charm) is a different tool solving an adjacent problem: instead of recording a live session, you write a declarative `.tape` script (window size, theme, typing speed, key sequences, waits) and `vhs` renders it deterministically to GIF/MP4/WebM/PNG-sequence, or to plain ASCII/text — the text mode is diffable in version control and is explicitly marketed for CI-based "does this demo still work" checks, with an official GitHub Action ([github.com/charmbracelet/vhs](https://github.com/charmbracelet/vhs)). It depends on `ttyd` and `ffmpeg`. Where asciinema captures what actually happened in a real terminal, VHS scripts a reproducible re-enactment — the two solve different halves of "tested example → visible demo" and several projects use both.

### 10. Accessibility of animated terminal demos

WCAG's animation rules apply directly to any embedded `.cast` player or GIF: nothing may flash more than three times per second (seizure risk), any animation running longer than five seconds needs a pause/stop/hide control, and a `prefers-reduced-motion` media query should be honored — commonly by swapping to a static frame via `<picture>` for viewers who have that OS preference set (search-sourced across WCAG-focused a11y blogs, cross-checked against multiple independent write-ups converging on the same three rules: 3-flash limit, 5-second control threshold, reduced-motion fallback). Neither the ocx docs-style rule nor the ADR for tested doc commands mentions pause controls or a reduced-motion fallback for the `<Terminal>` component — this is a gap in the fleet's one existing implementation of the "tested asciicast" pattern the frame treats as settled best practice.

### 11. Interactive code elements and OpenAPI consoles

StackBlitz's WebContainers run a real Node.js dev environment inside the browser via WebAssembly with "zero network round-trips during normal use," and per its own marketing is used by Google, Meta, Shopify, Salesforce, Stripe among others for embedded live examples (search-sourced, corroborated by the official `webcontainers.io` product framing). Sandpack (used for lighter embedded playgrounds) is no longer actively maintained but remains functional and widely embedded; CodeSandbox has pivoted toward AI infrastructure rather than the embed use case (search-sourced). For type-checked static code samples rather than a live sandbox, Shiki's Twoslash transformer runs the real TypeScript compiler over a code sample to produce accurate hover/error/type callouts baked into the highlighted HTML at build time — no runtime sandbox needed, at the cost of TypeScript-only scope ([shikijs.github.io/twoslash](https://shikijs.github.io/twoslash/), corroborated via the shiki/twoslash GitHub repos).

For OpenAPI-driven API references, Scalar ships a modern, actively developed, free "Try It" console plus an automatic code-snippet generator and a full API-client mode; Redoc gives clean static reference rendering; Redocly's own commercial "Reference" product paywalls its "Try It" feature; Stoplight Elements bundles reference + guides + changelog into one portal with a visual OpenAPI editor for governance (search-sourced, cross-checked across independent 2026 comparison posts converging on the same vendor-tier split). A rule recommending "an interactive try-it console" needs to name which one and its licensing, not just gesture at the category.

### 12. Docs observability: what's actually measurable now

Mintlify's analytics dashboard reports per-page thumbs-up/thumbs-down feedback with a bar chart of feedback over time, explicitly framing it as "pages with the most positive feedback show what works... pages with the most negative feedback indicate what needs attention," alongside separate page/search/assistant analytics and a breakdown of traffic by AI platform (search-sourced across Mintlify's own guides/blog: `mintlify.com/docs/optimize/feedback`, `mintlify.com/guides/success`, `mintlify.com/blog/agent-analytics`). This is the concrete, buildable version of "observability of docs" the frame's hypothesis #4 gestures at without specifying a mechanism: page-level feedback capture (thumbs + optional free text) plus a traffic-source split (human vs. agent) is now a documented, productized pattern, not a research question.

### 13. Prose linting as a CI gate

Vale is the standard mechanism, used per its own site at AWS, NVIDIA, Microsoft, GitLab, and Red Hat, reading Markdown/AsciiDoc/reST/HTML/plain text against a configurable rule set (search-sourced, `vale.sh`, cross-checked against Grafana's own public "Writers' Toolkit" Vale docs). The documented rollout pattern from a January 2026 guide: start with `MinAlertLevel = warning` so the linter doesn't block merges while the team absorbs the noise, use `filter_mode: added` so a CI gate only fails on lines a given PR actually adds or modifies (pre-existing prose debt doesn't block), then tighten to `error` once noise subsides ([buildwithfern.com/post/docs-linting-guide](https://buildwithfern.com/post/docs-linting-guide), search-sourced). This is precisely the "verification, not a reading opinion" mechanism the frame's own constraints require for a plain-English rule, and the ocx docs-style rule currently has none — its prose requirements ("short paragraphs," "no em-dash" implied by the shipped-rule constraint, precision language) are stated as taste, unchecked by any lint.

### 14. Diataxis and the page-type question

Diataxis — tutorial (learning), how-to (task), reference (lookup), explanation (understanding) — was created in 2020 by Daniele Procida (Django core dev, now at Canonical) and is described by current 2026 commentary as newly relevant *because* agents retrieve fragments rather than reading front-to-back, which rewards Diataxis's sharp separation of "what kind of need is this passage serving" ([diataxis.fr](https://diataxis.fr/), corroborated by independent 2026 commentary converging on the same four-way split and the same "agents retrieve fragments" rationale). This is **four** content types, and a landing page is a navigation layer sitting above all four rather than a fifth type in the same series — the frame's hypothesis #2 ("three kinds: landing, guide, reference") collapses "how-to" and "reference" together and omits "explanation" (conceptual background, the "why," distinct from a how-to's "steps" and a reference's "facts") as its own category entirely. Any page-type contract this program ships should reconcile with, or explicitly diverge from, the four-way Diataxis split rather than silently inventing a three-way one.

## AI-agent angle

- **Reaches for an em-dash ban as if it were an AI-detector.** An LLM asked to "sound less like AI" will often just delete em-dashes and stop there, leaving stacked clauses and hedging untouched — the measured data shows em-dash alone is a weak, gameable signal. *Check:* run the actual prose through a Vale style (sentence length, passive voice, weasel words) rather than a single-character grep; treat em-dash removal as a house-style choice, not a slop fix.
- **Writes an llms.txt and calls the docs "agent-ready."** An LLM will happily generate the file because it's cheap and well-specified, without touching whether the real pages are legible to an agent. *Check:* grep for whether pages actually respond to `Accept: text/markdown` or serve a `.md` twin — llms.txt existing is not evidence of anything else being agent-ready.
- **Assumes VitePress 2 / current-gen SSG features exist because training data mentions the version number.** VitePress 2.0 is alpha-only in September 2026; an LLM trained on forward-looking blog posts about "VitePress 2" may write config or components against features that aren't in the stable release. *Check:* `npm view vitepress version` (or the lockfile) against what the draft assumes before shipping SSG-specific guidance.
- **Recommends "add a Terminal/asciicast demo" without a pause control or reduced-motion fallback.** LLMs replicate the pattern they've seen (an animated GIF/cast embed) without the WCAG wrapper, because most training-corpus examples don't have one either. *Check:* grep the component's props/slots for anything named `pause`, `static`, or `reduced-motion` — its absence is the finding.
- **Treats "tested documentation" as synonymous with "shell script plus asciicast," even in a Python or Rust repo.** An LLM pattern-matching off the ocx ADR will propose the same shell-script mechanism for a language whose native doctest tooling (Sybil, `cargo test --doc`, ExUnit.DocTest) already does this without an extra script. *Check:* does the repo's primary language have `doctest`/`sybil`/`mdbook test` already available in its build tooling before reaching for a shell-script wrapper.
- **Cites a specific asciicast version without checking which one the pipeline emits.** LLMs conflate "asciinema" as a single unversioned thing; v3 (Sept 2025) silently breaks anything targeting a v2-only player. *Check:* `head -1 *.cast` for `"version": 3` vs `2`, and confirm the player dependency's version supports it.
- **Names "landing, guide, reference" as the complete set of page types**, because that's the frame's own working hypothesis, without checking that Diataxis's four-way split (adding "explanation") is the actual prevailing industry model. *Check:* does the page-type contract have a slot for conceptual/background content that isn't steps and isn't a lookup table — if not, it's missing "explanation."

## Contested / evolving

- **llms.txt itself is mid-spec-change.** A v2 update landed 2026-08-10, four weeks before this scout's era date — any hard requirement built on the v1 shape risks being stale within the same quarter. Trending: toward richer per-page metadata (content negotiation, `.md` twins, discovery headers) and away from the bare index file being the whole story.
- **DocSearch v4's flagship AI feature is already being deprecated in favor of Agent Studio**, per Algolia's own "Legacy" label on the Ask AI docs, even as Docusaurus 3.9 just shipped first-class support for it. Trending: the AI-chat-in-search-bar pattern is being absorbed into broader "agent platform" products faster than SSGs can finish integrating the previous generation of it.
- **Whether progressive disclosure (the standard human-UX practice) is good or bad for docs is now genuinely two different answers depending on the reader.** Cloudflare's guidance says it "actively hurts agents." No consensus yet on how a single page should serve both audiences — current practice is parallel formats (HTML for humans, Markdown for agents) rather than one page trying to satisfy both. Trending: toward content negotiation (same URL, different representation) rather than a single universal page shape.
- **Static-site search is consolidating around Pagefind for the free/self-hosted tier** (search-sourced comparisons consistently favor it over Orama for bandwidth reasons) while the hosted tier (Algolia) is racing to fold in AI chat before its own product cycle turns over again. Trending: hosted search vendors bundling AI chat as standard; self-hosted search staying deliberately dumb-but-cheap (Pagefind).
- **Versioned docs remains genuinely unsettled for Astro/Starlight sites** — no first-party mechanism, a young community plugin, and at least one real team reverting to branches. Trending: unclear; this is the one item in this survey where "current best practice" is still "pick the least-bad workaround."
- **Whether an em-dash (or any single lexical tell) is a legitimate quality signal is an active argument, not settled.** The measured overlap between AI and classic-literature rates argues against a hard rule; the "AI slop" backlash argues for cracking down anyway regardless of false positives. Trending, per the cited study's own framing: away from single-signal detection and toward structural/statistical detectors (perplexity, burstiness) — none of which this scout verified in depth; flagged as a gap for a follow-up pass, not a settled recommendation.
