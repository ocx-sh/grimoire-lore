## Summary

- No linter in the survey checks the concurrency escape hatches. SwiftLint 0.65.1 has exactly six concurrency-adjacent rules (`incompatible_concurrency_annotation`, `unhandled_throwing_task`, `async_without_await`, `redundant_sendable`, `private_swiftui_state`, `unneeded_throws_rethrows`) and none for `@unchecked Sendable`, `nonisolated(unsafe)`, `Task.detached`, `DispatchQueue`, `MainActor.run`, `assumeIsolated` or `ObservableObject`. The only enforced ban in the corpus is Airbnb's `custom_rules` regex `no_unchecked_sendable`.
- The compiler is the real concurrency linter. Verified on 6.4: `MutableGlobalVariable`, `SendableClosureCaptures`, `SendingRisksDataRace`, `NoUseUnstructuredThrowingTask` fire; `@unchecked Sendable` and `nonisolated(unsafe)` stay silent, except that `-strict-memory-safety` flags a use of a `nonisolated(unsafe)` variable as "expression uses unsafe constructs but is not marked with 'unsafe'".
- Escape hatches are common in good code, so a ban is wrong and a "guard must be visible" rule is right: across the exemplar corpus (Sources only, regex-counted) `@unchecked Sendable` appears 867 times in 34 of 40 repos, `nonisolated(unsafe)` 2,503 times in 23 (2,006 of them in one app), `@preconcurrency` 936 times in 26, `assumeIsolated` 147 times in 11.
- Formatter defaults do not match how Apple's own repos format. The bundled swift-format defaults to 2-space indent and 100 columns; 16 of 21 parseable `.swift-format` files in the corpus override to 4 spaces and 12 set `lineLength: 120`. Running defaults over swift-log gives 3,381 `[Indentation]` hits; its shipped config gives 0. The config file is the product, not the tool.
- SwiftLint's default roster is mostly style noise on modern code. Defaults over 37.7k LOC of swift-log/swift-system/swift-async-algorithms gave 1,703 hits: 858 style, 348 metrics, 384 lint (of which 258 `comment_spacing` and 101 `todo`), 113 idiomatic. All three SwiftLint users in the corpus that tune it disable or loosen `identifier_name` and `line_length`.
- Zero of SwiftLint's 256 rules target Swift Testing. All test rules are XCTest/Quick/Nimble (`balanced_xctest_lifecycle`, `empty_xctest_method`, `final_test_case`, `test_case_accessibility`, `xct_specific_matcher`, ...). SwiftFormat has `preferSwiftTesting`, `swiftTestingTestCaseNames`, `redundantSwiftTestingSuite`, `validateTestCases`; swift-format added `SwiftTestingNamingConventions` on main after 603 (not in the 6.4 bundle).
- Compiler warning groups are the new stable lint interface. 75 `GROUP(...)` entries in 6.4.0 `DiagnosticGroups.def` are addressable by `-Werror <Group>` / `-Wwarning <Group>`, SwiftPM `.treatWarning("Group", as: .error)` / `.treatAllWarnings(as:)` (SE-0480, 6.2) and, new in 6.4, the in-source `@diagnose(Group, as: error|warning|ignored, reason:)` attribute (SE-0522). Opt-in groups worth knowing: `ExplicitSendable`, `PerformanceHints` (sub-groups `ExistentialType`, `ReturnTypeImplicitCopy`, `UntypedThrows`), `StrictMemorySafety`, `StrictLanguageFeatures`, `EmbeddedRestrictions`.
- Upcoming features: Swift 6 mode bundles 15 `UPCOMING_FEATURE`s; six more are tagged `LanguageMode::future` in 6.4 (`ExistentialAny` SE-0335, `InternalImportsByDefault` SE-0409, `MemberImportVisibility` SE-0444, `InferIsolatedConformances` SE-0470, `NonisolatedNonsendingByDefault` SE-0461, `ImmutableWeakCaptures` SE-0481). Manifest adoption in the corpus: `MemberImportVisibility` 19, `ExistentialAny` 15, `InternalImportsByDefault` 11, `InferIsolatedConformances` 7, `NonisolatedNonsendingByDefault` 7.
- Strict memory safety (SE-0458, `-strict-memory-safety` / `.strictMemorySafety()`, 6.2) is adopted by only 3 of 40 manifests (swift-collections `Package.swift:111`, swift-testing, vapor `Package.swift:246`); no style guide mentions it.
- The largest shared enforcement artifact is not a linter but `swiftlang/github-workflows` `soundness.yml`, reused by 22 of 40 exemplars: API-breakage (`swift package diagnose-api-breaking-changes`), docs with `--analyze`, unacceptable-language, license headers, broken symlinks, format check, shellcheck, yamllint.
- `-warnings-as-errors` / `treatAllWarnings(as: .error)` is the dominant "lint": 12 exemplars gate on it (swift-nio `.github/workflows/main.yml:18`, swift-aws-lambda-runtime `Package.swift:7`). swift-testing documents a catch: `treatWarning(..., as: .warning)` is ineffective in packages consumed as dependencies because SwiftPM suppresses dependency warnings (`Package.swift:436`).
- Style guides disagree by era. Airbnb (pushed 2026-10-06) is current: 136 rules, a SwiftPM command plugin, an AI skill, Swift Testing preferred, `@unchecked Sendable` essay. Google's guide has not changed since 2018-05 (no concurrency content), Kodeco is "Updated for Swift 5" (2025-04 push), LinkedIn "last updated for Swift 4.0" (2018-02). Treat the last three as historical.
- Security catalogues are Apple-app-shaped. MASTG iOS tests (88 beta tests, v2.0.0 2026-06-30) are mostly binary/Frida-level; CodeQL's 27 Swift queries are all `Security/` (zero code-quality queries), taint-flow over `URLSession`, `WKWebView`, `NSPredicate`, `Regex`, CryptoKit/CommonCrypto, SQLite. For a Linux CLI/server fleet the portable subset is: command injection, path injection, SQL injection, regex injection/ReDoS, cleartext logging, weak hashing/ECB/static IV/constant salt/insufficient PBKDF iterations, hard-coded keys, insecure TLS, XXE, string length conflation.
- CodeQL `swift/string-length-conflation` is the only catalogue entry that targets a Swift-specific String trap (mixing `NSString.length`/UTF-16 offsets with `String.count`); no linter has an equivalent.
- Things nobody enforces but that bite on Linux CLIs: Foundation divergence (verified: `import Combine` fails, `URLSession` needs `import FoundationNetworking`), non-atomic `String.write(toFile:atomically: false)`, `exit(1)` with no exit-code contract, `Date()` for timing, unsorted Dictionary iteration into output, `String.Index` offset math.
- Versions drift quickly in this corpus: SwiftFormat flipped `isEmpty`, `preferContains`, `preferFirstWhere`, `preferCountWhere`, `preferMinOverSorted`, `preferFlatMap`, `emptyExtensions` to disabled-by-default in 0.62.1 (2026-07-07) and `redundantSendable` to opt-in in 0.62.0; any pinned config must carry `--swift-version` and a tool version.
- Airbnb's SwiftFormat config sets `--swift-version 6.4` but `--language-mode 5`: the most-cited current guide still formats as if in Swift 5 language mode.

### 4. Airbnb Swift style guide and its enforced config

Note the plugin: `swift package format`, `--lint`, `--swift-version`.

### 5. Google, Kodeco and LinkedIn guides

- [Google Swift Style Guide](https://google.github.io/swift/) (repo `google/swift`, last commit 2018-05-13): column limit 100, K&R braces, 2-space indent; "Compiler Warnings: Code should compile without warnings when feasible"; "Force-unwrapping and force-casting ... a comment should be present that describes the invariant"; IUO only for UI lifecycle; "Naming Conventions Are Not Access Control"; "Trapping vs. Overflowing Arithmetic" (use `+`, avoid `&+` unless required); "Sentinel values are avoided"; "Error Types" via `throws`; nesting over name prefixes; zero occurrences of `async`, `await`, `Sendable`, `MainActor` or "concurren" (no Swift Concurrency guidance). ### 6. The compiler as a rule engine: diagnostic groups and flags

Documented behaviour worth rule-sized attention:
- `StrictMemorySafety` (SE-0458, `-strict-memory-safety`, SwiftPM `.strictMemorySafety()`): flags `@unsafe` functions/types, unsafe pointer use, `unowned(unsafe)`, unsafe storage; acknowledge with `unsafe` expressions, `@unsafe`, or `@safe`. Verified on 6.4: also flags uses of a `nonisolated(unsafe)` variable.
- `StrictLanguageFeatures`: without it, a misspelled name in `-enable-upcoming-feature` or `-enable-experimental-feature` is silently ignored, so a typo'd flag in `Package.swift` does nothing.
- `PerformanceHints` is off by default (`-Wwarning PerformanceHints`): sub-groups `ExistentialType` ("incur heap allocation, reference counting, exclusivity enforcement, and dynamic dispatch overhead"), `ReturnTypeImplicitCopy` (functions returning `Array`/`Dictionary`), `UntypedThrows` ("`any Error` ... heap allocation on each throw"). Verified: fires per `any`/untyped `throws`, noisy on ordinary code.

### 9. Migration guide and vision documents

[swift-migration-guide](https://github.com/swiftlang/swift-migration-guide) (`Guide.docc`: CommonProblems, DataRaceSafety, EnableDataRaceSafety, FeatureMigration, IncrementalAdoption, LibraryEvolution, MigrationStrategy, RuntimeBehavior, SourceCompatibility). Content that is effectively rules: a `swift-tools-version: 6.0` manifest enables Swift 6 mode for all targets; per-target `.swiftLanguageMode(.v5)`; CLI `-Xswiftc -swift-version -Xswiftc 6`; Common Problems enumerates fixes (unsafe global and static variables, protocol conformance isolation mismatch, crossing isolation boundaries, `sending`, non-isolated init/deinit, `@preconcurrency import`); IncrementalAdoption uses `MainActor.assumeIsolated` to recover isolation synchronously; LibraryEvolution says how to add `Sendable`/`@MainActor`/`sending` annotations to a published library without breaking clients; `swift package migrate --to-feature NonisolatedNonsendingByDefault` rewrites `async` functions to `@concurrent` where behaviour would change.

[Approachable concurrency vision](https://github.com/swiftlang/swift-evolution/blob/main/visions/approachable-concurrency.md): three phases (sequential, async without data-race errors, then parallelism); default `@MainActor` for executable targets and UI modules, explicitly not a library default. WWDC25 session 268 "Embracing Swift concurrency" repeats it: start single-threaded, use default main-actor isolation for UI modules, offload with `@concurrent`, `nonisolated` for library APIs, introduce actors only when main-actor contention shows in Instruments. Other vision documents in the repo: `memory-safety.md`, `swift-testing.md`, `macros.md`, `embedded-swift.md`, `webassembly.md`, `networking.md`.

## Contested

- Default `@MainActor` isolation (SE-0466/0478). Vision doc and WWDC25-268 recommend it for app and UI modules; the 2026-07 forum thread "Contemplating Default Isolation Control" argues it is a "false simplification", that it breaks libraries designed as nonisolated by default, that MainActor is not the main thread off Apple platforms, and that isolation then depends on settings outside the code. Others report it works for app and package code. Trend: a per-target app setting, not a library default (H8 plausible); SwiftPM's handling of the setting in tests was reported unreliable (2025-10-06 amendment thread).
- Is `@unchecked Sendable` forbidden or conditionally fine? Airbnb enforces a ban with a mandatory written justification and prefers `@MainActor`, `@preconcurrency import`, restructuring; corpus code uses it heavily (867 uses) mostly for lock- or atomics-guarded types. Trend: toward `Mutex`/actors (SE-0433, 190 `Mutex<` uses) and `sending`, with the unchecked form needing an in-code reason.
- Which formatter. swift-format ships in the toolchain (since 6.0) and 24 of 40 exemplars use it with 4-space overrides; SwiftFormat has more rules and 7 users; SwiftLint is used for lint-only duties in 4 and for custom bans. The guides disagree on indentation (Google/Airbnb/Kodeco 2 spaces; most exemplar repos 4) and line length (100 vs 120 vs Airbnb's soft 100 / hard 130). No convergence.
- Force-unwrap policy. Google: allowed with an invariant comment, free in tests; swift-format: `NeverForceUnwrap` off by default and on in 4 repos; Airbnb: avoid in tests too, `#URL` macro; SwiftLint: `force_try`/`force_cast` on, `force_unwrapping` opt-in. Corpus: 10k `!`-shaped uses in swift-syntax-heavy code. Trend: macros and `#require` replace `!`.
- Explicit `any`. `ExistentialAny` is tagged `future` (no longer "Swift 7"), 15/38 manifests enable it, but `PerformanceHints::ExistentialType` warns on `any` use, so the compiler both demands and discourages it; the practical answer depends on API surface versus hot path.
- Swift Testing vs XCTest. Tools and Airbnb push Swift Testing; SwiftLint has no support; XCTest persists for UI/performance tests and in older repos (141 vs 344 imports; element-x and Tuist mix).
- `explicit_acl` / `explicit_top_level_acl` style versus Google's "omitting an explicit access level is permitted": SwiftLint's opt-ins flag 876+ declarations in swift-async-algorithms for code its maintainers consider correct.
- Whether warnings-as-errors belongs in a library's own manifest. swift-aws-lambda-runtime sets `.treatAllWarnings(as: .error)` unconditionally (`Package.swift:7`); swift-testing gates to development builds because SwiftPM suppresses dependency warnings and rdar-tracked behaviour (`Package.swift:436`); the safer pattern is CI-only `-Xswiftc -warnings-as-errors` (swift-nio).
