## Summary

- **Release cadence is two-a-year with a third line in flight.** 6.0 (2024-09-17), 6.1 (2025-03-31), 6.2 (2025-09-15), 6.3 (2026-03-24), 6.4 (2026-09-14, blog dated 2026-09-15); "Swift next" is already 6.5 (ST-0026 and SwiftPM 6.5 notes say "Swift 6.5"). Source: `releases.json`, blog posts, evolution Status lines.
- **Swift Build is the default SwiftPM engine in 6.4.** `swift build --help` on the swift:6.4 image prints `--build-system` default `swiftbuild`, with `native` and `xcode` both labeled "(deprecated)"; fallback is `--build-system native`; output goes to a different bin path (`swift build --show-bin-path`), one test runner per test target, `--static-swift-stdlib` is now an error where unsupported. Measured.
- **The approachable-concurrency story is now a bundle plus a default-isolation switch, and they are independent.** `ApproachableConcurrency` is a pseudo upcoming feature expanding to `DisableOutwardActorInference`, `GlobalActorIsolatedTypesUsability`, `InferIsolatedConformances`, `InferSendableFromCaptures`, `NonisolatedNonsendingByDefault` (compiler source + Xcode setting docs agree). `defaultIsolation(MainActor.self)` / `SWIFT_DEFAULT_ACTOR_ISOLATION` is separate and app-oriented.
- **`swift package init` in 6.4 writes `// swift-tools-version: 6.4` and `.enableUpcomingFeature("ApproachableConcurrency")` into every target, library and test targets included, and no `swiftLanguageModes`.** The 6.3 template wrote `swiftLanguageModes: [.v6]` and no upcoming features. Neither template enables default MainActor isolation. Measured on both images.
- **Warning control became a three-layer system.** Command line `-Werror <Group>` / `-Wwarning <Group>` (SE-0443, 6.1), manifest `.treatWarning(_:as:)` / `.treatAllWarnings(as:)` (SE-0480, 6.2), and source-level `@diagnose(Group, as: error|warning|ignored, reason:)` (SE-0522, 6.4; it was pitched as `@warn`). `@diagnose(DeprecatedDeclaration, as: ignored)` verified to silence a single declaration.
- **Concurrency escape hatches got first-class replacements.** `weak let` (SE-0481, 6.3) lets a class with a weak reference stay checked `Sendable` (compiled clean on 6.4); `~Sendable` (SE-0518, 6.4); `Mutex`/`Atomic` (Synchronization, 6.0); isolated conformances (SE-0470, 6.2); `isolated deinit` (SE-0371, 6.2); `sending` (SE-0430, 6.0). An agent trained on 2023-24 still reaches for `@unchecked Sendable` and `nonisolated(unsafe)`.
- **A new diagnostic fires on a classic agent mistake.** `Task { try work() }` with the task and its error discarded now warns `NoUseUnstructuredThrowingTask` (SE-0520, 6.4); reproduced. `Task.init` throwing overloads now use typed throws.
- **Async cleanup is now expressible.** `await` in `defer` (SE-0493, 6.4) plus `withTaskCancellationShield` (SE-0504, 6.4); `withDeadline(in:)` (SE-0526) is accepted but only in the CHANGELOG "Swift (next)" section, not in 6.4.
- **Swift Testing is the default test library and now interoperates with XCTest.** `swift package init` generates `import Testing` tests; ST-0021 (6.4) makes `XCTAssert` inside `@Test` and `#expect` inside XCTest report; Xcode 27 reports cross-framework failures as warnings by default; `swift test --repeat-until pass|fail --maximum-repetitions N` (ST-0024, 6.4); `Test.cancel()` and `Issue.record(severity: .warning)` (6.3); exit tests and attachments (6.2).
- **`Subprocess` reached 1.0** (swift-subprocess 1.0.0, 2026-08-04; 1.0.1 on 2026-10-09; requires swift-tools-version 6.2). Output limits are now explicit (`.string(limit:)`), `Executable.name` searches `PATH` only, `runDetached` was removed, only `SubprocessError` is thrown. `Foundation.Process` is the 2023-24 answer; Subprocess is the 2026 one.
- **Paths are in flux.** SE-0529 (`FilePath` into the stdlib) and SE-0513 (`CommandLine.executablePath`) are accepted, but a build on swift:6.4 fails with `cannot find 'FilePath' in scope` and `type 'CommandLine' has no member 'executablePath'`, while the WWDC26 talk says FilePath "was added". Treat `import System` (swift-system 1.8.x) as the working answer until a release confirms.
- **Platform reach widened and is official.** Static Linux SDK (6.0, musl, `swift sdk install <url> --checksum`), Wasm SDK on swift.org (6.2 and in `releases.json` for 6.2-6.4), Android SDK official in 6.3 and still listed in 6.4.0 (NDK r30), Windows via `winget install --id Swift.Toolchain` with an ARM64 installer, FreeBSD preview. The frame's "6.4.0 dropped the Android SDK" is false: `releases.json` lists `android-sdk` for 6.4.0.
- **Tool versions moved in lockstep with the toolchain.** swift-format 604.0.0 and swift-syntax 604.0.0 (2026-09-15/16), SwiftLint 0.65.1 (Windows build since 0.64.0, Bazel 7-9), SwiftFormat 0.63.1 (adds `--locale`, `ifExpressions`), swiftly 1.2.0 (Ubuntu 26.04, Debian 13). `swift format --version` on the swift:6.4 image printed `main`, not a number.
- **Real adopters have already moved to upcoming features.** Across 40 exemplar `Package.swift` files, `MemberImportVisibility` appears in 19, `ExistentialAny` 15, `InternalImportsByDefault` 11, `NonisolatedNonsendingByDefault` 7, `InferIsolatedConformances` 7; five roots declare `swift-tools-version: 6.4`. Zero root manifests set `defaultIsolation` (root-only scan, apps excluded).
- **Server stack is replatforming on structured concurrency.** Vapor 5 beta (2026-09-15) drops `EventLoopFuture`, requires Swift 6.4, is built on the new `swift-http-server`, `swift-configuration` (1.0 on 2025-12-11), `Span`, and enables `InternalImportsByDefault`, `NonisolatedNonsendingByDefault`, `.strictMemorySafety()`. A Networking workgroup was formed 2026-06-04.
- **Build-system maintainers have a concrete migration.** `-debug-module-path` replaces `-modulewrap` (Linux/Windows) and `-add_ast_path` (Darwin) in 6.4; relevant to the Bazel depth file (rules_swift 4.2.1 targets Bazel 8/9).
- **Memory-ownership vocabulary exploded and agents will over-apply it.** `Span`, `InlineArray`, `UniqueBox`, `UniqueArray`, `Ref`/`MutableRef`, `Iterable`, `borrow`/`mutate` accessors, `~Copyable` associated types: all 6.2-6.4. Opt-in `-strict-memory-safety` (6.2) and `@unsafe(always)` give the review hook.

## Contested

- **Is `FilePath` in the stdlib or not?** WWDC26 session 262 says "This year, we added a new filepath type to the standard library"; SE-0529 is "Accepted with modifications"; a swift:6.4 build fails with `cannot find 'FilePath' in scope`. Trend: stdlib `FilePath` arrives in 6.5; until then `import System`. Rule text should say "verify with a build", not assert either.
- **Should libraries enable the approachable-concurrency bundle?** The 6.4 `init` template says yes for every target (including libraries); WWDC25 recommends default MainActor only for app and UI modules; swift-log, swift-aws-lambda-runtime, swift-dependencies, vapor, sourcekit-lsp enable `NonisolatedNonsendingByDefault` in libraries while swift-nio, swift-system, swift-crypto and async-http-client do not. Trend: toward enabling, because the feature changes semantics for clients less than default isolation; default MainActor stays app-only.
- **Language mode 6 vs 5 for libraries.** Alamofire declares tools 6.4 with `swiftLanguageModes: [.v5]`; swift-collections pins one target `.v5`; TCA and swiftlang/swift-build mix `.v5`/`.v6`. Trend: 6 mode for new code, `.v5` only per-target during migration (frame floor Q2).
- **Formatter choice.** swift-format is bundled and used by swiftlang repos (`.swift-format` in swiftlang/swift-format); SwiftFormat 0.63 and SwiftLint 0.65 are actively released and now cross-platform. Defaults diverge (swift-format default: 2-space indent, `NeverForceUnwrap` off; SwiftFormat flips defaults between minors). No convergence; the map should pick by gate, not by taste (Q4).
- **XCTest vs Swift Testing interop default.** Xcode 26.4 turned XCTest/Swift Testing interop off by default (`SWIFT_TESTING_XCTEST_INTEROP_MODE=limited` to enable); Xcode 27 reports cross-framework failures as warning-severity issues by default; swift.org says 6.4 makes it safe. Trend: on by default as warnings; promote to failures once migrated.
- **Swift Build default vs known issues.** 6.4 makes it default and calls native and xcode "(deprecated)", yet release notes list SDK-generator Linux SDK failures and swift-java plugin failures. Trend: native is a short-lived fallback; rule must name `--build-system native` as an escape hatch with an issue link.
- **`@warn` vs `@diagnose`.** March 2026 digest called SE-0522's attribute `@warn`; shipped as `@diagnose` (CHANGELOG 6.4; the experimental feature was `SourceWarningControl`). Source of confusion for any 2026 pre-release blog or model memory.
- **Combine.** No official deprecation found (secondary web sources only; Apple documentation not reachable). Swift.org and WWDC material never mention Combine; Observation and async sequences are the direction. Treat "Combine is deprecated" as unverified.
- **Android SDK in 6.4.** The brief's hypothesis that 6.4.0 dropped it is contradicted by `releases.json` and the 6.4.0 Android getting-started article.

## Frame corrections and hypothesis evidence

- **Frame line 55-56 (Android dropped in 6.4.0): false.** `releases.json` 6.4.0 lists `android-sdk:Android SDK`; the getting-started article installs `swift-6.4.0-RELEASE_android.artifactbundle.tar.gz` with NDK r30. Likely an API artifact in the frame's earlier read.
- **H1 (most active exemplars are in 6 mode):** partly supported. 5 of 38 root manifests are tools 6.4, 2 are 6.3, 13 are 6.2; but Alamofire (tools 6.4) and several others still declare `.v5` modes. Not rejected; refine to "tools 6.x, language mode per target".
- **H2:** `@unchecked Sendable` 1131 hits in 37 of 40 repos; `Mutex` 448 in 16 (fixtures inflate both). Direction holds. New: 6.3 `weak let` and 6.4 `~Sendable` remove two reasons for the escape hatch.
- **H3:** `import Testing` 2754 (36 repos) vs `import XCTest` 2383 (30). Swift Testing already leads in raw count; fixtures inflate. Holds directionally.
- **H4/H5/H6:** not measured by this corpus beyond the swift-format default config and Package.resolved not examined.
- **H7:** supported and extended: `NoUseUnstructuredThrowingTask` and `UntypedThrows` diagnostics exist because the pattern is common.
- **H8:** supported. 6.4 `init` templates do not set `defaultIsolation`; zero exemplar roots do; WWDC25 scopes it to app modules.
- **New hypothesis:** Swift 6 mode is not the end state: six upcoming features are `LanguageMode::future`. A "Swift 7 / future mode" will bundle them; rules should recommend them individually.
