## Summary

- Matt Massicotte, the most-cited concurrency practitioner, says an actor is justified only when three things hold: non-Sendable state, atomic operations over it, and no existing actor (often MainActor) that can host it; "It is always a mistake to introduce an actor as a means of addressing a concurrency diagnostic you do not understand" ([actors](https://massicotte.org/actors/), updated 2026-05-27).
- The same author recommends against `defaultIsolation(MainActor.self)` / `SWIFT_DEFAULT_ACTOR_ISOLATION` ("We should not. I'm not sure we should even have the ability to do so", 2025-11-20), while Donny Wals recommends it for app targets and not necessarily for packages, and the Swift 6.2 vision document says executables suit it and libraries should stay `nonisolated`. This is the biggest live disagreement in the corpus.
- The "settings" literature has converged: Swift has 21 upcoming features as of 6.2; the ones with real consequences are `NonisolatedNonsendingByDefault`, `InferIsolatedConformances`, `DynamicActorIsolation`, `GlobalConcurrency`, `StrictConcurrency` and `DefaultActorIsolation`; the 12 other Swift-6-mode flags are safe to just turn on ([what-settings](https://massicotte.org/blog/what-settings/)).
- `NonisolatedNonsendingByDefault` ("Approachable Concurrency", SE-0461, Swift 6.2) is called the most important 6.2 change by Massicotte, and it flips the meaning of `nonisolated async`: it now runs on the caller's actor and `@concurrent` is the explicit opt-out. Any agent memory of "`nonisolated async` means background" is stale.
- Massicotte's late-2025/2026 design position is "Non-Sendable First Design": plain nonisolated classes, owned by one actor, with no `Sendable` conformance, are simpler and more general than actors or `@MainActor` types; the Swift Group Lab panel at WWDC 2026 reportedly discussed the same idea.
- Escape-hatch policy in practice: the official migration guide permits `@unchecked Sendable` for types that already synchronize manually, and says "if a type isn't already thread-safe, attempting to make it `Sendable` should not be your first approach"; the AvdLee agent skill requires "a documented safety invariant and a follow-up removal plan" for `@preconcurrency`, `@unchecked Sendable` and `nonisolated(unsafe)`.
- Typed throws: SE-0413's own text says untyped `throws` stays "the better default" and allows typed throws in exactly three circumstances (module-internal, generic pass-through, constrained/Embedded); its `loadBytes(from:) throws(FileSystemError)` example is labelled "should use untyped throws".
- Swift 6.4 (2026-09-14/15) makes Swift Build the default SwiftPM build system; `--build-system native` is the fallback, `--static-swift-stdlib` now errors on unsupported platforms, and Swift Build "fails to build projects with Linux SDKs generated by the SDK generator" (SwiftPM 6.4 release notes).
- Measured on the 6.4 toolchain: `swift package init` now writes `// swift-tools-version: 6.4`, adds `.enableUpcomingFeature("ApproachableConcurrency")` to both the library and test targets, and generates a Swift Testing test; `ApproachableConcurrency` is accepted as an upcoming-feature name by both 6.3.3 and 6.4. Wals's 2025 claim that a new package has no Approachable Concurrency is stale.
- `defaultSwiftSettings:` (SE-0540, "Accepted with modifications") does not exist in the 6.4 `PackageDescription`: measured error "extra argument 'defaultSwiftSettings' in call". Advice to "use package-level default settings" is next-release material.
- Testing: Swift 6.4 adds XCTest/Swift Testing interoperability with four modes (`none`, `limited`, `complete`, `strict`) selected by `SWIFT_TESTING_XCTEST_INTEROP_MODE`, whose default depends on both toolchain and `swift-tools-version` (<6.4 tools with a 6.4 toolchain: `limited`; >=6.4: `complete`).
- Agent-written async tests lean on `Task.sleep`; raska.io (2026-09-21) says even the newest models do this unless shown spies, and Massicotte and Point-Free both publish deterministic alternatives (event streams, controlled executors, task-local test traits).
- Matt Gallagher (Cocoa with Love, 2025-12-29) found LLMs "adding #availability checks for iOS 13, zero knowledge of async/await ... no idea what Swift 6 is" and Float/Double conversion errors; Nil Coalescing argues that deterministic structural checks (SwiftFairy) beat prose rules because "agents regularly miss rules stated in their instructions and skills". That is a design signal for this program: prefer greppable verification commands.
- Versioned manifests (`Package@swift-6.0.swift`) are called a mistake when they differ only in tools version ("zero benefit", "variants of your package that behave differently depending on compiler version", Massicotte 2025-12-29), yet Point-Free and others use traits to stage migrations; SwiftPM traits (SE-0450, 6.1) reached Xcode in 26.4 and are now the preferred way to avoid transitive dependencies.
- Diagnostics control moved to source level in 6.4: `@diagnose(DeprecatedDeclaration, as: warning, reason: "...")` (SE-0522) replaces Squires's protocol-based deprecation workarounds; group-level flags are `-Werror <Group>` / `-Wwarning <Group>` (SE-0443, 6.1) and SwiftPM `.treatWarning(_:as:)` / `.treatAllWarnings(as:)` (SE-0480, 6.2).
- Several 6.4 diagnostics target exactly the things agents and humans silently get wrong: an unused throwing `Task { }` (group `NoUseUnstructuredThrowingTask`, SE-0520) and a nested-closure `weak` capture whose outer closure still captures strongly (warning text "'weak' ownership of capture 'self' differs from implicitly-captured strong reference in outer scope").
- The server story has consolidated around structured concurrency: swift-service-lifecycle `ServiceGroup` with `gracefulShutdownSignals`, Swift HTTP Server, Vapor 5 beta (2026-09-15) "fully async/await" with `InternalImportsByDefault`, `NonisolatedNonsendingByDefault` and `.strictMemorySafety()` enabled and a Swift 6.4 floor.
- Boring but biting topics have almost no practitioner coverage in this corpus (atomic writes, signal handling, exit codes, locale, ABI): the corpus is strong on concurrency and settings, thin on I/O, and any rule for those must be grounded in exemplar code and proposals rather than blog posts.

## Survey

### 1. Matt Massicotte — concurrency, isolation, settings

The most systematic practitioner. Blog index read in full: [massicotte.org/blog](https://www.massicotte.org/blog) (latest entry 2026-10-05). Posts read:

1. [Problematic Swift Concurrency Patterns](https://www.massicotte.org/problematic-patterns) (2024-10-29, updated 2026-04-27). List of patterns that "often don't work out": "split isolation" (a class with both nonisolated and `@MainActor` members), `Task.detached` (does not inherit priority or task-local values; prefer an `@concurrent` function), explicit task priorities (comment why), `MainActor.run` ("rarely the right solution"), stateless actors, `@preconcurrency import` used to wrap completion-handler APIs with async extensions, redundant `Sendable` on global-actor types, `@MainActor @Sendable` closures (SE-0434 made plain `@MainActor () -> Void` Sendable; the pair is only needed for Swift 5/Xcode 15), RunLoop APIs, actors conforming to protocols with synchronous requirements, ObjC-to-async translations, blocking with `DispatchSemaphore`/`DispatchGroup` ("eventually going to deadlock"), too much code inside closures, unstructured when structured works, and avoiding non-Sendable types. Flags testing and `AsyncSequence` as areas where he lacks answers.
2. [When should you use an actor?](https://massicotte.org/actors/) (2025-09-06, updated 2026-05-27). Three conditions (non-Sendable state; atomic mutation; cannot live on an existing actor). Think of an actor as a "remote network service". A "network client" actor with zero non-Sendable state "does not make sense": a `MainActor` type with `async let` or `@concurrent` functions is "simpler, more flexible, and ... performs better". Proposes a joke-that-isn't: every actor needs a comment "this is an actor because..." that is not "it helps deal with concurrency errors". A `Sendable`-requiring protocol can itself push you to an actor.
3. [MainActor by Default](https://massicotte.org/blog/mainactor-by-default) (2025-11-20). Default `MainActor` is a "long-term mode" that "will remain optional", enabled for new Xcode 26 app targets; he recommends against it because exiting it needs deep understanding, "particularly when type hierarchies with protocols are involved".
4. [What Setting Should I Use?](https://massicotte.org/blog/what-settings/) (2025-12-05, updated 2026-05-13). Names: `ExistentialAny`, `InternalImportsByDefault`, `MemberImportVisibility` (ignore for now); `InferIsolatedConformances` ("about 75% sure"), `NonisolatedNonsendingByDefault` (adopt; "the only setting of consequence" in Approachable Concurrency); the 12 safe 6-mode flags (`BareSlashRegexLiterals`, `ConciseMagicFile`, `DeprecateApplicationMain`, `ForwardTrailingClosures`, `ImplicitOpenExistentials`, `ImportObjcForwardDeclarations`, `NonfrozenEnumExhaustivity`, `DisableOutwardActorInference`, `GlobalActorIsolatedTypesUsability`, `InferSendableFromCaptures`, `RegionBasedIsolation`, `IsolatedDefaultValues`); and the "cannot just turn on" trio `GlobalConcurrency`, `DynamicActorIsolation` (turns data races into runtime crashes), `StrictConcurrency` (6 mode = `complete`; he values `targeted`). `DefaultActorIsolation` is not an upcoming feature, in Xcode is `SWIFT_DEFAULT_ACTOR_ISOLATION`, in SwiftPM `.defaultIsolation`, and implicitly enables `InferIsolatedConformances`. 6 mode differs from 5 mode with all features on only in concurrency warnings becoming errors. Mentions Keith Harrison's `useyourloaf.com` technique for per-package settings.
5. [Non-Sendable First Design](https://massicotte.org/blog/non-sendable-first-design) (2025-12-17). Non-Sendable types are "the way" once `NonisolatedNonsendingByDefault` removes the catch-22 of `nonisolated async` on a type that cannot leave its actor; strengths: simplicity, generality (synchronous access from any owning actor, ordinary `Equatable`); weakness: starting `Task`s from inside (needs `isolated` parameters or `sending`).
6. [Revisiting "Split Isolation"](https://massicotte.org/blog/revisiting-split-isolation/) (2026-10-05). Still "something to avoid" but acknowledges valid uses: secondary functionality, a single `@MainActor init(controller:)`, and containing the spread during a migration ("mark just the offending function"). "Isolation is about protecting data, not controlling where things execute."
7. [Stateless Actors](https://massicotte.org/stateless-actors/) (2026-05-29). Softens the 2024 position: a stateless actor "can also make sense" (it keeps work off MainActor); blocked threads in the pool are "usually not an important detail"; "GCD is still here and you should not be afraid to use it"; "the first rule of actors": articulate why.
8. [Singletons with Swift Concurrency](https://massicotte.org/singletons/) (2025-10-19). `static let shared` of a class is global non-Sendable state; options: composition root ("passing arguments to functions"), `@unchecked Sendable` when a lock/queue already protects state ("asserting" vs "hoping"), `@MainActor` ("the correct solution for the majority of singletons"), `Mutex` (SE-0433, `Synchronization`; "makes it possible for a class that uses it to be checked Sendable"; availability workaround: copy the stdlib source) and `OSAllocatedUnfairLock`.
9. [Versioned Package.swift Files](https://massicotte.org/blog/package-swift/) (2025-12-29). "a package that uses tools '6.x' is compatible with the Swift 5 language mode"; versioned manifests used only to change tools version have "at best, zero benefit"; get settings right in one unversioned manifest.
10. [Package Traits in Xcode](https://massicotte.org/blog/package-traits-in-xcode/) (2026-03-27). Xcode 26.4 supports SE-0450 traits (SwiftPM 6.1); example `FancyStructures` trait with `.product(name:package:condition: .when(traits:))` and `#if FancyStructures`.
11. [(Some) Unanswered Swift Group Questions](https://massicotte.org/blog/wwdc26-unanswered-qa/) (2026-06-10). New Xcode 27 projects default to Swift 5 language mode (his guess: parts of Apple's SDK are hard in 6 mode); turning on 6 mode surprises people with crashes from dynamic actor isolation; `@preconcurrency import` means "missing annotations, but I'm using it correctly" and he prefers targeted `nonisolated(unsafe)`; "The only functions that are guaranteed to not end up on a background thread are those marked @MainActor"; with default MainActor, data-layer models must be marked `nonisolated` or moved to a nonisolated module.
12. [Swift Compiler Changes the Easy Way](https://massicotte.org/blog/compiler-changes-the-easy-way/) (2026-01-13). Errors in an unstructured `Task { try await ... }` vanish because `Task` creation is `@discardableResult`; he pitched non-discardable throwing tasks; Konrad Malawski's SE-0520 (Implemented 6.4) delivers the warning, documented as group `NoUseUnstructuredThrowingTask`. Massicotte notes a typed-throws-in-`Task` change needed no proposal.
13. [Testing with Event Streams](https://massicotte.org/blog/testing-event-stream/) (2026-02-18). `confirmation` in Swift Testing nests badly and cannot assert ordering; use `AsyncStream<String>.makeStream()` plus an `AsyncSequence` helper to assert order.
14. [Dependencies as a Package Author](https://massicotte.org/package-author-dependencies/) (2023-06-29, evergreen). 42 maintained packages; a closure parameter (`(String) -> Bool`) beats a protocol for breaking transitive dependencies; "People just don't like dependencies."
15. [Concurrency Step-by-Step: Designing Protocols](https://massicotte.org/step-by-step-designing-protocols/) (2026-04-26) and [Protocols and Global Actors](https://massicotte.org/blog/protocols-and-global-actors/) (2026-08-03). Three settings (`NonisolatedNonsendingByDefault`, `InferIsolatedConformances`, `DefaultActorIsolation`) "can have profound and subtle effects on protocol use"; a `Sendable`-requiring protocol "makes the API producer's life easier in exchange for making the API consumer's life more complex".
16. [Should You Enable Swift's Complete Concurrency Checking?](https://massicotte.org/complete-checking/) (2024-02-14): "You turn on complete checking to learn how Swift concurrency actually works"; leaving checks at `minimal` while writing `async` is risky.
17. [ConcurrencyRecipes](https://raw.githubusercontent.com/mattmassicotte/ConcurrencyRecipes/main/README.md): warns it is not updated for Swift 6.0 and the author's opinions changed; useful for its hazard vocabulary (Timing, Ordering, Lack of Caller Control, Sendability, Blocking, Availability, Async virality, Actor Reentrancy). Do not mine its recipes for Swift 6 era rules.

### 2. Core-team documents: vision, proposals, release posts

- [Approachable concurrency vision](https://raw.githubusercontent.com/swiftlang/swift-evolution/main/visions/approachable-concurrency.md). Endorsed by the Language Steering Group. Three-phase progressive disclosure; modules may default to "single-threaded"/MainActor: "Executable targets tend to center around the main actor. Command-line tools and scripts all start on the main actor"; "The same argument does not apply to libraries ... It would be reasonable for library targets to default to `nonisolated`". Names the risk: "Adding a per-module setting ... would introduce a new permanent language dialect" (readability, tooling). Also covers isolated conformances, isolated subclasses, "Mitigating runtime assertions due to isolation mismatches". Other visions listed in `visions/`: `memory-safety.md` ("Optional Strict Memory Safety for Swift"; headings and intro read), `macros.md`, `swift-testing.md`, `networking.md`, `embedded-swift.md`, `webassembly.md`, `using-c++-from-swift.md`, `using-swift-from-c++.md`.
- [SE-0413 Typed throws](https://raw.githubusercontent.com/swiftlang/swift-evolution/main/proposals/0413-typed-throws.md), section "When to use typed throws": three circumstances; "Resist the temptation to use typed throws because there is only a single kind of error"; says the section "will be added to the Swift API Design Guidelines".
- [SE-0518 `~Sendable`](https://raw.githubusercontent.com/swiftlang/swift-evolution/main/proposals/0518-tilde-sendable.md) (Implemented 6.4, experimental flag `TildeSendable`; measured: rejected as an upcoming feature name in 6.3.3 and 6.4). Motivation: for a public type without `Sendable` "it's difficult to determine the intent". [Review thread](https://forums.swift.org/t/se-0518-sendable-for-explicitly-marking-non-sendable-types/85132) (read via WebFetch): Jeremy Schonfeld wants `-require-explicit-sendable` in Foundation; accepted 2026-03-17.
- [SE-0504 Task Cancellation Shields](https://raw.githubusercontent.com/swiftlang/swift-evolution/main/proposals/0504-task-cancellation-shields.md) (6.4, `withTaskCancellationShield`) paired with [SE-0493 async `defer`](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0493-defer-async.md) (6.4); [SE-0526 `withDeadline`](https://raw.githubusercontent.com/swiftlang/swift-evolution/main/proposals/0526-deadline.md) (Accepted with modifications after three reviews; takes a continuous-clock instant); [SE-0529 `FilePath` in the stdlib](https://raw.githubusercontent.com/swiftlang/swift-evolution/main/proposals/0529-filepath-in-stdlib.md) (Accepted with modifications; "String is a poor fit for paths", stores native platform encoding, `FilePath.Anchor` for drive letters); [SE-0513 `CommandLine.executablePath`](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0513-commandline-executablepath.md) (Accepted).

- [SE-0540 Default Target Settings](https://raw.githubusercontent.com/swiftlang/swift-evolution/main/proposals/0540-default-target-settings.md) by Massicotte: `defaultSwiftSettings:` on `Package` plus a `defaults` placeholder; its text says the Swift 6.4 `swift package init` template repeats `.enableUpcomingFeature("ApproachableConcurrency")` per target (measured true). ### 3. Donny Wals

[Should you opt-in to Swift 6.2's Main Actor isolation?](https://www.donnywals.com/should-you-opt-in-to-swift-6-2s-main-actor-isolation/) (2025-09-11). Xcode 26 app targets: `Global actor isolation = MainActor.self` plus Approachable Concurrency; for SPM, "a newly created SPM Package will not have its defaultIsolation flag set" and had no Approachable Concurrency (stale for 6.4, measured). Recommends MainActor-by-default for app targets, `@concurrent` for background, `nonisolated` rarely; networking packages should not default to MainActor, UI packages should. [What is Approachable Concurrency in Xcode 26?](https://www.donnywals.com/what-is-approachable-concurrency-in-xcode-26/) was fetched but not read in depth and the search-surfaced quote that the 6.2 changes feel like an admission "nobody is actually going to do that" (secondary, via Michael Tsai, not fetched).

### 4. Antoine van der Lee (SwiftLee) and agent-skill prior art

The SwiftLee article index ([avanderlee.com/swift](https://www.avanderlee.com/swift/)) was read: 2026-08 articles on `Sendable`/`@Sendable`, `@MainActor`, `defer`. His [Swift Concurrency Agent Skill](https://raw.githubusercontent.com/AvdLee/Swift-Concurrency-Agent-Skill/main/skills/swift-concurrency/SKILL.md) is the closest prior art to this program. It begins with "Analyze `Package.swift` or `.pbxproj` to determine Swift language mode, strict concurrency level, default isolation, and upcoming features", states `swift-tools-version` "is not a reliable proxy" for language mode, tabulates SwiftPM spellings (`.enableExperimentalFeature("StrictConcurrency=targeted")`, `.defaultIsolation(MainActor.self)`, `.enableUpcomingFeature("NonisolatedNonsendingByDefault")`) and claims "Approachable Concurrency: N/A (use individual upcoming features)" for SwiftPM (contradicted by measurement: `ApproachableConcurrency` is accepted in 6.3.3 and 6.4 and is what the 6.4 template writes). Guardrails: no blanket `@MainActor`, prefer structured concurrency, document invariants for escape hatches, smallest safe change; maps diagnostics to fixes and cites SwiftLint `async_without_await` ("Never add fake awaits").

## Recent shifts seen in this corpus

Window: Swift 6.0 (Sept 2024) to 6.4 (Sept 2026); Xcode 16 to 27.

- **`nonisolated async` semantics (Swift 6.2, 2025-09; SE-0461, `-enable-upcoming-feature NonisolatedNonsendingByDefault`)**: runs on the caller's actor; `@concurrent` opts out. Invalidates the 2021-2025 rule "nonisolated async leaves the actor" and the standard `Task.detached`-to-get-off-main recipe. Massicotte now prefers `@concurrent` functions.
- **Default isolation (6.2, SE-0466)**: `.defaultIsolation(MainActor.self)` / `SWIFT_DEFAULT_ACTOR_ISOLATION`, on by default in new Xcode 26 app targets but not in packages (Wals, 2025-09). Invalidates "everything unannotated is nonisolated". Disputed (see Contested).
- **Swift 6.4 `swift package init` template (measured)**: tools 6.4, `ApproachableConcurrency` on all targets, Swift Testing sample. Invalidates 2025 blog statements that new packages lack Approachable Concurrency and AvdLee's "N/A for SwiftPM" table cell.
- **Swift Build default in SwiftPM (6.4, 2026-09)**: preview in 6.3 (`--build-system swiftbuild`), default in 6.4; `--build-system native` is the escape. Invalidates scripts that assume `.build/<triple>/<config>` (use `swift build --show-bin-path`) and silent acceptance of `--static-swift-stdlib`.
- **Source-level warning control (6.4, SE-0522 `@diagnose`)** after group flags (6.1, SE-0443) and SwiftPM warning settings (6.2, SE-0480). Invalidates protocol-based deprecation-silencing hacks (Squires, 2025-10).
- **Swift Testing maturity**: test scoping traits (6.1, 2025-04), `Issue.record(severity: .warning)` and `Test.cancel()` and image attachments (6.3), XCTest interop with four modes and `--repeat-until` (6.4). Invalidates "do not mix XCTest and Swift Testing assertions".
- **Throwing unstructured tasks are no longer silently discardable (6.4, SE-0520)**; the group `NoUseUnstructuredThrowingTask` replaces reliance on SwiftLint `unhandled_throwing_task`.
- **Cancellation tools (6.4)**: async `defer` (SE-0493) and `withTaskCancellationShield` (SE-0504); `withDeadline` (SE-0526) is accepted, not yet implemented. Invalidates ad-hoc "check `Task.isCancelled` in cleanup" patterns.
- **Observation (6.2/6.4)**: `Observations` AsyncSequence (SE-0475) and advanced tracking (SE-0506) answer Sinclair's 2025-09 complaint that `@Observable` only partially replaces `ObservableObject`; `MemberImportVisibility` default in new Xcode templates makes `ObservableObject` need `import Combine`.
- **Foundation on Linux/Windows (6.0, 2024-07 announcement)**: swift-foundation is the implementation behind `import Foundation`; 6.4 adds FileManager improvements on WASI. Invalidates the old corelibs-only mental model; `FoundationEssentials` for size.
- **Android SDK official (6.3, 2026-03-24), updated with NDK r30 in 6.4**: answers the frame's open question from the release posts: the 6.4 post describes the Android SDK built with NDK r30 and Swift Build support for Android, so it was not dropped; why `releases.json` omitted it is not explained in this corpus (reading only, not re-measured).
- **Package traits** (6.1, SE-0450) now in Xcode (26.4, 2026-03) and `swift package show-traits` (6.3). Point-Free's libraries adopted them in 2026-06; guidance moves from "avoid dependencies" to "gate them behind traits".
- **Prebuilt swift-syntax** (6.1.1 flag, 2025-05; shared macro libraries in 6.3): old advice "macros cost minutes of CI" now depends on prebuilt coverage and the package URL (`swiftlang/swift-syntax`).
- **Nonexhaustive enums for non-resilient libraries (SE-0487, 6.2.3)**: new in 6.2.3, so public-enum advice from earlier toolchains (every public enum is effectively frozen) is outdated for non-resilient packages.
- **Xcode 27 default language mode is still Swift 5** (Massicotte, 2026-06-10) while `swift package init` writes tools 6.4 (Swift 6 mode): app and package defaults diverge.
- **Server**: Vapor 5 beta (2026-09-15) removes `EventLoopFuture`, requires Swift 6.4; Subprocess 1.0 (6.4); Swift HTTP Server and Networking workgroup (2026-06-04).
- **Swift 6.4 type-checker and isolation regressions** hit Point-Free libraries within days of Xcode 27 beta 1; code that built on 6.3 may not build on 6.4.
- **Agent tooling for Swift** appeared 2025-2026 (AvdLee skill, Hudson AGENTS.md and skills, SwiftFairy MCP); Gallagher's Dec 2025 test shows the same stale-API failures H7 lists.

## Contested

- **Default MainActor isolation.** Against: Massicotte ("We should not", "challenging ... even for small projects"). For app targets: Wals ("when you're in doubt isolating to the Main Actor is a good default choice"), Apple's Xcode 26 template. Middle: the vision document (executables yes, libraries `nonisolated`, with "permanent language dialect" risk acknowledged). Trend: Apple's template makes it the app default; library guidance converges on `nonisolated`; Massicotte's 2026 WWDC Q&A still advises caution. Frame hypothesis H8 (apps only, not libraries) is supported by the vision and Wals, not by a measured package default (6.4 template leaves isolation unset).
- **Actors as the default shared-state tool.** Massicotte tightens the criterion (three conditions, justification comment) while softening on stateless actors in 2026. Wals suggests designing a networking object as an actor. Trend: fewer actors, more non-Sendable-first and MainActor types.
- **`@unchecked Sendable` and `nonisolated(unsafe)` as "cheating".** Massicotte: asserting an existing lock is legitimate; many prefer staying in Swift 5 mode. Official migration guide: allowed for manually synchronized types, "not your first approach". AvdLee skill: require invariant plus removal plan. Frame hypothesis H2 (most are avoidable with `Mutex`) is plausible from Massicotte's `Mutex` advice but is not tested here.
- **GCD in new code.** twostraws AGENTS.md: "Never use old-style Grand Central Dispatch". Massicotte (2026-05): "GCD is still here and you should not be afraid to use it" for blocking work. Trend: structured concurrency first, GCD tolerated for blocking C APIs. H7's "GCD in new code is a failure" is only partly supported.
- **Swift 6 language mode for new projects.** Massicotte says Xcode 27 defaults to 5 and warns about runtime crashes from dynamic isolation; the migration guide and Vapor 5 push 6; the 6.4 package template uses tools 6.4. Trend: packages Swift 6, apps lag.
- **Versioned manifests and toolchain support.** Massicotte: avoid unless new manifest API is needed. Ecosystem practice (swift-configuration, Point-Free) loops over targets and uses traits. SE-0540 proposes a package-level default that is not in 6.4.
- **Upcoming features worth adopting.** Massicotte: ignore `ExistentialAny`, `InternalImportsByDefault`, `MemberImportVisibility` for now. Vapor 5 and swift-configuration enable them (and `.strictMemorySafety()`). Trend: new libraries enable all; app code waits.
- **Mocking and dependency injection.** Napier ("Minimize dependency injection. Test real code.") vs Point-Free (Dependencies with task locals and test traits) vs Massicotte (closures over protocols). No resolution; trend is toward fewer abstractions in libraries.
- **Observation vs `ObservableObject`.** Agents' AGENTS.md rules say never `ObservableObject`; Sinclair argued the replacement was incomplete in 2025-09; 6.2/6.4 additions close most of the gap. Trend: `@Observable` default, with the `@MainActor` caveat.
- **Typed throws.** SE-0413 says untyped by default; Embedded Swift and fixed-error libraries use typed. Trend: stays restricted; Vapor 5 and Embedded use it in specific places.
- **Force unwrap policy.** No compiler stance (Xiaodi Wu: warning "a nonstarter"); lint rules are opt-in (SwiftLint `force_unwrapping`) or off by default (swift-format `NeverForceUnwrap`); AGENTS.md says avoid unless unrecoverable. Trend: lint-level policy per project.
- **Architecture (MV vs MVVM vs TCA).** Only search-surfaced skills catalogs and vendor pages; no primary source read. Left open.
- **Whether LLMs can write Swift.** Gallagher's one-shot tests (Dec 2025) found stale APIs; Nil Coalescing and raska.io (Sept 2026) say agents still skip rules and write sleep-based tests, but agentic harnesses do much better. Implies verification commands over prose.
