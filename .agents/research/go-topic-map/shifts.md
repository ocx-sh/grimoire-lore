## Summary

- Go 1.22's per-iteration loop variables (Mar 2024) retroactively invalidate every "capture the loop variable" workaround an LLM trained on pre-2024 code will reach for; `go vet`'s `copylock` analyzer was updated in 1.24 to catch `sync.Locker` copies in 3-clause loops, but the semantic change itself needs no fix — the fix pattern (`x := x`) is now dead code, not a bug shield.
- Iterators are no longer experimental: range-over-func (`iter.Seq`, `iter.Seq2`) shipped non-experimental in Go 1.23 (Aug 2024), and `strings`/`bytes`/`slices`/`maps` all gained `*Seq`-returning iterator functions (`Lines`, `SplitSeq`, `FieldsSeq`, `slices.All`, `maps.Keys`, etc.) across 1.23–1.24 — an agent that hand-rolls a `[]string` return from a splitting helper is emitting pre-1.23 style.
- `go fix` was completely rewritten in Go 1.26 (Feb 2026) as the "modernizers" home (accepted in proposal [golang/go#71859](https://github.com/golang/go/issues/71859), published analyzer catalog in [golang/go#75266](https://github.com/golang/go/issues/75266)); the old `cmd/fix` was gutted to no-ops in the same cycle ([golang/go#73605](https://github.com/golang/go/issues/73605)). `go fix` is now a legitimate CI/pre-commit step, not just a migration one-off.
- golangci-lint v2 (the "2.x" line, current 2.14.0 released 2026-09-24) is a hard config-format break from v1: mandatory `version: "2"` key, `gofmt`/`gofumpt`/`goimports`/`gci` moved out of `linters` into a new `formatters` section, `gosimple`+`stylecheck` merged into `staticcheck`, 13 deprecated linters deleted outright (`deadcode`, `structcheck`, `varcheck`, `golint`, `interfacer`, `maligned`, `scopelint`, `ifshort`, `nosnakecase`, `execinquery`, `exhaustivestruct`, `exportloopref`, `tenv`), and `linters.presets` removed in favor of listing linters directly. Any `.golangci.yml` an LLM emits from pre-2025 training data will not parse under a v2 install.
- staticcheck absorbing `gosimple`/`stylecheck` (a golangci-lint-side config change, not a staticcheck-side one) means a `linters: enable: [gosimple, staticcheck, stylecheck]` block from an older tutorial now double-declares one linter under v2.
- `errors.AsType` (generic form of `errors.As`) and the `new(expr)` language change (letting `new()` take an initializer expression, not just a type) both landed in Go 1.26 — confirming, not inventing, two items the orchestrator's frame had flagged as unverified hypotheses.
- Generic type aliases went preview (`GOEXPERIMENT=aliastypeparams`, 1.23) → default-on (1.24, with an opt-out removed in 1.25) → self-referential generic types allowed (1.26) → the cycle restriction on type parameters lifted and type parameters allowed as alias RHS (accepted proposals [#75883](https://github.com/golang/go/issues/75883)/[#75885](https://github.com/golang/go/issues/75885), landing in 1.27-era). This is now stable, unconditional language surface.
- `testing/synctest` went experimental (1.24, `GOEXPERIMENT=synctest`, API `Run`/`Wait`) → GA (1.25, renamed API `Test`/`Wait`, old `Run`-based API removed in 1.26 per [golang/go#73567](https://github.com/golang/go/issues/73567)) → gained a `Sleep()` convenience helper in 1.27. Code samples using `synctest.Run` are already stale.
- `sync.WaitGroup.Go(f func())` (Go 1.25) is a smaller, more idiomatic replacement for the four-line `wg.Add(1); go func() { defer wg.Done(); f() }()` boilerplate every pre-1.25-trained agent still emits; the `go fix` modernizer that rewrites this is literally named `waitgroupgo`.
- Container-aware `GOMAXPROCS` (Go 1.25, [go.dev/blog/container-aware-gomaxprocs](https://go.dev/blog/container-aware-gomaxprocs)) makes `go.uber.org/automaxprocs` redundant for anything built with Go ≥1.25 and run in a cgroup — the blog post explicitly credits automaxprocs's maintainers and says the new runtime default "considers cgroup CPU bandwidth limits" without a third-party import.
- The Green Tea garbage collector went experimental in 1.25 (`GOEXPERIMENT=greenteagc`, 10–40% GC-CPU reduction, modal ~10%) and became the **default** in 1.26 (opt-out `GOEXPERIMENT=nogreenteagc`) — release binaries built with a Go 1.26+ toolchain get this for free with no code change.
- `encoding/json/v2` (package `encoding/json/v2` plus `encoding/json/jsontext`) is still experimental behind `GOEXPERIMENT=jsonv2` as of Go 1.27 (Aug 2026); it is real, shipped, and faster to unmarshal, but "use it by default" is premature — a Go SDK for OCX should watch this, not adopt it, until a stable-by-default release notes entry appears.
- GODEBUG is a real deprecation clock, not a suggestion: Go 1.27 permanently removed seven settings that were 1-2 releases old (`asynctimerchan`, `tlsunsafeekm`, `tlsrsakex`, `tls3des`, `tls10server`, `x509keypairleaf`, `gotypesalias`), and a formal "policy for removing GODEBUG flags" proposal ([golang/go#76163](https://github.com/golang/go/issues/76163)) was accepted in Nov 2025 — a rule that tells agents to "check GODEBUG" needs a recency test, not a static list.
- `go vet` grew real correctness analyzers in this window that catch bugs an agent is likely to write: `waitgroup`→renamed `waitgroupgo` in 1.27 (misplaced `sync.WaitGroup.Add`), `hostport` (1.25, wrong IPv6 `host:port` construction — use `net.JoinHostPort`), `tests` (1.24, malformed `Test`/`Fuzz`/`Benchmark`/`Example` signatures), and `stdversion` (1.23, now run by default under `go test` as of 1.27 — flags stdlib symbols newer than the module's declared `go` version).
- The ecosystem's "mocking framework" answer changed underneath agents mid-corpus: `golang/mock` was archived January 2024 (measured via GitHub API: `archived: true`, last push 2024-01-08) in favor of the community fork `go.uber.org/mock` — any generated code importing `github.com/golang/mock/gomock` is importing a dead repository.
- `testify` is not moving to a v2: issue [stretchr/testify#306](https://github.com/stretchr/testify/issues/306), open since the library's early years, is still open with no resolution as of 2026-09; testify v1's import path remains the answer, and the "testify v2 is coming" belief some training data carries is not supported by the repo's own tracker.
- `gorilla/mux`'s last push to `main` was 2024-08-15 — over two years stale as of this research date — while `net/http.ServeMux`'s Go 1.22 routing patterns (method matching, `{wildcard}`, `{path...}`, `{$}`) cover most of what people reached for `gorilla/mux` to get. Not archived, but a "why add this dependency" flag for new code.
- `pkg/errors` is not archived (still receives occasional maintenance pushes, most recently 2026-03) but has had no feature work since stdlib `fmt.Errorf("%w", err)` + `errors.Is`/`As`/`Join` subsumed its `Wrap`/`Cause` API years ago; agents still emitting `errors.Wrap` from older training data are reaching for a library the ecosystem has already replaced with stdlib.

## Survey

### 1. Go 1.22 release notes

[go.dev/doc/go1.22](https://go.dev/doc/go1.22) — released March 2024 (six months after 1.21). Language: per-iteration `for` loop variables (no more capture bug), `for i := range 10` range-over-int, `GOEXPERIMENT=rangefunc` preview. Stdlib: new `math/rand/v2` package (`ChaCha8`, `PCG`, `N[T]`), `cmp.Or`, `slices.Concat`, `net/http` routing patterns with method + wildcards (`Request.PathValue`/`SetPathValue`, `{id}`, `{path...}`, `{$}`), `go/version` package. Tooling: `go work vendor`, new `vet` warnings (no-op `append`, non-deferred `time.Since` in `defer`, mismatched `log/slog` key-value pairs). GODEBUG additions: `httplaxcontentlength`, `httpmuxgo121`, `tlsrsakex`, `tls10server`, `tlsunsafeekm`, `x509usepolicies`, `gotypesalias` (default 0), `noallocheaders`, `noexectracer2`.

### 2. Go 1.23 release notes

[go.dev/doc/go1.23](https://go.dev/doc/go1.23) — released August 2024. Language: range-over-func GA (`func(func() bool)`, `func(func(K) bool)`, `func(func(K,V) bool)` iterator shapes accepted by `range`); generic type aliases previewed via `GOEXPERIMENT=aliastypeparams`. Stdlib: new `iter`, `unique` (`unique.Make[T]`), `structs` (`structs.HostLayout`) packages; `slices`/`maps` gained `All`, `Values`, `Keys`, `Collect`, `Sorted`, `Backward`, `Insert` iterator functions. Major semantic change: `Timer`/`Ticker` channels become unbuffered (cap 0, was 1) and GC-eligible immediately once unreferenced — gated on `go 1.23.0+` in `go.mod`, GODEBUG `asynctimerchan=1` to revert. Tooling: `go telemetry` command (opt-in, default `local`, `go telemetry on` to upload weekly), `godebug` directive in `go.mod`/`go.work`, `vet`'s new `stdversion` analyzer. GODEBUG: `tlskyber=0`, `tls3des=1`, `x509sha1` (slated removal in 1.24), `gotypesalias` default flips 0→1, `winsymlink`/`winreadlinkvolume` default 1.

### 3. Go 1.24 release notes

[go.dev/doc/go1.24](https://go.dev/doc/go1.24) — released February 2025. Language: generic type aliases on by default (`GOEXPERIMENT=noaliastypeparams` to opt out, removed in 1.25). Stdlib: `os.Root`/`os.OpenRoot` (directory-confined filesystem access), `weak` package (weak pointers), `testing/synctest` experimental (`GOEXPERIMENT=synctest`, `Run`/`Wait`), `testing.B.Loop()`, `testing.T.Context()`/`B.Context()`, `testing.T.Chdir()`/`B.Chdir()`, `runtime.AddCleanup` (replaces `SetFinalizer` for many uses), new `crypto/mlkem`, `crypto/hkdf`, `crypto/pbkdf2`, `crypto/sha3`. FIPS 140-3: `GOFIPS140` env var, `GODEBUG=fips140=on|only`, a Go Cryptographic Module under CMVP review. Swiss-Tables map implementation (`GOEXPERIMENT=noswissmap` to revert). New `tool` directive in `go.mod` for tracking executable dependencies (`go get -tool`), `GOAUTH` env var, `-json` on `go build`/`go install`/`go test`. `encoding.TextAppender`/`BinaryAppender` interfaces added broadly across `crypto/*`, `hash/*`, `time`, `net/netip`. `strings`/`bytes` gained `Lines`, `SplitSeq`, `SplitAfterSeq`, `FieldsSeq`, `FieldsFuncSeq` iterators. `net/http/httputil.ReverseProxy` groundwork continues (Director deprecation lands in 1.26, see below).

### 4. Go 1.25 release notes

[go.dev/doc/go1.25](https://go.dev/doc/go1.25) — released August 2025. No language changes. Stdlib: `testing/synctest` promoted out of experiment (renamed API `Test`/`Wait`), `encoding/json/v2` experimental (`GOEXPERIMENT=jsonv2`, plus `encoding/json/jsontext`), `sync.WaitGroup.Go()` method, `go.mod` `ignore` directive, `runtime/trace.FlightRecorder` (ring-buffer tracing). Runtime: container-aware `GOMAXPROCS` (considers cgroup CPU bandwidth limits on Linux, periodic re-check; `GODEBUG=containermaxprocs=0`/`updatemaxprocs=0` to disable), Green Tea GC experimental (`GOEXPERIMENT=greenteagc`), DWARF5 debug info by default (`GOEXPERIMENT=nodwarf5` to revert), `GODEBUG=checkfinalizers=1` diagnostics. Vet: new `waitgroup` analyzer (misplaced `Add`), new `hostport` analyzer (bad IPv6 `host:port` construction, suggests `net.JoinHostPort`). `go build -asan` defaults to leak detection at exit. GODEBUG: `decoratemappings`, `containermaxprocs`, `updatemaxprocs`, `tlssha1=1` (SHA-1 sigs disallowed in TLS 1.2 by default), `x509sha256skid`.

### 5. Go 1.26 release notes

[go.dev/doc/go1.26](https://go.dev/doc/go1.26) — released February 2026. Language: `new(expr)` — `new()` now accepts an expression as its operand, not just a type; generic types may self-reference in their own type-parameter list (`type Adder[A Adder[A]]`). Tooling: **`go fix` completely rewritten** as the home of Go's modernizers, with a source-level inliner honoring `//go:fix inline` directives; `cmd/doc`/`go tool doc` removed in favor of `go doc`; `go mod init` now defaults to `go 1.(N-1).0` in new `go.mod` files. Runtime: Green Tea GC **on by default** (`GOEXPERIMENT=nogreenteagc` to disable), ~30% cgo call overhead reduction, 64-bit heap-base-address randomization by default (security hardening), experimental `goroutineleak` pprof profile type. Stdlib: `errors.AsType` (generic `As`), new `crypto/hpke` package, experimental `simd/archsimd`, experimental `runtime/secret`. `gotypesalias` GODEBUG slated for full removal in 1.27 (already always-Alias by this point in practice).

### 6. Go 1.27 release notes

[go.dev/doc/go1.27](https://go.dev/doc/go1.27) — released August 2026, confirmed in-page: "The latest Go release, version 1.27, arrives in August 2026, six months after Go 1.26." Language: generic methods (`(*Rand) N[Int intType](Int) Int` — a method may declare its own type parameters; interface methods still cannot); struct literal keys may be any valid field selector, not just top-level field names ([golang/go#9859](https://github.com/golang/go/issues/9859)); function type inference generalized to all assignment/conversion contexts ([#77245](https://github.com/golang/go/issues/77245)). New packages: `encoding/json/v2` + `encoding/json/jsontext` ship as real packages (still `GOEXPERIMENT=nojsonv2` to disable, "expected removal in a future release" — i.e., still pre-default-on), `crypto/mldsa` (ML-DSA / FIPS 204), `uuid`, `simd` (portable) + `simd/archsimd` (arch-specific). Removed GODEBUGs: `asynctimerchan`, `tlsunsafeekm`, `tlsrsakex`, `tls3des`, `tls10server`, `x509keypairleaf`, `gotypesalias` — all gone; Go 1.27+ still recognizes them in `go.mod`/source but accepts only the final default value. `go fix` gained modernizers `atomictypes`, `embedlit`, `slicesbackward`, `unsafefuncs`; removed `fmtappendf`; renamed `waitgroup`→`waitgroupgo`. `go test` now runs the `stdversion` vet check by default. Goroutine leak profile stabilized out of experiment.

### 7. GODEBUG settings history (go.dev/doc/godebug)

[go.dev/doc/godebug](https://go.dev/doc/godebug) — the authoritative deprecation clock. Confirms the version-by-version table used throughout this document: `x509sha1` added 1.22 era, removed 1.24; `tlskyber` added 1.23, removed 1.24 (replaced by `tlsmlkem`); `asynctimerchan` added 1.23, removed 1.27; `gotypesalias` added 1.22 default 0, flipped to default 1 in 1.23, removed 1.27; `tlsunsafeekm`/`tlsrsakex`/`tls10server`/`tls3des`/`x509keypairleaf` all added 1.22–1.23, all removed 1.27. Newer additions: `containermaxprocs`/`updatemaxprocs` (1.25), `tracebacklabels` (1.26, default flips to 1 in 1.27), `cryptocustomrand` (1.26), `urlstrictcolons` (1.26), `htmlmetacontenturlescape` and `x509sslcertoverrideplatform` (1.27, the latter's removal already scheduled for **Go 1.31**). The removal-scheduling itself (naming a target release in the doc) is new practice, matching the accepted "policy for removing GODEBUG flags" proposal (source #13 below).

### 8. golangci-lint v1→v2 migration guide

[golangci-lint.run migration guide, raw source](https://raw.githubusercontent.com/golangci/golangci-lint/main/docs/content/docs/product/migration-guide.md) — fetched in full (1734 lines). Confirms: top-level `version: "2"` is now required in config. `gci`, `gofmt`, `gofumpt`, `goimports` move from `linters.enable` to a new `formatters.enable` section. `gosimple` + `stylecheck` linters are removed as separate entries — `staticcheck` alone now covers all three. `linters.fast` boolean removed, replaced by `linters.default: fast` (declarative) or the `--fast-only` CLI flag. `linters.presets` removed entirely — the guide inlines the full preset→linter-list mapping (`bugs`, `comment`, `complexity`, `error`, `format`, `import`, `metalinter`, `module`, `performance`, `sql`, `style`, `test`, `unused`) for anyone migrating a preset-based v1 config by hand. Thirteen deprecated linters deleted outright: `deadcode`, `execinquery`, `exhaustivestruct`, `exportloopref`, `golint`, `ifshort`, `interfacer`, `maligned`, `nosnakecase`, `scopelint`, `structcheck`, `tenv`, `varcheck`. Alternate linter names removed (`gas`→`gosec`, `goerr113`→`err113`, `gomnd`→`mnd`, `logrlint`→`loggercheck`, `megacheck`→`staticcheck`, `vet`/`vetshadow`→`govet`). CLI flags removed: `--disable-all`, `--enable-all`, `-p/--presets`, `--fast`, `-e/--exclude`, `--exclude-*`, `--go`, `--sort-order`, `--sort-results`, `--out-format` (replaced by explicit `--output.<format>.path` style flags), `--print-issued-lines`, `--print-linter-name`. A built-in `golangci-lint migrate` command exists to convert a v1 config automatically (comments are not preserved; deprecated/unknown fields are dropped silently).

### 10. staticcheck (dominikh/go-tools) release notes, 2025–2026

[GitHub releases API, dominikh/go-tools](https://github.com/dominikh/go-tools/releases) — confirms current version **2026.2.1, published 2026-08-21**, matching the frame. ### 14. Container-aware GOMAXPROCS blog post

[go.dev/blog/container-aware-gomaxprocs](https://go.dev/blog/container-aware-gomaxprocs) — Go 1.25 feature. The runtime defaults `GOMAXPROCS` to the cgroup CPU limit when it is lower than the visible core count, and periodically re-checks it if the limit changes at runtime. Explicitly credits `go.uber.org/automaxprocs`'s maintainers for feedback and states the new default makes that pattern built-in. Caveats worth carrying into a rule: it only engages when `GOMAXPROCS` is otherwise unset (an explicit env var or `runtime.GOMAXPROCS()` call still wins); CPU limits model *throughput* (CPU-seconds per wall-clock period), not a *parallelism* ceiling, so spiky/bursty workloads can see added latency under this model; fractional limits round up.

### 15. Green Tea GC blog post

[go.dev/blog/greenteagc](https://go.dev/blog/greenteagc) — new mark/sweep GC design organized around pages rather than individual objects, for better cache locality. Experimental in Go 1.25 (`GOEXPERIMENT=greenteagc`), the post states the team's plan to make it the default in Go 1.26 — which the Go 1.26 release notes (source #5) confirm actually happened. Typical improvement ~10% GC-CPU time reduction; some workloads up to 40%.

## Contested

- **testify vs stdlib+go-cmp** (frame's H5): the ecosystem signal is genuinely split. testify remains extremely actively maintained (pushed within the last 24 hours of this research) and dominant by adoption, but its own maintainers have an unresolved, multi-year-old open issue ([#306](https://github.com/stretchr/testify/issues/306)) admitting the API has warts they can't fix without a breaking v2 they've concluded they can't ship. The Go team's own style (and this survey did not independently re-verify a current Google internal-style citation this pass) leans stdlib + `go-cmp`. Trend: no resolution in sight; a rule set picking a position should pick testify-v1-as-the-pragmatic-default while flagging its known argument-order/`Times(0)` footguns, rather than wait for a v2 that issue #306 shows is not coming.
- **`encoding/json/v2` adoption timing**: it is real, shipped as an importable package, and staticcheck already updates checks for it (SA5008 "better support for encoding/json/v2" per source #10) — but it is still `GOEXPERIMENT=nojsonv2`-gated as of Go 1.27 and the release notes call its own future removal-of-the-disable-flag merely "expected," not scheduled. Trending toward default-on, not there yet; a rule should track this, not adopt it, until a release note says the experiment flag is gone.
- **Green Tea GC being "free"**: the blog post is unambiguous that it's a net win for most workloads (10–40% less GC CPU), but "some workloads" is explicitly hedged — this survey did not find a fetched source quantifying which workload shapes regress. Trending toward "just upgrade and benefit," but a performance-sensitive rule should say "verify with your own benchmark before assuming," not promise a universal win.
- **automaxprocs vs built-in container-aware GOMAXPROCS**: the Go blog frames this as a clean handoff, but real fleets running on Go <1.25 toolchains (or needing finer control than the built-in heuristic) still have a legitimate reason to keep the dependency. Trend is toward dropping it for anything targeting Go ≥1.25, but "always redundant" would be an overstatement this survey's sources don't support.
- **gorilla/mux and pkg/errors: dead vs merely quiet**: neither is archived, both still receive occasional commits, and this survey found no repo-authored deprecation notice for either in the material actually fetched (only the top of each README, not the full text or any pinned issue). Calling them "deprecated" would overstate what was verified; "superseded by stdlib/newer patterns for new code, not formally dead" is the defensible claim from this pass's evidence.
