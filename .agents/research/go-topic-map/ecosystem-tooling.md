## Summary

- `GOTOOLCHAIN` defaults to `auto` (shorthand `local+auto`); the `go` line in
  `go.mod` is a **mandatory minimum toolchain requirement since Go 1.21**, not
  advisory — a toolchain older than the declared `go` line refuses to load
  the module at all.
- The `tool` directive (Go 1.24+) replaces the `tools.go` blank-import hack
  for tracking build-time tool dependencies in `go.mod`; `go get -tool` and
  `go tool <name>` are the new surface. 4 of 35 exemplars
  (`aquasecurity/trivy`, `hashicorp/terraform`, `syncthing/syncthing`,
  `tailscale/tailscale`) already use it; most exemplars still don't.
- `go.work` is explicitly documented as **should-not-be-committed**
  (go.dev/ref/mod), yet 4 of 35 exemplars commit one anyway
  (`bazelbuild/bazel-gazelle`, `kubernetes/kubernetes`,
  `prometheus/prometheus`, `etcd-io/etcd`) — all multi-module monorepos,
  suggesting the "don't commit" rule has an unstated exception for
  intentionally-multi-module repos with no external consumers of the
  top-level module.
- MVS (Minimal Version Selection) picks the **lowest** version satisfying
  all requirements, is deterministic, and is *not* cached in a lockfile —
  `go.sum` records checksums, not resolved versions; `go list -m all` is the
  only reliable way to see the actual build list.
- Module authentication is two-layered: `go.sum` (local, per-module) plus
  the global checksum database at `sum.golang.org` (`GOSUMDB`); `GOPRIVATE`
  implies both `GONOPROXY` and `GONOSUMDB` for matching glob patterns.
- `GOAUTH` (Go 1.24+) controls how the go command authenticates to private
  proxies/VCS hosts: `off`, `netrc` (default), or `git <dir>` (shells out to
  `git credential fill`) — this is the primary lever for CI credential
  injection, and it is easy to leave at the insecure `off`/no-auth default.
- Integration-test coverage is a first-class, separate pipeline from unit
  coverage: `go build -cover` + `GOCOVERDIR` + `go tool covdata
  percent|textfmt|merge`, deliberately decoupled from `go test -cover`.
- PGO (`default.pgo`, auto-detected since Go 1.21, GA since 1.20) gives
  2–14% CPU improvement (measured through Go 1.22) but is **source-position
  sensitive**: renaming or moving a hot function silently degrades — not
  breaks — its own optimization without any build error.
- `runtime/trace.FlightRecorder` (new in Go 1.25) is the low-overhead
  answer to "I want a trace only around the bad event," replacing
  always-on execution tracing for production diagnosis.
- `goroutineleak` went from experimental (`GOEXPERIMENT=goroutineleakprofile`,
  1.26) to GA in `runtime/pprof` and `/debug/pprof/goroutineleak` in Go
  1.27 — a stdlib alternative to hand-rolled `goleak`-style leak tests that
  the fleet has not yet had a chance to adopt anywhere.
- goreleaser's `brews` config is deprecated in favor of `homebrew_casks`
  (since v2.10) — this is **not a rename**: casks are macOS-only (formulas
  served Linuxbrew too), live under `Casks/` not `Formula/`, need an
  explicit `binaries:` list, and need a post-install hook to strip the
  Gatekeeper quarantine xattr or the binary refuses to run.
- goreleaser's SBOM step defaults to Syft against **archives**, not binaries
  or container images — "container images generated by GoReleaser are not
  available to be cataloged by the SBOM tool" is a documented gap.
- cosign keyless signing (Fulcio + Rekor) needs no long-lived key material
  at all: an ephemeral keypair, an OIDC-bound short-lived cert, a Rekor
  transparency-log entry, then the private key is destroyed — the natural
  fit for a CI pipeline with no secret-management story.
- rules_go under bzlmod resolves Go SDK version from `go.mod`/`go.work` via
  `go_sdk.from_file()`, with the `toolchain` directive taking precedence
  over the `go` directive; `go_sdk.host()` is explicitly discouraged as
  non-reproducible.
- Gazelle's `go_deps` bzlmod extension needs every **direct** dependency
  re-listed in `use_repo()`; Bazel ≥7.1.1 auto-fixes this via `bazel mod
  tidy`, older Bazel only warns with a fixup command.
- `nogo` (rules_go's built-in static analyzer, distinct from `go vet`/
  golangci-lint) runs by default on all main-repo Go targets but not
  external ones, and only the root module's `go_sdk.nogo()` tag is honored.
- Doc comments have had a formal, parsed markup syntax since Go 1.19
  (`# Heading`, `[pkg.Name]` doc links, `Deprecated:` paragraphs) that
  `gofmt`, `go doc`, and pkg.go.dev all render identically — pre-1.19
  implicit-heading style still renders via heuristic but is deprecated.
- Prometheus best practice has moved decisively toward **native histograms
  over both classic histograms and summaries**: summaries aren't
  aggregatable across instances at all, and the guidance is now unqualified
  ("prefer them over both").
- OpenTelemetry Go's traces and metrics APIs/SDKs are stable (v1.4x line);
  the Logs API/SDK only reached release-candidate status in 2026 — a Go SDK
  reaching for OTel logging today is adopting pre-v1 surface.

## Survey

### 1. `go help` topics (installed Go 1.27.1 toolchain)

Read via `~/.cache/research-lang/go-tools/run.sh go help <topic>` for:
`build`, `buildconstraint`, `cache`, `environment`, `gopath`, `goproxy`,
`importpath`, `modules`, `module-auth`, `packages`, `private`, `testflag`,
`testfunc`, `vcs`, `buildjson`, `buildmode`, plus `mod`, `work`, `tool`,
`env` subcommand help. No stable URL — cited as `go help <topic>` against
the locally installed 1.27.1 toolchain, per the task brief's own citation
convention for this source.

Key facts not already folded into Summary:
- `buildjson`: `go build/install/test -json` emits newline-delimited
  `BuildEvent{ImportPath, Action, Output}` where `Action` is
  `build-output` or `build-fail`; non-JSON error text can still appear on
  stderr even with `-json` — "consumers should be robust to this."
- `cache`: build cache does **not** detect changes to C libraries linked
  via cgo — `go clean -cache` or `-a` is required after a native library
  upgrade. Debug knobs: `GODEBUG=gocacheverify=1`, `gocachehash=1`,
  `gocachetest=1`. `GOCACHEPROG` lets an external process own the cache.
- `private`: `GOPRIVATE` is a comma-separated glob list (Go's `path.Match`
  syntax) of module-path prefixes; `GONOPROXY`/`GONOSUMDB` override it
  per-concern; `go env -w` persists these for future invocations.
- `buildconstraint`: `//go:build` expressions combine tags with
  `|| && !` and parens; feature-level tags stack (`GOAMD64=v2` implies
  `amd64.v1` and `amd64.v2`); in a module with `go 1.21+`, a build
  constraint naming a Go-release term (e.g. `go1.22`) sets the *compiled*
  language version for that file to the minimum implied version.
- `testfunc`: `ExampleXxx` with a trailing `// Output:` comment is
  compiled **and executed**, compared exactly; `// Unordered output:`
  compares ignoring line order; an example with no such comment is
  compiled only, never run.
- `module-auth`/`goproxy`: full protocol reference deferred to
  <https://go.dev/ref/mod#goproxy-protocol> and `#authenticating`.

### 2. [go.dev/doc/toolchain](https://go.dev/doc/toolchain)

`GOTOOLCHAIN` forms: `local`, `<name>`, `<name>+auto`, `<name>+path`,
shorthand `auto` = `local+auto`, `path` = `local+path`. On a version
mismatch the go command downloads up to three candidate toolchains
(unreleased rc, latest patch of newest minor, latest patch of previous
minor) and picks the **minimum** satisfying one — MVS applied to
toolchains themselves. Toolchains download as the synthetic module
`golang.org/toolchain@v0.0.1-go<VERSION>.<GOOS>-<GOARCH>`. Version
ordering: `1.21 < 1.21rc1 < 1.21rc2 < 1.21.0 < 1.21.1`. Minimum-version
enforcement (Go 1.21+) was backported to 1.19.13+ and 1.20.8+, so even old
toolchains refuse a newer `go` line. `GODEBUG=toolchaintrace=1` (Go 1.24+)
traces the selection.

### 3. [go.dev/ref/mod](https://go.dev/ref/mod)

The full modules reference. Beyond Summary: `go.sum` records checksums for
the graph needed by the go version *one below* the declared `go` version
(pruned since 1.17); `-compat` overrides. Proxy fallback triggers **only**
on 404 or 410 from all path-prefix queries. `retract` needs a *new,
higher* tag containing the retraction to take effect and is hidden from
`go list -m -versions` and `@latest`/`@>=` queries unless `-retracted` is
passed. Major-version suffix rule (`/v2`, `/v3`, …) is the mechanism that
lets multiple majors coexist as distinct module paths; `+incompatible` is
the escape hatch for pre-modules v2+ tags. `go.work`'s `use` directive is
**not** recursive into subdirectories. Auto-vendor activates when the main
module's `go` version is ≥1.14 **and** `vendor/modules.txt` is consistent
with `go.mod` — `-mod=vendor|readonly|mod` overrides explicitly.

### 4. [go.dev/doc/build-cover](https://go.dev/doc/build-cover)

`go build -cover [-coverpkg=patterns]` instruments only main-module
packages by default. `GOCOVERDIR=dir ./binary` writes `covmeta.*` (once)
and `covcounters.*` (per run) — unset `GOCOVERDIR` runs the binary
normally but **silently drops coverage data with a warning**, which is an
easy CI footgun. `go tool covdata percent|textfmt|merge -i=dir1,dir2
-o=out -pkg=pattern` is the whole downstream toolchain; `textfmt` bridges
back to the legacy `go tool cover -html/-func` pipeline.

### 5. [go.dev/doc/pgo](https://go.dev/doc/pgo)

PGO uses CPU pprof profiles; `default.pgo` in the main package directory
is auto-detected (`-pgo=auto`, the default); `-pgo=off` or an explicit
path override it. Recommended to commit `default.pgo` for reproducible,
performant builds. 2–14% gains as of Go 1.22 on representative programs.
Robust to source changes *outside* hot functions; may silently lose
effectiveness (not error) when hot-function code moves or is renamed,
because matching is by line-offset. Applies compiler-wide, including
stdlib and dependencies, in the same build. Microbenchmark profiles are
explicitly called out as poor PGO input.

### 6. [go.dev/doc/go1.27](https://go.dev/doc/go1.27), [go1.26](https://go.dev/doc/go1.26), [go1.24](https://go.dev/doc/go1.24)

Primary release notes; full detail folded into [Recent shifts](#recent-shifts-seen-in-this-corpus).
Notable tooling items not already summarized: `go doc pkg@version` and
`go doc -ex` (1.27); `go test -json`'s new `OutputType` field
(`error`/`error-continue`/`frame`, 1.27); `go mod tidy` auto-merging
duplicate require blocks for `go 1.27+` modules; `go fix`'s modernizer
renames/additions per release (`waitgroup`→`waitgroupgo`, new
`atomictypes`/`embedlit`/`slicesbackward`/`unsafefuncs` in 1.27); `cmd/doc`
deleted in 1.26 in favor of `go doc`; `go mod init`'s new default of
writing a **lower** `go` line than the running toolchain (1.26+).

### 7. [go.dev/blog/generate](https://go.dev/blog/generate)

`//go:generate` must start at column 0 with no space before `go:generate`.
Generated code intended for `go get` consumers **must be checked in** —
generation tools are not assumed available to clients. `go generate` is
explicitly **not** part of `go build`; nothing invokes it implicitly.

### 8. [go.dev/doc/comment](https://go.dev/doc/comment)

Formal doc-comment grammar since Go 1.19: `# Heading` (blank-line-set-off,
unindented), `[Name]`/`[pkg.Name]` doc links to identifiers, `[Text]: url`
reference-style links, `- ` bullet lists, `1. ` numbered lists, indented
text as preformatted code blocks. `Deprecated:`-prefixed paragraphs are
parsed as deprecation notices by tooling. `gofmt` canonicalizes doc
comments (moves `//go:generate`-style directives to the end, converts
pre-1.19 implicit headings to `#` form). First-sentence conventions are
prescriptive per declaration kind (packages: "Package x …", booleans:
"reports whether …").

### 9. goreleaser docs: [builds/builders/go](https://goreleaser.com/customization/builds/builders/go/), [sbom](https://goreleaser.com/customization/sbom/), [docker_sign](https://goreleaser.com/customization/docker_sign/), [homebrew_casks](https://goreleaser.com/customization/publish/homebrew_casks/)

Reproducibility config surface: `mod_timestamp: "{{ .CommitTimestamp }}"`,
`flags: [-trimpath]`, `ldflags` templated off `{{.CommitDate}}` rather than
`{{.Date}}` (the wall-clock default), `env: CGO_ENABLED=0`; the docs
explicitly warn against the non-deterministic `time` template function.
`goos`/`goarch`/`goarm`/`goamd64` build a full matrix unless `targets`
pins it. SBOM step defaults to Syft over `archive` artifacts; `artifacts:
binary|archive|package|source|any`; documented gap: container images
aren't cataloged. `docker_signs` runs in the **publish** phase (after
push, because cosign mutates registry state), templated on `${digest}`
extracted from the push; parallels the artifact-level `signs` pipe.
`homebrew_casks` (since v2.10) needs `directory: Casks`, `binaries:`, and
a quarantine-stripping `postinstall` hook that `brews` never needed.

### 10. [ko.build](https://ko.build/)

`ko build`/`publish`/`apply` build Go binaries straight into OCI images by
running `go build` locally — no Dockerfile, no Docker daemon. Default base
is a distroless/Chainguard static image (no shell, no glibc), overridable
per-package via `.ko.yaml`'s `baseImageOverrides`. SBOM generation is a
built-in default, not an opt-in step (contrast with goreleaser's
opt-in-and-gapped Syft integration). Multi-platform is native.

### 11. [docs.sigstore.dev/cosign/signing/overview](https://docs.sigstore.dev/cosign/signing/overview/)

Keyless flow: ephemeral in-memory keypair → Fulcio verifies OIDC identity,
issues a short-lived cert binding identity to the public key → private key
destroyed immediately → signing event witnessed and timestamped in Rekor
(hash + pubkey + signature) → verification replays that chain, and "the
signer will be monitoring the log … and will know if there is an
unexpected signing event" (i.e. Rekor is the detection mechanism for
identity misuse, not a preventive control).

### 12. [github.com/bazel-contrib/rules_go: docs/go/core/bzlmod.md](https://github.com/bazel-contrib/rules_go/blob/master/docs/go/core/bzlmod.md)

`bazel_dep(name = "rules_go", version = "0.57.0")` / `gazelle` in
`MODULE.bazel`. `go_sdk.from_file(go_mod=...)` or `go_work=...)`: version
comes from the `toolchain` directive if present, else the `go` directive;
absent either, rules_go falls back to its own minimum-supported SDK
(1.20). `go_sdk.host()` is discouraged — host toolchain upgrades outside
Bazel's control break reproducibility. `go_deps.from_file(go_mod=...)`
requires every **direct** dependency in `use_repo()`; Bazel ≥7.1.1
auto-syncs via `bazel mod tidy`. `go.work` support exists but is
root-module-only, with a documented divergence limitation for indirect
deps (tracked at bazel-gazelle#1797). Go 1.24 `tool` directives surface in
Bazel as `GO_TOOLS` from `@gazelle//:go_tools.bzl` (needs Gazelle ≥0.47.0)
for `bazel_env.bzl` integration; pre-1.24 tools use the `tools.go` pattern
plus optional `isolate = True` extension usage. Override precedence:
`go_deps.gazelle_override` (per-module) > `go_deps.gazelle_default_attributes`
> the public [default_gazelle_overrides.bzl](https://github.com/bazelbuild/bazel-gazelle/blob/master/internal/bzlmod/default_gazelle_overrides.bzl)
registry. `nogo` is configured via `go_sdk.nogo(nogo=..., includes=[...],
excludes=[...])`; default scope is main-repo-only, root-module-only tag.
Not yet supported: git-repository deps, `go.mod` `exclude` directives.

### 13. [github.com/bazel-contrib/bazel-gazelle](https://github.com/bazel-contrib/bazel-gazelle/blob/master/README.md), [gazelle-reference.md](https://github.com/bazel-contrib/bazel-gazelle/blob/master/gazelle-reference.md), [language/go/reference.md](https://github.com/bazel-contrib/bazel-gazelle/blob/master/language/go/reference.md)

Directive syntax `# gazelle:key value`, scoped to its directory and
subdirectories. Core directives: `gazelle:prefix`, `gazelle:build_file_name`,
`gazelle:resolve <kind> <import> <label>`, `gazelle:resolve_regexp`,
`gazelle:default_visibility`, `gazelle:repository go_repository name=...
importpath=...`. Go-specific: `gazelle:go_naming_convention
import|go_default_library`, `gazelle:go_generate_proto`,
`gazelle:go_test default|file`, `gazelle:go_visibility`,
`gazelle:importpath_prefix`, `gazelle:go_grpc_compilers`. `update` vs
`fix`: `fix` additionally rewrites/deletes deprecated rule usage
(analogous to `go fix`) and is opt-in because it can delete/rename rules.

### 14. [github.com/actions/setup-go README](https://github.com/actions/setup-go)

Caching **on by default**; cache key derived from `go.mod` hash unless
`cache-dependency-path` is set to widen it to `go.sum` or a monorepo glob.
`go-version-file` accepts `go.mod`, `go.work`, `.go-version`, or
`.tool-versions`; `go-version` (if both given) wins. `check-latest`
defaults `false`. YAML gotcha called out explicitly: quote version strings
(`'1.20'`) or the parser truncates `1.20` → `1.2`.

### 15. [github.com/golang/govulncheck-action README](https://github.com/golang/govulncheck-action)

Wraps govulncheck; inherits `go-version-input`/`go-version-file`/
`check-latest`/`cache`/`cache-dependency-path` semantics from
actions/setup-go. `output-format: text|json|sarif` — **critical gate
detail**: "Specifying the output format 'json' or 'sarif' will return
success even if there are some vulnerabilities detected" — only `text`
format fails the job on a finding; `json`/`sarif` need a separate
downstream check of the output content, not the action's own exit code.
Marked "currently experimental."

### 16. [prometheus.io/docs/practices/histograms](https://prometheus.io/docs/practices/histograms/)

Summaries: quantiles computed client-side, cheap to query, **not
aggregatable** across instances (averaging precomputed quantiles is
"statistically nonsensical"), fixed quantile/window set at instrumentation
time. Classic histograms: bucketed counts, server-side `histogram_quantile()`,
aggregatable, but bucket boundaries are hard to change after the fact and
error is bounded by bucket width. Native histograms: single series,
dynamic exponential buckets, aggregatable, resolution-bounded error — "if
you can, use native histograms and prefer them over both classic
histograms and summaries."

### 17. [opentelemetry.io/docs/languages/go](https://opentelemetry.io/docs/languages/go/)

Traces and metrics APIs/SDKs: stable. Logs: release-candidate as of the
2026 [Go Logs RC announcement](https://opentelemetry.io/blog/2026/go-logs-api-sdk-rc/)
— log exporters and `logtest` remain experimental even under that RC.
Instrumentation is split: core repo (API/SDK) vs. a separate Contrib repo
for exporters and library instrumentation. `semconv/v1.39.0` is the
current semantic-conventions package version cited in search grounding.

## Recent shifts seen in this corpus

- **Go 1.24 (Feb 2025)**: `tool` directive in go.mod (replaces `tools.go`);
  generic type aliases; `os.Root`/`OpenRoot` directory-scoped FS access;
  `testing/synctest` experimental; `weak` package; `sync.WaitGroup.Go`;
  `testing.B.Loop`; `T.Context()`/`T.Chdir()`; `GOAUTH` env var;
  Swiss-table maps by default; FIPS 140-3 `GODEBUG=fips140`. Invalidates:
  any advice defaulting to the `tools.go` blank-import pattern as the *only*
  way to track tool deps, and any advice ignoring `GOAUTH` for private-repo
  CI auth.
- **Go 1.25 (Aug 2025)**: `runtime/trace.FlightRecorder`; `GOEXPERIMENT=greenteagc`
  (new GC, opt-in); `GOEXPERIMENT=jsonv2` experimental `encoding/json/v2` +
  `encoding/json/jsontext`; macOS 13+ required going forward. Invalidates:
  "always-on execution tracing is the only way to capture a runtime trace"
  advice for production services.
- **Go 1.26 (early 2026)**: `go fix` rewritten as the home of "modernizers"
  (dozens of fixers, `//go:fix inline`), obsoleting ad-hoc modernization
  scripts; `go mod init` now writes a **lower** default `go` line than the
  running toolchain; `cmd/doc` deleted (use `go doc`); Green Tea GC on by
  default (10–40% GC overhead reduction); `errors.AsType[T]`; new
  `runtime/metrics` scheduler keys; `crypto/hpke`; heap-base ASLR by
  default; `goroutineleak` GOEXPERIMENT. Invalidates: any doc referencing
  `cmd/doc`/`go tool doc`, and any advice treating `go mod init`'s emitted
  `go` line as "the toolchain's own version."
- **Go 1.27 (Aug 2026, current per frame)**: `go vet`'s `stdversion` check
  now runs by default under `go test`; `asynctimerchan` GODEBUG **removed
  permanently** (time channels always synchronous — obsoletes any doc
  still describing buffered timer channels as a live concern);
  `gotypesalias` GODEBUG **removed permanently**; `goroutineleak` profile
  GA; `bzr` VCS support removed from `go get`; `encoding/json/v2` still
  experimental (opt-out via `GOEXPERIMENT=nojsonv2`, not opt-in); new
  `crypto/mldsa` (post-quantum signatures, FIPS 204); `go mod tidy`
  auto-merges duplicate require blocks for `go 1.27+` modules; goroutine
  labels now appear in traceback headers by default (`GODEBUG=tracebacklabels=0`
  to opt out).
- **Tool ecosystem, roughly the same 18–24 months**: `golangci-lint` moved
  to a v2 config schema (this corpus's installed version is 2.14.0);
  `staticcheck` moved to calendar versioning (`2026.2.1`); `goreleaser`
  deprecated `brews` in favor of `homebrew_casks` since v2.10 — not a
  rename, a structurally different config; `github.com/golang/mock` is
  archived in favor of the `go.uber.org/mock` fork, which is the only one
  still tracking current Go releases; rules_go/gazelle's bzlmod path
  (`go_deps`, `go_sdk` module extensions) is now the documented default,
  with `WORKSPACE`-based setup treated as legacy; OpenTelemetry Go's Logs
  API/SDK only reached release-candidate status in 2026, years after
  traces/metrics stabilized — any "use OTel logging" advice predating that
  RC was recommending pre-v1, breaking-change-prone surface.

## Contested

- **Vendoring vs module cache + proxy**: go.dev's own docs present
  vendoring as a normal, first-class mode (auto-activated even), while the
  broader ecosystem trend among the exemplars leans toward relying on a
  pinned proxy/checksum-db combination and skipping `vendor/` for CLIs and
  libraries (vendoring is more common in vendored-dependency-sensitive
  infra projects like Kubernetes). Trend: proxy+sumdb for libraries and
  most CLIs; vendoring persists mainly in large infra monorepos and
  air-gapped-build contexts.
- **`go.work` commit policy**: go.dev/ref/mod says don't commit it; four
  large multi-module exemplars commit one anyway. This looks less like
  disagreement and more like an unstated exception the docs don't spell
  out (single-consumer monorepo vs a library other repos import) — worth
  resolving explicitly in the eventual rule rather than repeating either
  blanket claim.
- **Summary vs histogram, resolved but not universally applied**: Prometheus's
  own docs have moved to unconditionally preferring native histograms, but
  this is a relatively recent, strong position change from the older
  "summaries are fine for latency SLOs" guidance still visible in a lot of
  existing Go service code (client_golang's API still fully supports
  summaries, so nothing forces migration).
- **`brews` deprecation timeline**: goreleaser's own words are "should be
  removed in the next major version (v3, not planned date yet) unless
  someone finds a big reason not to" — i.e. the maintainers themselves
  haven't committed to a removal date, so "migrate now" is a
  recommendation, not yet a forced deadline. A rule that treats `brews` as
  already-broken would be ahead of the tool's own stance.
- **SBOM completeness claims**: goreleaser markets SBOM generation as a
  release-hygiene checkbox, but its own docs admit container images aren't
  covered — so "goreleaser produces an SBOM" is true but incomplete for any
  pipeline that also publishes images (via `ko` or goreleaser's docker
  pipe), and the two tools don't obviously agree on which one owns image
  SBOMs when both are in the same pipeline.
