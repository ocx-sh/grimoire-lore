## Verdict

1. **Position.** Emitted shell text is data crossing a parser boundary. Every target gets its own quoter, every emitted change is idempotent, reversible and append-safe, and nothing counts as done until a real interpreter round-tripped it. The rules bind *emitted code and the code that emits it* (an `ocx`-style `Shell` enum, a `tool init <shell>` command, a `tool completions <shell>` generator, a template set) and *installers that edit rc files*. They do not bind CI steps, dev scripts or sourced libraries unless those generate shell text for another shell.
2. **One quoter per (target, context), never a shared POSIX quoter** (SH-EMIT-01..02). Reusing the POSIX quoter fails 3 of 35 hostile cases on fish 3.6.0 to 4.9.3 and 6 of 35 on nu 0.105.1/0.116.0 and elvish 0.21.0 (re-run today); mise and starship ship that reuse.
3. **PowerShell single-quoted literals double all five of U+0027, U+2018, U+2019, U+201A, U+201B** (SH-EMIT-03). ocx, direnv 2.37.1 and mise 2026.10.2 double only the ASCII apostrophe, and a project-controlled value then executes on pwsh 7.4.7, 7.6.6 and Windows PowerShell 5.1.26100.9444 (re-run today: `pwned=True` on all three). Decided: **escape the class, do not refuse it**; doubling is lossless on all three versions. Refusal is reserved for values a target cannot carry (NUL everywhere; empty on PowerShell 7.4.7/5.1 and on cmd.exe), SH-EMIT-05. The same class executes through a **generated completion script**: clap_complete 4.6.8 and 4.6.9 (ocx and grim) escape `'` and U+2019 only, so a help string carrying U+2018, U+201A or U+201B runs on all three versions (re-run today, `pwned=True`; SH-EMIT-41).
4. **The hostile corpus is a gate, not an example** (SH-EMIT-04): 36 cases (35 round-trip plus NUL refused), run in the real interpreter of each target, byte for byte, oldest and newest version of each family. The wave-1 20-case corpus scored the apostrophe-only PowerShell quoter 20/20; the 15 added cases are exactly the 7 it fails. cmd.exe is the one refusal-based target: its gate is the Batch predicate of SH-EMIT-48 (re-run today on the 35 round-trip cases plus 8 C0 controls: the predicate admits 25 values and 200 runs round-trip in all four channels; ocx's four-character predicate admits 37 and 90 of 296 runs are wrong).
5. **Data channel order** (SH-EMIT-06/07): spawn with the environment, else emit data for the target's native parser with an ASCII payload (nu `from json`, elvish `from-json`, PowerShell base64), else a literal from the SH-EMIT-02/03 quoter. `ConvertFrom-Json` is not value-safe on pwsh 7.4.7/7.6.6 (an ISO-date string becomes `[DateTime]`; 34 of 35 corpus values, while Windows PowerShell 5.1 keeps the string and passes 35 of 35). Re-measured on the Windows host in the third pass: base64 35 of 35 on 7.6.6, 7.4.7 and 5.1; `-DateKind String` exists on 7.6.6 only (blw F14).
6. **Never emit** `$'..'` for an sh target (0/35 on dash 0.5.12, yash 2.52, posh 0.14.1), `source <(cmd)` (silent no-op on bash 3.2; parse error on dash, mksh, posh, POSIX-mode bash before 5.1), or another shell's quoting facility (`printf %q`, `${x@Q}`) (SH-EMIT-09, 12, 13). `eval "$(tool)"` hides the tool's failure on every shell measured (SH-EMIT-14). The ban holds for completion bootstraps: `source <(grim completions bash)` registers nothing on bash 3.2.57 while `eval "$(...)"` and a stored file register on all eight bash versions (re-run today, SH-EMIT-34).
7. **rc edits** (installer/bootstrap kind): target the file the shell reads (a login bash reads only the first of `.bash_profile`, `.bash_login`, `.profile`), give fish and nushell a file of their own and ask nu and PowerShell where it is rather than building the path, write a whole-line marker pair, repair the trailing newline, keep every other byte of the user's file including its line endings (an awk or sed editor is LF-only and breaks under Git Bash's text mode), resolve a symlinked rc and keep its mode, ship removal and an opt-out (SH-EMIT-16..23, 51). A PowerShell profile is appended with `Add-Content`, never `Out-File -Append`, `>>` or `[IO.File]::AppendAllText`: `AppendAllText` (all three engines) and `Out-File -Append` (7.x) append UTF-8 to a UTF-16LE profile and it stops loading, while on 5.1 `Out-File -Append` appends UTF-16LE and breaks the ASCII, LF and BOM profiles instead; `Add-Content` was green in all 12 (file shape, engine) cells (SH-EMIT-51). ocx@5de9d777eb7d violates the target, symlink and mode rules (reproduced against the real binary; unchanged at ocx HEAD 3485207c1), and has no Windows branch for the nu and elvish files (SH-EMIT-16, 17, 38; plant, not the real binary on Windows). Completions follow the same edit contract wherever they need an rc line: zsh, elvish and PowerShell have no zero-rc user location (SH-EMIT-35, 38, 39); bash and fish do (SH-EMIT-34, 36).
8. **Hooks** (interactive rc/integration kind): register through each shell's append-safe mechanism and prove it with a user hook already present, sourced once and twice (SH-EMIT-24..29 for the prompt, SH-EMIT-42..44 for directory change and pre-exec). Bash `PROMPT_COMMAND` is extended as a string through element 0, because only element 0 of an array runs on bash 3.2 to 5.0; the clobber, naive-string, `+=(...)` and ocx-array shapes fail 32, 24, 23 and 5 of 40 scenarios, the twin 0 (re-run today). **The guarantee is scoped at ble.sh, by build** (settled in the third pass, blw F1..F8): on ble.sh v0.4.0-devel3 (the tagged "Latest", 2023-04-03) and nightly 0.4.0-nightly+d81fd54, bash 4.4.23 to 5.3.20, `ble-edit/adjust-PS1` moves `PROMPT_COMMAND` aside at `ble-attach` and `restore-PS1` writes the copy back at the first prompt, so a write made in that window is lost: the SH-EMIT-24 twin fires 9 of 9 prompts when sourced before attach, 0 of 9 after it (once or twice, both images), and 9 of 10 when typed at the first prompt. The discard is a window, not "after attach": a write before attach, after the first prompt or with no `ble-attach` line survives. README §1.3 puts `ble-attach` at the end of `.bashrc`, so a tool's appended lines land in the window. A `blehook` registration fires in every order, gated on `declare -F blehook` and never on `BLE_VERSION` alone: stable v0.3.4 sets `BLE_VERSION` and has no `blehook` (the `BLE_VERSION`-only plant fires 0 of 9), and on it the string extension fires in every order because ble.sh only evals `PROMPT_COMMAND` element 0 (SH-EMIT-24, 43). bash-preexec 0.5.0 and 0.7.0 coexist with the string extension (60 of 60 pty scenarios, cdh).
9. **Emitted PowerShell that must run on 5.1 is ASCII only, no BOM, 5.1 syntax** (SH-EMIT-08). Decided between "ASCII" (qc) and "ASCII or BOM" (rh): ASCII, because a BOM breaks `irm | iex` on all three engines and non-ASCII is always avoidable with `[char]0xNN` or base64. The decision extends to **generated completion scripts** (SH-EMIT-40) and was re-tested for them: on Windows PowerShell 5.1.26100.9444 grim's non-ASCII PowerShell script fails to load through `Get-Content -Raw | iex` and a dot-sourced `.ps1`, loads with mojibake tooltips through the native pipe, and loads cleanly with a UTF-8 BOM through all three routes (re-run today, R2). A BOM helps three routes and breaks `irm | iex` (conflict 4), and the emitter does not choose which route a user takes; ASCII works on every route, so the dive's "or emit a BOM" alternative is dropped.
10. **Guards are numeric or probes, never parsed text, and newer syntax lives in a separate file** (SH-EMIT-30): a dead `?:` branch makes Windows PowerShell 5.1 reject the whole file.
11. **Completion registration** (SH-EMIT-33..41). "Registered" is a read-back from the live engine, never a file on disk (SH-EMIT-33). Zero-rc locations exist for bash (`${BASH_COMPLETION_USER_DIR:-${XDG_DATA_HOME:-$HOME/.local/share}/bash-completion}/completions/<cmd>`, lazy) and fish (`completions/<cmd>.fish`); **none exists for zsh, elvish or PowerShell**, where an rc line is the only user-scope route (SH-EMIT-34..36, 38, 39). nu registers per command with an `export extern` module in an autoload directory and never assigns the single `external.completer` slot (SH-EMIT-37). PowerShell registers with `-Native -CommandName <cmd>` using the bare command name (it serves six spellings on 7.6.6, 7.4.7 and 5.1; registering only `<cmd>.exe` serves two and leaves four on file completion, SH-EMIT-33); `-NativeFallback` is one session-wide slot that a tool displaced the user's on 7.6.6 and that throws on 7.4.7 and 5.1 (SH-EMIT-39). A generated completion script is executed text: it is ASCII only and its help strings are untrusted input (SH-EMIT-40, 41).
12. **Directory-change and pre-exec hooks** (SH-EMIT-42..47). Directory change has an append-safe point in every shell except bash: zsh `add-zsh-hook chpwd`, fish `--on-variable PWD`, nu `env_change.PWD`, elvish `$after-chdir`, PowerShell 7.x `LocationChangedAction` through `[Delegate]::Combine` (assignment drops the user's handler, 0 of 4; `+=` throws); Windows PowerShell 5.1 has no such property and wraps `prompt`. In both PowerShell forms the hook body must test `$PWD.Provider.Name -eq 'FileSystem'`, because `Set-Location Env:` fires the same hook (unguarded, the body ran for `Environment` on 7.4.7, 7.6.6 and 5.1; re-run today, R3). A `cd` wrapper sees 2 of 4 changes (`pushd`/`popd` bypass) and fails every harness (SH-EMIT-42). bash has no directory event: a `PROMPT_COMMAND` compare, and `blehook CHPWD` under ble.sh 0.4 behind the `declare -F blehook` probe, because the compare is lost in the attach-to-first-prompt window (0 of 1 `cd` events on v0.4.0-devel3 and the nightly, fires on v0.3.4; SH-EMIT-43). A bash pre-exec hook is the one place where the safe form depends on what else is loaded; do not own one unless the feature needs it (SH-EMIT-44). PowerShell has no per-line pre-exec point (`PreCommandLookupAction` fired 5 times for one typed line, SH-EMIT-45) and nu's `env_change.PWD` fires at the next REPL cycle (SH-EMIT-46).
13. **The cmd.exe Batch arm** (SH-EMIT-48..50). Measured on the real Windows host (build 26100, `cmd.exe /c` from a `C:` cwd, four channels, delayed expansion off/on): the refusal set for `SET "K=v"` is `% " LF CR` plus `!`, NUL, U+001A, the empty string, any non-ASCII byte and a statement over 8000 characters. ocx's four-character set leaves 62 of 186 admitted runs wrong (dive) and 90 of 296 on the 36-case corpus (re-run today). Doubling `%` is right only in a batch file (SH-EMIT-49).

#### A. Caught by the hostile-corpus round trip (real interpreter, byte-for-byte)

`bash $FQ/check.sh <quoter> <family>...` evaluates each of the 36 corpus lines in the target, prints the hex of the resulting variable, and exits 1 on any mismatch or on `NOT-REJECTED`.

**SH-EMIT-01 (MUST). Use one quoter per (target shell, quoting context) and name it for both** (`fish_single_quoted`, `fish_double_quoted`, `posix_single_quoted`); never reuse a quoter across targets whose quoting grammar differs.
- Why: the failure set follows the grammar. fish gives `\` meaning inside `'..'`; nu and elvish `'..'` cannot hold `'` at all.
- Verify: `bash $FQ/check.sh fish_posixquoter fish` exits 1 (`32/35 FAIL backslash,trailing_bs,dbl_bs` on fish 3.6.0, 4.0.2, 4.7.0, 4.9.3); `check.sh nu_posixquoter nu` exits 1 (`29/35 FAIL squote,inject,curly_mixed,nu_hash,trail_sq,big4k` on 0.105.1 and 0.116.0); `check.sh elvish_posixquoter elvish` exits 1 (29/35, 0.21.0). Twins `check.sh fish fish`, `nu_raw nu`, `elvish elvish` exit 0 at 35/35. Reading heuristic: `grep -rnF -e 'shell_words::quote' -e 'shell_escape::unix::escape' -e 'shlex.quote' --include='*.rs' --include='*.py' DIR`; every hit must sit in an sh/bash/zsh/ash/ksh/dash arm.
- Watched: yes, re-run today (qc §2).
- Scope: any code emitting more than one target shell.

**SH-EMIT-02 (MUST). Quote a value for each target with exactly this literal form.**
- sh family (sh, bash, zsh, ksh, mksh, dash, ash, yash, posh): `'..'` with `'` written `'\''` and nothing else.
- fish: `'..'` escaping `\` first, then `'` (`\\`, `\'`). A fish double-quoted form escapes `\`, `$`, `"` and leaves the backtick alone.
- nushell: raw string `r#'..'#` with n hashes, n = 1 + the longest run of `#` directly after any `'` in the value; or a plain `".."` escaping `\` then `"`. Never `'..'` for arbitrary data, never an interpolating `$".."` or `$'..'`.
- elvish: `'..'` with `'` doubled; backslash is ordinary.
- Why: documented grammars ([POSIX XCU 2.2.2](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html), [fish quotes](https://fishshell.com/docs/current/language.html#quotes), [nu strings](https://www.nushell.sh/book/working_with_strings.html), [elvish 3.3](https://elv.sh/ref/language.html)); a fixed hash count breaks on `'#` (`nu_hash`).
- Verify: `bash $FQ/check.sh sh posix bash zsh` (35/35 on dash 0.5.12, busybox ash 1.35/1.37, mksh R59c, ksh93u+m x2, posh 0.14.1, bash 3.2/5.2 `--posix`, zsh 5.9 `emulate sh`, bash 3.2 to 5.3, zsh 5.0.8 to 5.9; yash 2.52 23/35 in the C locale and 35/35 under `LC_ALL=C.UTF-8`, so the run exits 1 on the yash C-locale row until yash gets the locale), `check.sh fish fish`, `nu_raw nu`, `nu_dq nu`, `elvish elvish`. Reds are SH-EMIT-01's plants.
- Watched: yes, re-run today for `sh posix`, `fish`, `nu_raw`, `elvish`.
- Scope: each target as named; fish 3.6.0 to 4.9.3, nu 0.105.1 to 0.116.0 (the quoting grammar was stable across both), elvish 0.21.0.
