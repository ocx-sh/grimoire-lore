## Verdict

**Premise check: accurate, with one correction.** The Bun Zig→Rust port is real and dated — trial branch 2026-05-05, "Rewrite Bun in Rust" merged 2026-05-11–14 (6,502 commits, 1,448 `.zig` files, ~1M net lines added), shipped in Claude Code v2.1.181 on 2026-06-17 ([bun.com/blog/bun-in-rust](https://bun.com/blog/bun-in-rust); [The Register 2026-05-05](https://www.theregister.com/software/2026/05/05/anthrophics-bun-team-trials-port-from-zig-to-rust/5222094)). Anthropic *has* published on it ([claude.com/blog/ai-code-migration](https://claude.com/blog/ai-code-migration)). The correction: Anthropic acquired Bun in late 2025, so that post is a vendor writing up its own model rewriting its own product — methodology worth copying, numbers worth discounting.

1. **OCX does not get Bun's playbook.** Bun's big-bang run was licensed by a 1M+-assertion pre-existing suite. Grimoire has zero `tests/` directory and 207 inline `#[cfg(test)]` blocks (`crate-architecture.md:271-276`); ocx has 354 plus 7 integration files. We take the Rust-for-Linux/strangler-fig model — one boundary at a time, old path live until the new one has equivalent coverage (PORT-20).
2. **Conflict resolved — determinism-first, not AI-first.** Anthropic's post treats LLM bulk generation as the default with compilers/tests as the net; the counter-position ([ecosystem4engineering](https://ecosystem4engineering.substack.com/p/the-value-of-ai-for-large-scale-refactoring)) treats recipes as the default and AI as the exception. We take recipe-first: rust-analyzer SSR is name-resolution-aware and free, our transforms are mostly mechanical, and we lack the suite that makes AI-first survivable (PORT-04).
3. **Conflict resolved — "green suite" is a gate, not evidence.** Bun's 100%-green merge still shipped 19 regressions; Andrew Kelley's objection (a suite that missed bugs in the Zig cannot certify 1M lines of unreviewed Rust) is methodologically correct even where its tone is not. We require the oracle's *power* be measured before it is trusted (PORT-06) and a parity snapshot captured pre-refactor (PORT-05).
4. **Conflict resolved — the owner's stated pain point is half wrong.** Grimoire is *more* free-function-dense than ocx (38.9% vs 24.6% of non-test fns; 6.97 vs 5.15 per kLOC, `crate-architecture.md:40-44`). ocx's real defect is the inverse: one `PackageManager` with 603 methods across 23 `impl` blocks in 23 files (`crate-architecture.md:67-90`). Two different refactors, not one.
5. **Unsafe-density and FFI-boundary rules are out of scope here.** Bun's ~4%/13,000 `unsafe` sites are an artifact of porting a manual-memory language across a JSC/BoringSSL/SQLite FFI seam; neither ocx nor grimoire has that shape. We keep only the generalized form: do not move a trust or I/O boundary inside a structural refactor (PORT-09).
6. **The port itself is not the deliverable; the loop is.** "You don't fix the code, you fix the process that produced the code" ([claude.com/blog/ai-code-migration](https://claude.com/blog/ai-code-migration)) is the single rule the rest hang off — every defect found gets patched in the rulebook, not the file (PORT-13).

## The ruleset

| ID | Rule | Rationale | Verification | Severity |
|---|---|---|---|---|
| **PORT-01** | Write a single rulebook (target shape, ownership/error conventions, dependency map, known gaps) and commit it *before* the first code-move commit. | Parallel workers each answer an unstated design question differently; Bun spent ~3h on `PORTING.md` + `LIFETIMES.tsv` before touching 1,448 files. | `git log --diff-filter=A --format=%ci -- <rulebook>.md` predates the first commit that moves code. | MUST |
| **PORT-02** | Validate the rulebook on 2–5 representative units with full adversarial review before fanning out to the rest. | A systemic rule error costs 1000× more to fix after 1000 files than before. Bun trialled 3 files with 1 implementer + 2 reviewers + 1 fixer. | `git log --oneline` shows a small trial range, then a review gap, then the bulk range. | MUST |
| **PORT-03** | Size every work package so its completion is checkable from disk/build state alone (file exists + `cargo check` passes + its tests pass) — never from an agent's self-report. | This is what makes the queue rebuildable after a crash, rate limit, or context reset. | Delete the task list, regenerate it from a filesystem + `cargo check --workspace` scan; the remaining set must be identical. | MUST |
| **PORT-04** | For any transform expressible as a structural pattern (rename, `use`-path update, signature-preserving call-site rewrite), use rust-analyzer SSR (`$pat ==>> $repl`) or ast-grep — not an agent, and never `sed`/`grep -l \| xargs sed`. | SSR resolves names, so it distinguishes two identically-spelled `foo::Bar`; regex silently rewrites strings and comments. Extends ocx's existing "prefer LSP over Grep for symbol ops" rule (`rules-inventory.md:327`) from *reading* to *writing*. | For a pure rename, `git diff` must show zero changes inside `//`, `///`, or string literals. Reviewer asks "could this have been one `ast-grep --update-all`?" — if yes and it wasn't, reject. | MUST |
| **PORT-05** | Capture characterization snapshots of CLI behaviour (stdout, stderr, exit code, filesystem effects) from the **pre**-refactor binary, commit them before any structural change, and re-run them unmodified at every merge point — not only at the end. | Compiling + unit tests green is necessary and insufficient: Bun shipped 19 regressions off a 100%-green suite. Localising a regression one crate-move after it lands is far cheaper than after the whole split. | Snapshot diff empty (`cargo insta test --unreferenced=reject`); snapshot files' add-commit predates the refactor branch point and was not regenerated mid-refactor. | MUST |
| **PORT-06** | Run `cargo mutants` on the **pre**-refactor code and record the kill rate before treating "tests pass" as an equivalence oracle. | A green suite with a low kill rate will not notice most regressions a refactor introduces. This is the mechanised form of ocx's own "Unchecked Green" rule (`rules-inventory.md`, §5) — a green check is evidence only if a red one was reachable. | `cargo mutants --baseline=skip --in-diff <refactor.diff>`; kill rate recorded in the rulebook, threshold enforced in CI on the baseline. | MUST |
| **PORT-07** | Gate merge on the suite that **predates** the change, at unchanged pass criteria. A suite or assertion written during the port is not a parity oracle. | A suite invented alongside the new code encodes the new code's assumptions. | `git log -1 --diff-filter=A --format=%ci -- <test path>` predates the refactor branch point; CI runs the same job on both branches. | MUST |
| **PORT-08** | Review agents get the diff **only** — never the implementer's reasoning, plan, or chain-of-thought — and are instructed to assume the code is wrong. | Same-context reviewers evaluate whether the rationale is self-consistent, not whether the code is correct. This is the control that caught Bun's use-after-free, `trunc`/`floor`, and `unwrap_or` bugs. | Inspect the review subagent's prompt: it must contain the diff and the rulebook, and must not contain the implementer's transcript. | MUST |
| **PORT-09** | A structural refactor must not change any trust, I/O, or wire boundary in the same pass — exit-code mapping, OCI request shape, path-containment guards, `std::fs` call sites stay byte-identical. | Bundling a boundary redesign with a move makes every regression ambiguous between the two. Bun kept every JSC/BoringSSL/SQLite call verbatim precisely so bugs were provably on the ported-logic side. This is the Two Hats Rule (`rules-inventory.md:745`) extended from optimization to boundaries. | `git diff` filtered to `path_safety.rs`, `classify.rs`/`ClassifyExitCode`, `oci/`, and any `AnchoredPath` call site must be empty for a move-only commit. | MUST |
| **PORT-10** | No `debug_assert!` may contain a side effect (mutation, I/O, state change) — only a pure predicate. | Its body is compiled out in release, so "tests pass" and "production behaves the same" diverge silently. Bun's #30678 broke HMR exactly this way. | `grep -rn --include='*.rs' 'debug_assert' src/` and read every match; any argument containing `=`, `.push`, `.insert`, `.take`, or a call with side effects fails. | MUST |
| **PORT-11** | `unwrap_or` may take only a literal or a bare variable; anything computed goes in `unwrap_or_else`. | The argument is evaluated eagerly, so a fallback that panics fires precisely in the `None` case it was meant to cover. Canonical LLM mistake — the short form dominates training data. | `grep -rn --include='*.rs' '\.unwrap_or(' src/` then inspect every match whose argument contains `(`, `[`, `?`, or an operator. Same for `ok_or`/`map_or`. | MUST |
| **PORT-12** | After any "make it compile" pass, scan for stubs; reject any workaround that needs a paragraph-long justification comment. | Bun's team watched Claude read "get the crates to compile" as licence to stub function bodies. Code that defends itself at length is hiding a shortcut. | `grep -rn --include='*.rs' -E 'todo!|unimplemented!|not implemented' src/` returns nothing new, and `git diff --stat` shows no function body that collapsed to `Ok(Default::default())`. | MUST |
| **PORT-13** | When a defect pattern appears, patch the rulebook and re-run the affected package — do not hand-fix the one file. Bucket compile and test failures by root cause, not by file. | The fix must propagate to every future generation; per-file fixes leave the generator producing the same defect. | Each fix commit that follows a bucketed failure touches the rulebook; the failure category does not recur in a later package. | MUST |
| **PORT-14** | Every item newly made `pub` at a crate boundary is reviewed individually, and `cargo semver-checks` gates the extracted crate in CI. Do not report "API compatible" on a green run when a field or parameter *type* changed — the tool does not yet detect that. | Extraction is visibility-widening by construction; the agent's fastest fix for a private-item error is `pub`, which permanently enlarges the API. Currently unmentioned anywhere in ocx/grimoire rules (`rules-inventory.md:1060`). | `cargo semver-checks check-release` (0 pass / 100 violations / 101 tool error) plus `git diff -U0 \| grep -E '^\+\s*pub '` reviewed line by line. | MUST |
| **PORT-15** | An agent that hits a private-item error exports the original; it never inlines a copy. | The copy compiles and silently forks behaviour — the failure mode is invisible to every gate in this table. | `grep -rn --include='*.rs' -F "<moved fn name>" src/` returns exactly one definition. | MUST |
| **PORT-16** | Any diff that loosens an assertion or deletes a test during a refactor carries production-code review weight and an explicit reason. | Weakening the assertion is how a real regression becomes invisible; under pressure to turn red green, this is the cheapest move available to an agent. | CI flags any commit touching `assert*!` or `#[test]` bodies in the same change as moved production code for separate sign-off. | MUST |
| **PORT-17** | One git worktree per agent, one branch each. Agents may run only `git` commands that commit named files — never `git stash`, `git reset`, `git checkout -- .`, or `git clean`. | Bun adopted this after losing work; concurrent `git`/`cargo` in one tree also produced index and disk-space failures at 64 agents. Split at ~16 agents per tree. | The agent's allowed-command list denies `stash`/`reset`/`clean`; `git reflog` shows no destructive entries on the integration branch. | MUST |
| **PORT-18** | Merge in dependency order — leaves first, per the rulebook's dependency map — not in completion order, and serialize compilation through one build path even when generation is parallel. | Concurrent compiles contend for CPU and produce flaky failures that get misattributed to the refactor. | Merge-commit order matches the dependency map; CI shows one compile job at a time. | SHOULD |
| **PORT-19** | Converting a free function to a method requires a passing parity diff, not just a green build. | `fn f(cfg: &Config, p: &Path)` → `impl Config { fn f(&self, p: &Path) }` can change borrow duration or drop an implicit clone — compiles, behaves differently. | PORT-05 snapshots re-run on the converted path; `cargo mutants --in-diff` on the conversion diff kills its mutants. | MUST |
| **PORT-20** | For an intra-repo restructure, name specific module boundaries with a per-boundary "old path removed" milestone; do not schedule a single "whole crate rewritten" milestone. Keep a `#[deprecated] pub use` shim at each old path and remove all shims in one final, separately revertible commit. | Bun's big-bang depended on an unusually complete suite and one accountable owner watching 64 agents; neither codebase here has the first. | The plan lists boundaries and per-boundary milestones; `grep -rn '#\[deprecated\]' src/` is empty only after the final shim-removal commit. | MUST |
| **PORT-21** | Run parser/decoder fuzzing and dedicated security review as a **post**-merge phase, and treat merge as the start of a fix window, not the finish line. | Fuzzing finds a different bug class than a fixed assertion suite structurally can — Bun's post-merge fuzzing produced ~15 fix PRs after the suite was already green. | `cargo fuzz list` covers every manifest/lockfile/config parser; the fuzz job runs on a schedule, not only pre-merge. | SHOULD |
| **PORT-22** | Add a source-text structural regression test for any security-relevant call the refactor could silently drop. | ocx already does this: `ocx_cli/src/main.rs:39-60` reads its own source and asserts the `sanitize_for_terminal` call and `{err:#}` token survive, because the original defect was an *absent* call no positive behavioural assertion could catch (`errors-async-security.md:112,121`). | The test exists and fails when the call is removed (verify by deleting the call locally). | SHOULD |
| **PORT-23** | Use the cheapest capable model for bulk mechanical fan-out; reserve the top tier for rulebook authoring and adversarial review. Never the reverse. | Token volume dominates cost in bulk work; judgment quality dominates outcome in rules and review, where a mistake propagates. | Spawn logs (`.claude/state/subagents.jsonl`) show the rulebook and review agents on the higher tier. | SHOULD |
| **PORT-24** | Treat `cargo fix --edition` as a starting point: doctests, `build.rs`, and macros/proc-macros are explicitly out of its scope and need a manual pass. | The tool says so; an agent will report the migration complete anyway. | `cargo test --doc` passes; the diff is checked for untouched `build.rs` and proc-macro crates. | SHOULD |
| **PORT-25** | Do not blanket-trait-ify during a restructure. Introduce a trait only where 2+ genuinely different implementations exist or a real I/O seam is being closed. | ocx already carries 4 utility extension traits (`StringExt`/`SerdeExt`/`ResultExt`/`VecExt`) that are the trait-for-trait's-sake pattern (`crate-architecture.md:289`); a refactor pass is exactly when an agent multiplies them. | Every trait added in the diff names its second implementor or the fake it enables. | CONSIDER |

## Applied to OCX

**Already satisfied.**
- Semantic tooling over text search for symbol ops is already a rule (`rules-inventory.md:327`, `:740`); PORT-04 only extends it from reading to writing.
- The Two Hats Rule — never mix refactoring with optimization, commit before switching (`rules-inventory.md:745`) — is PORT-09's parent; PORT-09 adds boundaries to the list of hats.
- "Unchecked Green" (ocx only, absent from grimoire's copy) already states that a green check counts only if red was reachable; PORT-06 is its mechanised form.
- Verification Honesty's banned-phrase table (`rules-inventory.md`, §5) already makes "should work" a Warn and "verified" without evidence a Block — this is PORT-03's cultural half.
- PORT-22 is already practised in ocx: `ocx_cli/src/main.rs:39-60` (`errors-async-security.md:112`).
- Layering is clean in ocx — 33 apparent `ocx_cli` hits inside `ocx_lib` are all doc comments, zero real imports (`crate-architecture.md:206-211`), so PORT-18's dependency-ordered merge has a real graph to follow.

**Violated or absent.**
- No `cargo-semver-checks`, no MSRV policy, no mutation testing, no snapshot/`insta` guidance anywhere in the rules (`rules-inventory.md:1041`, `:1060`) — PORT-05, PORT-06, PORT-14 are new commitments, not restatements.
- Grimoire has **zero** `tests/` directory; 100% of Rust-level testing is inline units (`crate-architecture.md:272,276`). The only existing CLI-level parity oracle in either repo is the Python acceptance tree at repo root (`crate-architecture.md:275-276`). PORT-05 has no Rust-side harness to attach to yet.
- Grimoire's `main.rs:191` writes `{err:#}` to stderr with no terminal sanitization, where `ocx_cli/src/main.rs:20-27` neutralizes the chain against CWE-150 with an explicit comment and a structural test (`errors-async-security.md:45`). Under PORT-09 this divergence must be closed *before* a restructure, not during one.
- 1,664 (ocx) / 906 (grimoire) direct `std::fs`/`tokio::fs` call sites with no filesystem trait seam (`crate-architecture.md:221-228`, e.g. `ocx_lib/src/package/description.rs:51`, `utility/fs/path.rs:296`, `setup/shims.rs:314`, `grimoire/src/catalog/forge.rs:263`). PORT-09 forbids closing these seams inside a move commit; PORT-25 forbids doing it wholesale.

**Newly committed to.**
- **ocx's `PackageManager` decomposition is the PORT-20 test case.** 603 methods across 23 `impl PackageManager` blocks in 23 files (`crate-architecture.md:70-90`, worst: `composer.rs` 154, `tasks/resolve.rs` 100, `tasks/inspect.rs` 53). The file split already encodes the boundaries, so each file's block becomes one type — a per-boundary milestone set that falls out of the existing layout for free, with `#[deprecated] pub use` shims per PORT-20.
- **`grimoire/src/catalog/forge.rs` is the one place an agent, not a codemod, is warranted.** 39 free fns in near-perfect `github_*`/`gitlab_*` pairs (`crate-architecture.md:192`) → one `ForgeApi` trait with two implementors. It clears PORT-25's bar (two real implementations) and fails PORT-04's (SSR cannot decide which type owns behaviour).
- **`grimoire/src/command/config.rs`** — 5,158 LOC, 46 free fns, **zero** `impl` blocks (`crate-architecture.md:178-190`) — splits into `ConfigKeyParser`/`ConfigValidator` and `ConfigMutator`, each conversion gated by PORT-19.
- **Not every free-fn cluster is a defect.** `grimoire/src/tui/state.rs`, `tui/render.rs`, `tui/event.rs` are a deliberate functional-core/imperative-shell split documented in their own doc comments, and `ocx_lib/src/package/bin_scan.rs` is a legitimate pipeline (`crate-architecture.md:143,149,196`). A restructure agent must be told these are out of scope, or PORT-25 gets violated in the name of consistency.

## AI-agent failure modes

Ranked by observed frequency.

1. **Stubbing to satisfy "make it compile."** Bun's team watched Claude read the instruction as licence to replace bodies with placeholders. Caught by PORT-12.
2. **Weakening the assertion instead of fixing the code.** The cheapest path from red to green, and it destroys the oracle. PORT-16.
3. **Over-widening visibility to unblock a private-item error.** `pub` compiles; it also permanently enlarges the API. PORT-14.
4. **Reporting "all tests pass" as proof of equivalence.** Bun: 100% green pre-merge, 19 post-merge regressions. PORT-05 + PORT-06.
5. **Reaching for `sed`/regex for a Rust-wide rename**, matching identifiers inside strings, comments, and unrelated modules. PORT-04.
6. **Reviewer given the author's context rubber-stamps.** It grades the rationale's internal consistency, not the code. PORT-08.
7. **Eager `unwrap_or`** — `unwrap_or(1.0 - x.unwrap())` compiles, works in the common case, panics exactly when the fallback was needed. PORT-11.
8. **Inlining a copy of a private item** rather than exporting it — a silent duplication that every other gate misses. PORT-15.
9. **`debug_assert!` with a side effect**, invisible until release. PORT-10.
10. **Free-fn → method conversions that change borrow duration or drop an implicit clone.** Looks purely mechanical. PORT-19.
11. **Claiming semver safety `cargo-semver-checks` does not verify** — type-shape and generic/lifetime changes are outside its coverage. PORT-14.
12. **Destructive git (`stash`, `reset`, `clean`) in a shared tree.** Rare but unrecoverable. PORT-17.
13. **Declaring `cargo fix --edition` a finished migration** with doctests and macros untouched. PORT-24.

## Open questions

- **Mutation-kill-rate threshold (human decision).** No source proposes a numeric norm; PORT-06 requires one per repo. Someone must pick the number for `ocx_lib` and for `grimoire` before PORT-06 is enforceable in CI.
- **`PackageManager` decomposition shape (one-way door, needs an ADR).** Field-per-extracted-type, `Deref` delegation, or explicit forwarding methods? 603 methods and 23 call-site families make this expensive to reverse (`crate-architecture.md:284`).
- **Is `cargo-semver-checks` meaningful here at all?** Both are binary crates with no external library consumers (`crate-architecture.md:216`). PORT-14 may reduce to "review new `pub` items" with the tool adding nothing. Needs a decision before it goes in CI as a hard gate.
- **Research round warranted — CLI characterization testing for a side-effecting binary.** PORT-05 has no Rust harness in either repo, and the rules inventory names snapshot testing as an explicit gap (`rules-inventory.md:1041`). Specific question: what combination of `insta`, `trycmd`/`assert_cmd`, a temp-dir filesystem oracle, and `wiremock` for the ghcr.io path produces a parity snapshot that is deterministic across Linux/macOS/Windows — and can the existing Python acceptance trees be the oracle instead of new Rust harnesses?
- **Research round warranted — Rust workspace splitting under a binary crate.** Specific question: what actually breaks when `grimoire`'s single crate is split — `[patch]`/`[profile.*]` being root-manifest-only, feature unification across new members, and build-time regression from losing a single compilation unit. None of the consulted sources measured the cost side.
- **Not worth researching:** unsafe density, FFI boundary conventions, `Miri`. Neither codebase has the shape that made those load-bearing for Bun.
