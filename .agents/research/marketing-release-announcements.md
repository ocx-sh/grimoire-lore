# Release announcements

The fleet does not write its release notes. A generator writes them. git-cliff renders the commit history through `cliff.toml`, and cargo-dist (grimoire only) wraps the result with install blocks. This file decides the contract that makes those generated bodies something a user can act on. The contract covers commit subjects and footers, the template, the CI gate on the rendered body, which tags must carry a Release, and how deprecations and breaking changes are announced. It does not cover announcement venues (blog, social, email), GitHub release mechanics such as immutability and the Latest flag, or the CHANGELOG file format. Channels owns the first two. `docs-quality` DOC-TYPE-37..41 owns the file format.

## Verdict

1. **The template is the release-note author. The lever is `cliff.toml` and the commit footer, not a prose skill.** Generated notes ship at 9 of 9 released repositories ([distribution-posture.md](product-audit/distribution-posture.md), smell 5 under "What this contradicts"). 6 of the 12 fleet `cliff.toml` files start with the header `ocx-baseline: template-owned file — change ocx-sh/conventions`. So one change to `ocx-sh/conventions/template/cliff.toml.jinja` fixes ocx, ocx-mirror, rules_ocx, website, devcontainer-features and conventions in one copier round. The dives treated the problem repo by repo. This consolidation found the shared owner (measured below) and routes the fix there first.
2. **Adopt grimoire's model (generated entry plus a footer-fed Migration line) fleet-wide, and retire the "the body is never read" model.** grimoire renders 5 Migration lines for 5 BREAKING bullets. ocx renders 0 for 45 ([release-body-contract.md](marketing-release-announcements/release-body-contract.md) F1). The cause is one template block, `grimoire-rs/grimoire/cliff.toml:29-30` against `ocx-sh/conventions/template/cliff.toml.jinja:29`. The vscode rule "never hand-write" stays: generation is right, and only the template is wrong. This does not contradict DOC-TYPE-38 ("never let a version section be a re-rendered commit log"; its check flags a section where every line matches a Conventional Commits prefix verbatim with no rewrite). The template rewrites every subject: it strips the `type(scope):` prefix, regroups by Keep a Changelog category, drops internal scopes (MKT-REL-06), adds Migration lines (MKT-REL-03) and opens notable releases with a summary (MKT-REL-14). The tested render in `~/.cache/research-lang/exemplars/product/cliff-test/notes.md` has 0 prefixed bullets, and MKT-REL-10 now fails any body with one. A patch body stays one rewritten line per user-facing commit, which is the residue DOC-TYPE-38 tolerates as a reading heuristic, not a check.
3. **Conflict resolved: route Deprecated, Removed and Security by commit footer, not by new commit types.** The body-contract dive proposed `deprecate:`, `remove:` and `sec:` types. The fleet's commit-msg check accepts only `feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert` (`ocx-sh/conventions/template/taskfiles/baseline.taskfile.yml:50`), so those commits would be rejected at commit time. A `Changelog: deprecated|removed|security|skip` trailer, plus a `Deprecated:` trailer that carries the replacement, works with the existing type list. It was tested with git-cliff 2.14.1 (see MKT-REL-05).
4. **Conflict resolved: breaking items are marked `**BREAKING:**` and listed first inside their Keep a Changelog category. There is no separate `### Breaking changes` heading.** The body-contract dive copied uv's heading. DOC-TYPE-37 requires the six Keep a Changelog headings exactly, and the GitHub body and `CHANGELOG.md` come from the same template (cargo-dist copies the file section). A seventh heading would break the docs check on every changelog. Common Changelog's bold-prefix, breaking-first form ([common-changelog.org](https://common-changelog.org/)) meets both rules. The `Documentation` group in all 12 fleet templates breaks DOC-TYPE-37 in the same way (19 `### Documentation` headings in the ocx CHANGELOG, 23 in grimoire's), so that group is removed.
5. **Conflict resolved: the fleet under-marks and over-marks breaking changes, and one definition fixes both.** The body-contract dive called the main defect over-flagging. The deprecation dive called it under-marking. Both happen in ocx. Measured by the reviser on 2026-11-27 in the `ocx-sh/ocx` checkout (main): `git log -1 --format='%h %cs %s' 0c7c3ffc` prints `0c7c3ffc 2026-11-15 ci(release)!: Windows release archives are named for the gnullvm target they contain`, its body says "Consumer-visible rename: ocx-{x86_64,aarch64}-pc-windows-gnullvm.zip replaces the msvc names", and `git tag --contains 0c7c3ffc` lists `v0.6.7` first. The `^ci` skip parser dropped it: `grep -ci gnullvm CHANGELOG.md` prints `0`, although the file has a `## [0.6.7] - 2026-11-15` section (line 14). Meanwhile `sed -n 231p CHANGELOG.md` prints `- Dissolve ocx_lib into 17 responsibility-derived crates **BREAKING**` (section `## [0.6.3] - 2026-09-25`), an internal crate split announced as breaking. I read all 34 `!:` subjects in the last 400 ocx commits. About 5 do not break an existing invocation, and the rest change exit codes, defaults or outputs. The dominant defect is therefore the missing migration, not the flag rate. The definition in MKT-REL-02 decides each case: a change is breaking when something that worked against the previous release now fails or means something else.
6. **Conflict resolved: a stable tag always gets a Release. A tag with nothing user-facing gets the body "No user-facing changes." plus the reason.** The body-contract dive allowed skipping the Release. The coverage dive requires one per pinned tag, because copier, Renovate and npm consumers upgrade to the tag whether or not a Release exists. Coverage wins: the consumer reads the tag, so the human beside the consumer needs the sentence. Tested: a chore-only range renders a 0-byte body, so the gate in MKT-REL-10 is not optional.
7. **Conflict resolved: the summary sentence enters through `git-cliff --with-tag-message`, and the tag is annotated with the same text. The body-contract dive's "annotated tag message" route alone does not work, and the dive marked it untested (release-body-contract.md:259).** The fleet's tags are almost all lightweight. Reviser measurement, 2026-11-27: `git for-each-ref --format='%(objecttype)' refs/tags | sort | uniq -c` prints `38 commit` in `ocx-sh/ocx` and `31 commit, 3 tag` in `grimoire-rs/grimoire` (the annotated ones are v0.1.0, v0.2.0 and v0.15.0); `git cat-file -t` prints `commit` for ocx v0.6.8 and grimoire v0.17.0. So the template's `message` field is empty for nearly every past release. `--with-tag-message` sets it for the release being rendered ([git-cliff args](https://git-cliff.org/docs/usage/args), v2.14.0). Tested for the git-cliff lane: in fixture `repo2`, `git-cliff --config ../cliff.final.toml --unreleased --tag v9.9.9 --with-tag-message "Publish now takes --version; the --tag flag is removed."` (git-cliff 2.14.1) prints that sentence as the first line, above `### Added`; output saved with its command at `~/.cache/research-lang/exemplars/product/cliff-test/with-tag-message.out`. **Unverified:** the cargo-dist lane (grimoire), where cargo-dist renders the body itself, and whether a full regeneration reads the message back from an annotated tag (documented in the [git-cliff context](https://git-cliff.org/docs/templating/context), not run here, because creating a tag changes repository state). The sentence is required only when a release adds, removes, deprecates or breaks something. A fix-only patch gets no boilerplate sentence, which reverses the body-contract dive's "Fixes N bugs" filler.
8. **Deprecate before removing on any surface the project has called stable. The window number is an owner decision, kept in one published policy file.** The fleet has never deprecated its own surface before removing it: 0 of 26 removal-worded BREAKING entries had an earlier deprecation ([release-deprecation-breaking.md](marketing-release-announcements/release-deprecation-breaking.md) finding 1). grimoire's README says "released surfaces are frozen contracts" (`grimoire-rs/grimoire/README.md:26-27`), but `GRIM_RATING_HOST` was removed in a single release (`CHANGELOG.md:398-399`). The promise and the practice disagree, and only the owner can say which one changes. Default windows are proposed for that decision in MKT-REL-08.
9. **Commit hashes never appear as visible text. A reference is a `[#N]` pull-request link or nothing.** Common Changelog allows a linked hash. No measured upstream CLI prints one (0 hashes in 20 bodies from uv, ruff, deno and bun), and a 7-hex string tells a reader nothing.
10. **Licence, terms and pricing changes are announced by the owner, never by an agent.** The agent drafts the notice to a fixed field list and stops. This file owns only the notice that rides a release. The licence and pricing decision belongs to the owner, and the wording of a price, limit or licence claim on copy surfaces belongs to marketing-claims-evidence (MKT-CLAIM-03 for prices and limits, MKT-CLAIM-12 for SPDX ids).
11. **Dropped from the dives:** the 125,000-character body limit (its source is a community issue, and the largest fleet body measured is 9,730 characters); the README pre-1.0 statement (messaging territory); immutable releases and `releases/latest` behaviour (channels: GitHub as a channel); per-release curated site pages (an owner decision, not a rule).

## The ruleset

Every verification below was run or was read against the named file on 2026-11-27. "Tested" means the command was run against a synthetic repository with git-cliff 2.14.1 (`ocx exec -g release -- git-cliff`). The tested template is at `~/.cache/research-lang/exemplars/product/cliff-test/cliff.final.toml`.

| MKT-REL-01 | Change the release-notes template in the file that owns it. When `cliff.toml` is generated from an upstream template (its header names the owner), edit the upstream template and propagate it. Never edit the downstream copy. *Fleet-scoped:* the header string checked below is the ocx-sh `ocx-baseline` copier header; an adopter substitutes its own generator's header. | 6 of 12 fleet `cliff.toml` files are copier output from `ocx-sh/conventions/template/cliff.toml.jinja`. | MKT-REL-02 | Mark a commit breaking (`!` and a `BREAKING CHANGE:` footer) exactly when an invocation, flag, environment variable, config key, file format, exit code, JSON field or download name that worked on the previous release now fails or means something else. Write the migration in the footer: what to change, the replacement, and the version from which the old form stops working. An internal refactor or an additive opt-in is never breaking. | Under-marking drops user-visible changes (the ocx gnullvm archive rename, `0c7c3ffc`, is absent from the notes; Verdict 5 gives the commands). Over-marking teaches readers to skip the flag ("Dissolve ocx_lib..." at `ocx-sh/ocx/CHANGELOG.md:231`). Conventional Commits 1.0.0 items 12-16 ([spec](https://www.conventionalcommits.org/en/v1.0.0/)). | (a) Per commit, not by totals: `for c in $(git log --format=%H <last-tag>..HEAD); do git log -1 --format=%s $c \| grep -qE '^[a-z]+(\([^)]*\))?!:' && ! git log -1 --format=%B $c \| grep -qE '^BREAKING[ -]CHANGE:' && echo $c; done` prints nothing. Over the last 400 ocx commits it prints 31 hashes (reviser, 2026-11-27): 34 `!` subjects, and only 3 of the 5 footers sit on a `!` commit, which a comparison of totals hides. | MKT-REL-03 | Render every breaking commit as `**BREAKING:** <subject>`, list breaking items first inside their Keep a Changelog category, and render `commit.breaking_description` as a `**Migration:**` line directly under the item. | MKT-REL-05 | Route deprecations, removals and security fixes with a commit trailer (`Changelog: deprecated`, `Changelog: removed`, `Changelog: security`, or `Changelog: skip` to omit a commit), matched by `footer` parsers placed before the type parsers. The fleet hook allows 11 types only (`conventions/template/taskfiles/baseline.taskfile.yml:50`). Tested: `{ footer = "^Changelog: ?removed", group = "Removed" }` routes a `feat(publish)!:` commit to `### Removed`. | `grep -cE 'footer = "\^Changelog' cliff.toml` is at least 4. The commit-msg regex in the hook is unchanged. A fixture commit for each trailer renders under its heading in a template test. | MUST |
| MKT-REL-06 | Skip commits by internal scope before any group parser, with the repository's internal scopes listed in one place: the skip parser itself (`{ field = "scope", pattern = "^(<internal scopes>)$", skip = true }`; the fleet list is `test\|ci\|deps\|release\|build\|chore\|lint\|taskfile\|claude\|agents`). Tested: `fix(test)` and `feat(claude)` are dropped by the `field = "scope"` matcher. | With `S` set to the pattern read from that skip parser: `grep -cE "^- .*\*?\(($S)\)" notes.md` prints 0. `grep -c '"Documentation"' cliff.toml` prints 0. | MUST |
| MKT-REL-07 | Give every deprecation a `Deprecated:` trailer that names the replacement and the removal version or date, rendered as a `**Migration:**` line under the entry. Kubernetes ([policy](https://kubernetes.io/docs/reference/using-api/deprecation-policy/), no date on the page, read 2026-11-27) requires deprecations to be announced in the release notes and deprecated CLI elements to warn on use, but does not require a removal version in the notice ([release-deprecation-breaking.md](marketing-release-announcements/release-deprecation-breaking.md) rows 3 and 4.1). Tested: `commit.footers \| filter(attribute="token", value="Deprecated")` renders the trailer. | `awk '/^### /{s=($0=="### Deprecated")} s' notes.md` gives the section. | MKT-REL-09 | Make a deprecated flag, config key or environment variable print one stderr line on use that names the replacement and the removal version. ## Agent failure modes

Ranked by how often each bites in the fleet evidence. Grouped by mechanism.

**A. Following a repository rule that leaves no route (most frequent).**
1. Writes `type!: subject` and no `BREAKING CHANGE:` footer, because the rule says the body is never read: 31 of 34 `!` commits in ocx have none. Caught by MKT-REL-02 (a) and MKT-REL-12.
2. Edits the downstream `cliff.toml`, which the next copier run overwrites. Caught by MKT-REL-01.
3. Hand-edits `CHANGELOG.md` or a published body because the task says "update the changelog". Caught by `git diff --name-only | grep -x CHANGELOG.md` in feature pull requests where the repository forbids it.

**B. Treating the generator's output as final.**
4. Ships a compare-link-only or empty body (indexbot 7 of 10; tested 0-byte chore-only render). Caught by MKT-REL-10.
5. Adds `protect_breaking_commits = true` and stops, which yields `### chore` headings. Caught by the MKT-REL-04 heading check.
6. Invents `deprecate:` or `sec:` types that the commit-msg check rejects, or a `scope =` key that overrides scope instead of matching it. Caught by the MKT-REL-05 fixture test.

**C. Mis-judging what is breaking.**
7. Uses `ci:` or `chore:` for a change users see (archive names), so it vanishes. Caught by MKT-REL-02 (c) and MKT-REL-04.
8. Marks internal refactors `!` "to be safe". Caught by MKT-REL-02 (b): a footer that restates the subject fails, and a "No migration needed" footer (accepted by DOC-TYPE-39) sends the agent back to the breaking definition.
8a. Gives a user-visible fix an internal scope (`fix(release): shipped binaries shrink...`), so MKT-REL-06 drops it. Caught by the MKT-REL-15 listing.
9. Removes a flag in one release with no deprecation, as the fleet does today (0 of 26). Caught by MKT-REL-08.

**D. Releases and tags.**
10. Reports "released" after `git push --tags`, or judges a template or preset repository "not a product". Caught by `release-gap.sh` and the consumer grep (MKT-REL-11).
11. Compares tags with `gh release list` at its default of 30 rows and reports a false gap or a false clean. Caught by `--paginate` in `release-gap.sh`.
12. Deletes and re-pushes a pinned tag to "fix" a missing Release. Prevention: `gh release create <tag> --verify-tag` on the existing tag.

**E. Invented facts in the notice.**
13. Writes a deprecation window ("12 months") as if it were policy. Caught by MKT-REL-08: the number must trace to the policy file.
14. Invents a docs URL for a Migration link. Caught by `lychee` (MKT-REL-16).
15. Drafts a licence or pricing post with an undefined restricted party or an unqualified "unlimited". Caught by MKT-REL-13.

## What an agent must ask a human

- Whether a change is breaking when no document or test names the surface as public. Propose `!` and a Migration draft, and let the owner confirm.
- The deprecation window numbers and the compatibility-policy text, and whether grimoire's "frozen contracts" README line or its removal practice changes.
- Moving ocx and the other conventions-templated repositories from the subject-only model to the footer model. This changes `AGENTS.md:33`, a rule that names the owner's workflow.
- Annotated tags and a `SUMMARY` input to the release task (a release-mechanics change), and whether a minor release also gets a curated site page or a blog post.
- Whether to backfill Releases for legacy tags (the coverage dive recommends conventions yes, indexer no), whether to release `website v0.4.0` and `ocx-mirror v0.5.3` late, and which tags go in the baseline file.
- Any licence, terms, pricing or limit change, its date and its wording. Whether a security fix is disclosed in the body, and when.
- Skipping a deprecation window for a security or legal reason.
- Whether ocx's stated pre-1.0 "no warning schedule" (`AGENTS.md:21`) also excludes the MKT-REL-02 Migration footer. The line forbids migration prose in user docs, not in the release notes, so this file reads it as compatible, but the owner wrote it.
