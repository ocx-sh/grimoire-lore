## Summary

- The bash pitfall literature is overwhelmingly one failure family: an unquoted expansion undergoes field splitting and then globbing. [BashPitfalls](https://mywiki.wooledge.org/BashPitfalls) #1, #2, #4, #5, #14, #24, #36, #50 are all that; Chazelas calls an unquoted variable "by far the number one source of security vulnerabilities associated with shell code".
- `set -e` is the single most contested feature. BashFAQ/105 lists three maintainers with three positions (do not use / use with care / handle errors explicitly); Maxwell's "unofficial strict mode" and MIT SIPB (`set -euf -o pipefail`) recommend it. The semantics differ by context (tested conditions, functions called from `if`/`&&`, `$(...)`, `local x=$(cmd)`, process substitution), by bash version, and by POSIX mode.
- `echo` is unportable for any data you do not control: POSIX leaves `-n` and backslashes unspecified. Measured: dash 0.5.12 prints `-e a<TAB>b` for `echo -e "a\tb"`; yash prints `-e` and `-n x`. The canon says `printf '%s\n' "$x"` and never a variable in the format string (SC2059).
- Filenames are arbitrary bytes except NUL and `/`: leading dashes need `--` or a `./` prefix, newlines defeat line-based tools, and `ls`/`find | xargs` parsing is "fatally flawed" ([BashPitfalls #1](https://mywiki.wooledge.org/BashPitfalls), [ParsingLs](https://mywiki.wooledge.org/ParsingLs)). POSIX.1-2024 now standardizes `find -print0` and `xargs -0`.
- POSIX.1-2024 (Issue 8) moved several "bashisms" into the standard: `set -o pipefail` (Austin Group Defect 789), `$'...'` dollar-single-quotes, `read -d`, `-nt`/`-ot`/`-ef` and `<`/`>` in `test`; it removed `test -a`/`-o` and `(`/`)`. Implementations lag: measured on dash 0.5.12, `pipefail`, `$'..'` and `read -d` all fail.
- macOS `/bin/bash` is 3.2.57 (GPLv2 ceiling) and `/bin/sh` is that same bash in POSIX mode, so bashisms under `#!/bin/sh` pass on a Mac and fail on dash and busybox ([Scripting OS X](https://scriptingosx.com/2020/06/about-bash-zsh-sh-and-dash-in-macos-catalina-and-beyond/), 2020; macOS 26 unverified). Bash 3.2 lacks assoc arrays, `mapfile`, `${x,,}`, `[[ -v ]]`, `|&`, `&>>`, `;&`, `local -n`, `wait -n`, `${x@Q}`, `coproc` (all measured).
- A parse-time bash 4+ construct kills the whole script on 3.2, not just the branch that uses it: `[[ -v x ]]` inside a never-called function still raises `conditional binary operator expected` (measured; BashFAQ/031 shows the same).
- `set -u` has version traps: measured on bash 3.2, `"${@}"` with no arguments is "unbound variable"; on bash 4.0 and 4.2 an empty array `"${arr[@]}"` is too (4.4+ fine). jmmv's bash-3.2 complaint is reproducible.
- `pipefail` combined with early-exit consumers (`grep -q`, `head -n1`) yields spurious failures from SIGPIPE (exit 141; measured `yes | head -1` with pipefail gives 141 in dash-family and bash, 1 in ksh93u+m, 397 in yash). The Wooledge advice is to enable it per pipeline, not globally.
- Temp files, traps and locks form one cluster: `mktemp -d` plus `trap cleanup EXIT` (POSIX sh needs HUP INT TERM too and a re-raise), `mkdir` as the atomic lock, `flock` where available, never PID files or `ps | grep` ([BashFAQ/062](https://mywiki.wooledge.org/BashFAQ/062), [/045](https://mywiki.wooledge.org/BashFAQ/045), [ProcessManagement](https://mywiki.wooledge.org/ProcessManagement)).
- Locale is a hidden input: `LC_ALL` overrides every `LC_*`, `[a-z]` and `sort` order depend on it, and bash 5.0 to 5.2 `read -d ''` can read past the delimiter in UTF-8 locales unless `LC_ALL=C` ([BashPitfalls #65](https://mywiki.wooledge.org/BashPitfalls), edited 2025-07-18; fixed in 5.3).
- Arithmetic contexts evaluate: `$(( ))`, `(( ))`, `let`, array subscripts and `[[ -eq ]]` run `a[$(cmd)]` as code, and a leading zero is octal (`08` is an error in bash). Pitfalls #7, #45, #46, #59, #62 and BashFAQ/121 cover it; validate with `case` before use.
- For code that emits shell, the canon gives one quoting primitive (`'` becomes `'\''`, Rich's `quote()`), but the per-shell rules diverge: fish has no `$'..'` and treats `\n` unquoted, nushell/elvish/pwsh have their own literals. Rc-file edits are order-sensitive: bash login vs non-login ([DotFiles](https://mywiki.wooledge.org/DotFiles)) and zsh instant-prompt I/O redirection ([powerlevel10k](https://github.com/romkatv/powerlevel10k)).
- PowerShell 5.1 vs 7 is a three-way split: syntax (no `?:`, `&&`, `??` on 5.1; measured parse errors), encoding (`>` writes UTF-16LE with BOM on 5.1, bytes `255,254,104,0`; UTF-8 without BOM on 7.x, measured), and native commands (`$PSNativeCommandArgumentPassing` 7.3+, `$PSNativeCommandUseErrorActionPreference` 7.4+, defaulting to `$false`, absent on 5.1).
- GitHub Actions: the default `run:` shell on Linux/macOS is `bash -e {0}` (no pipefail); only explicit `shell: bash` gives `bash --noprofile --norc -eo pipefail {0}`; on Windows the default is `pwsh -command ". '{0}'"` ([workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax)).
- The advice to leave shell is itself a mainstream position: Google's guide says rewrite at "more than 100 lines long, or that uses non-straightforward control flow", MIT SIPB's first rule is "Don't", Rich says POSIX sh is for "super-portable, lowest-common-denominator" bootstrap scripts only.
- ShellCheck is the shared mechanical layer: SC2086, SC2046, SC2155, SC2164, SC2181, SC2230, SC2064, SC2059 for hygiene; SC3001 to SC3067 for "undefined in POSIX sh"; optional checks (`require-double-brackets` SC2292, `check-extra-masked-returns` SC2312, `deprecate-which` SC2230).
- The fish, nushell and elvish literature is about differences from bash, not pitfalls: fish does no word splitting and has no heredocs; nushell breaks syntax roughly every release (0.114.0, 2026-07-04: submodules no longer implicitly imported, `enforce-runtime-annotations` opt-out, `str upcase` deprecated); elvish turns non-zero exit into an exception.

## Survey

### 1. BashPitfalls: all 65 entries, classed

Read in full: [mywiki.wooledge.org/BashPitfalls](https://mywiki.wooledge.org/BashPitfalls), last edited 2025-07-18. The index runs #1 to #65. Distinct classes (each is a candidate):

- **Split + glob on unquoted expansions**: #1 `for f in $(ls *.mp3)` (six listed problems: whitespace, globs, no delimiter, ls mangling, `$(...)` strips trailing newlines, leading dash), #2 `cp $file $target`, #4 `[ $foo = "bar" ]`, #5 `cd $(dirname "$f")` (quote nesting: `cd -P -- "$(dirname -- "$f")"`), #14 `echo $foo`, #24 `for arg in $*` (use `"$@"` or bare `for arg`), #29 `sed 's/$foo/…/'` (single quotes), #36 `[ -n $foo ]`, #50 `hosts=( $(aws …) )` (use `read -ra`, `readarray -t`, or `IFS=$'\n' read -r -d '' -a hosts < <(aws … && printf '\0')` for 3.x), #56 `xargs` without `-0`, #57 `unset a[0]` (use `unset -v 'a[0]'`).
- **Filenames**: #1, #3 leading dashes (`--`, `./*`), #42 `[[ $file != *.* ]]` after a `./` prefix, #52 `find . -exec sh -c 'echo {}' \;` (code injection; use `sh -c 'echo "$1"' x {}`), #56.
- **Test syntax**: #4, #6 `&&` inside `[` (and `-a`/`-o` are "obsolescent in POSIX-2008", gone in 2024), #7 `[[ $foo > 7 ]]` (string compare; in `[` it is a redirection that creates a file named `7`), #9 `if [grep foo myfile]`, #10 missing spaces, #11 `if [ [ a = b ] && … ]`, #20 `[ a == b ]`, #34 `[[ $foo = $bar ]]` (RHS is a pattern), #35 `[[ $foo =~ 'some RE' ]]` (quoted RHS is a string; put the regex in a variable), #37 `[[ -e "$broken_symlink" ]]` (add `|| -L`).
- **Arithmetic**: #7, #45 `y=$(( array[$x] ))` (command injection through the subscript), #46 `read num; echo $((num+1))` (injection via `a[$(…)]`), #59 `i=$(( 10#$i ))` (breaks on a sign), #61 `[[ -v hash[$key] ]]` (works properly only in 5.2; single-quote `'hash[$key]'` in 4.3 to 5.2), #62 `(( hash[$key]++ ))` (bash 5.2 broke the backslash workaround; `assoc_expand_once` breaks others).
- **Pipelines and subshells**: #8 `grep foo bar | while read -r; do ((count++)); done` (POSIX leaves last-pipe-element subshell unspecified; ksh93 and bash 4.2+ `shopt -s lastpipe` differ), #63 `while … done <<< "$(foo)"` (use `< <(foo)`), #64 `cmd > "file$((i++))"` (redirection runs in a subshell, `i` unchanged in bash and ksh, changed in dash).
- **Redirection and file descriptors**: #13 `cat file | sed … > file` (clobbers), #17 `echo <<EOF`, #43 `2>&1 >>logfile` (order), #53 `sudo mycmd > /myfile`, #54 `sudo ls /foo/*`, #55 `2>&-` (closed fd, not /dev/null).
- **Error handling and status**: #19 `cd /foo; bar` (check `cd`), #22 `cmd1 && cmd2 || cmd3` (not if/else; `((i++))` returns 1 when `i` was 0), #27 `local var=$(cmd)` masks status, #44 `cmd; (( ! $? )) || die`, #60 `set -euo pipefail` (60.1 errexit, 60.2 pipefail, 60.3 nounset).
- **Portability of syntax**: #18 `su -c` (needs a user name), #20 `==`, #23 `echo "Hello World!"` (history expansion; interactive only, changed in bash 4.3), #25 `function foo()`, #26 and #28 tilde (`echo "~"`; `export foo=~/bar` is shell-dependent), #38 `ed` with `\{0,3\}`, #39 `expr` with the keyword `match` (GNU `+` prefix; "stop using expr"), #33 `{1..$n}` (brace expansion precedes parameter expansion).
- **Environment, IFS, CDPATH**: #47 `IFS=, read -ra fields <<< "$csv_line"` (POSIX IFS is a terminator; trailing empty field dropped), #48 `export CDPATH` (changes `cd` target and prints the path into `$(cd …)` captures), #49 `OIFS="$IFS"` (cannot tell unset from empty; use `local IFS` or a subshell).
- **Encoding and locale**: #30 `tr [A-Z] [a-z]` (globbing, wrong notation, locale ranges; use `LC_COLLATE=C tr A-Z a-z` or `tr '[:upper:]' '[:lower:]'`), #40 UTF-8 BOM ("Files starting with BOM should be considered equally foreign as those with MS-DOS linebreaks"), #65 `IFS= read -r -d ''` (bash 5.0 to 5.3-rc1 read-past-delimiter bug in multibyte locales; `IFS= LC_ALL=C read -r -d ''`; backported only by Gentoo and Arch as of 2025-07).
- **Processes and time**: #31 `ps ax | grep gedit` (use `pgrep`; `grep '[g]edit'` trick), #51 non-atomic output with `xargs -P` (writes over ~8192 bytes split), #58 `month=$(date +%m); day=$(date +%d)` (call `date` once; `printf -v now '%(%s)T' -1` needs 4.2, `$EPOCHSECONDS` 5.0), #32 `printf "$foo"` (format-string exploit), #41 `content=$(<file)` (strips trailing newlines; `printf x` sentinel trick).
- **Misc**: #12 `read $foo`, #15 `$foo=bar`, #16 `foo = bar`, #21 `./something &;`, #32.

Also recorded: #45/#46/#61/#62 are the same root cause (arithmetic and subscript contexts expand then re-parse) and one rule ("validate with `case` first; never expand into `(( ))`") answers all of them.

### 2. BashFAQ

[Index](https://mywiki.wooledge.org/BashFAQ) (123 numbered entries, read). Entries that matter for this project, with the exact position taken:

- [FAQ 1](https://mywiki.wooledge.org/BashFAQ/001): template `while IFS= read -r line; do … done < "$file"`; handle a missing final newline with `|| [[ -n $line ]]`; `find … -print0 | while IFS= read -r -d '' file`; stop commands (`ssh`, `ffmpeg`) eating the loop's stdin (FAQ 89); `_` as throwaway is "only guaranteed to work in Bash".
- [FAQ 31](https://mywiki.wooledge.org/BashFAQ/031): `[` vs `[[`; footnotes state that as of POSIX.1-2024 `<`/`>` are standardized and `-a`, `-o`, `( )` "are no longer standardized"; `[[` works in ksh, bash, zsh, "recent versions of yash and busybox sh (if enabled at compilation time)". A bad `[[` operator is a parse-time error: `bash-3.2: line 2: conditional binary operator expected` for `[[ -v $1 ]]` in a function that is never called.
- [FAQ 35](https://mywiki.wooledge.org/BashFAQ/035): "Do not use getopt(1)"; manual loop for long options; `getopts` cannot do `--long` or optional arguments; reset `OPTIND=1` (make it local in functions); `shift "$((OPTIND-1))"`.
- [FAQ 45](https://mywiki.wooledge.org/BashFAQ/045): `[ -f lock ]` then create is a race; `mkdir -- "$lockdir"` is atomic ("do not use `mkdir -p`"); `ln -s`; `set -C` (noclobber) fails on ksh88; `flock -n 9` on GNU/Linux; stale locks after SIGKILL remain.
- [FAQ 62](https://mywiki.wooledge.org/BashFAQ/062): "distressingly difficult"; best portable answer is a private directory (`$HOME`, `$XDG_RUNTIME_DIR`), else `mktemp -d -- "${TMPDIR:-/tmp}/XXXXXXXXXXXXXX"` plus `trap cleanup EXIT HUP INT TERM`, else `mkdir -m 700` retry loops (never `mkdir -p`; awk `srand()` seeds are predictable).
- [FAQ 105](https://mywiki.wooledge.org/BashFAQ/105) (last edited 2021-03-11): the five exercises (`let i++` and `((i++))` returning 1; `test … && echo` inside a function; `read -r foo < configfile`), `local var=$(cmd)` does not exit while `local var; var=$(cmd)` does, `inherit_errexit` (4.4), process substitution discards status, `set -e -o pipefail` with `somecmd | head -n1`; the "robot" allegory.
- [FAQ 112](https://mywiki.wooledge.org/BashFAQ/112): `set -u` is "controversial"; false positives on `$1`, on empty arrays ("an error in bash 4.3, but not in bash 4.4"); fix with `${1-}`.
- [FAQ 121](https://mywiki.wooledge.org/BashFAQ/121): "value too great for base" (`$((09))`); a hex/octal/`x[$(date >&2)0]` injection example from 2021; validate untrusted numbers.
- [FAQ 52](https://mywiki.wooledge.org/BashFAQ/052): CR-LF scripts; detect with `sed -n l yourscript` (`\r$`).
- Index entries worth a rule each: 24 (pipeline variables vanish), 28 (script location), 30 (rename), 33 and 42 (process by name; still running), 48 (eval and security), 50 (command in a variable), 54 (valid number), 55 (`2>&1`), 58 (binary data), 60 (script cannot change caller's cwd), 61 (features by bash release), 68 (timeout), 72 (cron environment), 81 (`command -v`), 82 (`$(…)` over backticks), 84 (return a string), 95 (argument list too long), 97 (dangling symlink), 101 (warn/die), 104 (`foo=bar echo "$foo"`), 106 (logging), 108 (wait for spawned processes), 109 (sourced vs executed), 111 (Shellshock), 112 (nounset).

### 3. Wooledge reference pages

- [ProcessManagement](https://mywiki.wooledge.org/ProcessManagement): `$!` for the PID, `kill -0 "$pid"` as the portable liveness test, PID files are racy ("risk of letting the parent die"), "Do not use kill -9, ever", Bash 4.3 `wait -n` to keep N jobs running (with `set -m`), `trap … EXIT` to kill children, "you cannot write a general purpose service manager in a shell", `setlock` from daemontools.
- [SignalTrap](https://mywiki.wooledge.org/SignalTrap): five forms of `trap`; names preferred over numbers because numbers vary by OS; most scripts should not ignore signals; special notes on SIGINT/SIGQUIT and what Ctrl-C does.
- [WordSplitting](https://mywiki.wooledge.org/WordSplitting): order of expansions; the `args` helper script (`printf "%d args:" "$#"; printf " <%s>" "$@"`); non-whitespace IFS generates empty words; globbing after splitting ("737 args" example); `IFS=2; args $(( 11 * 11 ))` splits digits.
- [Quotes](https://mywiki.wooledge.org/Quotes): "When in doubt, double-quote every expansion"; `$'...'` and `$"..."` are "nonstandard Bash extensions" (pre-2024 wording; `$'..'` is now POSIX.1-2024).
- [ParsingLs](https://mywiki.wooledge.org/ParsingLs): globs plus `shopt -s nullglob`; `stat -c %s` is GNU only; `LC_ALL=C ls -nd` as a fallback; GNU coreutils 9.0 (2021) added `ls --zero`; `--quoting-style=shell-always` combined with `eval` (2016+); name files `YYYYMMDD` so glob order is time order.
- [Bashism](https://mywiki.wooledge.org/Bashism) (last edited 2025-04-19): a table "works in bash / change to for dash". Updated for POSIX.1-2024: `$'…'`, `<`/`>`, `-nt`/`-ot`/`-ef` are marked "Standardized in POSIX.1-2024; available in dash, ksh, yash, and zsh" (for the test operators). Still non-POSIX: `;;&` `;&`, C-style `for ((;;))`, extglob, `select`, `$(<file)`, brace expansion, process substitution, `${name:n:l}`, `${name/foo/bar}`, `${!name}`, arrays, `[[`, `(( ))`, `++`/`--`, `**`, `&>`, `|&`, `<<<`, `echo -n/-e`, `printf -v`, `shopt`, `local`, `SECONDS`, `RANDOM`, `PIPESTATUS`, `FUNCNAME`. Recommends `checkbashisms` (Debian devscripts).
- [DotFiles](https://mywiki.wooledge.org/DotFiles) (last edited 2024-07-07): login shells read `/etc/profile`, then `.bash_profile`/`.bash_login`/`.profile`; `.bashrc` is not read by login shells so put `source ~/.bashrc` at the end of `.bash_profile`; non-interactive ssh sources `.bashrc` only when the distro compiled that in; test `-t 0`/`$-` before printing.

### 4. Rich's sh tricks and Sven Mascheck

- [Rich's sh (POSIX shell) tricks](https://www.etalabs.net/sh_tricks.html): stance that Bourne-derived languages are "on the same order of badness as Perl" and POSIX sh is for "super-portable, lowest-common-denominator" scripts; `printf %s\\n "$var"` and "NEVER use echo like this"; a table of `echo` output under POSIX, Unix (XSI) and Bash; `quote () { printf %s\\n "$1" | sed "s/'/'\\\\''/g;1s/^/'/;\$s/\$/'/" ; }`; arrays via `set --`; overriding locale categories (`LC_COLLATE=C ls` fails if `LC_ALL` is set; `eval export \`locale\` ; unset LC_ALL`); the C locale guarantees ASCII-ordered ranges and sort but not that bytes above 0x7F are characters; dotfile globs `.[!.]* ..?*`; `is_empty` via `set -- .[!.]*`; `date +%s` "is not portable" (so a hand-rolled epoch formula; POSIX.1-2024's `date` page still has no `%s`, checked).
- Mascheck: [bourne/](https://www.in-ulm.de/~mascheck/bourne/) (shell family history and per-release bug fixes, e.g. when `set -e` stopped applying to `if`/`while` conditions), [various/portability](https://www.in-ulm.de/~mascheck/various/portability/) (link list, updated 2024-06-16, with a "POSIX 1003.1-2024 some news" line: `readlink`, `realpath`, `find -print0/-iname`, `xargs -0`, `read -d`, `sed -E`, `-o pipefail`), [various/set-e](https://www.in-ulm.de/~mascheck/various/set-e/) (a result table of `set -e` across V7, SVR2 to SVR4, ksh, bash, dash and others; questions: pipelines, `!`, subshell inheritance, `{ …; } || cmd3`, function bodies; "Using set -e has its quirks. As alternative, you can connect your commands with &&"). Other Mascheck pages exist for `echo`/`printf`, `IFS`, shebang, `ARG_MAX`, `${1+"$@"}`, system shells per Unix (index read; those pages fetched but not mined).

### 5. Chazelas on Unix & Linux Stack Exchange

The StackExchange HTML is behind Cloudflare; bodies were read through the API (`api.stackexchange.com/2.3/questions/<id>/answers?site=unix&filter=withbody`).

- [Why is printf better than echo?](https://unix.stackexchange.com/questions/65803/why-is-printf-better-than-echo) (score 1028, last edit 2026-07-07): history of `echo`; `-e`/`-n`/`-E` differ per implementation; bash's behaviour changes with `xpg_echo` and POSIX mode; "POSIX should actually say: if the first argument matches `^-([eEn]*|-|-help|-version)$` … or any argument contains backslashes … then the behaviour is unspecified"; `printf '%s\n' "$var"`; the format string must not contain data; `%q` and `%b` vary; reimplementing `echo` with `printf`; `print -r --` for ksh88/pdksh.
- [Why does my shell script choke on whitespace or other special characters?](https://unix.stackexchange.com/questions/131766/why-does-my-shell-script-choke-on-whitespace-or-other-special-characters) (Gilles, last edit 2022-06-21): split+glob model; arrays for lists (`mksh`, `ksh93`, `yash`, `bash`, `zsh`; none in dash/ash); `while IFS= read -r line`; avoid `xargs`, or `xargs -0`; prefer `find … -exec …`; "don't use `` `foo` ``".
- [Security implications of forgetting to quote a variable](https://unix.stackexchange.com/questions/171346/security-implications-of-forgetting-to-quote-a-variable-in-bash-posix-shells) (last edit 2024-08-06): `cmd $var` is `cmd(glob(split($var)))`; "You quote your variables because it is wrong not to"; attack vectors (CGI, setuid, DHCP hooks, file names, `ForcedCommand`); also applies to `$(…)` and `$((…))` output.
- [Why is using a shell loop to process text considered bad practice?](https://unix.stackexchange.com/questions/169716/why-is-using-a-shell-loop-to-process-text-considered-bad-practice) (last edit 2024-03-26): the shell orchestrates, tools process; `while read; do echo $line | cut -c3; done` forks per line; use one `awk`/`sed`/`cut` over the whole stream.

### 6. The strict-mode literature

- [Aaron Maxwell, "Use Bash Strict Mode (Unless You Love Debugging)"](http://redsymbol.net/articles/unofficial-bash-strict-mode/): `set -euo pipefail` plus `IFS=$'\n\t'`; use `${1:-}` for positional defaults; `|| true` for expected non-zero; `set +u; source venv/bin/activate; set -u`; `trap finish EXIT` for scratch dirs; warns that `[[ -f $f ]] && echo …` as the last line makes the script exit 1.
- [betterdev.blog, "Minimal safe Bash script template"](https://betterdev.blog/minimal-safe-bash-script-template/) (2020-12-14): `#!/usr/bin/env bash`, `set -Eeuo pipefail`, `trap cleanup SIGINT SIGTERM ERR EXIT`, `script_dir=$(cd "$(dirname "${BASH_SOURCE[0]}")" &>/dev/null && pwd -P)`, `msg()` to stderr with colors only if `[[ -t 2 ]]`, `NO_COLOR` unset and `TERM` not `dumb`, a manual `parse_params` loop that errors on unknown `-?*`; rejects `getopt`/`getopts` because macOS `getopt` "behaves completely differently". The template itself uses `echo >&2 -e`, which fails under dash.
- [MIT SIPB, "Writing Safe Shell Scripts"](https://sipb.mit.edu/doc/safe-shell/) (migrated page, footer says updated 2026-10-10 but marked "not manually reviewed"): "Don't" first; `set -euf -o pipefail` ("In dash, set -o doesn't exist, so use only set -euf"; dash 0.5.12 measured: `Illegal option -o pipefail`); `shopt -s failglob`; always quote; `--` or `./`; use ShellCheck; points to Google's guide.
- [Julia Evans, "Bash scripting quirks & safety tips"](https://jvns.ca/blog/2017/03/26/bash-quirks/) (2017-03-26): quote variables, `[` is a command, `set -u`, `set -e`, `set -o pipefail`, `set -x`, use ShellCheck. Historical (2017) but still the entry-level text agents have seen most.
- [Google Shell Style Guide](https://google.github.io/styleguide/shellguide.html): "Bash is the only shell scripting language permitted for executables"; `#!/bin/bash`; rewrite scripts longer than 100 lines or with non-straightforward control flow; SUID/SGID forbidden; use arrays for lists of flags; `getopts` example; ShellCheck mandated.
- [Google Testing Blog, "Shell Scripts: Stay Small & Simple"](https://testing.googleblog.com/2023/10/shell-scripts-stay-small-simple.html) (2023-10): unquoted `?` expanded as a glob; command-line arguments are world-readable (secrets leak); errors are ignored by default and `set -e` is "inconsistent"; subshells hide variable changes (`foo="$(run_or_exit false)"` exits only the `$()` subshell).

### 8. POSIX.1-2024 (Issue 8), primary

### 12. fish

- [fish for bash users](https://fishshell.com/docs/current/fish_for_bash_users.html): command substitution `$(cmd)` or `(cmd)` (no backticks), split on newlines only (`string split0` for NUL); variables set with `set -gx`/`set -l`/`set -e`; no word splitting (all variables are lists); no `${var:-default}` (use `set -q`); globs `*` and `**` only (a non-matching glob fails the command, except `for`, `set`, `count`); no `$'..'` (escapes are processed unquoted: `echo a\nb`); string ops via `string`; special variables `$argv`, `$status`, `$fish_pid`, `$last_pid`; process substitution is `(cmd | psub)`; no heredocs; `$(…)` is accepted in fish 3.4+ (docs-current wording).

Unreleased: command substitutions allowed in command position, `command -- -q`. Earlier: 3.5.0 made `stderr-nocaret` read-only; 3.6.0 abbreviations moved out of universal variables.

## Recent shifts seen in this corpus

Dates in the last 24 months (2024-10 to 2026-10) unless noted.

- **POSIX.1-2024 (Issue 8, published 2024)**: adds `set -o pipefail` (Defect 789), `$'…'`, `read -d`, `find -iname`/`-print0`, `xargs -0`, `readlink`, `test -nt/-ot/-ef` and `<`/`>`; removes `test -a/-o` and `( )`. Invalidates "pipefail is a bashism", "`$'..'` is a bashism", "`xargs -0` and `find -print0` are GNU-only". Does not invalidate the dash caveat: dash 0.5.12 (Debian 12, measured) implements none of `pipefail`, `$'..'`, `read -d`. Wooledge's [Bashism](https://mywiki.wooledge.org/Bashism) page (2025-04-19) and [FAQ 31](https://mywiki.wooledge.org/BashFAQ/031) already reflect it; older write-ups (Rich's tricks, Bash Hackers wiki, Quotes page wording) do not.
- **Bash 5.3 (2025)**: funsubs `${ cmd; }` and `${| cmd; }` (no fork), `GLOBSORT`, `array_expand_once` (replaces `assoc_expand_once` from 5.0), `BASH_MONOSECONDS`, `source -p`, `trap -P`, `MULTIPLE_COPROCS` on by default. [BashPitfalls #65](https://mywiki.wooledge.org/BashPitfalls) (edit 2025-07-18) records that `read -d ''` read past the delimiter in multibyte locales in 5.0 to 5.3-rc1 (fixed in 5.3; only Gentoo and Arch backported). It also records that associative-array subscripts in `(( ))` broke the backslash workaround in 5.2: advice from before 2022 (`(( hash[\$key]++ ))`) is now wrong.
- **fish 4.0.0 (2025-02-27) to 4.9.3 (2026-09-08)**: Rust rewrite; `?` is no longer a glob; `{echo,echo}` is a compound command (4.1, 2025-09); UTF-8 assumed (4.2, 2025-11); no default universal variables (4.3, 2025-12); non-interactive shells get no default theme (4.7, 2026-05); `status=123 echo $status` errors (4.9, 2026-09). Distros: Debian 12 carries fish 3.6.0 and Debian 13 carries 4.0.2 (per frame), so emitted fish must span both. Older advice invalidated: any tutorial using `?` globs or `bind -k` terminfo names.
- **nushell 0.110 (2026-01-17) to 0.116.1 (2026-10-04)**: `let` in pipelines (0.110/0.111), proper `finally` (0.111), `%` sigil and `from md` (0.112.1), script-argument quoting regression fixed in 0.112.2 (2026-04-15), POSIX `--`, `run`, opt-out `enforce-runtime-annotations`, submodule import change and `str upcase` deprecation (all 0.114.0, 2026-07-04), YAML rework and `$ans` (0.115.0). Anything an agent learned from pre-0.114 nushell documentation about module imports or runtime type annotations is wrong now.
- **PowerShell**: 7.5 GA 2025-01-23, 7.6 LTS GA 2026-03-18 (EOL 2028-11-14), 7.7-preview in progress; 7.4 LTS and 7.5 both reach end of support 2026-11-10. Older (7.3 in 2022, 7.4 in 2023) but still a source of stale advice: `$PSNativeCommandArgumentPassing` (7.3, breaking) and `$PSNativeCommandUseErrorActionPreference` (7.4, default `$false`). Windows PowerShell 5.1 is unchanged (measured 5.1.26100.9444 on the Windows host).
- **ShellCheck**: the wiki carries SC2329 ("function never invoked") next to SC2317; SC3001 to SC3067 replaced the retired SC2039 for "undefined in POSIX sh". Any rule that cites SC2039 is stale.
- **StackExchange canonical answers keep being edited** (echo vs printf last edited 2026-07-07; quoting security 2024-08; shell loop 2024-03): the positions are stable but the details (zsh, POSIX 2024) are updated.
- **Older advice these invalidate**: "never use `[[`/`pipefail` in portable scripts" (now partly standard), "`xargs -0` is GNU" (standard), bash 4.3 history-expansion note in Pitfalls #23, "use `which`" (SC2230), "Write-Host does nothing non-interactively" (pre-5.0 PowerShell), `-UseBasicParsing` on 7 (no-op).

## Contested

- **`set -e` / strict mode**: GreyCat "don't use set -e", rking "use it but beware", geirha "handle errors properly" ([FAQ 105](https://mywiki.wooledge.org/BashFAQ/105)); Maxwell and SIPB recommend `set -euo pipefail` / `set -euf -o pipefail`; betterdev adds `-E` and an `ERR` trap. [Bash Pitfalls #60](https://mywiki.wooledge.org/BashPitfalls) calls the combination "many pitfalls". Trend: practice is toward explicit `|| return`, a linter, and pipefail only where the pipeline cannot close early; CI runners already apply `-e` (GHA `bash -e {0}`), and POSIX.1-2024 legitimises `pipefail`, so "strict by default, audited" is gaining over "never".
- **`IFS=$'\n\t'`**: Maxwell sets it globally; Wooledge and Chazelas say quote instead of changing IFS ([Pitfalls #49](https://mywiki.wooledge.org/BashPitfalls) shows why save/restore of IFS is itself wrong). Trend: dropped; it is absent from every later template (betterdev, SIPB, Google).
- **`[[` vs `[`**: ShellCheck's optional SC2292 prefers `[[` in bash/ksh; FAQ 31 says `[` when POSIX matters; busybox/yash have `[[` only in some builds. Trend: dialect-dependent, decided by T01.
- **`local` in POSIX sh**: ShellCheck SC3043 calls it undefined; every shell in the matrix except ksh93u+m has it (measured). Trend: de facto portable except ksh93; flag, do not forbid, unless ksh93 is a target.
- **`echo`**: Chazelas, Rich and POSIX recommend `printf`; betterdev's template and much CI code use `echo -e`. Trend: printf wins in any file that may run under dash, yash or posh.
- **`xargs`**: Pitfalls #56 permits non-`-0` xargs with a comment; Gilles says avoid xargs; POSIX.1-2024 adds `-0`. Trend: `-exec … {} +` or `-0`.
- **Option parsing**: Wooledge "Do not use getopt(1)"; betterdev rejects both because macOS `getopt` differs; Google uses `getopts`. Trend: manual `case` loop for anything with long options.
- **Process substitution**: Pitfalls #63 says `< <(cmd)` is the right answer; Bash Hackers says use FIFOs for portability. Trend: bash scripts use `< <()`, POSIX scripts restructure.
- **Is shell the right tool?** Rich (bootstrap only), SIPB ("Don't"), Google (100 lines) vs pure-bash-bible (do it in pure bash). Trend: shrinking scope for shell, with ShellCheck as the floor for what remains.
- **macOS bash 3.2 as a target**: jmmv says 3.2.57 is "broken enough to be problematic"; Google mandates `#!/bin/bash` without a version; Homebrew bash is not on PATH in non-login contexts (frame H7, unverified here). Trend: write to 3.2 or require an explicit interpreter.
- **Terminal capabilities**: pure-bash-bible prints raw ANSI because `tput` "is not actually portable"; betterdev gates colors on `[[ -t 2 ]]`, `NO_COLOR` and `TERM != dumb`. Trend: raw ANSI behind a tty and `NO_COLOR` check.
- **`Write-Host`**: PoshCode says avoid (pre-5 it was uncapturable); since 5.0 it writes to the information stream; PSScriptAnalyzer still ships `PSAvoidUsingWriteHost`. Trend: rule remains, rationale is weaker.
