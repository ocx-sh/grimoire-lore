## Summary

- ShellCheck is the de facto lint standard and is the only widely-adopted analyzer that models shell dialects: `-s sh|bash|dash|ksh|busybox` (busybox since 0.10.0, 2024-03-07). It does NOT parse zsh, fish, nu, elvish or pwsh (SC1071 "ShellCheck only supports sh/bash/dash/ksh scripts"), so any rule that says "gate with shellcheck" must scope itself to those dialects and name a different parse check for the rest.
- The wiki holds 521 coded checks: 130 SC1xxx (parse/syntax), 326 SC2xxx (semantic), 65 SC3xxx (POSIX-portability, "In POSIX sh, X is undefined"). SC3xxx is the machine-readable bashism list; it only fires when the dialect is sh/dash/busybox/ksh, so a script with the wrong shebang is never checked for portability at all.
- SC3xxx is not ground truth for real shells. Measured 2026-10-10 across 11 POSIX-mode interpreters, `local` (SC3043) works in everything except ksh93u+m, `$'..'` fails in dash, yash and posh, `set -o pipefail` fails only in dash and posh, and `[ a == a ]` fails in dash and posh. The lint and the runtime disagree, and the project must pick which one the rule enforces.
- POSIX.1-2024 moved the baseline: ShellCheck 0.11.0 (2025-08-03) removed SC3013 (`-nt/-ot/-ef`) and relaxed SC3012 (`\<` `\>` in `test`); master removes SC3003 (`$'..'`) and accepts `pipefail` in SC3040. Debian Policy 10.4 still cites POSIX.1-2017 plus `echo -n`, `test -a/-o`, `local`, numeric `kill`/`trap` as the allowed `/bin/sh` extras. "What may a /bin/sh script assume" now has three answers (POSIX 2024, Debian policy, shipped dash 0.5.12).
- Google's guide mandates bash-only with `#!/bin/bash`, `[[ ]]`, arrays, `local`, `main "$@"`, 2-space indent, 80 columns, `${var}` bracing, `==` in `[[ ]]`, and "rewrite in a real language past 100 lines". Its own `[[ "filename" =~ ^[[:alnum:]]+name ]]` example is fine but its `=~ foo:(\d+)` example never matches in bash on glibc (measured, 3.2 to 5.3): style guides are rationale, not verified spec.
- errexit is the most-codified hazard: BashPitfalls #60, oils' nine named pitfalls, and ShellCheck's SC2310/2311/2312/2251, SC2181, SC2155 and optional `check-set-e-suppressed` / `check-extra-masked-returns` all describe the same contract failure. Measured: `local x=$(false)` leaves `$?` at 0 on every bash 3.2 to 5.3; `f && g` suppresses `set -e` inside `f` on every version; but failing `(( i++ ))` and `[[ ]]` only abort under `set -e` from bash 4.2 up (3.2 and 4.0 do not), so "set -e" is a version-dependent contract on macOS /bin/bash.
- shfmt 3.13.0 (2026-03-09) added zsh to the parser and formatter (`-ln zsh`, EditorConfig `[[zsh]]`); 3.14.0 (2026-08-28) added `--detect`, many interpreter fixes, `${ cmd; }` funsubs. `.sh` implies `-ln posix` even if the body uses bash arrays (measured error "arrays are a bash/mksh/zsh feature; tried parsing as posix") unless the shebang says bash. Taskfile `cmds` run in mvdan/sh's interpreter, whose gaps are tracked in the same changelog.
- PSScriptAnalyzer 1.25.0 (module in the toolchain, measured) has 75 rules; the ones that matter for cross-version scripting are all opt-in: `PSUseCompatibleSyntax` (Disabled by default, severity Error, `TargetVersions`), `PSUseCompatibleCommands` (Disabled, `TargetProfiles`), `PSUseCompatibleTypes`. The bundled compatibility profiles stop at PowerShell 7.0 / 6.1-era data (no 7.2 to 7.6 profiles), so the analyzer cannot tell you what 7.4 vs 5.1 differ on beyond syntax.
- PowerShell lifecycle (Microsoft Learn, 2026-08-13): 7.6.6 is the current LTS, 7.5.11 the current Stable, 7.4.20 supported until 2026-11-10, 7.7-preview.3 the preview. Windows PowerShell 5.1 stays a Windows component. A rule that targets "5.1 and 7.4+" has 4 weeks left before 7.4 drops.
- PowerShell encoding is a codified trap: PSScriptAnalyzer `PSUseBOMForUnicodeEncodedFile` (Warning, always on) exists because Windows PowerShell 5.1 reads a BOM-less UTF-8 script as the ANSI code page, while pwsh 6+ writes `utf8NoBOM` by default and Unix tools mishandle a BOM. Same file, opposite requirements. Bash side: ShellCheck SC1082 (BOM) and SC1017 (CR); measured `#!/bin/sh\r` yields "bad interpreter: /bin/sh^M" (exit 127).
- Security guidance converges: avoid the shell (CWE-78, OWASP), pass argv not strings, validate against allowlists, `--` ends options but "does not prevent additional transfers" in curl. GitHub's hardening guide says route `${{ }}` context through `env:` into `run:` or use an action; the catalog has no sibling rule for this (nix-quality and bazel-quality only touch secrets).
- `curl | sh` guidance is practice, not standard: docker's `install.sh` wraps everything in `do_install` "so that we have some protection against only getting half the file"; rustup ends with `main "$@" || exit 1`; deno's install.sh does not wrap. Checksums and signatures move trust to the publisher channel and need a bootstrap.
- The test-framework landscape is bash-centric: bats-core 1.14.0 (2026-07-21) supports bash 3.2.57 to 5.2 (5.3 not yet in the matrix), and changed `run` to honour `set -e` inside functions; shellspec targets dash, busybox ash, ksh, mksh, posh, yash, zsh but its last release in the clone is 2024-09; shunit2 covers sh/bash/dash/ksh/mksh/zsh; kcov only instruments bash among shells and is C-oriented. Pester is at 5.7.1 in the toolchain with Pester 6 `Should-*` assertions in preview (6.2.0 notes in-tree). nushell ships `std testing` attributes and `std assert`; fish tests are `tests/checks/*.fish` littlecheck files (215 in the clone).
- oils/YSH (0.38.0, September 2026) is the most complete codified critique: `strict_errexit`, `strict_argv`, `strict_arith`, `strict_word_eval`, `strict_tilde`, `strict_nameref`, `eval_unsafe_arith`, `process_sub_fail`, `command_sub_errexit`, `sigpipe_status_ok`. Each is a named shell wart that an agent can be told to avoid in bash.
- bash 5.3 (NEWS) adds `${ cmd; }` / `${| cmd; }`, `GLOBSORT`, `BASH_MONOSECONDS`, `BASH_TRAPSIG`, `compgen -V`, `trap -P`, and "Treat a NULL value for $PATH as equivalent to `.`". The last one is a security-relevant behaviour shift for any script that clears PATH.
- Bash 3.2 detection is partly mechanical: ShellCheck SC3xxx fires only for sh dialects, `checkbashisms` is a Perl regex list with about 45 patterns (function keyword, brace expansion, `[[`, `echo -e`, `$[ ]`, `${x,,}`, `printf -v`, `coproc`, `trap ... ERR|DEBUG|RETURN`, `source`), and nothing codified detects "bash 4+ feature in a #!/bin/bash script meant for macOS". That gap is the biggest hole in the codified corpus for the project's Q1 default.

## Survey

### 1. Google Shell Style Guide

[google.github.io/styleguide/shellguide.html](https://google.github.io/styleguide/shellguide.html) (fetched in full 2026-10-10; 35 KB of text). Rule families, with exact forms:

- Dialect: "Bash is the only shell scripting language permitted for executables"; executables start `#!/bin/bash` with minimal flags, options via `set` so `bash script_name` still works; legacy exceptions only. Shell only for small utilities; over 100 lines or non-trivial control flow means rewrite. SUID/SGID forbidden.
- Files: executables `.sh` or no extension; libraries `.sh` and not executable.
- Output: errors to STDERR via an `err()` helper (`echo "[$(date +'%Y-%m-%dT%H:%M:%S%z')]: $*" >&2`).
- Comments: file header, function header blocks with `Globals:`, `Arguments:`, `Outputs:`, `Returns:`; `TODO(name)`.
- Formatting: 2-space indent, no tabs (except `<<-` bodies); 80 columns; here-docs for long strings; pipelines one segment per line with the pipe starting the next line and consistent `\`; `; then` / `; do` on the same line; `case` alternatives indented two spaces, `a) cmd ;;` one-liners, avoid `;&` and `;;&`; no `(` before patterns.
- Expansion and quoting: prefer `"${var}"` over `"$var"`; do not brace single-char specials or positionals unless `${10}`; always quote strings with variables, command substitutions, spaces or metacharacters; `"$@"` unless `$*` is specifically wanted; arrays for argv; never quote literal integers; `${ccs:+"--cc" "${ccs}"}` idiom.
- Features: ShellCheck "recommended for all scripts"; `$(...)` not backticks; `[[ ... ]]` over `[ ]`/`test`; `-z`/`-n` not filler characters; `==` over `=` in `[[ ]]`; `(( ))` for numerics, careful with `<` `>` in `[[ ]]` (lexicographic); `./*` not `*`; avoid `eval`; arrays not strings; process substitution or `readarray` (bash 4+) not pipe-to-while; `(( ))`/`$(( ))` not `let`, `$[ ]`, `expr`; avoid standalone `(( i++ ))` under `set -e` ("`set -e; i=0; (( i++ ))` will cause the shell to exit"); no aliases in scripts.
- Naming: lower_snake functions and variables; `pkg::func` namespaces; constants and exports UPPER_CASE with `readonly`/`export` (prefer these over `declare -xr`); `local` for function variables, and "Declaration and assignment must be separate statements when the assignment value is provided by a command substitution"; functions together near the top; `main "$@"` as last line.
- Calls: always check return values; `PIPESTATUS` capture (`return_codes=( "${PIPESTATUS[@]}" )` immediately); prefer builtins and parameter expansion (`${string/#foo/bar}`, `=~` with `BASH_REMATCH`) over `expr`/`sed`.

Verified against the interpreters: the guide's `[[ "foo:42" =~ foo:(\d+) ]]` returns no match on bash 3.2, 4.0, 4.2, 4.4, 5.0, 5.1, 5.2, 5.3 in Linux containers (`\d` is not POSIX ERE; macOS libc may differ, read-only, unverified). The `(( i++ ))` warning is real only from bash 4.2 (see section 13).

### 3. ShellCheck optional checks, directives, .shellcheckrc

[Optional](https://github.com/koalaman/shellcheck/wiki/Optional) and `run.sh shellcheck --list-optional` (0.11.0) give exactly 11 optional checks:

| Check | Code | Effect |
|---|---|---|
| `add-default-case` | SC2249 | require `*)` in `case` |
| `avoid-negated-conditions` | SC2335 (+ SC2236/2237) | `[ ! "$var" -eq 1 ]` to `[ "$var" -ne 1 ]` |
| `avoid-nullary-conditions` | SC2243/2244 | `[ "$var" ]` to `[ -n "$var" ]` |
| `check-extra-masked-returns` | SC2312 | `rm -r "$(get_chroot_dir)/home"` masks the substitution's status |
| `check-set-e-suppressed` | SC2310/2311 | `func && echo ok` suppresses `set -e` inside `func` |
| `check-unassigned-uppercase` | SC2154 (uppercase) | `echo $VAR` with `VAR` never assigned |
| `deprecate-which` | SC2230 | `which javac` to `command -v javac` |
| `quote-safe-variables` | SC2248 | quote even `var=hello; echo $var` |
| `require-double-brackets` | SC2292 | `[ -e f ]` to `[[ -e f ]]` in bash/ksh (also busybox since 0.11.0) |
| `require-variable-braces` | SC2250 | `$var` to `${var}` |
| `useless-use-of-cat` | SC2002 | default-off since 0.11.0 |

The wiki warns that `-o all` is for evaluation only because optional checks "are more subjective rather than more comprehensive, and may conflict with each other". Master adds `require-double-equals` (SC2338).

Directives ([Directive](https://github.com/koalaman/shellcheck/wiki/Directive)): `disable=`, `enable=`, `external-sources=`, `source=`, `source-path=`, `shell=`, plus `--rcfile`. Semantics worth encoding: a directive immediately after the shebang (or before the first command) applies file-wide; otherwise it scopes to the next complete command including compound commands; it cannot sit before an `else` or a single `case` branch (SC1123/SC1124); there is no way to scope to "the first structure", the documented workaround is a dummy `true`; `disable=SC1000-SC9999` ranges; "silencing parser errors is purely cosmetic"; `external-sources=true` only in `.shellcheckrc` (SC1144), individual files can disable but not enable it; `source-path=SCRIPTDIR` and `SCRIPTDIR/../lib`; one leading dynamic segment is stripped when following `"${VAR}/lib.sh"`; `.shellcheckrc` or `shellcheckrc` is searched from the script's directory upward, then `~/.shellcheckrc`, then the XDG location, and only the first file found is used; Docker cannot read `~/.shellcheckrc`; Snap needs the dotless name. [Ignore](https://github.com/koalaman/shellcheck/wiki/Ignore) notes issue 3448: a directive applies only to the first command of a `;`-chained series. CLI: `-s` (sh, bash, dash, ksh, busybox), `-S` severity, `-f` (checkstyle, diff, gcc, json, json1, quiet, tty), `-x`, `-a`, `-P`, `-e/-i`, `-o`, `--norc`, `--extended-analysis=bool`. The GitHub-Actions wiki page recommends `find . -type f -name "*.sh" -exec shellcheck {} +`, which misses extensionless executables and `.bash`/`.ksh` files.

### 4. shfmt

[mvdan/sh README](https://github.com/mvdan/sh), [shfmt(1)](https://github.com/mvdan/sh/blob/master/cmd/shfmt/shfmt.1.scd), [CHANGELOG](https://github.com/mvdan/sh/blob/master/CHANGELOG.md); installed 3.13.1 (latest in changelog: 3.14.1, 2026-09-06).

- Flags: `-l[=0]`, `-w`, `-d`, `--apply-ignore`, `--detect default|exec|all` (3.14.0), `--filename`, `-ln|--language-dialect bash|posix|mksh|bats|zsh` (default `auto`), `-p`, `-s` (simplify), `-i N` (0 = tabs, the default), `-bn` (binary ops may start a line), `-ci` (indent `case`), `-sr` (space after redirects), `-kp` (deprecated, to be removed), `-fn` (deprecated, use `-bl`), `-bl` (block next line), `-mn` (minify), `-f` (find), `--to-json`/`--from-json`.
- Dialect detection: `auto` reads the extension, then the shebang, then falls back to bash; "The filename extension .sh is a special case: it implies posix, but may be overridden by a valid shell shebang"; dash shebangs recognised for `-ln=auto` since 3.14.0. Measured 3.13.1: a `#!/bin/sh` file containing `arr=(a b)` fails with "arrays are a bash/mksh/zsh feature; tried parsing as posix (parsed as posix via -ln=auto)".
- zsh: parser and printer support landed in 3.13.0 (2026-03-09, "far enough for many use cases"), EditorConfig `[[zsh]]` and filename-based detection (`.zshrc`, `.bash_profile`) in 3.13.1; 3.14.0 adds `${=name}` `${~name}` `${^name}`, `;|`, subscript-flag patterns. Measured: `shfmt -ln zsh -d` parses `typeset -A h`, `**/*(.N)`, `${(k)h}`, `${=PATH[1,3]}`; `-ln posix` rejects the same file at the extended glob.
- EditorConfig: formatting options come from `.editorconfig` unless any parser/printer flag is given ("A default like `-i=0` can be used for this purpose"); keys are `indent_style`, `indent_size`, `language_dialect` (older `shell_variant`), `simplify`, `binary_next_line`, `case_indent` (older `switch_case_indent`), `space_redirects`, `keep_padding`, `function_next_line`, `block_next_line`, `minify`, `ignore = true` per path; sections may be `[[shell]]`, `[[bash]]` or `[[zsh]]` to match shebang-only scripts (outside the EditorConfig spec). The man page states `shfmt -i 2 -ci -bn` "closely resemble[s] Google's shell style" and that shfmt can replace `bash -n` (it parses statically and requires valid UTF-8). 3.13.0: `-l` now exits non-zero when it prints filenames.
- The same repo ships the interpreter that Taskfile `cmds` use. 3.13/3.14 changelog entries (`;&`/`;;&` terminators, `-N`, integer bases in arithmetic, sparse arrays, `BashOpts`, `help`/`times` builtins, `exec` ENOEXEC fallback, `$-`, empty here-docs) are a de facto list of what that interpreter lacked before.

### 5. checkbashisms, Debian Policy 10.4, Ubuntu DashAsBinSh

- [checkbashisms.pl](https://github.com/Debian/devscripts/blob/master/scripts/checkbashisms.pl) (32 KB, Perl, regex-driven; invoked by `lintian`/`devscripts`). The `%bashisms` table, read directly, includes: `function name`, brace expansion `{a,b}` and `{a..z}`, `read` flags other than `-r`, `echo -e`/`echo -en` and escapes inside `echo` strings, `[`/`test` with unary `-a`, `[[`, `>&`/`<&` to a filename, `local -opt`, `name () {` oddities, `pushd/popd`, `readonly -a/-f`, `sh -r/-D/-O` and `--long`, `printf -v`, `coproc`, `command -p/-v` combos, `trap ... ERR|DEBUG|RETURN`, `exit/return -N`, `~+ ~-` tilde forms, `$[ ]`, `${var,,}`/`${var^^}`, `${@:n}`, `${arr[i]}`, `$HOSTTYPE/$HOSTNAME`, `++`/`--`/`**` in `$(( ))`, `printf %q`, `source`.
- [Debian Policy ch.10 section 10.4 "Scripts"](https://www.debian.org/doc/debian-policy/ch-files.html): "Scripts may assume that /bin/sh implements the POSIX.1-2017 Shell Command Language plus": `echo -n` (builtin must not emit a newline), `test -a`/`-o` as binary operators, `local` including `local a b c=delta d`, XSI `kill -signal` with numeric signals 0,1,2,3,6,9,14,15, XSI `trap` with numeric signals including 13. Scripts needing more must name the shell on the shebang and depend on it. "Checking your script with checkbashisms ... or running your script with an alternate shell such as posh may help"; "If in doubt ... use /bin/bash". Any script creating files in world-writable dirs "must use a mechanism which will fail atomically if a file with the same name already exists" (`mktemp`; `tempfile` is deprecated, SC2186). Every script should use `set -e` or check every exit status. Still cites POSIX.1-2017, not 2024.
- [Ubuntu DashAsBinSh](https://wiki.ubuntu.com/DashAsBinSh) now returns an empty "no text on this page" stub (wiki migrated; content archived in github.com/ubuntu/wiki-archives). The historical guidance (Ubuntu 6.10 switched `/bin/sh` to dash) is therefore not citable from the live wiki; treat it as historical-only.
- Alpine/busybox: no standalone "guidance" page exists; the machine-readable form is busybox's own build config (section 12) and ShellCheck's `busybox` dialect plus SC2330.

### 6. BashPitfalls (Wooledge) as a codified list

[mywiki.wooledge.org/BashPitfalls](https://mywiki.wooledge.org/BashPitfalls) (fetched; 65 numbered pitfalls). ### 10. Security guidance

- **CWE-78** ([cwe.mitre.org/data/definitions/78.html](https://cwe.mitre.org/data/definitions/78.html), v4.20): "Improper Neutralization of Special Elements used in an OS Command"; mitigations: use library calls rather than external processes, sandbox/jail (limited effectiveness), attack-surface reduction, vetted libraries, output encoding ("properly quote arguments and escape any special characters"), allowlist input validation, least privilege.
- **OWASP OS Command Injection Defense Cheat Sheet** ([source](https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/OS_Command_Injection_Defense_Cheat_Sheet.md)): "Every OS Command Injection is also an Argument Injection"; primary defenses: avoid calling OS commands (use `mkdir()` not `system("mkdir ...")`), escape per OS (`escapeshellarg` single-quotes but "an attacker can still pass a single argument"), parameterization plus input validation (allowlist of commands, allowlist regex excluding the metacharacters `& | ; $ > < ` \ ! ' " ( )` and whitespace), `--` to end option parsing but in curl "later arguments are still URL operands: `--` does not prevent additional transfers"; run least-privilege.
- **GitHub Actions** ([secure-use](https://github.com/github/docs/blob/main/content/actions/reference/security/secure-use.md), [workflow-syntax](https://github.com/github/docs/blob/main/content/actions/reference/workflows-and-actions/workflow-syntax.md)): script injection mitigations in preference order: use an action (context value passed as an input, never interpolated into a shell script) or an intermediate environment variable (`env: TITLE: ${{ github.event.pull_request.title }}` then `"$TITLE"` in `run:`; the doc's attack string `a"; ls $GITHUB_WORKSPACE"` stays inert), restrict `GITHUB_TOKEN` permissions; `pull_request_target` and `workflow_run` with untrusted checkout are privileged and exploitable; pin third-party actions; Dependabot version updates; OpenSSF Scorecards; hardened runners. Built-in shell semantics: for `bash`/`sh`, "fail-fast behavior is enforced using `set -e`"; "When `shell: bash` is specified, `-o pipefail` is also applied"; custom template `shell: bash {0}` or `perl {0}` hands over full control; `pwsh`/`powershell` prepend `$ErrorActionPreference = 'stop'` and append the `$LASTEXITCODE` epilogue; `cmd` has no fail-fast.
- **Shellshock (CVE-2014-6271)**. Not fetched as a page; behaviour measured instead. All eight bash versions in the matrix (3.2.57, 4.0.44, 4.2.53, 4.4.23, 5.0.18, 5.1.16, 5.2.37, 5.3.20) ignore an environment value `() { :;}; echo VULNERABLE` (probe printed only `probe-ran`) and import functions only through the `BASH_FUNC_name%%` form (`env 'BASH_FUNC_foo%%=() { echo imported-foo; }' bash -c foo` prints `imported-foo`). So the fix is universal on the matrix; what remains is the mechanism: exported functions travel in `BASH_FUNC_*%%` variables, relevant for `env -i`, `sudo`, and `ssh` environment forwarding. Historical-only as a vulnerability.
- **curl | sh**. Primary evidence in the exemplar corpus: docker `install.sh` ends with "wrapped up in a function so that we have some protection against only getting half the file during 'curl | sh'" then `do_install` (docker__docker-install@2b32480025b2:install.sh:809-813); rustup-init.sh ends `main "$@" || exit 1` (rust-lang__rustup@61271d00a979:rustup-init.sh:931) and uses `set -u`, `# shellcheck shell=dash`, a `has_local` probe with `alias local=typeset`; deno_install `install.sh` states "Keep this script simple and easily auditable", runs `set -e`, and is not wrapped. Debate (secondary): [Atomic Object, "The Security Spectrum of curl | sh"](https://spin.atomicobject.com/security-spectrum-curl-sh/) frames it as a spectrum (HTTP worst, TLS-skipping subtle); checksums/signatures only move the trust point to whoever publishes them (witness issue 418 on cosign bootstrap). No authoritative standard exists.

### 11. oils/YSH as a codified critique

[oils.pub docs](https://oils.pub/release/latest/doc/) (version 0.38.0, generated 2026-09-17; repo clone at 2026-10-07). Relevance to this project: a ready checklist of named hazards, and a comparison shell for "what does a correct script rely on".

## Recent shifts seen in this corpus

- **POSIX.1-2024 reached the tools (2025-2026).** ShellCheck 0.11.0 (2025-08-03) removed SC3013 (`-ot/-nt/-ef`) and stopped warning on `\<`/`\>` inside `test`; master makes `pipefail` legal in SC3040 and removes SC3003 (`$'..'`). Invalidates the long-standing advice "pipefail and `$'..'` are bashisms" for shells that implement POSIX.1-2024, while dash 0.5.12 and posh (measured) still lack them. Debian Policy 10.4 still cites POSIX.1-2017.
- **ShellCheck gained dataflow analysis (0.9.0, 2022-12-12) and the busybox dialect (0.10.0, 2024-03-07).** Invalidates "shellcheck cannot reason about values" and "busybox scripts must be checked as dash" (SC2187 still says Ash is checked as Dash in old docs).
- **ShellCheck 0.11.0 default changes.** SC2002 (useless cat) off by default; SC2236/SC2237 moved to optional `avoid-negated-conditions`; SC2015 no longer triggers when B is a test; new SC2329 (never-invoked functions), SC2330, SC2331, SC2332, SC3062. Master adds SC2337 and EditorConfig `shellcheck.*` keys, `--files-from`.
- **shfmt added zsh (3.13.0, 2026-03-09)** and now detects shell files by executable bit or shebang (`--detect`, 3.14.0, 2026-08-28). Invalidates "shfmt cannot format zsh" and "shfmt only finds `*.sh`". `-l` now exits non-zero (3.13.0), which changes CI scripts that treated `shfmt -l` as informational.
- **bats-core 1.14.0 (2026-07-21)** changed `run` to honour `set -e` inside functions and made an empty suite an error. Invalidates test files that relied on `run` swallowing errexit failures; tracks bash up to 5.2 only in the support matrix.
- **PSScriptAnalyzer 1.24.0 dropped PowerShell 3 and 4 hosts** and moved to .NET 8; 1.25.0 added `AvoidReservedWordsAsFunctionNames`, `UseConsistentParametersKind`, `UseConsistentParameterSetName`, `UseSingleValueFromPipelineParameter`, optional `UseConstrainedLanguageMode`. The bundled compatibility profiles did not follow: nothing newer than PowerShell 7.0.
- **PowerShell lifecycle (2026-08-13):** 7.6 is the LTS line, 7.5 Stable, 7.4 LTS ends 2026-11-10, 7.7 in preview. Invalidates "7.4 is the LTS" in recent training data.
- **PowerShell 7.3 (late 2022) `$PSNativeCommandArgumentPassing`** changed native-argument parsing with a documented breaking change; `$PSNativeCommandUseErrorActionPreference` is still opt-in (`$false` default). Invalidates 5.1-era quoting workarounds when run under 7.3+.
- **bash 5.3 (2025):** funsubs `${ cmd; }`, `GLOBSORT`, `BASH_MONOSECONDS`, null PATH equals `.`, `array_expand_once`. Invalidates "all `$( )` forks" and "empty PATH disables lookup" assumptions on 5.3 only.
- **Pester 6 preview** introduces `Should-*` assertions; most online Pester material is v4/v5 `Should -Be`. Pester 5.7.1 is the stable line in the toolchain.
- **Ubuntu's DashAsBinSh wiki page is gone** (migrated to an archive), removing a long-cited primary reference.
- **Shellshock (2014) is fully historical** on the measured matrix (all eight bash versions import functions only via `BASH_FUNC_name%%`); advice to "patch bash" no longer applies, but the env-var function encoding remains.
- **nushell AGENTS.md / std testing:** `attr test` attribute-based tests exist in `std testing` (current main); older `#[test]` comment-annotated style from earlier releases is stale (verify against the pinned nu version).

## Contested

- **Bash-only vs POSIX-first.** Google: bash is the only permitted shell, no need to avoid bashisms. Debian Policy, rustup, deno, docker install scripts, and the project's Q1 default: POSIX sh for anything that runs before a toolchain exists. Trend: split by context. Bash-only at Google-like monorepos with pinned images, POSIX for distributed installers; macOS 3.2.57 keeps "bash-only" from meaning "bash 5".
- **`[[ ]]` vs `[ ]`.** Google prefers `[[ ]]` (no splitting or globbing); ShellCheck's `require-double-brackets` (optional, since 0.8.0) agrees for bash/ksh; POSIX portability and `shfmt -ln posix` push `[ ]`. Busybox `[[ ]]` lacks glob matching (SC2330, 0.11.0). Trend: `[[ ]]` in bash-pinned scripts, `[ ]` plus `case` in sh.
- **`${var}` bracing.** Google "prefer brace-delimiting all other variables"; ShellCheck `require-variable-braces` is optional and off; most ecosystem code uses bare `$var`. Trend: not enforced by tooling; style choice only.
- **`set -euo pipefail`.** Google-style and Bash Strict Mode blog culture treat it as mandatory; BashPitfalls #60 lists three subsections of reasons not to rely on it, oils calls errexit fundamentally broken, ShellCheck's SC2310/2311 and optional `check-set-e-suppressed` exist to expose where it silently does not work. Debian Policy says "set -e or check the exit status of every command". Trend: toward explicit status checks and traps with `set -e` as a net, not a contract.
- **`local` in sh.** ShellCheck SC3043 flags it as undefined in POSIX sh; Debian Policy requires it; every measured sh except ksh93 runs it; rustup aliases to `typeset`. Trend: tooling still flags, practice accepts.
- **`readarray`/process substitution vs pipe-to-while.** Google recommends them; both are bash-only (process substitution also works in ksh93, zsh, busybox ash with the right build, not in dash/posh). Trend: POSIX scripts use temp files or here-docs.
- **Checksums and signatures for `curl | sh`.** Tooling pushes verification; critics note the checksum is only as trusted as the channel that serves it. No authoritative standard. Trend: function-wrap plus pinned versions plus package-manager alternatives.
- **shfmt tabs vs Google 2 spaces.** shfmt defaults to tabs (`-i 0`); Google specifies 2 spaces; `.editorconfig` overrides only when no flags are passed. Trend: whichever the repo's `.editorconfig` says; consistency over choice.
- **PowerShell `Write-Host`.** PSScriptAnalyzer `AvoidUsingWriteHost` is on by default; installers legitimately print to the host; the `ScriptingStyle` preset pairs it with `ProvideCommentHelp`. Trend: PowerShell 5+ routes `Write-Host` through the information stream, so the original objection weakened, but the rule remains default-on.
- **Execution policy.** Often presented as a guard rail in installers (`Set-ExecutionPolicy Bypass`); Microsoft states it is not a security boundary. Trend: documentation consensus is "defense in depth only".
- **Test framework choice for POSIX shells.** bats is bash-only (3.2 to 5.2); shellspec and shunit2 claim POSIX-shell coverage but shellspec's last repo activity in the clone is 2024-09-12. Trend: bats for bash, an unresolved gap for dash/ash.
