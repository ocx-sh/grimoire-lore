## Verdict

1. **Every network stall has a bound, and the right bound depends on the client kind.** An API-shaped client, whose responses are bounded (manifests, tokens, JSON), sets `Client.Timeout > 0`. A client that streams blobs of unbounded size leaves `Client.Timeout` at 0, because it would kill a live download. [fx] showed that at 5,120 of 10,240 bytes. That client bounds dial, TLS and time-to-first-byte on the transport, and bounds the body with an idle-read watchdog: a `time.AfterFunc` reset on every `Read` that makes progress, which cancels the request's own `context.WithCancelCause` context with a typed stall cause. go1.27.1 `net/http` has no per-`Read` body deadline of its own (`IdleConnTimeout` covers pooled connections between requests and `ResponseHeaderTimeout` covers only the headers, `transport.go:229,235`). [ssr] watched the difference: with no watchdog the read was still blocked 900 ms after the last byte, the watchdog failed it at 300.5 ms with `*StallErr` as the cause, and a 1 byte/100 ms trickle still finished. This **overrides [hcs]'s blanket "every client sets Timeout" MUST**. Binds CLIs, the SDK's bootstrap downloader and libraries.
   **Documented gap:** the watchdog is watched only on a bare `net/http` client. On go-containerregistry's pull path it can wrap only the outermost reader (`Layer.Compressed()`), and that wiring has not been fixtured ([ssr] Contested).
2. **Stdlib's redirect credential stripping does not protect a credentialed client.** It compares `Hostname()` only, ignoring scheme and port. [fx] watched the default client forward `Authorization: Bearer secret` over an https→http redirect. Any client that sends credentials therefore installs a `CheckRedirect` that keeps the 10-hop cap, refuses the downgrade and binds credentials to the origin (scheme, host, port). The shape comes from oras-go and from the fleet's own `ocx-sdk-python` C-005. This **replaces [hcs]'s "the default already does the safe thing" SHOULD**.
3. **Transports are cloned from `http.DefaultTransport`, never written as a bare `&http.Transport{}` literal.** A bare literal silently drops `HTTP_PROXY`/`HTTPS_PROXY` support and every dial, TLS and idle timeout. [fx] shows 0 proxy hits for the literal and 1 for the clone. The corpus has 73 bare literals against 10 clones.
4. **`go vet`'s `hostport` is not the check for `net.JoinHostPort`.** It inspects only `net.Dial`, `net.DialTimeout` and `(*net.Dialer).Dial`, so it is silent on `DialContext`, the form GO-CONC-03 mandates. A grep is the check.
5. **Response bodies: close on every path (a MUST); drain rarely (a SHOULD); bound every read (a MUST).** `bodyclose` stays a SHOULD (GO-GATE-19). Measured on regclient it is about 92% false positives, yet 2 real leaks sit inside that noise, so the close MUST is a reading heuristic. Stdlib already reuses a connection after `Close` when at most 256 KiB remains unread, so drain boilerplate only matters above that.
6. **Retry is a fleet decision, not a library default.** go-retryablehttp, go-containerregistry and oras-go all retry without checking the method, and two of the three mishandle `Retry-After`. The fleet retries only transport errors, 408, 429 and 5xx except 501. It retries only idempotent or replayable requests, with capped jittered backoff and both `Retry-After` forms.
   **Settled for go-containerregistry writes ([ssr]):** `remote.Write`, `WriteLayer` and `WriteIndex` do not replay a consumed body and do not leak the discarded response. Each upload runs under `retry.Never(ctx)` (`write.go:386,624`), so the status-code `retryTransport` is a no-op (`transport/retry.go:97-99`). Instead the whole upload session is retried: a fresh `POST`, a fresh `layer.Compressed()` and the same full `PATCH` body. The loop is `retry.Retry(tryUpload, w.predicate, w.backoff)` at `write.go:469`, and its predicate reads a hardcoded set, `temporaryStatusCodes` {408, 429, 500, 502, 503, 504} (`transport/error.go:153-160`). Measured: 8 requests over 2 TCP connections, so the 503 body was closed and the connection reused. This makes `remote.WithRetryStatusCodes` inert on writes; `WithRetryPredicate` is the lever that works. The default backoff adds at least 1 s to every retried write (measured 1.006–1.071 s). The one exception is read from source, not fixtured: a `*stream.Layer` returns `ErrConsumed` on the second `Compressed()` (`pkg/v1/stream/layer.go:132-139`), so a retried streaming-layer write fails loudly instead of replaying.
7. **Registry content is untrusted until it is verified at EOF.** Parse digests strictly. Stage every blob off its final path, then verify size and digest. Rename only after verification, and treat an existing target as success. Staging, not a lock, is the concurrency fix. This **promotes GO-IO-18 from SHOULD (unwatched) to MUST (watched)** as GO-NET-14.
8. **Library choice by code kind:** CLIs build registry access on `google/go-containerregistry` (`pkg/v1/remote`, `pkg/authn`) and wrap its four gaps (the fourth, write-path retry control, was found by [ssr]). The SDK imports no OCI library at all (stdlib only, owner Q2). Its only network surface is the bootstrap download, which mirrors `ocx-sdk-python`'s `_dist.py` contract. Services get the server rules as SHOULD-level hygiene (owner Q8), except `ReadHeaderTimeout`, which gosec already gates.
9. **The dist CDN's user-agent block did not reproduce.** On 2026-09-26, `https://setup.ocx.sh/dist.json` and the GitHub release asset it points to both returned 200 for `Go-http-client/1.1`, `Python-urllib/3.14` (the exact `urllib` default), `ocx-sdk-go/0.0.0` and `curl/8.5.0` [ssr]. That contradicts `_dist.py:23-24`. GO-NET-18 stays a SHOULD, now justified as cheap client identification rather than as avoiding a block.
   **Documented gap:** one request from one IP cannot rule out blocking by volume, reputation or TLS fingerprint. Whether the CDN blocks any user agent is unknown, not "no".

## Conflicts resolved

1. **ID collision.** Both dives numbered their candidates GO-NET-01..10. They are renumbered above; the dives' numbers are dead.
2. **"Every client sets `Timeout`" ([hcs] GO-NET-01, MUST) against registry blob streaming ([reg], and go-containerregistry itself sets no `Timeout`, `fetcher.go:76-79`).** [fx] `stream_test.go` shows `Client.Timeout` aborting a live stream. **Resolved:** split by client kind in GO-NET-06. [hcs]'s own Contested section anticipated `ResponseHeaderTimeout` for streaming but still wrote the blanket MUST.
3. **"The default client already does the safe thing on a cross-host redirect" ([hcs] GO-NET-06, SHOULD).** The source compares `Hostname()` only (`client.go:1031-1038`), and [fx] watched `Authorization` cross an https→http hop. **Resolved:** GO-NET-05 is a MUST on every credentialed client, and [hcs]'s SHOULD/MUST pair merges into it.
4. **`hostport` scope.** [hcs] and the map (M-H-11) say vet fires when the address "reaches `net.Dial`/`net.Listen`". The analyzer's callee list is `Dial`, `DialTimeout` and `Dialer.Dial` only (`hostport.go:166-170`), and [fx] watched it stay silent on `DialContext`. Combined with GO-CONC-03, vet catches nothing in compliant code. **Resolved:** the grep is the check (GO-NET-04).
5. **Where the 256 KiB auto-drain comes from.** [hcs] §3 cites `server.go:1164` (`maxPostHandlerReadBytes`) and `transfer.go:983-1012` (`doEarlyClose`). `doEarlyClose` is set only for server request bodies (`server.go:1098`). The client constant is `maxPostCloseReadBytes` (`transport.go:2420`, applied at `:2605`). The threshold is the same, the citation was wrong, and [fx] confirmed the behaviour at 1 KiB, 64 KiB and 2 MiB. **Resolved:** GO-NET-10 is a SHOULD with the corrected citation.
6. **Retry defaults in go-containerregistry.** [hcs] §4 says its retry is "opt-in — nothing is retried unless the caller names status codes". That holds for `transport.NewRetry`, but `remote.makeOptions` installs `defaultRetryStatusCodes` (408, 429, 500, 502, 503, 504, 499, 522) on every remote call (`options.go:95-104,142,179`). **Resolved:** all three reference libraries ignore the method, so the method check in GO-NET-11 is a fleet addition.
7. **Retry status set.** [hcs] retries "429, 503 and other 5xx except 501". The map (M-H-05) lists 408. oras-go retries every 5xx including 501. **Resolved:** transport errors, 408, 429 and 5xx except 501. 408 invites a repeat and 501 is permanent (RFC 9110 §15.5.9, §15.6.2). The set matches `ocx-sdk-python`'s C-005 classes.
8. **GO-IO-18 (SHOULD, "watched red: no") against [reg] GO-NET-04 (MUST, watched).** **Resolved:** MUST as GO-NET-14. io.md keeps GO-IO-18's ID as a one-line pointer to GO-NET-14 (IDs are never reused).
9. **[reg] "no lock needed" against GO-IO-19 (CLIs take locks).** The scopes differ: staging fixes blob ingest, and GO-IO-19 still governs mutable state. Windows (owner Q6) breaks [reg]'s POSIX-only "atomic replace" argument when the target is open, so GO-NET-14 treats a failed rename onto an existing same-digest target as success. GO-IO-17's bounded retry covers other rename failures.
10. **M-G-15 (format versioning) family.** The map files the row under GO-IO; the dive answered it as GO-NET. **Resolved:** GO-NET-15, because it is the only watched answer and the store is its first consumer. io.md carries a pointer line (see Open questions).
11. **[reg]'s library-choice argument cited the SDK's stdlib-only promise as a reason to pick go-containerregistry.** That reasoning is backwards. **Resolved:** go-containerregistry is for CLIs only. The SDK's network surface is the bootstrap download (the Go port of `_dist.py` C-005), and it uses stdlib `net/http`.
12. **`bodyclose` status.** GO-GATE-19 left regclient's 78 non-test hits unclassified. [hcs] classified them: 2 of 13 functions really leak and about 92% of hits are false positives. **Resolved:** GO-GATE-19's SHOULD stands, and GO-NET-09 is a MUST enforced by a reading heuristic.
13. **Item 6 said go-containerregistry installs `defaultRetryStatusCodes` "on every remote call".** [ssr] found that true for reads only. Writes wrap their context in `retry.Never` (`write.go:386,624`), so the status-code transport never retries them. Writes are retried whole, through the writer's predicate over `temporaryStatusCodes` (`transport/error.go:153-160`). **Resolved:** item 6's point stands, since neither path checks the method. GO-NET-17 gains gap (4).
14. **[ssr] AI-agent item 7 says `time.After` in a watchdog's `Read` "leaks one timer per `Read`".** GO-CONC failure mode 10 records that the leak was fixed in go 1.23 and the opt-out removed in 1.27. **Resolved:** `time.After` is still the wrong shape, but because nothing can reset or stop it and it cancels nothing. It does not leak.
15. **[ssr] §1 says the watchdog's copy error "wraps `context.Canceled`".** On the re-run, the go1.27.1 error text is the cause itself: `copyErr=stream stalled: …`. **Resolved:** GO-NET-06 prescribes `errors.As(context.Cause(ctx), &stall)` (GO-CONC-17), which is correct either way. Never assert on `ctx.Err()` or on the identity of the copy error.
16. **[ssr] AI-agent item 5 says a retried upload "starts a fresh session … no such bug exists".** That holds for ordinary layers. For a `*stream.Layer`, the second `Compressed()` call returns `ErrConsumed` (`pkg/v1/stream/layer.go:132-139`), matching the `write.go:319` comment "We can't retry streaming layers". **Resolved:** Verdict 6 records the exception, read from source and not fixtured. The failure is loud, so no rule changes.
17. **[ssr] candidates 2, 3, 4 and 6 overlap existing rules.** **Resolved:** the typed cause (candidate 2) cites GO-CONC-17. The `ResponseHeaderTimeout` plus watchdog pair (candidate 3) and the discouraged `SetReadDeadline` dialer (candidate 4) are folded into GO-NET-06. An explicit `WithRetryBackoff` (candidate 6) is folded into GO-NET-17. The follow-up adds no new ID.
18. **GO-NET-18's rationale (`_dist.py:25-29`: the CDN returns 403 for library user agents) against the 200s [ssr] measured live.** **Resolved:** the rule text and its SHOULD severity stay. The rationale no longer states a block as fact, and the verification is now watched (Verdict 9).

## AI-agent failure modes

Ranked by how often each one bites, judged by corpus frequency and tutorial prevalence:

1. **A bare `io.ReadAll(resp.Body)`** with no bound: 215 sites against 105 bounds. Check: the GO-NET-07 grep.
2. **A `&http.Client{}` with no timeout, or with `Timeout` on a blob stream.** 61% of literals lack a timeout, and a `Timeout` on a stream kills large pulls. Check: the GO-NET-06 constructor count plus a reading of the client kind.
3. **`&http.Transport{TLSClientConfig: cfg}`,** written to "just add TLS", which silently drops proxy support and every timeout (73 against 10). Check: the GO-NET-03 grep.
4. **Trusting stdlib redirect stripping.** Agents know the rule exists but not that it is blind to scheme and port. A custom `CheckRedirect` then drops the hop cap. Check: both GO-NET-05 locators.
5. **Retry that ignores the method and replays a consumed body,** copied from go-retryablehttp or oras-go defaults. Check: read the GO-NET-11 predicate for `req.Method` and `GetBody`.
6. **`Retry-After` parsed as an integer only.** Check: the GO-NET-08 grep.
7. **`fmt.Sprintf("%s:%d")` with a false sense of safety from `go vet`.** Check: the GO-NET-04 grep; vet is blind to `DialContext`.
8. **`defer resp.Body.Close()` on the success path only,** or a wrapper whose `Close` nobody traced. Check: the GO-NET-09 reading of the error branches.
9. **Treating "no error from `Read`" as "verified",** or comparing digests by prefix. Check: GO-NET-12/13 readings and the `HasPrefix(.*digest` grep.
10. **Writing a blob straight to its final path, then adding a `flock` to "fix" concurrency.** Check: the GO-NET-14 grep for `os.Create`/`O_TRUNC`.
11. **A credential helper whose exec error collapses into an anonymous request.** Check: the GO-NET-16 reading; errcheck/gosec only hint at it.
12. **`http.ListenAndServe(addr, h)` as the whole server.** Check: gosec G114 (GO-NET-01).
13. **`context.WithTimeout` presented as an "idle timeout" on a stream.** It bounds total time, so it kills a healthy large pull. Check: the GO-NET-06 reading of each `WithTimeout`/`WithDeadline` next to a body read loop.
14. **A watchdog whose `cancel` belongs to a different context than the request.** It cancels nothing, and the read never stops. Check: in the GO-NET-06 reading, the `WithCancelCause` variable must flow into both `NewRequestWithContext` and `Wrap`.
15. **`remote.WithRetryStatusCodes` on a push,** assumed to tune write retries. Check: the GO-NET-17 gap (4) locator.
16. **Citing another SDK's comment as a measured fact,** such as "the CDN rejects library user agents". Check: re-measure before copying a rationale across languages (GO-NET-18).
