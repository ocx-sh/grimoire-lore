## Verdict

1. **The gate is one ordered block** (SW-GATE-01): the format triple (1), the `Never*` rules on changed files (1b, adopted repositories), the K-07 tells (1c), `swift build -Xswiftc -warnings-as-errors` (2), `swift test` with the same flag and the SW-TEST-10 interop prefix (3), then API breakage (4) and DocC (5). Steps 4 and 5 bind libraries and the SDK; CLIs, servers and apps stop at step 3. A task is done when the applicable steps exit 0 on the tree named. The K-07 lines that a justification cannot clear mechanically are quoted in the pull request.
2. **Formatter of record is the toolchain's `swift format`, gated by the git-aware triple** (`format --in-place`, `lint --strict`, `git diff --exit-code`) over `git ls-files --cached --others --exclude-standard` (SW-GATE-02). Non-strict lint, a hand-typed directory and a tracked-only list each passed a planted violation.
3. **One root `.swift-format` with the full 43-rule block, 4 spaces and 120 columns for new repositories (owner Q2); an adopted repository's own formatter config always wins** (SW-GATE-04..06). SwiftFormat is a tolerated incumbent, never introduced and never chained (SW-GATE-09). An adopted repository that keeps `Never*` off still gets them on its changed files through a throwaway overlay (SW-GATE-28).
4. **The linter of record for escape hatches is the compiler's diagnostic groups plus the K-07 grep set, shipped as one script with a canary** (SW-GATE-10). A hatch passes only with an adjacent reason comment. SwiftLint is an advisory second reader, never the gate: 15 `custom_rules` matched the grep line for line and dropped 44 comment and string hits on three exemplars, but one `// swiftlint:disable:this` comment silences a rule and its own suppression rule while the E15 grep still prints it (SW-GATE-11), and the static binary exits 0 on a violating tree, so SwiftLint always runs through the SW-GATE-26 wrapper.
5. **Warnings: the CI flag `-Xswiftc -warnings-as-errors` on release-toolchain legs, nightlies exempt** (SW-GATE-13). The manifest form needs tools 6.2; settings that grow with the toolchain (`.treatAllWarnings`, newly added groups) need a pin or an environment switch in a library, while `StrictLanguageFeatures` and `ExplicitSendable` may be set unconditionally, because git and registry consumers never see a manifest setting and `path:` consumers see only the library's own error (SW-GATE-14, 29). Per-group promotion is a refinement: `UnknownWarningGroup` always, `StrictLanguageFeatures` with any enabled feature, `ExplicitSendable` for libraries and the SDK (SW-GATE-15..17). `ExplicitSendable` gates through `-Werror ExplicitSendable` or `.treatWarning("ExplicitSendable", as: .error)` (both exit 1 on a plant, 0 on the twin, 6.4.0 and 6.3.3); `-require-explicit-sendable` in any spelling is a no-op or a demotion and never a gate (SW-GATE-17). `@diagnose` always carries `reason:` and is guarded for 6.3 (SW-GATE-18).
6. **Library and SDK gates**: API breakage with full history and tags, and DocC with `.spi.yml` as part of the gate, because the shared docs check passes vacuously without it (SW-GATE-20, 21).
7. **CI hygiene**: SHA-pin every `uses:`, pass version lists explicitly (0.0.15 defaults omit 6.4), run merge-deciding gates inline because the shared scripts float, and keep a matrix of floor and current release (strict), one nightly (not strict) and each claimed platform (SW-GATE-23..25). Only the format step pins a toolchain patch.
8. **Not gates**: `--explicit-target-dependency-import-check` (silent on a planted violation, SW-GATE-22), `-require-explicit-sendable` (SW-GATE-17), SwiftLint's default rules (0 of 42 sampled hits were defects) and a universal coverage threshold (0 of 40 exemplars enforce one; the SDK floor and its command belong to SW-TEST-16, not to this block).
9. **One CI sanitizer job, filtered by report kind** (SW-GATE-27). `swift test --sanitize=thread` fails the job on `ThreadSanitizer: data race` only: correct `Mutex` classes produced only `Swift access race` reports (10 of 10 runs on 6.4, 0 `data race`), the three planted races produced `data race` (30 of 30 runs). It is a CI job, outside the local done-gate, and no suppression is ever written: none is scoped to `Mutex`, and name-based ones hid a real race. This supersedes the advisory-only clauses of SW-CONC-27 and SW-TEST-17.
10. **The four scripts write nothing into the work tree and work in a git worktree**: the K-07 script, the `Never*` overlay, the SwiftLint wrapper and the TSan check keep their scratch in `mktemp` files, and every "changed files" or "gate file diff" form compares against `git diff --merge-base "$BASE"`, never `HEAD` and never a two-dot diff. Two side effects are by design: gate step 1 rewrites files (`format --in-place`), and the two changed-files scripts stage `*.swift` with `git add -A` so that untracked files appear in the diff (the index changes, no file does).

### Documented gaps (the research established a gap, not an answer)

- **DocC on Swift 6.3.** The 6.3 harness fails the twin and the violation alike, so SW-GATE-21 is verified on 6.4 only. The macOS docs job is unverified: read only.
- **TSan filter blind spot (SW-GATE-27).** A real race that TSan reports only as `Swift access race` would pass the filter; none of the three plants was in that class (each also produced `data race`). A green run proves only the paths the tests execute. The cause of the `Mutex` report split is not established (the lock is inlined into the user module and no frame names `Synchronization`). The 6.3 evidence is single runs, not ten. swift-protobuf pins its sanitizer job to `swift:6.3` because "6.4 is failing for some reason" (its comment); the reason is unexplained. ASan is not measured here (SW-TEST-17 owns it).
- **SwiftLint as carrier (SW-GATE-11, 26).** The same-line `disable:this` hole; the custom-rule default mode is SourceKit although the rule description says SwiftSyntax (0.65.1); the dynamic binary was never run through the wrapper; the `excluded` scope tuning for directories not named `Tests` (216 of 733 production-rule hits in swift-nio sit under `Benchmarks`, `IntegrationTests`, `Example` or `Fixture` paths) is unmeasured. Re-run the static-trap rows after each SwiftLint bump.
- **`Never*` on changed files (SW-GATE-28).** File granularity: touching a dirty file costs a median of 3 findings (swift-nio: 131 of 309 source files carry one). A line-level or baseline-file variant was not built.
- **Manifest warning control (SW-GATE-29).** Measured for `StrictLanguageFeatures` and `ExplicitSendable` through git and `path:` consumers on both toolchains. That a library's `.treatAllWarnings` reaches a `path:` consumer is inferred from the same mechanism, not run.
- **ExplicitSendable demotion (SW-GATE-17).** That `-Xfrontend -require-explicit-sendable` demotes the group to an unpromotable warning is observed, not documented; re-run rows F, I and J of [GR5] at each toolchain bump.
- **Shared workflows.** The `swift_flags` and `swift_nightly_flags` fall-through and the floating `check-docs.sh` and `check-swift-format.sh` need one real Actions run (unverified: read only). Windows and macOS legs of every rule are unverified: read only (owner Q7).

## The ruleset

Conventions. A grep check's **output is the violation; empty output is a pass**; judge by the printed lines, never the exit status (`grep` exits 1 on no match, and 123 behind `xargs`). A "Red" line says whether the check was watched going red on a planted violation and green on a compliant twin; cites are to the dives' Verification runs (`[FL V..]`, `[WC R..]`, `[LC V..]`) or to this consolidation's runs (`[GC..]`, `[GR..]`). Commands use shell variables (`$BASELINE`, `$DOCC_TARGET`, `$GROUP`, `$FILE`, `$ALLOWLIST`, `$BASE`), never angle-bracket placeholders. `$BASE` is the merge target (`origin/main` in CI). Floors are Swift versions the rule assumes. "Binds" names the code kind: library (published package), SDK (the future Swift wrapper around the ocx CLI), CLI, server, Apple app, test code. The first severity word in a heading is the rule's severity; a MUST sentence inside a SHOULD rule (SW-GATE-17) is a sub-clause and not counted as a MUST rule. Four rules are scripts, not one-liners: `k07.sh` (SW-GATE-10), `swiftlint-gate.sh` (SW-GATE-26), `tsan-check.sh` (SW-GATE-27) and `never-gate.sh` (SW-GATE-28). Each is quoted in full in its rule, was run as quoted ([GR1], [GR2], [GR4], [GR6], [GR8]), writes nothing into the work tree (scratch is a `mktemp` file removed on exit; `k07.sh` with `BASE` and `never-gate.sh` stage `*.swift` with `git add -A`, which changes the index and no file) and works in a git worktree, where `.git` is a file; save the text under the name given and run it from the repository root.

### A. The gate itself (a command runs; the exit status is the verdict)

**SW-GATE-01 (MUST).** Run the gate block in order and call a change done only when every applicable step exits 0 on the tree you changed; name the command, the exit code and the tree. A step-1c line that is justified in writing (SW-GATE-10) is quoted in the pull request next to the exit code.

```sh
# 1 SW-GATE-02: format triple (formatting, lint-only rules, clean tree); 123 = a finding behind xargs
git add -A -- '*.swift' \
  && git ls-files -z --cached --others --exclude-standard -- '*.swift' | xargs -r -0 swift format format --parallel --in-place \
  && git ls-files -z --cached --others --exclude-standard -- '*.swift' | xargs -r -0 swift format lint --strict --parallel \
  && git diff --exit-code -- '*.swift'
# 1b SW-GATE-28: the Never* rules on changed files (adopted repositories whose .swift-format keeps them off; harmless elsewhere); 123 = a finding
BASE=origin/main bash never-gate.sh
# 1c SW-GATE-10: the K-07 tells, canary first; any output line is a violation; BASE only in an adopted repository (new repositories scan the whole tree)
BASE=origin/main bash k07.sh
# 2 build: warnings are errors (SW-GATE-13)
swift build -Xswiftc -warnings-as-errors
# 3 test: runs XCTest and Swift Testing; the variable pins XCTest interop to complete on 6.4+ legs whose manifest tools version is below 6.4 (SW-TEST-10) and is ignored below 6.4
env SWIFT_TESTING_XCTEST_INTEROP_MODE=complete swift test -Xswiftc -warnings-as-errors
# 4 libraries and SDK with tagged releases: no breaking public API versus $BASELINE (SW-GATE-20)
swift package diagnose-api-breaking-changes "$BASELINE"
# 5 libraries and SDK with doc targets in .spi.yml: DocC builds clean (SW-GATE-21)
swift package plugin generate-documentation --target "$DOCC_TARGET" --warnings-as-errors --analyze
```

- Why: format is the cheapest step, the two diff-scoped checks need no build and a planted defect must fail at its own step, the build surfaces warnings before tests, and only consumers of a library need the API and docs steps; each planted variant failed at its own step. The `git add` line is the local prefix; a CI checkout is clean and omits it (SW-GATE-02). Without the step-3 prefix a `@Test` that calls `XCTAssertEqual(1, 2)` exits 0 on 6.4.0 at tools 6.2 (C17).
- Check: the block; any non-zero exit stops it. Add `--force-resolved-versions` to steps 2 and 3 per SW-GATE-03. ### C. Escape-hatch greps, SwiftLint and weakening surfaces (grep with a directory operand, or `swiftlint`)

**SW-GATE-10 (MUST).** On every change that adds or touches non-test Swift, run `k07.sh` (the K-07 agent-tell set below, with a canary in front: whole tree in a new repository, `BASE="$BASE"` in an adopted one), remove each hit or justify it in writing, and treat the script's exit status as the verdict (1 on any output line); a hatch (`@unchecked Sendable`, `nonisolated(unsafe)`, `Task.detached`, `@preconcurrency`, `MainActor.assumeIsolated`) passes only when its line or the line above carries a multi-word comment stating the guard, and the script prints only the hatches that lack one. ```bash
#!/usr/bin/env bash
# k07.sh: the K-07 agent-tell set (SW-GATE-10). Run from the repository root. OUTPUT IS THE VIOLATION.
#   bash k07.sh                    canary, then every tell over the whole tree; exit 1 on any output line
#   BASE=origin/main bash k07.sh   the same, keeping only lines in Swift files changed since the merge base (adopted repositories)
#   bash k07.sh e01 e06            the raw grep of single entries (inventory: a justified hatch prints too)
P=(--include='*.swift' --exclude-dir='.build' --exclude-dir='Tests')
# E01 @unchecked Sendable, E02 nonisolated(unsafe), E03 Task.detached (SW-CONC; E01 E02 E03 E06 run through hatches() in the gate)
e01() { grep -rn "${P[@]}" -F -e '@unchecked Sendable' .; }
e02() { grep -rn "${P[@]}" -F -e 'nonisolated(unsafe)' .; }
e03() { grep -rn "${P[@]}" -F -e 'Task.detached' .; }
# E04 GCD (SW-CONC, map conflict 19); E05 MainActor.run (a tell and not a ban, map conflict 24)
e04() { grep -rn "${P[@]}" -F -e 'DispatchQueue.' -e 'DispatchQueue(' -e 'DispatchSemaphore' -e 'DispatchGroup' .; }
e05() { grep -rn "${P[@]}" -F -e 'MainActor.run' .; }
# E06 isolation hatches that need a justification (SW-CONC); E07 blocking or legacy sleeps in production code (SW-CONC)
e06() { grep -rn "${P[@]}" -F -e '@preconcurrency' -e 'MainActor.assumeIsolated' .; }
e07() { grep -rn "${P[@]}" -e 'Thread\.sleep' -e '[^.A-Za-z_]usleep(' -e 'Task\.sleep(nanoseconds' .; }
# E08 sleeps in tests: the SW-TEST-03 grep, whole-tree form (reads only Tests; silent when there is no Tests directory)
e08() { [ -d Tests ] || return 0; grep -rn --include='*.swift' -e '^usleep(' -e '^nanosleep(' -e '^sleep(' -e '[^[:alnum:]_]usleep(' -e '[^[:alnum:]_]nanosleep(' -e '[^[:alnum:]_]sleep(' Tests | grep -v -E -e 'func +sleep\(' -e 'func +usleep\(' -e 'func +nanosleep\('; }

e09() { grep -rn "${P[@]}" -F -e 'try!' -e ' as! ' .; }
e11() { grep -rn "${P[@]}" -e '[^A-Za-z_]Process()' -e NSTask -e '\.launchPath' .; }
e12() { grep -rn "${P[@]}" -F -e 'ObservableObject' -e '@Published' -e '@StateObject' -e '@ObservedObject' -e '@EnvironmentObject' .; }
# E13 completion-handler APIs and E14 pre-Mutex locks (SW-CONC)
e13() { grep -rn "${P[@]}" -e 'completion[A-Za-z]*: *@escaping' -e '@escaping *(Result<' .; }
e14() { grep -rn "${P[@]}" -F -e 'NSLock' -e 'NSRecursiveLock' -e 'os_unfair_lock' -e 'pthread_mutex' .; }
# E15 linter suppressions, tests included (SW-GATE-12)
e15() { grep -rn --include='*.swift' --exclude-dir='.build' -F -e 'swift-format-ignore' -e 'swiftlint:disable' -e 'swiftformat:disable' .; }
# E16 exit() outside the entry point: the SW-CLI-03 grep, one -e per alternative
e16() { grep -rn "${P[@]}" -e '^exit(' -e '[^.[:alnum:]_]exit(' -e '\bGlibc\.exit(' -e '\bDarwin\.exit(' -e '\bMusl\.exit(' -e '\bFoundation\.exit(' -e '\bucrt\.exit(' -e '\b_exit(' .; }
# E01 E02 E03 E06 pass only with a multi-word comment on the line or the line above: print the unjustified ones
hatches() {
  git ls-files -z --cached --others --exclude-standard -- '*.swift' ':(exclude)Tests' | xargs -r -0 awk '
    FNR == 1 { prev = "" }
    /@unchecked[[:space:]]+Sendable|nonisolated\(unsafe\)|Task\.detached|@preconcurrency|MainActor\.assumeIsolated/ {
      if ($0 !~ /\/\/[[:space:]]*[^[:space:]]+[[:space:]]+[^[:space:]]+[[:space:]]+[^[:space:]]+/ &&
          prev !~ /^[[:space:]]*\/\/[[:space:]]*[^[:space:]]+[[:space:]]+[^[:space:]]+[[:space:]]+[^[:space:]]+/)

    }
    { prev = $0 }'
}
canary() { grep -rl --include='*.swift' --exclude-dir='.build' -e 'import ' . | awk 'END { if (NR == 0) { print "K07 CANARY: no Swift file scanned" > "/dev/stderr"; exit 1 } }'; }

  git diff --name-only -z --diff-filter=ACMR --merge-base "$BASE" -- '*.swift' | tr '\0' '\n' | sed -e 's|^|./|' -e 's|$|:|'
}
k07() {

}

### G. Lint carriers, sanitizer job and changed-files gates (added in the revision; a script runs and its exit status is the verdict)

**SW-GATE-26 (MUST wherever a SwiftLint `custom_rules` gate, hook or editor check is configured).** Run SwiftLint through the wrapper below, which exits 70 when SwiftLint printed `Skipping enabled rule`, and never use the static `swiftlint` (`swiftlint-static`, the binary on a bare Linux PATH) for `custom_rules`.

The script, verbatim as run (save as `swiftlint-gate.sh`; `SWIFTLINT` is the command prefix as single-space-separated words, `SWIFTLINT_CONFIG` the config):

```bash
#!/usr/bin/env bash
# SW-GATE-26: SwiftLint through a wrapper that fails when it skipped a rule.
# SWIFTLINT = the command prefix, words separated by single spaces (no quoting inside it); SWIFTLINT_CONFIG = the config.
# Exit: 70 a rule was skipped (the carrier did not run); otherwise SwiftLint's own code (2 violations, 0 clean, 134 abort).
read -r -a cmd <<<"${SWIFTLINT:-swiftlint}"
log=$(mktemp); trap 'rm -f "$log"' EXIT
"${cmd[@]}" lint --config "${SWIFTLINT_CONFIG:-.swiftlint.yml}" --no-cache --quiet "$@" > "$log" 2>&1
rc=$?
cat "$log"
if grep -q -F -e 'Skipping enabled rule' "$log"; then
  echo 'FAIL: SwiftLint skipped an enabled rule; use the SourceKit image (the static binary skips custom_rules)' >&2
  exit 70
fi
exit "$rc"
```
